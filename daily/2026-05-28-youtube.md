### [The maturity phases of running evals — Phil Hetzel, Braintrust](https://www.youtube.com/watch?v=FB-MLPhL9Ms) — AI Engineer (?min, category: ai-agents)
**TL;DR:** Don't eval like unit tests — enumerate known failure modes, build a production-trace flywheel, and brace for the hard part: evaluating CRUD tool calls. _(transcript unavailable — summary based on title + description only)_

**Key insights:**
- Reframe: not exhaustive unit-test-style coverage, but enumerate your known failure modes, cover those, ship — then let production traces surface new ones in a flywheel back into offline experimentation. Directly applicable to Ara's eval strategy.
- Four maturity stages: (1) vibe-checking with documented human justifications (not thumbs up/down), (2) LLM-as-judge built from those justifications at scale, (3) tool calls where context-gathering tools are manageable, (4) CRUD tools, the hard case, because you must reconstruct external-system state at the exact moment the trace ran.
- Concrete CRUD-eval techniques: timestamp queries against a vector DB, and injecting captured system state directly into the trace. Reusable patterns for Ara once it touches stateful tools.

**Tools mentioned:** Braintrust, LLM-as-judge, vector database

**For /bookmark:** `https://www.youtube.com/watch?v=FB-MLPhL9Ms`
