### [Can LLMs generate Enterprise Quality Code? — Prasenjit Sarkar, Sonar](https://www.youtube.com/watch?v=NuePCNMpWGc) — AI Engineer (~15min, category: ai-agents)
**TL;DR:** Sonar benchmarked 53 LLMs on 4,444 Java assignments — Claude Sonnet 4.6 has the highest security-issue rate (300/M LOC), and they propose an ACDC pipeline (guide → verify → solve) with pre-commit SonarQube in 1–5s.

**Key insights:**
- Concrete leaderboard: pass rate, cyclomatic complexity, bug density, and security issues per model — GPT-4o produced <250K LOC for the suite; GPT 5.4 produced 1.2M; Claude Sonnet 4.6 produced 627K but with the worst security-issue rate.
- ACDC framework: static analysis runs pre-commit (1–5s) instead of CI (1–5min); a remediation agent then proposes one fix per remaining issue, re-runs analysis + compilation, and only surfaces fixes that don't regress.
- Useful counterweight to "AI writes great code" hype — Justin's Ara/Familiars stack should consider a verify-before-commit step rather than trusting model output blind.

**Tools mentioned:** SonarQube, Sonar's ACDC framework

### [Engineering voice agents: Latency, quality, and scale — Rishabh Bhargava, Together AI](https://www.youtube.com/watch?v=N7b1PJc7SFc) — AI Engineer (~20min, category: ai-agents)
**TL;DR:** Concrete latency budget for voice agents — users hang up above 1s; LLM dominates (200–300ms TTFT, 8–30B param sweet spot); colocating STT+LLM+TTS drops 75ms cross-DC overhead to ~5ms.

**Key insights:**
- Specific numbers: STT target P90 <100ms with ~6% WER; LLM 200–300ms TTFT; networks across data centers add 30% latency overhead in an already-optimized pipeline.
- Model-size tradeoff is real: <8B breaks tool calling; >30B blows the latency budget. The 8–30B band is the working range for real-time voice.
- "Small thinker + big tool call" pattern: tiny LLM handles conversation flow at speed, delegates complex requests via a single tool call to a larger model — keeps the fast path fast without sacrificing capability. Directly applicable to Ara if voice is on the roadmap.

**Tools mentioned:** Together AI's hosted inference stack

### [Spec-Driven Testing for Agents With A Brain the Size of A Planet — Steven Willmott, SafeIntelligence](https://www.youtube.com/watch?v=UQKg0td-Bf4) — AI Engineer (~20min, category: ai-agents)
**TL;DR:** Bigger models aren't automatically safer — they understand jailbreaks (e.g., malicious instruction wrapped in a poem) that small models ignore; agents need explicit specs covering rules, ontologies, roles, and robustness — not just test datasets.

**Key insights:**
- Spec ≠ test dataset. An agent spec should include explicit rules ("never offer more than 10% discount"), a domain ontology (an airline agent only handles destinations its airline actually flies), roles/rights, and robustness criteria (how many typos or rephrasings before it breaks).
- Specs must be written independently of implementation so they survive model swaps. They then drive both security/red-team testing and iterative improvement — same artifact, two uses.
- Counterintuitive safety result: large models execute disguised malicious instructions that small models can't even parse. More capability = bigger attack surface. Worth keeping in mind when picking the model for Ara's tool-using paths.

**Tools mentioned:** Safe Intelligence platform

**For /bookmark:** `https://www.youtube.com/watch?v=UQKg0td-Bf4`
