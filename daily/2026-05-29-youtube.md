### [Poolside Laguna M.1/XS.2 Technical Report — Paper Club](https://www.youtube.com/watch?v=QLfZamyMls0) — Latent Space (~55min, category: ai-agents)
**TL;DR:** Latent Space paper club breaks down Poolside's "Model Factory" — a fully programmatic training stack that took a 33B model from kickoff to release in five weeks. _(transcript unavailable — summary based on title + description only)_

**Key insights:**
- The headline is process, not the model: data pipelines, architecture choices, scaling-law derivation, and eval harnesses all live as code in one repo, so model building becomes repeatable automated experiments. This is the same "everything is code, runs are reproducible" discipline Justin should want for Ara's eval/agent-loop experiments — the velocity (5 weeks, small model) comes from the automation, not heroics.
- Concrete architecture notes worth filing: Token-Choice routing with 8/256 experts + 1 shared expert, interleaved sliding-window/global attention at a 3:1 ratio, and the first transformer layer kept dense for training stability. Useful reference points when reading any 2026 MoE report.
- Data strategy inverts the usual playbook: they prioritize *labeling over filtering* to recover high-quality docs that rule-based filters discard (30T tokens, 128k long-context stage). The transferable idea for agent pipelines — relabel/recover borderline data instead of hard-dropping it.
- Dagster control plane + a "Titan" infra library give end-to-end lineage and agent workflows over the training runs; explicit attention to reliability/hardware-fault recovery and benchmark reward-hacking in eval harnesses. The reward-hacking warning echoes the recurring "your eval harness is lying to you" theme from this week's AI Engineer talks.

**Tools mentioned:** Poolside Laguna (225B + 33B), Dagster, Titan (infra library), MoE / Token-Choice routing, sliding-window + global attention

### [How agent o11y differs from traditional o11y — Phil Hetzel, Braintrust](https://www.youtube.com/watch?v=XBaznoTRDFI) — AI Engineer (?min, category: ai-agents)
**TL;DR:** Braintrust built a database from scratch for agent observability — traces can exceed 1GB, single spans hit 20MB, and "is the system up?" is the wrong question. _(transcript unavailable — summary based on title + description only)_

**Key insights:**
- The core reframe for Ara's observability: agent telemetry is semistructured, text-heavy, real-time, and *huge* (GB-scale traces) — uptime-era tooling can't ingest or query it. If Justin instruments Ara's agent loops, plan for trace storage/search as a first-class problem, not an afterthought bolted onto logs.
- Their architecture is a concrete reference: write-ahead log for instant visibility + analytical indexes for fast filtering + a forked Tantivy (Rust full-text search, Lucene-like) so any engineer can grep every trace mentioning a specific word. Full-text search over traces is the feature to copy.
- The human-in-the-loop scoring model is the most portable idea: domain experts (clinicians, lawyers, advisers) open traces directly and grade agent responses; their *written justifications* become the training signal for automated scoring functions. Humans surface failure modes, scoring functions scale them — exactly the eval flywheel Ara needs.
- This is a different, more technical Braintrust talk than the org-design one from the 05-26 digest; watch this one for the infra, that one for the buyer/positioning argument.

**Tools mentioned:** Braintrust, Tantivy (Rust full-text search), write-ahead log, analytical indexes

- Throughput framing to quote: GitHub averaged ~275M commits/week in 2025 (tracking to ~14B/year) while approval infrastructure was never designed for that volume — the case for making governance executable.

### [Context Graphs for Explainable, Decision-Aware AI Agents — Andreas Kollegger & Zaid Zaim, Neo4j](https://www.youtube.com/watch?v=abvQEhvRI_c) — AI Engineer (?min, category: ai-agents)
**TL;DR:** Neo4j argues agents need the *why*, not just knowledge and tools — context graphs encode policies, rules, and prior decisions so each action is explainable in context. _(transcript unavailable — summary based on title + description only)_

**Key insights:**
- "Reference class validation" is the sharp idea: a drug correct 99% of the time is still fatal in the 1% case, and statistics alone don't tell the agent which group it's in — so before acting, the agent must establish its reference class. A useful safety primitive for any Ara action that has rare catastrophic outcomes.
- The five-stage decision framework is a concrete agent-architecture template: (1) frame the problem with causality + environment, (2) pull global rules + past precedent, (3) run a risk/value analysis, (4) act *or* escalate to an authority, (5) write the full reasoning chain back into the graph.
- Step 5 is the compounding mechanism — every decision becomes precedent and future agents inherit it. This is the "living memory" moat from the Accenture talk, implemented concretely on a graph. Strong pairing to watch back-to-back.
- For Ara specifically: a context graph of policies + prior decisions is a candidate substrate for explainable agent memory, and the explicit act-or-escalate branch is a clean pattern for human-in-the-loop gating.

**Tools mentioned:** Neo4j, context graphs / knowledge graphs

**For /bookmark:** `https://www.youtube.com/watch?v=abvQEhvRI_c`
