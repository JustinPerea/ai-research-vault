# AI Research Digest — Friday, November 20, 2026

## TL;DR
- **Beyond Weight Updates** (compare) — Run a reflective evolutionary optimizer over prompts, tool schemas and skills per domain before considering fine-tuning.
- **How Feedback-Free Self-Evolution Reshapes Agent Skills** (try-now) — Protect expert-written skill content from unattended self-rewriting and re-add knowledge outside the model prior.
- **DriftGuard** (compare) — Score each retrieved memory for risk before it enters the context for a tool call.
- **CompAct-Bench** (compare) — Evaluate compaction prompts by resuming a recorded trajectory and measuring task completion.
- **MemMend** (compare) — Gate answer revision behind a router and accept only edits that cite source spans.
- **HabitusMem** (compare) — Store preferences as beliefs with evidence, scope and status rather than raw history.
- **How Much Should an Agent Remember? Deployment Lessons from Self-Distilled Memory for LLM Agents** (compare) — Select the number of injected guidelines per model instead of always injecting all.
- **CANDID** (try-now) — Filter repeated actions and require consensus before accepting DONE.
- **Forget Freely, Grep Later** (try-now) — Keep an append-only log and expose a regex search tool instead of a vector store.
- **Evolve Where It Matters** (compare) — Label each skill instruction per run before editing the skill.
- **MATE** (try-now) — Insert an allow/block/ask layer between proposed UI actions and device effects.
- **Tether** (compare) — Track data-flow labels across steps and enforce them on observed side-effects.
- **Characterizing and Detecting Unfaithful Work Reports by Coding Agents** (try-now) — Cross-check an agent's work report against tool traces before handing off or accepting.
- **SkillBridge** (compare) — Statically screen skills for OS assumptions before running them on each OS.
- **Stop Going in Circles** (compare) — Escalate to a stronger model only when state-action repeats are detected.

## Items
### 1. Beyond Weight Updates: Evolving Agent Harnesses for Domain Specialization
- **Source:** arXiv (new submission)
- **Link:** https://arxiv.org/abs/2611.25380v1
- **Authors/org:** BoHao Chen
- **Focus area:** Evolving agent harnesses
- **What it is:** Evolves the harness (system prompt, tool schemas, skill library, planning scaffolding) with GEPA while the policy stays frozen; tested with a Claude Code-style agent on SWE-bench Verified, OfficeBench, Terminal-Bench.
- **Why it matters for Justin's agents:** Harness evolution recovers most of the gains of weight updates at a small fraction of the compute; a per-domain harness adapter fits a Claude Code / MCP stack with no GPU.
- **Action signal:** compare

### 2. How Feedback-Free Self-Evolution Reshapes Agent Skills: A Systematic Study
- **Source:** arXiv (new submission)
- **Link:** https://arxiv.org/abs/2611.25534v1
- **Authors/org:** Litao Guo, Man Chen, Xinli Xu, Jinsong Zhou, Zixin Zhang, Ying-Cong Chen
- **Focus area:** Agent skills
- **What it is:** Lets models rewrite expert skills round after round with no feedback; skills lose value, and SkillDiff marks the expert knowledge the model would not write itself.
- **Why it matters for Justin's agents:** Do not let an agent auto-rewrite skill files unattended; keep the human-authored parts and mark them.
- **Action signal:** try-now

### 3. DriftGuard: Online Memory-Drift Detection via Causal Attribution for LLM Agents
- **Source:** arXiv (new submission)
- **Link:** https://arxiv.org/abs/2611.25583v1
- **Authors/org:** Licheng Pan, Yuzhou Chen, Zhixuan Chu, Yichen Sun, Han Zheng, Zhiyu Wang et al.
- **Focus area:** Memory security
- **What it is:** DriftGuard estimates online which retrieved memory would change an agent's behaviour (memory drift), using offline counterfactual replays to train a cheap online risk model.
- **Why it matters for Justin's agents:** Persistent memory is an attack surface for a day-admin agent; gives a serving-time way to score retrieved memories before the agent acts.
- **Action signal:** compare

### 4. CompAct-Bench: A Benchmark for Working-Context Compaction in Long-Horizon Agent Tasks
- **Source:** arXiv (new submission)
- **Link:** https://arxiv.org/abs/2611.25673v1
- **Authors/org:** Jiayi Chen, Lizhe Chen, Yujia Chen, Shihan Dou, Ming Zhang, Chendi Ge et al.
- **Focus area:** Context compaction
- **What it is:** CompAct-Bench measures a compactor by inserting compaction boundaries into successful agent trajectories and letting the same executor continue, at controlled retention ratios.
- **Why it matters for Justin's agents:** Directly relevant to how Claude Code-style compaction should be judged: by downstream task completion, not summary quality.
- **Action signal:** compare

### 5. MemMend: A Selective Revision Framework for Memory Question Answering
- **Source:** arXiv (new submission)
- **Link:** https://arxiv.org/abs/2611.25721v1
- **Authors/org:** Sheng Shi, Geng Li
- **Focus area:** Memory QA
- **What it is:** MemMend routes potentially incomplete memory answers to an editor that makes bounded exact-text replacements and accepts only edits with resolvable source coordinates.
- **Why it matters for Justin's agents:** A cheap gate for memory answers: revise only when likely incomplete; the editing interface also improves Mem0 answers.
- **Action signal:** compare

### 6. HabitusMem: Belief Memory over Evolving User Preferences for LLM Agents
- **Source:** arXiv (new submission)
- **Link:** https://arxiv.org/abs/2611.25855v1
- **Authors/org:** Yifan Lu, Gaoyang Guo, Wen Chen, Ziyun Zou, Jian Wu, Han Zhu et al.
- **Focus area:** Personal memory
- **What it is:** HabitusMem treats memory as the assistant's belief about the user: a trained writer states beliefs with evidence, scope and status for a frozen agent.
- **Why it matters for Justin's agents:** Directly on point for a personal agent whose user preferences change; stores whether a preference is still current and where it applies.
- **Action signal:** compare

### 7. Context as a Resource
- **Source:** arXiv (new submission)
- **Link:** https://arxiv.org/abs/2611.26346v1
- **Authors/org:** Xufei Tian, Han Hu, Wenli Du
- **Focus area:** Always-on agent context
- **What it is:** ClonAct virtualizes context blocks with a non-generative Context MMU, Context Cells, a Synaptic Bus with trial merge gate, and a shared trunk, for concurrent tasks behind one interface.
- **Why it matters for Justin's agents:** Addresses cross-topic bleed in a single always-on personal-agent session and merge conflicts across parallel work.
- **Action signal:** track

### 8. How Much Should an Agent Remember? Deployment Lessons from Self-Distilled Memory for LLM Agents
- **Source:** arXiv (new submission)
- **Link:** https://arxiv.org/abs/2611.26361v1
- **Authors/org:** K. R. Jayaram, Vatche Isahagian, Aswath Vaithinathan Aravindan, Vinod Muthusamy, Punleuk Oum, Gaodan Fang et al.
- **Focus area:** Agent memory
- **What it is:** Mines lessons from an agent's own trajectories, consolidates them into guidelines, and gives all or a subset at inference; shipped in altk-evolve, used in IBM CUGA.

- **Action signal:** compare

### 12. Forget Freely, Grep Later: Lossless, Index-Free Memory for Long-Horizon LLM Agents
- **Source:** arXiv (cross-list)
- **Link:** https://arxiv.org/abs/2611.25123v1
- **Authors/org:** Ziyan Yang, Taiwei Shi, Jieyu Zhao
- **Focus area:** Agent memory
- **What it is:** GrepMem keeps an append-only plain-text log of full history and a regex search tool for recall; no embeddings, index or extraction model.
- **Why it matters for Justin's agents:** A lossless, index-free memory that matches how Claude Code already greps files; trained on Qwen3.5-9B so it fits local models.
- **Action signal:** try-now

### 13. Some Memories Must Fade: Persistence and Decay of User Memories in Model Parameters

- **What it is:** A fixed-capacity LoRA adapter with k-hot rank combinations and independent temporal decay, governed by a learned controller deciding what to remember and for how long.

### 14. Evolve Where It Matters: Coverage-Guided Self-Evolution of Agent Skills

### 16. Tether: Verified Stateful Policy Engine for System-Level Monitoring of Agents
- **Source:** arXiv (cross-list)
- **Link:** https://arxiv.org/abs/2611.25599v1
- **Authors/org:** Meghana Aparna Sistla, Alaia Solko-Breslin, Somesh Jha, Aditya Kanade, Krishnamurthy Dj Dvijotham
- **Focus area:** Agent runtime guard
- **What it is:** Tether runs each action in an ephemeral sandbox, infers semantics from system calls, and enforces stateful policies written in a Lean 4 DSL (IFC, access control, network).
- **Why it matters for Justin's agents:** Stateful policy enforcement catches multi-step data flows that stateless allowlists miss for shell-running agents.
- **Action signal:** compare

### 18. Characterizing and Detecting Unfaithful Work Reports by Coding Agents
