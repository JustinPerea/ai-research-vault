# AI Research Digest — Saturday, July 11, 2026

## TL;DR
- **Memory (headline)** — Meta's [arxiv:2607.08716] **Remember When It Matters** flips passive retrieval to a **proactive memory agent** running alongside the action agent: it decides *when* to inject reminders instead of what to store. On a Qwen3.5-27B action agent it lifts Terminal-Bench 2.0 pass@1 by **+8.3 pp** and τ²-Bench pass@1 by **+6.8 pp**, and — crucially — beats **passive retrieval, continuous injection, advisor-only, and general RAG** in the ablation. Plug-and-play over existing action agents. First strong data point that the "memory should be an agent that intervenes, not a store the actor polls" thesis is the winning architecture.
- **Local models (headline)** — [arxiv:2607.07964] **KronQ** (COLM 2026) makes **2-bit LLaMA-3-70B usable**: WikiText-2 perplexity **7.93** where GPTQ / GPTAQ collapse to **>2000** at the same bit-width. Kronecker-factored Hessian with gradient covariance + bidirectional incoherence + gradient-informed mixed-precision allocation. On M5 Max 64 GB this puts a 70B model in ~18–20 GB of weight memory with headroom for KV cache — the first credible route to running a compressed 70B locally without spilling. `local-fit` of the week.
- **Orchestration / reliability** — [arxiv:2607.08028] **From Prompts to Contracts** ships the auditable-agent architecture: enforcement moves from prompts into code + manifests + validators. Head-to-head result: **prompt-only permits safety violations; a bolt-on guardrail over-refuses (88/120 utility); the harness scores 120/120 utility while catching every deliberately-injected contract break**. Same paper: 3-model substitution across 270 runs with failures cleanly isolated to the model-composed layer. This is the deployment-time analog of yesterday's [arxiv:2607.07405] Reason-Less-Verify-More gates.
- **Orchestration / debugging** — [arxiv:2607.07989] **AgentLocate** (COLM 2026) attacks the "who broke it?" question for multi-agent runs: LLM judge + independent evaluators + confidence-weighted aggregation + lightweight adaptive fine-tuning. Consistently beats existing failure-localization methods at identifying **both** the responsible agent and the earliest decisive step, at lower token / wall-clock cost. Direct fit for Justin's autonomous-loop stack — this is the missing "root-cause primitive" for durable agents.
- **Orchestration / web** — [arxiv:2607.08662] **WebSwarm** — recursive multi-agent search that first probes how information is organized on the web, then dynamically instantiates child search nodes with per-node objective + search mode, reusing process experience across sibling nodes. Beats single-agent and prior multi-agent baselines on BrowseComp-Plus / WideSearch / DeepWideSearch / GISA. The "probe first, then delegate recursively" pattern is the operational shape of a deep-research MCP tool.
- **Long-context evaluation** — [arxiv:2607.08284] **PredicateLongBench** — instead of NIAH or multi-hop, ask the model to find the longest contiguous subsequence satisfying a predicate (e.g., lexicographic order). LLM-judge-free, systematically scales along explicit difficulty axes, and **frontier models degrade as difficulty scales** — the anti-saturation benchmark long-context has been missing. Pair with yesterday's Jet-Long as the natural harness.
- **Inference speed** — [arxiv:2607.08642] **DominoTree** — training-free speculative decoding combining tree-drafting with Domino's GRU causal correction: **up to 6.6× speedup, 10.7-token mean accept length**, +9–10% throughput over the Domino decoder baseline, up to +22% on Alpaca. Direct Qwen3-4B / 8B fit — the local-decoder line item on M5 Max.

## Items

### 1. Remember When It Matters: Proactive Memory Agent for Long-Horizon Agents
- **Source:** arXiv (cs.CL) — HF Daily Papers
- **Link:** https://arxiv.org/abs/2607.08716
- **Authors / org:** Yifan Wu, Lizhu Zhang, Yuhang Zhou, Mingyi Wang, Bo Peng, Serena Li, Xiangjun Fan, Zhuokai Zhao (Meta Research)
- **Focus area:** Agent memory
- **What it is:** A dedicated **memory agent** that runs alongside the action agent, maintains a structured memory bank, and **selectively injects context reminders** at the moments it judges most likely to prevent "behavioral state decay" (relevant information getting buried as the trajectory grows). Plug-and-play with frontier action agents — no changes to the action-side stack. The memory agent is a Qwen3.5-27B trained via SFT + GRPO on SETA. Ablation contrasts against passive retrieval, continuous injection, advisor-only guidance, and generic RAG — selective intervention wins on all. Headline numbers: **Terminal-Bench 2.0 +8.3 pp pass@1, τ²-Bench +6.8 pp pass@1**, with gains preserved across both weaker and stronger action agents. CC BY 4.0.
- **Why it matters for Justin's agents:** This is the memory-architecture pivot the vault has been tracking. Every prior memory system in the ledger — AutoMem, Memora, SelfMem, DynaKRAG, A-TMA — treats memory as **storage the actor polls**; Remember-When-It-Matters treats memory as **an agent that decides when to intervene in the actor's trajectory**. The ablation is the load-bearing part: passive retrieval, continuous injection, and advisor-only all lose to selective intervention. In practical terms for Justin's companion-app and MCP stack, this converts memory from a retrieval flag into an orchestration primitive — the memory agent becomes a peer subagent that watches the action agent's trajectory and injects only when a decay threshold is crossed. The Qwen3.5-27B recipe is important on its own: a 27B judge/interventionist is the size class that fits M5 Max at Q4 (~14–16 GB) alongside a smaller local action agent, so the whole architecture is buildable locally without a frontier call.
- **Action signal:** `try-now` — retrofit a Qwen3.5-27B (or Qwen3-14B distill) memory-intervention subagent in front of the current action-agent loop; measure pass@1 on a 30-task fixed-set before / after. Also `compare` with the "supervisor-as-advisor" pattern the vault has been assuming; Meta's ablation says advisor-only loses to selective intervention.

### 2. KronQ: LLM Quantization via Kronecker-Factored Hessian
- **Source:** arXiv (cs.LG) — COLM 2026
- **Link:** https://arxiv.org/abs/2607.07964
- **Authors / org:** Donghyun Lee, Yuhang Li, Ruokai Yin, Priyadarshini Panda
- **Focus area:** Local models & Apple Silicon fit / quantization
- **What it is:** Post-training weight-only quantization that folds **gradient covariance** into the Hessian via a Kronecker-factored approximation, then does **bidirectional incoherence processing** (input + output dimensions jointly) and **gradient-informed mixed-precision allocation**. The bar it clears: **2-bit weight-only on LLaMA-3-70B → WikiText-2 perplexity 7.93**, versus GPTQ / GPTAQ **degenerating to >2000 perplexity** under the same 2-bit budget. This is the first PTQ paper to make 2-bit 70B a usable-quality operating point rather than a demo.
- **Why it matters for Justin's agents:** 2-bit 70B at ~18–20 GB of weights fits M5 Max 64 GB with **~40+ GB left for KV cache, RAG buffers, and a second local model** (e.g., a Qwen3-8B tool-caller or the Remember-When-It-Matters-style 27B memory agent). This is the memory arithmetic that turns "70B local for local reasoning" from a stretch goal into a default. The gradient-covariance trick is the same **learn-your-primitive** meta-pattern the vault has been tracking (VBQ's learned-per-group precision, SelfMem's learned memory writes, self-evolving rubrics). KronQ is COLM 2026 so a reference impl should land soon; watch for a llama.cpp / MLX PR — until then it's a `local-fit` on the reading list, not on the drive.
- **Action signal:** `local-fit` — track for MLX / llama.cpp integration; when a KronQ 70B GGUF or MLX blob ships, benchmark against Qwen3-32B Q4 on the current coding-agent harness. `compare` with previously-tracked VBQ (learn-your-precision) — same meta-pattern, different quantization target (KronQ = static weights, VBQ = trained groups); together they define the two axes of the 2026 quantization frontier.

### 3. From Prompts to Contracts: Harness Engineering for Auditable Enterprise LLM Agents
- **Source:** arXiv (cs.AI)
- **Link:** https://arxiv.org/abs/2607.08028
- **Authors / org:** Joongho Ahn, Moonsoo Kim
- **Focus area:** Agent orchestration / production reliability
- **What it is:** A systematic migration path from **prompt-carried behavior** to a **code + manifest + validator harness** where enforcement lives outside the prompt. Three research questions, each with a clean measurement: **(1) contract preservation** — source-grounding, entity-routing, trace, output-hygiene, and recommendation contracts all survive fault-injection; **(2) model substitution** — 270 runs across three hosted models, all failures cleanly isolated to the model-composed layer; **(3) code-enforcement necessity** — head-to-head comparison shows prompt-only permits safety violations (recommendation-language + trace-leakage), a bolt-on guardrail over-refuses (**88/120 utility**), and the harness achieves **120/120 utility with zero safety violations**.
- **Why it matters for Justin's agents:** This is the paper Justin's federal-data-engineer hat has been waiting for. It gives an explicit contract taxonomy (source-grounding / entity-routing / trace / output-hygiene / recommendation) and shows the guardrail-shaped null hypothesis fails empirically — bolt-on external guards over-refuse, and prompt-only leaks. The 3-model substitution result is orthogonal but critical for a working MCP stack: it means model swaps produce **localized failures at the model-composed layer**, not silent regressions across the whole harness. For any companion-app product Justin ships, the contract-preservation frame + validators-that-catch-fault-injection is the compliance story that federal deployment will demand. This is the execution-time complement to yesterday's [arxiv:2607.07405] Reason-Less-Verify-More gates and to Justin's Verifiable Context Governance line (ContextNest, ProvenanceGuard) — same "gate-before-commit" pattern, now with a utility/safety Pareto curve.
- **Action signal:** `try-now` — inventory the current MCP tool surface, extract the implicit contracts, move them into deterministic validators; measure utility deltas on the current agent test set before/after. `compare` — extends the gate-before-commit cluster; adds the "bolt-on guards over-refuse" empirical fact to the ledger.

### 4. Who Broke the System? Failure Localization in LLM-Based Multi-Agent Systems (AgentLocate)
- **Source:** arXiv (cs.MA) — COLM 2026
- **Link:** https://arxiv.org/abs/2607.07989
- **Authors / org:** Yufei Xia, Anjun Gao, Yueyang Quan, Zhuqing Liu, Minghong Fang
- **Focus area:** Agent orchestration / debugging / monitoring
- **What it is:** A failure-localization framework for multi-agent trajectories that answers two coupled questions: **which agent is responsible** and **at what step the trajectory first became irrecoverable**. Combines an LLM judge, independent evaluator perspectives (multi-perspective verification), and confidence-weighted aggregation, then adaptively fine-tunes to sharpen accuracy. Consistently beats prior failure-localization methods on two benchmarks with different task complexity and agent configurations, while using less tokens and wall-clock time.
- **Why it matters for Justin's agents:** The vault has been tracking "how to keep autonomous loops honest" (self-pacing, heartbeats, verifier gates), but almost every prior primitive tells you **that** the loop failed — not **who** or **when**. AgentLocate is the missing root-cause primitive for multi-subagent stacks. Direct fit: when a Claude Code + MCP session goes off the rails, plug AgentLocate over the subagent transcript to score which subagent broke first and at which step, then feed that back into the memory-agent (item 1) or into a contract validator (item 3) as a training signal. The token / wall-clock savings vs prior localization methods is what makes it deployable on live traffic rather than only in post-mortem.
- **Action signal:** `try-now` — wire an AgentLocate pass on failed autonomous-loop runs; feed responsible-agent + earliest-decisive-step into the ledger. `compare` with prior "reflection" and "advisor" patterns which localize far less precisely.

### 5. WebSwarm: Recursive Multi-Agent Orchestration for Deep-and-Wide Web Search
- **Source:** arXiv (cs.CL / cs.AI / cs.MA)
- **Link:** https://arxiv.org/abs/2607.08662
- **Authors / org:** Xiaoshuai Song, Liancheng Zhang, Kangzhi Zhao, Yutao Zhu, Zhongyuan Wang, Guanting Dong, Jinghan Yang, Han Li, Kun Gai, Ji-Rong Wen, Zhicheng Dou (RUC + Kwai)
- **Focus area:** Agent orchestration / tools & connectors
- **What it is:** A recursive delegation framework for web-search agents. **First** WebSwarm probes how task-relevant information is organized on the web, using that structure to seed the initial fan-out. **Then** each search agent either solves its objective locally or **dynamically instantiates child search nodes**, each with a local objective + explicit search mode, with information flowing upward for expansion and aggregation. Process-level experience is reused across homogeneous sibling nodes. Consistently outperforms single-agent and prior multi-agent baselines on **BrowseComp-Plus, WideSearch, DeepWideSearch, GISA**; ablations across task difficulty, web-tool efficiency, model generalization.
- **Why it matters for Justin's agents:** This is the operational shape of a deep-research MCP tool — the "probe first, then recursively delegate, reuse sibling process traces" pattern. Justin's current research-assistant workflow does a single-shot fan-out with no recursion; WebSwarm says the delegation should be depth-adaptive per branch. The **sibling process-trace reuse** is the interesting bit — it's a mid-run memoization primitive that flat multi-agent frameworks don't get. Retrofit target: wrap the current MCP web-search subagent in a WebSwarm-style controller that decides "delegate deeper" vs "solve locally" per branch based on partial results.
- **Action signal:** `track` — no code repo confirmed in the abstract; wait for release. Meanwhile, prototype the "probe → recursive delegation → sibling trace reuse" pattern manually on the current research stack.

### 6. Understanding Axes of Difficulty For Long Context Tasks Via PredicateLongBench
- **Source:** arXiv (cs.AI)
- **Link:** https://arxiv.org/abs/2607.08284
- **Authors / org:** Siddhartha Jain, Ameya Velingker
- **Focus area:** Evaluation / context engineering
- **What it is:** A long-context benchmark built around a **conceptually simple, LLM-judge-free** task: identify the longest contiguous subsequence in a long input satisfying a predicate (e.g., lexicographic ordering). Both synthetic and real-world (natural-document-preserving) pipelines. Explicit difficulty axes rather than a single "context length" scalar, so the benchmark can be titrated. Headline: **frontier models degrade cleanly as difficulty scales along these axes** — no saturation, no ceiling from noise. CC BY 4.0.
- **Why it matters for Justin's agents:** Every long-context benchmark the vault tracks (NIAH, RULER, HELMET) is either saturated at the top or requires an LLM judge that can itself hallucinate agreement. PredicateLongBench sidesteps both — the task is verifiable in closed form and the difficulty is controllable. This is the eval harness to pair with yesterday's Jet-Long: run Qwen3-8B + Jet-Long across the PredicateLongBench axes and see where the tuning-free RoPE extension breaks in a way NIAH would never surface. For Justin's coding-agent stack: predicate-satisfaction tasks are close in shape to the "find the longest satisfying subtree" queries a repo-agent runs against a codebase, so degradation here is a direct signal for real work.
- **Action signal:** `try-now` — run the current default local-stack (Qwen3-8B and/or Qwen3-14B, with and without Jet-Long) across PredicateLongBench's difficulty axes; log the crossover point. `compare` with saturated NIAH/RULER numbers — expect PredicateLongBench to show gaps NIAH hid.

### 7. DominoTree: Conditional Tree-Structured Drafting with Domino for Speculative Decoding
- **Source:** arXiv (cs.CL / cs.LG)
- **Link:** https://arxiv.org/abs/2607.08642
- **Authors / org:** Saw S. Lin (Zhiqi Zhang), Jyh-Shing Roger Jang
- **Focus area:** Local & open models for Apple Silicon / inference efficiency
- **What it is:** Training-free speculative decoding that combines tree-structured drafting with Domino's GRU-based causal correction. On Qwen3-4B: **up to 6.6× speedup vs autoregressive**, **mean accept length up to 10.7 tokens per round** (highest of any evaluated method). Throughput is **+9–10% over the Domino decoder baseline overall, up to +22% on Alpaca**, and up to **+24% over DDTree/CaDDTree at T=0 on Qwen3-8B**. Eight benchmarks across a range of temperatures. GitHub code confirmed.
- **Why it matters for Justin's agents:** Speculative decoding is the largest single lever on the local-inference latency budget on M5 Max, because decode is memory-bandwidth-bound (600 GB/s) and speculative accept-lengths amortize KV reads. A **6.6× speedup at 10.7-token accept length** on Qwen3-4B is the fastest usable-quality Qwen3-4B on Apple Silicon this quarter. Practical stack: Qwen3-4B/8B action agent + DominoTree speculative decoder + KronQ-style compressed reasoning model in the background = the full "fast small model + heavy slow model" architecture on-device. Training-free means no adaptation cost to bolt it on.
- **Action signal:** `local-fit` / `try-now` — clone the GitHub repo, wire DominoTree over Qwen3-4B on MLX or llama.cpp, benchmark tokens/sec on M5 Max vs vanilla decoding, log the accept-length distribution on Justin's real tool-calling traffic (not just Alpaca).

## Local-model corner
Two items today are directly on the M5 Max / 64 GB stack.

**KronQ 2-bit LLaMA-3-70B**
- **Model:** LLaMA-3-70B (KronQ 2-bit weight-only PTQ). WikiText-2 PPL 7.93 (vs GPTQ / GPTAQ >2000 at same 2-bit budget).
- **Memory fit:** ~18–20 GB weights at 2-bit + KV cache. On M5 Max 64 GB this leaves ~40+ GB for KV cache, RAG buffers, and a co-resident 7–14B tool-caller. Comfortably fits **with** a Qwen3-4B/8B speculative-decode setup live.
- **Realistic tasks:** long-form reasoning, code review, deep-agent planning where 8B is a bottleneck but 70B FP16 was never viable locally. Do **not** expect 70B FP16 quality — expect "usable 70B" quality with a factor-of-3 loss margin vs 4-bit; use it where the reasoning delta from 8B → 70B matters more than the delta from 4-bit → 2-bit.
- **How to run:** Reference implementation only for now — COLM 2026 acceptance, no llama.cpp / MLX PR confirmed at time of writing. Track the repo drop; test against Qwen3-32B Q4 as the current sensible baseline.
- **Speed estimate:** No M5 Max benchmark published yet. On memory-bandwidth-bound decode, 2-bit weights should be **~2× faster than 4-bit** at the same bandwidth (weight loads halve), i.e., roughly 4-bit-Q4-70B speeds × 2 — order-of-magnitude ~10–15 tok/s single-user on M5 Max, pending real numbers.

**DominoTree speculative decoding on Qwen3-4B / 8B**
- **Model:** Qwen3-4B (headline results) and Qwen3-8B (throughput deltas). Training-free — layers on top of the base model.
- **Memory fit:** Qwen3-4B in Q4 ~2.6 GB + draft tree buffers; Qwen3-8B Q4 ~5.5 GB. Trivial on M5 Max — this is a speed knob, not a memory knob.
- **Realistic tasks:** any low-latency local task — MCP tool-caller loop, autocomplete-style code assistance, chat. Especially good on structured / templated outputs (long accept lengths) — the "up to +22% on Alpaca" hints at this. Weaker on high-entropy free-generation.
- **How to run:** GitHub repo referenced in the paper (URL redacted in the fetched abstract, but confirmed present). Expect a Python + PyTorch reference; MLX / llama.cpp port is where the M5 Max wins come from.
- **Speed estimate:** Paper reports **up to 6.6× vs autoregressive on Qwen3-4B, 10.7-token mean accept length**. On M5 Max, expect a lower multiplier than an H100 (memory bandwidth caps the ceiling), but a **3–4× decode speedup on structured workloads** is plausible.

## Conflicts & open questions
Cross-referenced against `_meta/claims-ledger.md`:
- **Conflict / extension — Memory as agent, not store.** [arxiv:2607.08716] Remember-When-It-Matters (proactive memory agent + selective intervention beats **advisor-only, passive retrieval, continuous injection, general RAG**) is in tension with the "advisor / supervisor" pattern implicit in many earlier memory + orchestration papers in the ledger. Not a strict refutation — the load-bearing distinction is between an **advisor that gives guidance** and an **interventionist that decides when to inject context** — but Meta's ablation says the interventionist role wins. Flag: revisit memory-orchestration entries and re-tag whether they're "advisor-shaped" or "interventionist-shaped."
- **Extension / compose — Gate-before-commit pattern grows again.** [arxiv:2607.08028] From-Prompts-to-Contracts and [arxiv:2607.07989] AgentLocate together **extend** the gate-before-commit cluster (Janus / SkillOpt / Mnemosyne / RoPoLL+Minority Sentinel / ProvenanceGuard / ContextNest / Reason-Less-Verify-More): AgentLocate is the **post-hoc localization** primitive, From-Prompts-to-Contracts is the **pre-commit contract enforcement** primitive. Neither replaces the earlier work — they compose. Add "post-hoc localization" and "pre-commit contract" as sub-tags on the cluster.

Open empirical questions raised today:
- Does the Meta memory-agent win survive the KronQ 2-bit weight-quantization regime? A memory agent that's a 2-bit quantized 27B is a very different beast; needs a same-benchmark ablation.
- PredicateLongBench + Jet-Long: does the tuning-free RoPE extension hold up on predicate-satisfaction tasks, or does it silently degrade in a way NIAH would never surface? Both are `try-now` for Justin's stack.
- DominoTree on Qwen3-4B with a bimodal traffic mix (short structured tool calls + long free-generation chat) — where does the speedup collapse? The Alpaca-favors-DominoTree signal suggests uneven gains across workloads; real number is a per-request-type histogram.
