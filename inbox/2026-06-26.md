# AI Research Digest — Friday, June 26, 2026

## TL;DR
- **Agent memory takes a parametric turn.** **Memory Depth / EVAF** (arxiv:2606.26806) introduces "surprise- and valence-gated LoRA consolidation" — durable goal-conditioned tendencies written into a small parametric store, complementary to retrieval. 2–3 writes per 200 events; 0.812–0.904 on goal persistence and post-unload recovery. This is the second parametric-memory paper in ten days (after Engram, June 17) — the substrate question is reopening.
- **Autonomous loops get a stopping rule with theory.** **Semantic Early-Stopping** (arxiv:2606.27009) halts iterative agent loops when consecutive draft embeddings stop changing in meaning — **−38% operational tokens at parity quality on HotpotQA**, judge-free, with machine-checked theoretical guarantees. The "quality-gated" variant they tried *increased* cost because per-round judging dominated savings — a clean counter-example to the reflexive instinct to "just add a judge."
- **Multi-agent ensembles hit a measurable ceiling.** **Co-Failure Ceiling** (arxiv:2606.27288) defines β as the rate at which *every* model is wrong on the same query and proves accuracy ≤ 1 − β. Across 67 frontier models / 21 providers: math β=0.052 (2.5× higher than Gaussian-copula prediction), code β=0.079, GPQA-Diamond β=0.127 when reformatted free-response. Heterogeneous low-correlation ensembles beat Self-MoA at matched quality. **Direct potential conflict with Contagion Networks** (arxiv:2606.20493, June 21) which claimed *homogeneous* committees outperform heterogeneous on aggregate bias — see Conflicts section.
- **Coding-agent rewards are not a solved problem.** **The Verification Horizon** (Qwen, arxiv:2606.26300) examines four reward constructions (test verifiers / rubric verifiers / user-as-verifier / agent verifiers) and argues **no fixed reward function remains effective as policy capability grows — verification must co-evolve with the generator**. This is the same week as Bayesian Control for Coding Agents (June 25) — the field is converging that "when and how to verify" is now the central coding-agent question.
- **Tool-use RL has a named collapse mode and a named fix.** **CASIA's tool-use RL paper** (arxiv:2606.26027) shows catastrophic collapses in multi-step tool-use RL stem from **unexpected probability spikes in control tokens**, not lost capabilities; **interleaving SFT with RL substantially improves stability**. Code at hypasd-art/Tool-RL-Box. Pairs structurally with the Verification Horizon thesis — if reward design alone can't carry training stability, supervision-side intervention has to.
- **Evaluation methodology continues its 2026 reckoning.** **The Capability Frontier** (arxiv:2606.26836) shows correcting single-model bias and single-run sampling effects together yields **82% error-rate reduction** and **85% cost reduction to match SOTA accuracy** on 21 LLMs × 16 benchmarks. ## Items

### 1. Memory Depth, Not Memory Access: Selective Parametric Consolidation (EVAF)
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.26806
- **Authors / org:** Haoliang Han
- **Focus area:** Agent memory
- **What it is:** Argues that long-running language agents need not just *memory access* (retrieval) but *memory depth* — durable goal-conditioned tendencies written into a small parametric store. Introduces **EVAF**: surprise- and valence-gated LoRA consolidation, where the gate decides when a trace is worth a parametric write and updates only a small adapter. Tested on GPT-2, TinyLlama, and Mistral-7B under a new "loop-drift" protocol that stresses recovery after the parametric store is reloaded. Retrieval accuracy on factual recall **0.956–0.973**; EVAF on goal persistence and post-unload recovery **0.812–0.904**; parametric efficiency **2–3 writes per 200 events**.
- **Why it matters for Justin's agents:** This is the cleanest articulation yet of "retrieval is not memory." For Justin's MCP/companion-app stack, the right read is that retrieval gives you access to facts but only parametric consolidation can store *what the agent should do now* — preferences, recurring failure patterns, persistent goal state. 2–3 writes per 200 events keeps the parametric overhead negligible; the LoRA-write substrate is portable to any Mistral-7B-class local model the M5 Max already runs. The companion-app angle is direct: a user's recurring "I prefer brief replies" goal could live in EVAF rather than in a system-prompt drift loop.
- **Action signal:** `track` — code not released; the surprise/valence gating math is the actionable piece even before the reference impl drops. Pairs with **Engram** (arxiv:2606.19172, June 17) which used hash-keyed memory tables; together they sketch a two-tier parametric stack — Engram for facts, EVAF for tendencies. See Conflicts for the open empirical question.

### 2. Semantic Early-Stopping for Iterative LLM Agent Loops
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.27009
- **Authors / org:** Sahil Shrivastava
- **Focus area:** Long-running / autonomous loops
- **What it is:** A judge-free stopping rule for iterative agent loops: halt when consecutive draft embeddings stop changing in meaning (semantic plateau). Contributes (a) machine-checked theoretical guarantees on the stopping criterion, (b) an evaluation protocol that replays policies over cached outputs (so policy comparison is apples-to-apples), and (c) empirical validation on HotpotQA. Headline: **−38% operational tokens vs fixed-iteration baseline at parity quality** (ΔIS = −0.004, p = 0.81). A quality-gated variant the author tried was **counterproductive** because per-round judging cost dominated savings; the oracle best-round-selection policy carries a **+0.115 Information Score** advantage (p ≈ 4e-11) over all practical policies. Open-source implementation and reproducible harness released.
- **Why it matters for Justin's agents:** The judge-free part is the load-bearing finding. Most agent harnesses today either (a) use a fixed iteration cap (wasteful) or (b) bolt on an LLM-as-judge stop signal (often more expensive than the savings). This paper formally shows the second pattern fails in a typical regime and that a cheap embedding-divergence signal already captures most of the win. For Justin's MCP-tool agents that run multi-round refine loops, this is the right replacement for hand-tuned `max_iter` knobs. The 38% token reduction at parity quality is large enough to justify integration even at a single MCP server.
- **Action signal:** `try-now` — code released, single-author paper but with formal proofs; the stopping criterion is small enough to add as a 50-line wrapper around any iterative agent loop. Composes structurally with **SelfCompact** (arxiv:2606.23525, June 23) which decides "when to compact" via model rubric — together: SelfCompact governs context lifecycle, Semantic Early-Stopping governs loop termination. Both are model-decided expensive-op gating.

### 3. The Co-Failure Ceiling on Routing, Voting, and Mixture-of-Agents
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.27288
- **Authors / org:** Josef Chen
- **Focus area:** Agent orchestration / multi-agent
- **What it is:** Formalizes a hard ceiling on multi-model ensembles: define **β** as the rate at which *every* model in the ensemble is wrong on the same query — accuracy of any router/vote/MoA system is bounded by **1 − β**. Measured across **67 frontier models from 21 providers** on math, code execution, and reformatted GPQA-Diamond. Findings: **math β = 0.052** (vs predicted 0.023 under Gaussian copula — a 2.5× underestimation by independence assumptions), **code execution β = 0.079**, **GPQA-Diamond β = 0.127** when reformatted from MCQ to free-response. Key insight: "**gains come from models failing on different questions, not from adding more models**." Heterogeneous ensembles with low error correlation outperform Self-MoA configurations at matched quality.
- **Why it matters for Justin's agents:** This is the right framework for deciding when to use multi-LLM orchestration at all. If β on your domain is 0.05, adding more identical-failure-mode models past the second buys ~nothing. The actionable lever is **error decorrelation**, not committee size — pick models with different training data / different post-training recipes / different reasoning chains, not three Sonnet-class models with rotated prompts. For Justin's Claude Code + Codex / OpenClaw multi-model orchestration, this gives a concrete diagnostic: measure pairwise co-failure on the actual task distribution and route accordingly. The MCQ-vs-free-response gap (0.052 → 0.127 by reformatting alone) also says that current ensemble-strength estimates assuming MCQ benchmarks are systematically optimistic.
- **Action signal:** `track` → `try-now` if you ever run >2 models in ensemble. Single-author paper but the math is rigorous and the 67-model dataset is the real artifact. **Direct potential conflict with Contagion Networks (arxiv:2606.20493, June 21)** which claimed homogeneous committees outperform heterogeneous on aggregate bias — see Conflicts section.

### 4. The Verification Horizon: No Silver Bullet for Coding Agent Rewards (Qwen)
- **Source:** arXiv (Qwen team)
- **Link:** https://arxiv.org/abs/2606.26300
- **Authors / org:** Binghai Wang, Chenlong Zhang, Dayiheng Liu, Jiajun Zhang, Jiawei Chen, Mouxiang Chen, Rongyao Fang, Siyuan Zhang, Xuwu Wang, Yuheng Jing, Zeyao Ma, Zeyu Cui (Qwen / Alibaba)
- **Focus area:** Coding agents / evaluation
- **What it is:** Position + measurement paper from the Qwen team arguing that the classical "verifying is easier than producing" intuition has inverted for modern coding agents. Examines four reward constructions: (a) test verifiers, (b) rubric verifiers, (c) user-as-verifier, (d) automated agent verifiers — each across different task types. Core thesis: **no fixed reward function can remain effective as policy capability continues to grow; verification must co-evolve with the generator**. Identifies intent underspecification and reward hacking as the two structural challenges. Reports "significant gains across multiple internal and public benchmarks" using the co-evolved-verifier strategy; concrete numbers not in the abstract.
- **Why it matters for Justin's agents:** This is the Qwen team telling the rest of the field that the Qwen3-Coder / Qwen-AgentWorld training-data + reward design recipe was carried by adaptive verification, not by reward construction tricks. For anyone training small specialist coding agents (Justin's "what would a fine-tuned Qwen-3 32B do on my federal data engineering scripts" thread), the lesson is to design the verifier **with** the policy from day one and budget verifier updates into the training loop. Combined with same-week **Bayesian Control for Coding Agents** (arxiv:2606.24453, June 25), the picture is: verification cost and timing must both be modeled and dynamic. Static `pytest`-as-reward is over.
- **Action signal:** `track` — read the full PDF for concrete reward-co-evolution recipe. Workshop-grade format but frontier-lab authorship. Composes with the Bayesian control framework as the "*when* to verify" piece next to this paper's "*how* to verify" piece.

### 5. Why Multi-Step Tool-Use RL Collapses and How Supervisory Signals Fix It
- **Source:** arXiv (CASIA)
- **Link:** https://arxiv.org/abs/2606.26027
- **Authors / org:** Yupu Hao, Zhuoran Jin, Huanxuan Liao, Kang Liu, Jun Zhao (CASIA / Chinese Academy of Sciences)
- **Focus area:** Tools & connectors / agent training
- **What it is:** Diagnoses **catastrophic collapse** in multi-step tool-use RL — performance abruptly drops and tool-invocation structure (e.g., the agent stops emitting `<tool_call>` brackets) fails mid-training. The mechanism is **not** lost capability but **unexpected probability spikes in control tokens** that crash the policy distribution. Tests off-policy supervision, hint-based guidance, and erroneous-example supervision. Headline finding: **interleaving SFT with RL substantially improves stability** — the supervision side, not the reward side, is the lever. Performance still degrades under out-of-distribution evaluation. Code at https://github.com/hypasd-art/Tool-RL-Box.
- **Why it matters for Justin's agents:** Anyone training their own MCP-tool-use small model (Qwen-3-class, ~7-30B) has hit exactly this failure — the model's tool-use formatting suddenly degrades two-thirds of the way through RL, and resuming from a checkpoint just delays the collapse. This paper names the failure mode (control-token probability spikes) and offers a concrete fix (interleaved SFT). Useful both as training recipe and as a diagnostic — if your model's failure mode matches the spike pattern, you don't need to redesign rewards, you need to mix SFT back in. Pairs with **The Verification Horizon** (item 4): reward design alone can't carry stability; supervision has to participate.
- **Action signal:** `try-now` for anyone training tool-use models; `track` otherwise. Code released. The control-token-spike diagnosis is reusable as an instrumentation pattern — log per-token probabilities for `<tool_call>` and friends across training to catch the collapse before it manifests in evaluation.

### 6. SKILL-DISCO: Distilling and Compiling Agent Traces into Reusable Procedural Skills
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.26669
- **Authors / org:** Zhongxin Guo, Danrui Qi, Hanwen Gu, Peng Cheng, Yongqiang Xiong
- **Focus area:** Agent memory / agent orchestration
- **What it is:** Targets the "agents repeatedly solve similar task instances from scratch" problem by mining **reusable procedural subgraphs** from successful traces and compiling them into callable skills the agent can invoke as composite tools on later tasks. Evaluated on ALFWorld and WebArena. Reports improved success rates and reduced agent turns across benchmarks and model scales; concrete deltas not in the abstract.
- **Why it matters for Justin's agents:** This is the same family as **Metis** (arxiv:2606.24151, June 25) — promotion of recurring patterns into executable tools — but at the *trace subgraph* level rather than the *full task* level. For Justin's agents that run repetitive MCP workflows (digest builds, data pulls, vault enrichment), subgraph-level distillation can catch sub-tasks that aren't task-shaped but still repeat. The compile-to-callable-skill substrate matches how Claude Code Skills already work, so the integration cost is one wrapper script per skill. The risk pattern is the same as for any skill library — pollution by malformed early traces — so this should layer behind a quality gate.
- **Action signal:** `track` until concrete numbers land in the full PDF. Most useful as a design pattern to pair with Metis (which already has +20.6 pts AppWorld numbers): Metis defines the substrate (text + code memory), SKILL-DISCO defines the distillation pipeline that populates it.

### 7. The Capability Frontier: Benchmarks Miss 82% of Model Performance
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.26836
- **Authors / org:** Bradley Fowler, Ryan Smith, Daniel Thi Graviet, William Myers, Joshua Greaves, Narmeen Fatimah Oozeer, Antía García, Philip Quirke, Amirali Abdullah, Fazl Barez, Shriyash Kaustubh Upadhyay
- **Focus area:** Evaluation
- **What it is:** Proposes the **Capability Frontier** — optimal achievable accuracy at each cost level when (a) corrected for single-model evaluation bias and (b) corrected for single-run sampling effects. Across 21 LLMs and 16 benchmarks spanning coding, reasoning, medicine, factuality, instruction following, and agentic tasks. Headline numbers: **54% error-rate reduction** from correcting single-model bias; **82% error-rate reduction** when *also* correcting for single-run sampling; **85% cost reduction to match SOTA accuracy** when leveraging both. Core claim: traditional benchmarks systematically underestimate the *collective* capabilities of available LLMs, especially in heterogeneous data settings.
- **Why it matters for Justin's agents:** Combined with **Co-Failure Ceiling** (item 3), this is the operational answer to "how do I get more out of my existing models without retraining anything?" The 85% cost reduction figure says: route + multi-sample with awareness of error decorrelation, and you can hit the same quality at fraction of the cost. For Justin's MCP stack, this is the design argument for never picking a single model statically — the right primitive is a router with per-query budget and a sampling/voting policy aware of co-failure structure.
- **Action signal:** `track` for the methodology; `try-now` for the underlying pattern (cost-conditioned multi-sample routing). The 82% / 85% headlines are the kind of number that needs replication; the framework itself is sound regardless. Pairs at evaluation-methodology layer with last month's predictive-validity work (arxiv:2606.19704, June 19) — both arguing the single-score-leaderboard era is ending.

### 8. Ask, Don't Judge: Binary Questions for Interpretable LLM Evaluation (BINEVAL)
- **Source:** arXiv (Workshop on Compositional Learning, ICML 2026)
- **Link:** https://arxiv.org/abs/2606.27226
- **Authors / org:** Sangwoo Cho, Kushal Chawla, Pengshan Cai, Zefang Liu, Chenyang Zhu, Shi-Xiong Zhang, Sambit Sahu
- **Focus area:** Evaluation
- **What it is:** Decomposes LLM-as-judge into **atomic binary questions** auto-generated via meta-prompt, then aggregates per-question verdicts into multi-dimensional scores. Each binary question is answered independently — no single rubric pass with implicit weight allocation. On SummEval, Topical-Chat, and QAGS, matches or exceeds strong baselines (UniEval, G-Eval), with especially strong results on factual-consistency benchmarks (QAGS); also produces better-calibrated score distributions matching human ratings. Demonstrates improved iterative prompt optimization on summarization and IFBench.
- **Why it matters for Justin's agents:** The atomic-binary-decomposition primitive is the right answer to the perennial "my LLM-as-judge keeps giving 7/10 to everything" problem. Each binary question has a clear yes/no answer; the model can't hide ambiguity in a single rubric score. For Justin's eval pipelines (and for any companion-app A/B test using LLM judging), this is a drop-in upgrade — replace one judge prompt with N binary judge prompts, aggregate the verdict vector. The interpretability bonus (per-dimension failure attribution) is valuable for debugging which axis of a response failed.
- **Action signal:** `try-now` — workshop-grade paper but the technique is small enough to prototype in an afternoon. Pairs with **Grading the Grader** (arxiv:2606.24839, June 25) — that paper's three-layer cascade is a process pattern; BINEVAL is the decomposition pattern at the judge-prompt layer. Combined: cascade architecture + binary-question decomposition = the current best-practice reference design for LLM-as-judge.

### 9. Autoformalization of Agent Instructions into Policy-as-Code (Cedar)
- **Source:** arXiv (Workshop on Agents in the Wild, ICML 2026)
- **Link:** https://arxiv.org/abs/2606.26649
- **Authors / org:** Adam Mondl, Matthew Maisel, John H. Brock
- **Focus area:** Agent orchestration / governance / tools & connectors
- **What it is:** An autoformalization pipeline that translates **agent prompts, MCP tool descriptions, and natural-language policy documents** into formally verified policies expressed in **Cedar Policy Language**, via an LLM-driven translation loop. On MedAgentBench, the autoformalized policies achieved substantially greater coverage of the source natural-language specification than hand-coded symbolic enforcement from prior work. The argument: probabilistic safety methods can't give guarantees; Cedar's evaluator can.
- **Why it matters for Justin's agents:** This is the **MCP-server-policy** thread maturing into something actionable. The federated-data-engineering world Justin works in (and many regulated-domain MCP deployments) ultimately needs policy enforcement that an auditor can read. Cedar is already mature, already deployed at AWS, already has formal verification tooling. The contribution here is the autoformalization pipeline: you write the policy once in English in the tool description, the LLM compiles it down to Cedar, the Cedar evaluator enforces it deterministically at runtime. Composes naturally with **ToolPrivBench** (arxiv:2606.20023, June 25): ToolPrivBench measures the over-privileged-escalation failure; Cedar-as-MCP-policy enforces against it at the connector layer, not the prompt.
- **Action signal:** `track` — workshop paper, MedAgentBench-only evaluation. The structural argument (use a mature deterministic policy language with autoformalization, not prompts-as-guardrails) is the durable read. Worth a closer look at the Cedar evaluator's MCP-server integration cost.

### 10. CUGA FLO: A Process Harness for Uplifting Legacy Workflows to Agentic BPM
- **Source:** arXiv (IBM Research, CUGA follow-up)
- **Link:** https://arxiv.org/abs/2606.27188
- **Authors / org:** Fabiana Fournier, Lior Limonad (IBM Research)
- **Focus area:** Agent orchestration
- **What it is:** Extends yesterday's **CUGA** open-source agent harness with **CUGA FLO** — a "process harness" that wraps a policy-governed agentic layer around an existing deterministic workflow engine *without replacing it*. Introduces the **Task-Decision-Flow (TDF) model** with three policy-governed agent types — `TaskAgent`, `DecisionAgent`, `FlowAgent` — invoked only at designated control points. Demonstrated on a loan-approval workflow showing all three agent types and regulatory-override behavior. The reconciliation pitch: imperative requirements through deterministic workflow execution + normative requirements through agentic autonomy at policy-framed control points. No quantitative benchmarks; this is a design paper.
- **Why it matters for Justin's agents:** Most production "agentify our pipeline" projects fail because they try to replace the deterministic workflow engine. CUGA FLO's pattern — keep the existing engine, attach agent decision points at control boundaries — is the realistic adoption path for federal-data-engineering pipelines that already have audited deterministic logic. The three-agent type-decomposition (task / decision / flow) is also a sharper vocabulary than the usual "supervisor / executor" split. Combined with **Cedar autoformalization** (item 9): TDF gives the control-point shape, Cedar gives the policy enforcement at each control point.
- **Action signal:** `track` — design paper, no benchmarks. Most useful as a reference pattern for hybrid agentic / deterministic systems. Worth re-reading the CUGA Apache-2.0 codebase to confirm the TDF primitives map cleanly onto today's CUGA primitives.

### (Bonus) AllenAI: Which Tokens Does a Hybrid Model Predict Better?
- **Source:** Hugging Face blog (AllenAI)
- **Link:** https://huggingface.co/blog/allenai/hybrid-token-prediction
- **Focus area:** Context engineering / frontier-architecture analysis
- **What it is:** Controlled comparison of **Olmo 3 (7B transformer) vs Olmo Hybrid (7B attention+recurrence)** trained on identical data, tokenizer, and recipe. Token-level loss decomposition: hybrid wins on **content words (nouns, verbs, adjectives; loss gap ~0.04)** and tokens requiring **sequential state tracking (pronouns)**. Transformers win on **verbatim repetition** (hybrid advantage approaches zero on tokens that reproduce earlier text) and on **bracket-matching** (closing braces). Argument: single aggregate loss obscures architectural strengths.
- **Why it matters for Justin's agents:** This is the cleanest empirical story to date on the attention-vs-recurrence tradeoff at constant data. For Justin's local-inference choices, the practical read is: hybrid architectures are *not* a strict upgrade — they trade verbatim-retrieval and structured-text quality for state-tracking and content-word fluency. Code workloads (heavy bracket-matching, frequent verbatim reuse from local files) will *lose* on hybrid. Conversational / multi-turn user-modeling workloads (state-tracking-heavy) will *win*. This argues against the reflexive "swap in a hybrid model and pocket the throughput win."
- **Action signal:** `track` / `local-fit` — analysis, not a release. Worth referencing every time someone asks "should I pick HydraHead / DiffusionGemma / hybrid X for my workload?" The right answer is "depends on whether the workload looks more like state-tracking or more like verbatim retrieval."

## Conflicts & open questions
Cross-referenced against `_meta/claims-ledger.md`:

- **Heterogeneous vs homogeneous multi-model ensembles.** **Co-Failure Ceiling** (item 3) claims heterogeneous low-correlation ensembles outperform Self-MoA at matched quality. **Contagion Networks** (arxiv:2606.20493, June 21) claimed that **homogeneous** committees outperform heterogeneous on aggregate bias (cross-model contagion coefficients are 3–5× stronger than within-model). Resolution: these papers are measuring *different things* — Co-Failure Ceiling measures task-accuracy ceiling under joint-failure structure, Contagion Networks measures bias propagation through the evaluator network. Both can be right if heterogeneous ensembles win on *accuracy* but lose on *bias correlation*. Open empirical question for production: which one matters more for your use case (accuracy-bound RL signal → heterogeneous; bias-bound LLM-as-judge → homogeneous)?
- **Parametric memory: Engram tables vs EVAF LoRA consolidation.** **EVAF** (item 1, today) writes goal-conditioned tendencies into a small parametric LoRA via surprise/valence gating. **Engram** (arxiv:2606.19172, June 17) writes *facts* into hash-keyed memory tables per user, with ~33,000× lower footprint per user than per-user LoRA. The two substrates are not redundant — Engram targets *factual lookups* (indirect-reasoning accuracy), EVAF targets *behavioral tendencies* (goal persistence). Open empirical question: does a stack with Engram for facts + EVAF for tendencies + retrieval for everything else outperform any single-substrate baseline at the same total parameter cost? Likely yes, but no paper has tested it.
- **Verification: when, how, and how often.** **The Verification Horizon** (item 4) says "verification must co-evolve with the generator" — the verifier and policy update together. **Bayesian Control for Coding Agents** (arxiv:2606.24453, June 25) says "use Bayesian belief state to decide *when* to verify." **The Multi-Step Tool-Use RL Collapse** paper (item 5) says "interleave SFT with RL to keep verification-relevant control tokens stable." All three converge on the same meta-claim: **static verifiers are no longer adequate; verification has to be a dynamic, adaptive component of the agent training and inference loop.** Open question: does anyone in the open-source coding-agent stack (Aider, SWE-agent, Mini-SWE-Agent) treat verification as adaptive? Mostly no.
- **Stopping rules: cheap signals beat expensive judges.** **Semantic Early-Stopping** (item 2) showed the quality-gated (LLM-as-judge) stopping variant was counterproductive vs cheap embedding-divergence. This is the same lesson as **Grading the Grader** (June 25) — LLM-as-judge has hidden cost dynamics that often eat the savings. Open empirical pattern emerging: **the right place to put an LLM-as-judge is at evaluation-time on a small sample, not at production-time on every decision**. For production decisions, prefer cheap deterministic signals (embedding divergence, regex, schema validation, Cedar policy eval).
