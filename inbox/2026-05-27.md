### 1. MiniMax-M2 Series tech report — 229.9B / 9.8B active, MIT-licensed
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2605.26494
- **Authors / org:** MiniMax team (204+ contributors; lead authors Aili Chen, Li Yuan)
- **Focus area:** Frontier models
- **What it is:** Full tech report for the MiniMax-M2 series — a 229.9B-parameter MoE with only 9.8B activations per token (4.3 % activation rate). Headline contribution is an agent-driven data pipeline producing large-scale, verifiable trajectories plus specialized RL infrastructure. The M2.7 checkpoint reportedly demonstrates self-debugging "self-evolution" behavior. Weights released MIT on Hugging Face (`MiniMaxAI/MiniMax-M2` and `MiniMax-M2.7`); GGUF community quants exist.
- **Why it matters for Justin's agents:** This is the first formal write-up of the M2 stack he's been seeing pop up in agent-coding benchmark threads. The architectural posture — tiny activation footprint with frontier ambitions — is exactly the trade Justin would want for cheap, high-concurrency plan-act-verify loops; the paper is the citable reference for that argument.
- **Action signal:** `track` (the public model has been out since late 2025; the tech report is the new artifact)

### 2. MUSE-Autoskill — skill memory as long-lived, testable assets
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2605.27366
- **Authors / org:** Huawei Lin, Peng Li, Jie Song, Fuxin Jiang, Tieying Zhang (ByteDance / academic collab)
- **Focus area:** Agent memory / orchestration
- **What it is:** A self-evolving agent framework that unifies skill creation, memory, management, and evaluation as a single lifecycle. Skills are first-class persistent objects accumulating experience across tasks; quality is enforced via unit tests + runtime feedback. Evaluated on SkillsBench. 30 pages.
- **Why it matters for Justin's agents:** Justin runs heavy Claude Code with Markdown skills + MCP. MUSE's "skill = long-lived testable asset with skill-level memory" framing is exactly what he can borrow for the vault — pair each skill file with a small test suite + a runtime-success log and you have an audit trail without rebuilding infra.
- **Action signal:** `compare` — seventh skill-lifecycle paper in 30 days alongside SkillOS [arxiv:2605.06614], CODESKILL [arxiv:2605.25430], SkillOpt [arxiv:2605.23904], SkillsVote [arxiv:2605.18401], the model-generated skill study [arxiv:2605.23899], and Constant-Context Skill Learning [arxiv:2605.05413]. The field is converging on "skill = Markdown + test harness + experience log."

### 3. MobileGym — verifiable RL environment for mobile GUI agents
- **Source:** arXiv (HF Daily, 36 upvotes)
- **Link:** https://arxiv.org/abs/2605.26114
- **Authors / org:** Dingbang Wu, Rui Hao, Haiyang Wang, et al. (CASIA + collaborators)
- **Focus area:** Tools & connectors / computer-use agents
- **What it is:** A browser-based simulator for 28 real mobile apps with 416 parameterized tasks (256 test / 160 train). Captures full environment state as structured JSON for deterministic judging, supports hundreds of parallel instances at ~400 MB each with ~3 s cold start. GRPO on Qwen3-VL-4B-Instruct gains +12.8 pp; **95.1 % of simulation-side training gains transfer to real devices** on a 59-task subset.
- **Why it matters for Justin's agents:** This is a credible cheap-to-spin parallel rollout environment for any computer-use agent that touches mobile-style UIs. The 95.1 % sim-to-real transfer is the number to internalize — it makes it defensible to spend GPU on simulator training instead of paying for device farms.
- **Action signal:** `try-now` (open-source platform; usable as benchmark even without RL training)

### 4. Trajel — trajectory-level hallucination audit in multi-agent workflows
- **Source:** arXiv (HF Daily)
- **Link:** https://arxiv.org/abs/2605.24219
- **Authors / org:** Harshada Badave, Santosh Borse, Andrea Gomez, Harshitha Narahari, Sara Carter, Vishwa Bhatt, Aishani Rachakonda, Shuxin Lin, Dhaval Patel (IBM Research)
- **Focus area:** Evaluation
- **What it is:** A dataset + taxonomy + detector benchmark for hallucinations in *intermediate* multi-agent steps (not just final answers). Taxonomy: factual, referential, logical, procedural, scope-based. Key finding: **nearly 50 % of hallucinated trajectories involve multiple types simultaneously**; detectors with high binary accuracy still misclassify subtle types; trajectory-aware detection substantially outperforms post-hoc verification.
- **Why it matters for Justin's agents:** If you wire a guardrail layer, this is the taxonomy to instrument against — and the 50 %-overlap finding means single-classifier hallucination detectors will systematically under-report. Practical implication: log + score every agent message against the five-category taxonomy, don't just gate on the final response.
- **Action signal:** `compare` — extends [arxiv:2605.06635] AST-parser citation factuality (the deep-research depth/accuracy decay paper) and [arxiv:2605.12925] AgentLens lucky-pass problem; both arguments now converge on "final-answer eval is structurally insufficient for multi-step agents."

### 5. HarnessMutation — governed self-modifying agent runtimes
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2605.27328
- **Authors / org:** Mariano Garralda-Barrio (independent)
- **Focus area:** Long-running / autonomous loops + tools
- **What it is:** Formalizes agent-generated code artifacts as persistent runtime capabilities ("HarnessMutation") rather than disposable outputs. Defines a governance loop with explicit validation, traceability, evaluation, and rollback constraints, so self-modification stays bounded and observable. Reference implementation at https://github.com/mgarralda/governed-runtime.
- **Why it matters for Justin's agents:** Closest published analogue to what Justin already does informally — agents writing new skills/MCP tool definitions into the repo and reusing them later. The paper gives him a vocabulary and a rollback contract for that pattern.
- **Action signal:** `try-now` (small reference impl, single-author, CC BY-NC-SA license — read it as a design template, not a vendor dependency)

### 6. ATOM — budget-controllable multi-agent collaboration
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2605.26178
- **Authors / org:** Xinkui Zhao, Sai Liu, Yifan Zhang, Qingyu Ma, Zewen Lin, Naibo Wang, Guanjie Cheng, Chang Liu, Yueshen Xu
- **Focus area:** Agent orchestration
- **What it is:** A nucleus-electron hierarchy: a stable offline-learned backbone (nucleus) plus dynamically activated query-specific agents (electrons), trained via task-driven RL that generates collaboration graphs based on complexity-aware budgeting. Claims SOTA across 6 benchmarks while **improving token efficiency up to 30 % vs strong baselines**.
- **Why it matters for Justin's agents:** Token cost in multi-subagent workflows is one of the practical bottlenecks for the companion-app side. The "nucleus that always runs + electrons activated only when difficulty warrants" pattern is implementable today on top of Claude Code subagents — gate cheap default agents and only spawn expensive ones when a complexity classifier votes yes.
- **Action signal:** `track` — pairs with [arxiv:2605.05007] Uno-Orchestra (learns full decomposition + worker + budget) and [arxiv:2605.22177] Maestro (hierarchical model-skill ensembles).

### 7. AKBE — RL recipe for the tool-use knowing-doing gap
- **Source:** arXiv (HF Daily)
- **Link:** https://arxiv.org/abs/2605.26952
- **Authors / org:** Dingwei Chen, Zefang Zong, Zhipeng Ma, Leo Luo, Yang Li, Chengming Li, Peng Chen, Jie Jiang
- **Focus area:** Tools & connectors / reasoning
- **What it is:** During RL training, agents do dual-path rollouts (with-tool and no-tool) on the same query; the comparison generates targeted signal teaching when parametric knowledge suffices vs when a tool is needed. **+1.85 avg accuracy across 7 QA benchmarks, 18 % fewer tool calls, 25 % higher tool productivity**, with no accuracy-efficiency trade-off. Plug-and-play across RL algorithms.
- **Why it matters for Justin's agents:** Direct positive recipe for the "model calls tools when it doesn't need to (or vice versa)" failure mode documented all month. Cheaper agents at no quality cost is the headline trade for the indie products.
- **Action signal:** `compare` — provides a training-time fix for the failure modes surfaced by [arxiv:2605.14038] Model-Adaptive Tool Necessity (knowing-doing gap), [arxiv:2605.00737] hidden-state tool-need estimators, and [arxiv:2605.00136] tool-use tax. AKBE is the orthogonal axis (training-time vs inference-time mitigation).

### 8. ReMoE — router fine-tuning for memory-constrained MoE inference
- **Source:** arXiv (ICML 2026)
- **Link:** https://arxiv.org/abs/2605.27081
- **Authors / org:** Xiongwei Zhu, Xiaojian Liao, Tianyang Jiang, Yusen Zhang, Liang Wang, Limin Xiao
- **Focus area:** Local & open models
- **What it is:** Fine-tunes the MoE router to bias toward *recently selected* experts, producing temporally stable routing that fits cache locality. Tested on DeepSeek + Qwen. **26 % more expert reuse; 8.4 % throughput gain on vLLM GPU-CPU offload; 1.77–1.99× decode speedup on Jetson Orin NX with llama.cpp; 43.6–49.8 % TPOT reduction**; downstream task quality preserved. Code released.
- **Why it matters for Justin's agents:** The Jetson + llama.cpp pairing is the same offload regime he'd use on M5 Max for large MoEs that don't quite fit in 64 GB. The pattern — keep a hot expert cache, lean on temporal coherence — applies directly.
- **Action signal:** `local-fit`

## Local-model corner

Today's local-relevant signal is the **ReMoE pattern**, not a specific drop-in model.

- **Pattern:** Router-fine-tuning so the model itself biases toward expert reuse, making CPU/SSD offload viable for larger MoEs.
- **Memory math for M5 Max (64 GB):** A 100 B-parameter MoE at Q4 (~50 GB weights) + 8–12 GB KV at agent contexts + system + app overhead exceeds unified memory headroom in steady state. With ReMoE-style routing, you can run with only the hot subset of experts resident and stream the cold ones from SSD, paying the I/O cost only when the router actually escapes the recent set.
- **Realistic tasks:** Long-horizon coding agent loops where the same domain context dominates a session and most token-level routing decisions stay inside a stable expert subset. Less useful for highly diverse, short-burst prompts where every call hits a new expert.
- **How to run:** llama.cpp on M5 Max supports MoE offload to disk; today there's no published ReMoE-fine-tuned checkpoint, so the practical move is to **track community ports** (Unsloth or the authors' repo) and meanwhile experiment with the existing MLX/llama.cpp expert-cache flags.
- **Speed estimate:** Authors report 1.77–1.99× decode on Jetson Orin NX; M5 Max with 600 GB/s unified bandwidth should land closer to the upper end *if* expert hits stay in unified memory.

**Note on MiniMax-M2 for M5 Max:** At 229.9B total / 9.8B active, even aggressive ~3-bit dynamic quants land around 90 GB — over the 64 GB ceiling once KV and system overhead are counted. Not a clean local-fit today; revisit if a sub-50 GB community quant lands.

Open empirical questions raised:
- **Skill-lifecycle convergence (MUSE-Autoskill):** Seven distinct papers in 30 days all converge on "skill = Markdown + tests + experience log," but none have run head-to-head against each other on a shared benchmark. Open question whether the differences (CODESKILL's RL skill curation vs SkillOS's frozen-executor split vs MUSE's unit-test gating) matter once you control for the underlying base model + retrieval mechanism.
- **Trajectory hallucination overlap (Trajel):** 50 % of hallucinated trajectories show multiple types simultaneously — does this mean the five-category taxonomy is too fine-grained (categories actually correlated) or that there's a latent "agent confusion" factor underlying multiple failure modes? Open empirical question for follow-up.
- **AKBE generalization:** Does the dual-path with-tool / no-tool training signal hold when the "tools" are large MCP servers with long output streams, not just calculator/search? Authors test 7 QA benchmarks; untested at the SWE-bench / TerminalBench scale.
