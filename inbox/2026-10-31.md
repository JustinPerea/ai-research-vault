### 1. Online Dense Reinforcement Learning with Planning-Grounding Agent for UI Navigation on Live IOS Apps
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.39264
- **Authors/org:** Peitong Duan, Khashayar Gatmiry, Jeffrey Nichols, Samy Bengio et al.
- **Focus area:** online RL for UI navigation on live iOS apps
- **What it is:** Splits the agent into a Planning agent and a UI Grounding model and trains it online on live iOS apps with PPO, using an LLM-as-a-Judge for dense step-level rewards plus a terminal reward; GiGPPO stabilizes the critic with rewards from visually similar states across concurrent trajectories. Infrastructure runs hundreds of concurrent virtual iOS devices. 8B RL agents get nearly 7x the SFT baseline on out-of-distribution Android, beat Gemini-3.5-Flash and tie Gemini-3.1-Pro on real iOS apps (UINavBench, iOSWorld, AndroidWorld).
- **Why it matters for Justin's agents:** The most direct iOS-agent paper in weeks: a small planner+grounder trained on live iOS apps matching a frontier model is the shape Mitamaton's on-device UI layer wants. Watch for code/infra release.
- **Action signal:** `track`

### 2. When Skills Tell Agents Not to Ask: A Large-Scale Study of Oversight Directives in Agent Skills
- **Source:** arXiv (cross)
- **Link:** https://arxiv.org/abs/2610.37734
- **Authors/org:** Timofey Sanko, Yuan Tian
- **Focus area:** oversight-loosening directives in agent skills
- **What it is:** Analyzes 1.53M English skills from GitSkills with a hand-labelled codebook (2,097 units) and a trained detector. About 1 in 17 skills (~88,000) carries a directive that loosens oversight (proceed without approval, `--no-verify`, keep going without check-in), mostly via permission flags, 70.1% unconditional. Skills that run shell, install packages or use sudo have 1.7-1.8x the odds. Spread is upstream: 2.4% of skill families account for half of all copies. Open-source skill scanners catch at most 46% (precision <0.4); the same LLM prompted with the codebook catches 61% at 0.71.
- **Why it matters for Justin's agents:** Every third-party skill we load into Claude Code can silently remove approval checkpoints. Grep our installed skills for `--no-verify` / 'without asking' style lines before trusting them.
- **Action signal:** `try-now`

### 3. Compile Away Uncertainty: Self-Evolving Agent Skills via Programmatic Compilation
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.39508
- **Authors/org:** Chengyu Yang, Yunxiang Zheng, Zongzheng Li, Jiamei Li et al.
- **Focus area:** compiling self-evolving skills into programs
- **What it is:** SkillCompiler decomposes textual skills into fine-grained operations, analyzes executability, and builds hybrid skill skeletons: context-dependent steps stay as LLM reasoning, well-specified ones become validated programs. Validated programs are kept as reusable assets and retrieved before new synthesis. Up to 32.33% task-performance gain over prior methods across five benchmarks and six model families.
- **Why it matters for Justin's agents:** Matches how our skills should mature: once a step is deterministic, freeze it as a script the skill calls instead of re-reasoning it each run (less variance in nightly pipelines).
- **Action signal:** `compare`

### 4. Tracekit Box: Running AI Agents in Micro-VMs Where Every Way Out Is Decided and Signed
- **Source:** arXiv (cross)
- **Link:** https://arxiv.org/abs/2610.38458
- **Authors/org:** Bravish Ghosh
- **Focus area:** micro-VM sandbox with signed egress for agents
- **What it is:** Tracekit Box (open source, MIT, v0) runs each agent job in a Firecracker micro-VM with no network card; the only exits are host-side 'doors' over vsock (commands, outbound connections, secrets, model calls, workspace patch), each decided and signed by a signer the agent cannot reach. Private and cloud-metadata addresses are always refused, secrets never enter the VM (placeholders swapped by a host proxy), and changes return as a patch approved file by file. 13/13 end-to-end checks pass; 15 fuzz targets found nine issues, all fixed. Limits: no Firecracker jailer yet, co-located signer required.
- **Why it matters for Justin's agents:** A concrete, inspectable design for running unattended coding agents with keys kept outside the box and a verifiable record of what left it; relevant to the shared-box agent setup.
- **Action signal:** `compare`

### 5. PCM: A Proof-Carrying Message Protocol for Verifiable Multi-Agent Communication
- **Source:** arXiv (cross)
- **Link:** https://arxiv.org/abs/2610.39109
- **Authors/org:** Bravish Ghosh
- **Focus area:** proof-carrying messages between agents
- **What it is:** PCM makes each inter-agent claim ('tests passed', 'a person approved this refund') carry evidence: append-only Merkle-log records with inclusion proofs signed by an attesting signer the agent cannot control; receivers verify offline and grade each claim proven / unproven / failed. Authority travels as narrowing grant chains rooted in a recorded human approval. On 926 messages from real runs (712 lies in 16 classes), PCM accepts 10 lies, all stale evidence (1.4%); plain A2A accepts all 712 and six deployed protocol models accept 504-712. Verification ~1 ms.
- **Why it matters for Justin's agents:** MCP and A2A authenticate the channel, not the claim. For multi-agent handoffs, 'approved by Justin' should be a verifiable record, not text.
- **Action signal:** `track`

### 6. What Does "Now" Mean to Your Computer-Use Agent? Stale Screenshots, Page Loads, and Which Check to Run Before a Click
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.39282
- **Authors/org:** Vasundra Srinivasan
- **Focus area:** stale screenshots and pre-click checks in computer-use agents
- **What it is:** Measures planned clicks on 31 public pages: 0.4% of clicks planned on fully loaded pages went stale within 30 s vs 17% of clicks planned in the first second after load. Waiting ~1 s for network idle removes most risk, yet 8 of 10 popular open-source agents' wait rules leave >1% stale. Commercial pages keep loading longer than .gov pages. Before irreversible actions, a pixel comparison verifies target position as accurately as a frontier VLM at 1/8 the latency, and a 4B model matches the frontier model at verifying the previous action. Releases a benchmark generator, a break-even formula and three rules.
- **Why it matters for Justin's agents:** Cheap, immediately applicable guard for any GUI/browser agent: network-idle wait plus a pixel diff before irreversible clicks.
- **Action signal:** `try-now`

### 7. CALM: Conflict-Aware Lifecycle Memory Governance for Long-Horizon Language Agents
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.38573
- **Authors/org:** Chang Li, Xianhao Ou, Xinyan Ma, Hao Li et al.
- **Focus area:** conflict-aware memory lifecycle governance
- **What it is:** CALM separates preserving memory from admitting it at query time: records become evidence-grounded memory cells whose validity and lifecycle state are updated from support, conflict and dependency signals, and query-time gating (training-free or learned) admits evidence by temporal applicability. Best overall accuracy on LongMemEval-S and LoCoMo with Qwen and GPT backbones; preserving superseded records keeps past-state questions answerable without hurting current-state answers.
- **Why it matters for Justin's agents:** Continues Oct 28's stale-facts thread with a design that keeps old facts but blocks them from present-tense answers — the right shape for a personal assistant's preference history.
- **Action signal:** `compare`

### 9. Masked Erosion: How Acceptance Gates Lose Redundant Safeguards in Self-Improving Agents
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.38392
- **Authors/org:** Hau-Sing So, Daixian Liu, Weicai Long
- **Focus area:** silent loss of safeguards in self-improving harnesses
- **What it is:** Self-improving agents edit their harness and keep edits that score higher; when safeguards overlap, deleting one is masked because others still block harm. Measures harm for all subsets of four safeguards in two environments, 411 improvement loops under ten gate rules, plus three GEPA runs. A paired significance test blocks chance deletions; at the same cost 20-task batches kept every harness protected while 40-task batches lost all six. GEPA kept safety rules verbatim, yet two of three final harnesses misused credentials under a weaker model. Freezing safety text or auditing one-layer ablations preserves depth.
- **Why it matters for Justin's agents:** If we let an optimizer edit prompts/skills, freeze the safety block and test with a weaker model; redundancy erodes invisibly otherwise.
- **Action signal:** `try-now`

### 31. Artifact Distillation: Training-Free Transfer from Frontier to Small Language Models
- **Source:** arXiv (cross)
- **Link:** https://arxiv.org/abs/2610.37680
- **Authors/org:** Mustafa Safa Ozdayi, Somin Wadhwa

- **What it is:** A teacher solves training instances and writes its procedure into an artifact bank that a student queries at inference, no gradients. ### 32. The Coordination Tax and the Heterogeneity Dividend: Break-Even Conditions for Multi-Agent LLM Pipelines
- **Source:** arXiv (cross)
- **Link:** https://arxiv.org/abs/2610.37700
- **Authors/org:** Andreas Zettl, Diego Gosmar
- **Focus area:** cost break-even for multi-agent pipelines
- **What it is:** Closed-form model of coordination tax vs heterogeneity dividend, measured with Open Floor Protocol on 135 HumanEval/ClassEval tasks (2,430 runs, Claude Opus 5.5 and Haiku 5.5). Protocol overhead is tiny (7.2 ms/handoff), but planner-coder-reviewer costs 3.22x a single strong call, takes 3.24x as long and solves no more; moving roles to the cheap model is still worse. ### 33. Goal-Aware Dynamic Multi-Agent Collaboration for Long-Horizon Tasks
