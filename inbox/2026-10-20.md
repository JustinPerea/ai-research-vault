### 1. When the harness decides success: state that cannot be re-observed
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.26632
- **Authors/org:** Raimondas Lencevicius
- **Focus area:** harness context policy / re-observable state
- **What it is:** Asks when harness context choices (drop, summarize, replay reasoning) change success, not just cost. Pre-registered probe: truncation costs nothing when a needed fact can be looked up again but drops success to chance when it cannot be re-observed (92.5-point gap, 90% CI [89.5, 95.5]); replicated on a second provider. On ARC-AGI-3, summarizing old turns instead of dropping them, while keeping the Standard harness's note-taking invitation, recovers 86% of a 63-point harness gap; without the invitation 43%, and native reasoning replay recovers the remaining 57% (single-run point estimates).
- **Why it matters for Justin's agents:** Rule for Claude Code-style compaction: anything that cannot be re-fetched (user statements, one-shot tool results) must survive compaction or be written to notes; re-fetchable facts can be dropped.
- **Action signal:** `try-now`

### 2. Same Simulation, Different Evidence: Where Retrieved Tool Output Costs LLM Agents Accuracy
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.26836
- **Authors/org:** Ke Zhang, Sahchit Chundur, Jerry Peprah Owusu et al. (5 authors)
- **Focus area:** tool-output offloading / evidence use
- **What it is:** Harnesses that keep long tool outputs in files instead of context: with the PHREEQC geochemistry simulator (reports up to 846.8k chars, 158 execution-verified items), reading via a section index costs GPT-5.1 / GPT-5.2 11.3 / 7.9 points, with no detectable cost for Claude Opus 4.6 / Sonnet 4.6. Replaying 11,007 logged calls shows the GPT models still compute the keyed value; they answer from their own output files instead ('evidence substitution'). Naming the authoritative output adds 6.3–7.9 points for three GPT models; inlining outputs that fit works as well for GPT-5.1/5.2.
- **Why it matters for Justin's agents:** If Justin's MCP tools spill large results to files, name the authoritative output explicitly in the tool response, and inline when it fits; the cost is model-dependent.
- **Action signal:** `try-now`

### 3. One Skill Takes Over: Clashing Agent Skills and a One-File Fix
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.25064
- **Authors/org:** Parsa Razmara, Seyedarmin Azizi, Ardalan Aryashad
- **Focus area:** agent skills conflict / SKILL.md authoring
- **What it is:** SkillClash: 16 pairs of same-job skills with code-checked rules. Across seven models (4B open to Qwen3-235B and GPT-4.1), a skill's rules are followed 93–99% alone but 61–62% when a same-job skill is loaded beside it; most outputs show 'takeover' (one skill's unique rules all followed, the other's all dropped), driven by the worked examples. Ending each skill with one example that follows both cuts takeover to 1–15%; priority instructions don't help. One merged file written by Claude Opus 5.5 gets all seven models to 96–99% of achievable rules.
- **Why it matters for Justin's agents:** Directly about Justin's skills setup: avoid two active skills for the same job; if unavoidable, merge them or add one correct worked example that satisfies both.
- **Action signal:** `try-now`

### 4. When Code Becomes an LLM Call: An Empirical Study of Call-Site Contracts in Agentic Systems
- **Source:** arXiv (cross-list)
- **Link:** https://arxiv.org/abs/2610.24545
- **Authors/org:** Shihao Weng, Longtian Wang, Yang Feng et al. (9 authors)
- **Focus area:** LLM call-site contracts in agent code
- **What it is:** Empirical study of 496 LLM call sites in 40 popular open-source agentic systems (13.4 MLOC). 48% of LLM outputs reach control flow or execution and 73% of those never reach a person; 67% of prompt-side constraints are only requested of the model; 82% of call sites are checked before/after the call, yet 63% of expected constraints are unmet and only 5.3% of sites satisfy their whole contract. Ten patterns explain 99% of gaps; 38 runtime-triggering mechanisms are all stopped by a small code fix enforcing the expected constraint.
- **Why it matters for Justin's agents:** Audit Mitamaton's LLM call sites: any model output that drives a tool call or branch needs a code-enforced post-condition, not a prompt request.
- **Action signal:** `try-now`

### 5. Whose Credential Is It? How Owner Attribution in Agent MemoryShapes Cross-User Account Misuse
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.25707
- **Authors/org:** Hau-Sing So, Daixian Liu, Carl Hou et al. (6 authors)
- **Focus area:** shared agent memory / credential owner attribution
- **What it is:** Three-stage audit (exposure → behavior → state) for cross-user credentials in shared agent memory on AppWorld. A store mixing 763 logins retrieves another user's credential for 84.7% of required apps, yet agents rarely act on it; in a stress test where memory presents one foreign credential as the user's, seven agents use it in 80–94% of runs and change the victim's account in up to 43%. Naming the owner before or inside each credential line cuts misuse from 92 to 1 of 305 paired runs (costs 3–5 successful tasks per model on clean memory); a wrongly written owner restores misuse.
- **Why it matters for Justin's agents:** Any memory store holding secrets or account data should record the owner on every line; test behavior and state change, not just retrieval exposure.
- **Action signal:** `try-now`

### 6. MemDerive: A Diagnostic Benchmark for Agent Memory over Evolving Data
- **Source:** arXiv (cross-list)
- **Link:** https://arxiv.org/abs/2610.25373
- **Authors/org:** Sen Gao, Yongan Li, Han Chen et al. (8 authors)
- **Focus area:** agent memory over derived / evolving state
- **What it is:** MemDerive: 10 symbolically specified scenarios (4,692 events, 1,503 queries) with Datalog-derived gold answers and derivation DAGs. On derived state, every one of four memory systems falls behind plain BM25, although the same answer model reaches 96.01% given the supporting events. Most failures are 'ungathered' (the system holds the intermediate state but doesn't retrieve it), and implicit changes rarely propagate. Proposed principles: gather along the derivation, store versioned rules, maintain derived state via recorded dependencies.
- **Why it matters for Justin's agents:** Task state like 'what's done / what still holds' in Mitamaton is derived state; store it explicitly with dependencies instead of hoping retrieval reconstructs it. Keep a BM25 baseline in memory evals.
- **Action signal:** `compare`

### 8. Bud ContextCompact 2.0: Context Compaction for Agent Success and Accuracy with Small Language Models and Constrained Context Windows
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.25516
- **Authors/org:** Jithin VG, Ditto PS
- **Focus area:** context compaction for small models
- **What it is:** Bud ContextCompact 2.0 (Bud agent runtime). Recall over recorded sessions: compaction to 16K raises a 1.2B model to 0.335 (vs 0.247 truncation, 0.176 full 32K history) and a 9B model from 0.515 to 0.577. - **Why it matters for Justin's agents:** Direct evidence for local-model agents on constrained windows: compaction helps if triggered early, but budget its wall-clock cost on Mac inference.

### 9. Claim Laundering: When Agent Decision Models Trust Records Over Reality
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.25947
- **Authors/org:** Tina Khezresmaeilzadeh, Seyedarmin Azizi, Erfan Baghaei Potraghloo et al. (5 authors)
- **Focus area:** action records vs observations / silent failures
- **What it is:** Across Android screen traces, ALFWorld and WebShop, paired states vary observation, logged action and explicit success claim. In all 12 configurations (four decision models × three domains), records outweigh observations; after claimed-but-failed steps models still stop, advance or purchase in 53–100% of cases. Linear probes on hidden states separate success from failure (AUROC 0.77–1.00); EVIGATE, an intermediate-layer veto adding 0.04–2.0% latency, improves success under injected silent failures by 18.7 (ALFWorld), 5.0 (WebShop) and 5.1 points (phone simulator). Offline-calibrated gates don't transfer reliably to live trajectories.
- **Why it matters for Justin's agents:** For iOS actions that can fail silently, re-observe state after acting instead of trusting the agent's own 'done' log.
- **Action signal:** `compare`

### 26. From Trace to Fix: Residual Task State in Long-Horizon Agents

- **What it is:** TRACE-FIX turns execution logs into a dependency-linked ledger prioritizing unresolved requirements over salient surface errors, then plans recovery under a budget with outcome forecasting and an explicit repair reserve. ## Conflicts & open questions

- **What context management costs depends on what can be re-observed and on the model.** When the harness decides success (2610.26632) finds dropping turns harmless for re-fetchable facts but fatal otherwise; Same Simulation (2610.26836) finds file-offloaded tool output costs GPT-5.1/5.2 but not Claude 4.6 models; Bud ContextCompact (2610.25516) helps only when triggered early and loses its gain under wall-clock budgets; NCE (2610.25550) moves editing into the model. Extends the Oct 16 carry-forward (compaction helps or hurts): the answer looks like "it depends on re-observability, trigger time and model family."
- **Skill / harness self-evolution gains vs held-out stability.** EvoSkill v2 (2610.25931), SELM (2610.24630) and Hippo (2610.24453) report gains; Are Self-Evolving Agents Continual Learners? (2610.25858) shows plasticity costs stability on drifting streams, and the GEPA/SkillOpt local replication (2610.26020) sees SkillOpt's validation gain reverse on held-out. Consistent with Oct 19's Harness-Delta Attribution (most evolution gains are overfitting). Open: none of tonight's evolution papers report drift-stream or HDA-style tests.
- **Small controllers and monitors: pay off or not?** StopLoss (2610.25525) and SURE-Act (2610.24194) report savings/gains; Good Judgment, Bad Advice (2610.24649) finds a Jev decision controller raised cost 19% with no pass-rate change because it was poorly calibrated. Difference: StopLoss is outcome-trained and calibrated on successful runs; Jev was well-ranked but miscalibrated. Open: calibration, not ranking, seems to decide.
- **Sophisticated memory vs simple retrieval.** MemDerive (2610.25373): every memory system loses to BM25 on derived state; TokenWorth (2610.26453): sophisticated lifelong memory offers little over simple retrieval under tight budgets; HABIT-Bench (2610.24520): best 33.61%. Against that, Hippo and MemPrice report gains. Different benchmarks and budgets — no head-to-head. Carry-forward from Oct 19 (memory benchmark numbers not comparable) still open.
- **Requested vs committed actions; records vs reality.** Trust boundaries (2610.24298): models request protected actions in ~52–54% of invalid-proof trials while a tool gate commits none; Claim Laundering (2610.25947): agents trust their own success records; call-site contracts (2610.24545): checks exist at 82% of sites but 63% of constraints are unmet; injection window (2610.24048): single-run labels disagree with reruns up to 35%. Implication: evaluate commits and state changes with repeated runs. Today's Claude Code `decider: "person"` hook is a direct lever for the Oct 19 allow-rule escalation question.
