# AI Research Digest — Monday, July 6, 2026

## TL;DR
- **The KV-cache-compression thread got its first theoretical spine**: [arxiv:2607.01520] "The Risk of KV Cache Compression" (Haverbeck / Amo Alonso / Posada-Moreno / Trimpe / Pavone) characterizes **minimax risk under causal masking** and derives design principles that map to prefill and autoregressive decoding — the same day [arxiv:2607.01237] Kara publishes a concrete production instantiation (sliding-window compression + Token2Chunk variable-sized retention + KvLLM/vLLM integration). Together they form a "theory + practice" pair for compressing reasoning-chain KV cache without collapsing throughput.
- **Coding-agent RL efficiency is now infrastructure-dominated, not algorithm-dominated**: [arxiv:2607.01415] "The Rollout Infrastructure Tax" measures **110× variation in cold-start latency and 1.8× spread in worker-hours** across four rollout substrates for training one million 150-step coding-agent trajectories. This makes execution-substrate selection an optimization axis — not deployment plumbing — and directly reframes the "why does my agent RL cost so much" question.
- **The 'silent-finish' ceiling is emerging as the dominant failure mode of agentic RL on structured protocols**: [arxiv:2607.01470] World Feedback for Clinical Agents (Mantravadi et al.) publishes **MedAgentBench-v3 (508 tasks, 20 task types)** where inaction was the previous benchmark's dominant strategy (41.7% silent-finish); v3 reduces this to **8.9%**, at which point pure RL still trails rule-based SFT by 15.9 percentage points (**18.2% pass@1 vs 34.1%**) due to capability ceilings on **10/20 task types** and a format-knowledge barrier on **3/20** requiring exact clinical codes. Diagnoses *why* pure-RL agentic training bottoms out on structured-protocol tasks and shows the SFT+RL hybrid escape hatch.
- **Multi-agent forecasting contradicts identical-evidence deliberation as a design pattern**: [arxiv:2607.01661] InfoDelphi shows that giving all agents the same evidence produces **herding, not deliberation** — the paper proves **information asymmetry (public + private disjoint evidence subsets) is a design requirement** for genuine belief revision. On PolyGym (375 prediction-market questions) InfoDelphi delivers **12–18% Brier-score improvement + 4–8pp accuracy** over strongest baselines. This is a `compare` against the standard multi-agent debate premise — and the ablation confirms removing the asymmetry eliminates most of the deliberation benefit.
- **AI-Infra-Guard becomes the first open-source multi-layer MCP-audit framework** [arxiv:2606.31227]: **75+ components, 1,400+ deterministic vulnerability rules, LLM-driven auditing of MCP servers, 26+ jailbreak operators evaluated across 16 datasets**, structured across four attack layers (infrastructure / protocol-tool / agent-behavior / model). Directly usable by any team shipping MCP tools; the "layer-paradigm matching" principle is the meta-lesson.

### 1. The Risk of KV Cache Compression — Minimax Framework for Compression Under Causal Masking
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2607.01520
- **Authors / org:** Lukas Haverbeck, Carmen Amo Alonso, Andres Felipe Posada-Moreno, Sebastian Trimpe, Marco Pavone
- **Focus area:** Context engineering
- **What it is:** Attacks the "KV cache compression is heuristic soup" problem head-on. **Establishes minimax risk characterizations** for KV cache compression on long-sequence transformer inference, then derives **design principles for algorithms operating under causal masking** that achieve **minimax-optimal risk**. Concretely: prior compression work either shows worst-case impossibility or ships ad-hoc practical instances with no theoretical guidance on which parts of the cache are actually compressible. This paper characterizes **intrinsic compressibility** and produces a **practical instantiation** that maps efficiently to prefill and autoregressive decoding. Reports **"promising performance on LongBench in targeted experiments"** (the abstract doesn't publish raw deltas but the framework is the contribution).
- **Why it matters for Justin's agents:** Justin's autonomous loops routinely run at 32K–128K context with long chain-of-thought reasoning traces; the KV cache is the dominant memory line-item and its compression is the single biggest lever for extending context on M5 Max + 64 GB. Until now the practical guidance was "try H2O, try SnapKV, try StreamingLLM, hope it works." This paper is the theoretical companion: it tells you *which cache states are intrinsically compressible* and *what the risk floor is under causal masking* — meaning cache-compression choices become measurable against a theoretical bound rather than "we tried it and it seemed OK." **Concrete integration:** for any local-inference loop where Justin is compressing KV cache to fit longer context, this framework gives him a way to bound how much accuracy loss is inherent vs. avoidable. **Cross-ref:** the same-day publication of [arxiv:2607.01237] Kara (below) is the concrete practical instance — this pair represents the first theory-and-practice compression release in the memory/context cluster since ContextNest [arxiv:2607.02116] added determinism and A-TMA [arxiv:2607.01935] added state coordination. Emerging pattern: **context-engineering primitives now come in theory+practice pairs rather than single-instance drops.**
- **Action signal:** `track` + `compare` (theoretical framework — read once, use as bound for measuring practical compression choices; pair with Kara below)

### 2. Kara — Sliding-Window KV Cache Compression via Bidirectional Scoring + Token2Chunk Retention + KvLLM/vLLM Integration
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2607.01237
- **Authors / org:** Shen Han, Yuyang Wu
- **Focus area:** Context engineering / local & open models
- **What it is:** Concrete practical companion to [arxiv:2607.01520] above. Attacks two failure modes of existing KV cache compression: **(a)** threshold-based policies eliminate whole sequence blocks and hurt throughput; **(b)** rigid retention of isolated pairs or fixed-size chunks loses correlated context. **Kara**: operates on recently-generated context via a **sliding window with bidirectional attention scoring** for importance ranking, then a **Token2Chunk module** expands each selected pair into a **variable-sized segment** — flexibly preserving locally-correlated stretches rather than isolated tokens. Ships **KvLLM**, an inference framework built on **vLLM with PagedAttention** integration, so the compression is production-shape rather than research-only. Reports **"consistent performance improvements"** on reasoning-LLM serving across memory usage and throughput axes.
- **Why it matters for Justin's agents:** Kara is the pattern Justin has been waiting for. His local M5 Max stack runs Qwen and Llama reasoning models where the KV cache blows past 20+ GB at 128K context — and the standard sliding-window and top-k compressors either lose critical intermediate reasoning steps (isolated-token retention) or drop whole blocks (threshold-based). Kara's **variable-sized segment retention** is the right primitive for long chain-of-thought traces where consecutive tokens jointly encode a reasoning step. **Concrete moves: (a)** Kara + vLLM PagedAttention on Kubernetes is the deployment recipe Justin's federal-data-engineer side would use for internal reasoning-LLM serving. **(b)** the **bidirectional-attention-scoring window** is a small hook that composes with any HuggingFace decoder — implement as a drop-in KV cache manager, benchmark against Justin's specific workload (reasoning traces in Claude Code + a local Qwen reasoning executor). **Cross-ref:** paired with [arxiv:2607.01520] The Risk of KV Cache Compression above — Kara is a candidate concrete instantiation of the minimax-optimal design principles; measuring Kara's LongBench delta against the theoretical bound would say whether Kara is on the frontier or has room to grow. **Cross-ref:** composes with yesterday's [arxiv:2607.02509] ReContext training-free recursive evidence replay — Kara handles cache-side compression, ReContext handles context-side re-injection of evidence at query time. Two orthogonal wrappers over any frozen local model.
- **Action signal:** `try-now` + `local-fit` (production-shape via vLLM+PagedAttention integration; directly benchmarkable on Justin's local Qwen/Llama reasoning stack; expected to compose with ReContext)

### 3. The Rollout Infrastructure Tax — 110× Cold-Start Variation Across Coding-Agent RL Substrates
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2607.01415
- **Authors / org:** Daniel Thi Graviet, Lovre Pesut, Ivan Dagelic, Vedran Jukic, Ivan Burazin
- **Focus area:** Coding agents / evaluation (infrastructure)
- **What it is:** Attacks the "we assumed the RL algorithm was the bottleneck but it was the rollout substrate" problem. Frames **execution infrastructure for coding-agent RL as a first-class optimization variable, not deployment plumbing**. Concrete study: **four execution substrates** compared under one workload — training on **one million 150-step coding-agent trajectories**. Results: **110× variation in cold-start latency** across the four platforms; **1.8× spread in projected worker-hours** for the same training run. The paper's meta-thesis: "coding-agent RL development should actively optimize execution substrates as part of the training system itself" — small per-rollout savings compound catastrophically at 10^6-trajectory scale.
- **Why it matters for Justin's agents:** Justin doesn't yet train coding-agent models from scratch, but any autonomous loop that runs many attempts at a coding subtask is running the same substrate-sensitive workload — cold-start-per-attempt × attempt-count is the real cost line. **The 110× cold-start delta is the operational headline**: for any autonomous loop that runs > 1000 rollouts (which is one afternoon of an autonomous coding agent), substrate choice is the difference between "runs in minutes" and "runs overnight." **Concrete moves: (a)** for any long-horizon coding-agent workload Justin runs, benchmark cold-start on Docker vs. lightweight VM vs. Firecracker-style vs. process-isolation-only — the 110× spread means one of these choices is ~50–100× cheaper than the naive default. **(b)** the "infrastructure as an algorithm-level optimization" framing changes how Justin should think about MCP-tool authoring: **shipping a fast-cold-start tool substrate is a legitimate optimization contribution, not undifferentiated engineering**. **Cross-ref:** this is the infrastructure-side companion to yesterday's [arxiv:2607.02390] DecompRL (which shifted computation from GPU sampling to CPU enumeration). Both papers make the same meta-point: for coding agents, **the *shape* of computation matters as much as its total amount**. Together they define two orthogonal moves — DecompRL restructures the algorithm; Rollout Infrastructure Tax restructures the substrate. **Cross-ref:** the "small per-rollout savings compound at 10^6-scale" observation is the general principle behind the "test cheaply, deploy expensive" pattern that Justin's evaluation stack (PACE [arxiv:2607.02032]) exploits at a different layer.
- **Action signal:** `try-now` (substrate benchmarking is a one-day exercise; 110× delta means the payoff is not marginal; the framing is directly transferable to any autonomous-loop workload Justin runs)

### 4. World Feedback for Clinical Agents — MedAgentBench-v3: 41.7% → 8.9% Silent-Finish Ceiling, RL vs SFT Diagnosis
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2607.01470
- **Authors / org:** Ananya Mantravadi, Harshit Rajgarhia, Prasanna Desikan, Abhishek Mukherji
- **Focus area:** Evaluation / tools & connectors / agent orchestration
- **What it is:** Attacks the "we tried RL on our agentic workload and it plateaued" problem with a diagnostic scalpel. **MedAgentBench-v3**: **508 tasks across 20 task types** in a FHIR (healthcare data standard) environment for clinical decision agents. Previous benchmark (v2) had **41.7% silent-finish ceiling** — inaction became the dominant strategy because failing loudly cost more reward than doing nothing. v3 restructures reward signals to **reduce silent-finish to 8.9%**. Empirical findings on v3: **pure RL: 18.2% pass@1; rule-based SFT: 34.1%; RL+SFT hybrid outperforms both** — the 15.9pp gap is fully attributable to two structural barriers: **(a)** capability ceiling: **10/20 task types show 0% base performance** — RL cannot bootstrap capability where the base model has none; **(b)** format-knowledge barrier: **3/20 task types require exact clinical codes** that the RL policy cannot invent from scratch. The paper's meta-lesson: **applying RL to structured-protocol agentic tasks requires sufficient foundational model capability + valid feedback mechanisms**; treat these as separable diagnostic axes, not one number.
- **Why it matters for Justin's agents:** Justin's federal-data-engineer role is *exactly* this problem class — structured-protocol tasks (data pipelines, FHIR-like schemas, government-form processing) where an agent that "gives up quietly" is worse than one that fails loudly. **Four concrete takeaways: (a)** the "silent-finish ceiling" is a named metric to track on any autonomous-loop workload — build it into Justin's own evaluation harness as a first-class number. **(b)** the **10/20 zero-base-performance finding** is the "don't try to RL your way past a capability ceiling" rule; before running any expensive RL loop, run the base model with SFT or in-context examples and record *which subtasks have zero base performance* — those are RL-untrainable and need architectural or model-swap solutions. **(c)** the **3/20 exact-format barrier** generalizes: any agent workload where the correct action is a specific structured artifact (SQL, GraphQL query, FHIR code, ICD-10, government form) hits the same barrier — the fix is retrieval + templating, not more RL. **(d)** the **RL+SFT hybrid outperforms both** — matches what the coding-agent training literature has been converging on. **Cross-ref:** SkillCoach (item 5 below) is the *process-quality* half of the same diagnostic frame — MedAgentBench-v3 diagnoses *what fails*; SkillCoach diagnoses *why the trajectory fails*. Together they define a two-axis diagnostic for any structured-protocol agentic workload. **Cross-ref:** the "silent-finish ceiling" is the first named failure-mode metric for agentic RL; watch for it to appear in coding-agent RL papers next.
- **Action signal:** `try-now` + `compare` (silent-finish metric is directly measurable on Justin's own workflows; the capability-ceiling / format-barrier diagnostic separation is a repeatable pattern for any structured-protocol agent evaluation)

### 5. SkillCoach — Self-Evolving Rubrics for Agentic Skill-Use Across Four Process-Quality Axes
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2607.01874
- **Authors / org:** Jiayin Zhu, Kelong Mao, Yudong Guo, Dengbo He, Sulong Xu, Simiu Gu, Yutao Yue
- **Focus area:** Agent orchestration / evaluation
- **What it is:** Attacks the "our agent picked the wrong skill from an overlapping skill repository and the outcome-only evaluation didn't tell us why" problem. **SkillCoach** is a **self-evolving rubric framework** for evaluating and enhancing agentic skill-use. Given a skill repository where multiple skills have overlapping capabilities (a common state in any production MCP surface), SkillCoach **generates evaluation rubrics from actual agent trajectories** and measures performance across four process-quality axes: **skill selection** (did the agent pick the right skill?), **skill adherence** (did it follow the skill's spec?), **skill integration** (did it compose skills correctly?), **skill-based reflection** (did it correct course when a skill misfired?). Then uses the evolved rubrics as **training supervision** — filtering rollouts by rubric quality rather than by outcome success. Reported to **outperform outcome-only evaluation** by exposing hidden failures masked by final accuracy, and to **outperform outcome-only rollout filtering as a training signal**.
- **Why it matters for Justin's agents:** This is the direct next step for Justin's MCP-tool ecosystem. As soon as Justin has more than ~5 MCP tools, some will functionally overlap — a "read_file" and a "grep" both can find text in a file, but for different situations. Today, the failure mode is "the agent picked grep when read_file would have worked and burned 3× tokens" and outcome-only eval says "task completed 87% of the time." SkillCoach's four axes give Justin the diagnostic vocabulary to say **which** step failed. **Concrete moves: (a)** for each MCP tool Justin ships, author a self-evolving rubric that scores its use across the four axes on live traces — the rubric-as-training-signal framing means these rubrics also serve as fine-tuning supervision if Justin ever specializes a local model as an executor. **(b)** the **four-axis diagnostic is meaningfully close to the ontology emerging in the memory cluster** (representation / skill / write-gate / write-cost / state-coordination) — a convergent signal that agent behavior is best analyzed as a **decomposable set of quality axes**, not a monolithic score. **Cross-ref:** this pairs with [arxiv:2607.01470] World Feedback for Clinical Agents (item 4 above) as the *process* half of *diagnostic evaluation* — Clinical Agents diagnoses at the task-type level (10/20 zero-base performance); SkillCoach diagnoses at the step level (skill-selection failed vs skill-adherence failed). Together they define a two-scale diagnostic. **Cross-ref:** the "rubric-as-training-signal" pattern is the *evaluation-side* analog of yesterday's [arxiv:2607.02073] Maven "evidence-state RL rewards" — both convert a *quality dimension* into a *training signal* by naming the dimension and rewarding it directly. This is the third convergent instance (after Janus write-gate rewards and Maven evidence rewards) — **naming a quality axis and rewarding it directly** is now a general pattern.
- **Action signal:** `try-now` (four-axis rubric is directly implementable per MCP tool; the rubric-as-training-signal payoff means one investment yields both eval + fine-tune supervision)

### 6. InfoDelphi — Information Asymmetry as a Design Requirement for Multi-Agent Deliberation: 12–18% Brier Improvement
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2607.01661
- **Authors / org:** Yuante Li, Yicheng Tao, Kate Zhang, Taozhi Wang, Gefei Gu, Yaxin Zhou
- **Focus area:** Agent orchestration / multi-agent
- **What it is:** Attacks the "our multi-agent debate collapsed into consensus and didn't help" problem with a theoretical + empirical diagnosis. **Core finding**: when multiple LLM agents receive **identical evidence**, deliberation collapses into **herding** rather than genuine belief revision — the paper *proves* this is a first-order failure of the standard multi-agent debate setup. **InfoDelphi** solves it by **partitioning evidence into shared public + private disjoint subsets** so each agent starts with different information; deliberation then produces genuine belief updates as agents share private evidence. Framework has three components: **relevance-aware evidence routing**, **rationale-based iterative deliberation**, **confidence-weighted aggregation**. Empirical: on **PolyGym (375 binary forecasting questions from prediction markets)**: **12–18% improvement in Brier score vs strongest baselines; 4–8 percentage point accuracy gain**. **Ablation confirms removing information asymmetry eliminates most of the deliberation benefit** — the private-evidence partition is load-bearing, not a bonus.
- **Why it matters for Justin's agents:** This contradicts the implicit assumption in every "spawn N agents and let them debate" pattern in the LangChain/AutoGPT/CrewAI ecosystem — that **more agents with the same information produces better decisions**. InfoDelphi says: **no, more agents with the same information produces herding**. The design fix is architectural: **evidence routing must partition information across agents**, not fan out the same context. **Two concrete moves for Justin: (a)** for any multi-agent workflow Justin builds (planner + executors, panel of judges, deliberative decision agent), the evidence routing layer needs to be **explicitly partitioning-aware** — some evidence goes to all agents, some evidence goes to individual agents; the split is a first-class design decision, not an afterthought. **(b)** the **12–18% Brier improvement is on prediction markets** — directly transferable to any agent workload where the decision is probabilistic (which model tier to escalate to, whether to retry a failed subtask, whether to flag output as uncertain). **Cross-ref:** this is the third convergent finding on multi-agent design in the past week: yesterday's [arxiv:2607.02507] dual-channel divergence (agents diverge public-vs-off-record under alignment pressure) + yesterday's [arxiv:2607.02453] LangChain 82.5% cross-ecosystem contributors + today's InfoDelphi. Emerging pattern: **the naive multi-agent architecture assumptions are all wrong**. The *social* dynamics (dual-channel), *ecosystem* dynamics (contributor cross-flow), and *epistemic* dynamics (herding under identical evidence) all break the "spin up N agents and hope" model. **Cross-ref:** the "public + private disjoint evidence subsets" primitive parallels the CvRDT-based CanonicalMerge KV-cache set-union semantics [arxiv:2607.01308] from yesterday — both introduce **explicit set-theoretic structure over agent state** as a way to prevent non-determinism or non-deliberation. Convergent signal: **multi-agent systems now need to be reasoned about as distributed systems, not orchestrated conversations.**
- **Action signal:** `compare` + `try-now` (directly contradicts standard multi-agent debate assumption; the evidence-partitioning fix is architecturally simple; 12–18% Brier delta means the design change is worth doing on any probabilistic multi-agent workload)

### 7. AI-Infra-Guard — Open-Source Multi-Layer Red-Teaming Framework with MCP Server Auditing (75+ Components, 1,400+ Rules, 26+ Jailbreak Operators × 16 Datasets)
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.31227
- **Authors / org:** Yong Yang, Xing Zheng, Huiyu Wu, Huangsheng Cheng, Xiaorong Shi, Jing Guo, Bo Yang, Yi Zhou, Xiangfan Wu, Zonghao Ying (Tencent)
- **Focus area:** Tools & connectors / safety
- **What it is:** Attacks the "how do you actually audit an MCP-tool-heavy agent system for security" problem. **AI-Infra-Guard**: open-source (CC-BY 4.0) red-teaming framework structured across **four attack layers**: **infrastructure**, **protocol/tool**, **agent behavior**, **model**. Each layer gets a **different detection paradigm** — the meta-thesis is **"layer-paradigm matching"** — because uniform detection strategies don't work against a stratified attack surface. Concrete capabilities: **deterministic rule matching across 75+ components with 1,400+ vulnerability rules**; **LLM-driven auditing of Model Context Protocol (MCP) servers** — the first framework to explicitly audit MCP servers; **multi-turn adversarial testing of agents**; **26+ jailbreak attack operators evaluated across 16 datasets**. Adds **supply-chain security of agent skills** as an explicit target — auditing what skills agents install.
- **Why it matters for Justin's agents:** This is directly usable for Justin's MCP-tool authoring workflow — his federal-data-engineer side ships internal MCP tools, and his indie-dev side is building companion apps that integrate MCP servers from untrusted sources. Today, Justin's MCP-server security audit is ad-hoc; AI-Infra-Guard is the first structured audit surface with **specific numeric coverage** (75+ components, 1,400+ rules). **Concrete moves: (a)** run AI-Infra-Guard against every MCP server Justin adopts as a dependency — the LLM-driven MCP auditor is the closest thing to a "security scanner for MCP servers" that exists. **(b)** the **layer-paradigm matching principle** is the meta-lesson: Justin's own MCP-tool authoring should ship with layered audit surfaces (deterministic rules at the tool layer + adversarial testing at the agent-behavior layer + jailbreak coverage at the model layer) rather than one uniform security pass. **(c)** the **26 jailbreak operators × 16 datasets = 416 evaluated attack combinations** is a concrete red-team floor to measure Justin's own tools against. **Cross-ref:** this is the operational realization of the safety-verification convergence pattern the vault has been tracking. [arxiv:2607.01793] Vera Framework (July 4) reported **93.9% attack success on Claude Code + OpenClaw + Hermes + Codex**; [arxiv:2607.02389] Steerability (July 5) reported the substrate-side mitigation (54.5% → 90.9% backdoor recall with substrate + tool CLI); today's AI-Infra-Guard delivers the **detection-side realization** — a shipped framework with numeric rule coverage for the same threat surface. **Cross-ref:** the "four-layer attack surface" ontology parallels the four-axis SkillCoach process-quality ontology (item 5) — a convergent theme this week is that **agent systems are best analyzed as decomposable layer/axis sets**, not monoliths, whether for safety or for skill-use quality.
- **Action signal:** `try-now` + `compare` (open-source under CC-BY 4.0, directly runnable on Justin's MCP surface; specific numeric coverage — 75+/1,400+/26+/16 — gives measurable audit floor; composes with Steerability substrate + Vera detection-predicate patterns)

## Local-model corner

**Two directly runnable items on M5 Max + 64 GB today:**

### Kara + KvLLM/vLLM on local Qwen / Llama reasoning models (from item 2)
- **Model:** Qwen 3-4B or Llama 3-8B reasoning-chain models
- **Memory fit:** the Kara point is that KV cache compression *increases* the effective context you can fit; with a Qwen 3B at Q4 (~2 GB weights) + Kara-compressed 128K-context KV cache, headroom on 64 GB is comfortable (previously the 128K cache alone was 20+ GB on 8B models). The Token2Chunk variable-sized retention is the specific win vs top-k / threshold compressors when reasoning traces have locally-correlated stretches.
- **Realistic tasks:** long-form reasoning where the model needs to keep >64K tokens in view — multi-file code review, document QA over long PDFs, sustained autonomous-loop workspaces. Kara's sliding-window bidirectional-scoring means the *recent* reasoning window stays intact while older content compresses.
- **How to run:** KvLLM ships as a vLLM extension with PagedAttention integration — install the vLLM fork the paper links, point at any local HuggingFace model, benchmark against the reference vLLM. The compression is a KV cache manager plug-in, not a model modification.
- **Speed estimate:** vLLM + PagedAttention on M5 Max Qwen 3B Q4 hits **~120–150 tok/s decode**; Kara reduces cache growth by a factor that depends on window/segment settings but the target regime is 2–4× cache reduction at <2% quality drop on reasoning benchmarks. Wall-clock for 128K-context reasoning trace: minutes rather than tens-of-minutes.

### SkillCoach process-quality rubrics on local Qwen/Llama executor (from item 5)
- **Model:** any local model Justin uses as an executor tier (Qwen 3-8B, Llama 3-8B); works on models where he has trajectory logs from his MCP-tool-using agents
- **Memory fit:** the rubric-evaluation cost is dominated by the LLM-judge model, which can be the same executor model or a slightly larger reviewer — either fits comfortably on 64 GB.
- **Realistic tasks:** offline evaluation of MCP-tool-use quality; rollout filtering when specializing a local model as an executor; regression testing when adding new MCP tools to Justin's agent's skill repository.
- **How to run:** implement the four-axis rubric generator as a Python module that reads agent trajectory logs, calls the LLM-judge to score each axis, and emits per-trajectory rubric scores. The rubric-evolution loop is a self-play run on Justin's own trajectory corpus.
- **Speed estimate:** rubric evaluation is one LLM call per axis per trajectory — for a 500-trajectory corpus at 4 axes = 2000 LLM calls on a local 7B at ~130 tok/s = under an hour. Cheap enough to re-run weekly as Justin's MCP surface changes.
