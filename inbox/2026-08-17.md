## Items

### 1. Nanbeige4.2-3B on Apple Silicon
- **Source:** arXiv (Hugging Face Daily Papers)
- **Link:** https://arxiv.org/abs/2608.13987
- **Authors / org:** John T. Halloran
- **Focus area:** Local / on-device inference (Apple Silicon) + MCP agents
- **What it is:** Nanbeige4.2-3B is a 3B agentic Looped Transformer (one layer stack reused for a second forward pass). On Apple Silicon MPS the released HF checkpoint does not run: **five independent bugs**, including a silently-zeroed RoPE buffer and calls to removed `transformers` cache APIs. Fixing those is not enough — layer reuse **doubles peak attention memory**. A chunked-prefill strategy extends allowable context **2.7× on 32 GiB shared memory**. After system-prompt and MPS-native memory patches, the model is evaluable on MCP / tool-calling benches: **MCPMark subset 0% → 30%** real agentic task completion; BFCL near-perfect on single tool calls, majority-fail on multi-tool. Patched checkpoint + prompt optimizer + harnesses: https://github.com/johnhalloran321/Nanbeige4.2-3B-mps-fix. Submitted Aug 14; abs verified this run.
- **Why it matters for Justin's agents:** This is the week's only "it actually runs on a Mac" paper. 3B + MCPMark 30% is not a Claude replacement, but it is a candidate *on-device tool router* sitting under Mitamaton while Opus/Sonnet handle the hard turns. Two portable facts: (1) Looped Transformers punish unified memory twice — budget context as if the model were ~2× deeper; (2) "open-weight agentic 3B" does not mean "runs in transformers on MPS" until someone patches it. On 64 GB the 2.7× context extension from 32 GB numbers should have headroom; still verify before relying on long Mitamaton contexts.
- **Action signal:** `try-now` — clone the patched checkpoint and run the author's MCPMark subset on the M5 Max; do not promote it past router-tier until multi-tool BFCL moves.
### 2. Second Thought: Reasoning in Parallel as Agents Act and Observe
- **Source:** arXiv (Hugging Face Daily Papers)
- **Link:** https://arxiv.org/abs/2608.13667
- **Authors / org:** Zhensu Sun / Chengran Yang / Yunbo Lyu / Jieke Shi / David Lo
- **Focus area:** Agent orchestration (ReAct idle-window)
- **What it is:** In ReAct, reasoning is frozen while the action serializes and the environment returns. Second Thought is training-free: the instant a Thought ends, fork **four auxiliary branches**, decode them concurrently with the main loop, merge when the observation arrives. Three agentic benches × three reasoning LLMs: lower average turn count in **all nine** pairs; main-thread decoding reduced in **six of nine** by up to **43%** (~20% average among those); Pass@1 unchanged in seven pairs, **+12.4 and +10.2** in the two that move. Vs a compute-matched control that spends the same budget on the main thread's own reasoning: strictly higher Pass@1 with **1.3–3.2× less** sequential decoding in all four settings where the control applies. Submitted Aug 13; abs verified this run.
- **Why it matters for Justin's agents:** Claude Code / Mitamaton already wait on MCP, calendar, and shell. That wait is free compute if the harness can fork a second thought (next-tool hypothesis, constraint check, "should I ask the user"). The paper says putting that budget on the *main* CoT is worse — so do not just raise thinking_level; fork. Smallest port: one background "what will I do with the tool result" pass, merge on observation, abort if the observation falsifies it.
- **Action signal:** `try-now` as a single background fork on the 3–5 slow Mitamaton tools; `compare` against raising the primary thinking level at matched tokens.
### 3. ClawGym II: Black-Box RL on Agent Harness
- **Source:** arXiv (also on HF Daily Aug 18; placed on submitted date)
- **Link:** https://arxiv.org/abs/2608.16798
- **Authors / org:** Huatong Song / Fei Bai / Ming Yang / Renyuan Li / Jia Deng / Jujie He / Zhange Zhang / Daixuan Cheng / Yan Xing / Qi Yun / Xuxing Chen / Danyang Li / Feng Chang / Chuan Hao / Ran Tao / Jian Yang / Bryan Dai / Wayne Xin Zhao / Mingjie Tang / Ji-Rong Wen
- **Focus area:** Harness-native RL + Claude Code
- **What it is:** RL *through* an opaque harness (not a rewritten gym). Sandboxed concurrent rollouts; a serving proxy at the model boundary captures calls; prefix trees reconstruct multi-turn trajectories; PPO and GRPO adapted to the tree; mix-harness training lets one model learn from heterogeneous harnesses. Qwen3-30B-A3B: ClawGym-Bench Pass@1 **+9.98 pp via OpenClaw, +14.81 pp via Claude Code**, stable over **200–400** optimization steps; gains also on JobBench and OfficeQA. Submitted Aug 17; abs verified this run.
- **Why it matters for Justin's agents:** This is the OpenForgeRL [arxiv:2607.21557] shape with a Claude Code number attached: **+14.81 pp on the harness Justin already runs**, on a 30B-A3B that is the local-fit class. You do not have to run the RL. The reusable piece is the proxy-at-the-model-boundary — the same tap produces training data (or just traces) without forking Claude Code. Mix-harness training is the reason not to overfit a model to one wrapper.
- **Action signal:** `track` the trainer; `try-now` the proxy-tap if you want traces out of Claude Code without a hook war.
