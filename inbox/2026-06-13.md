# AI Research Digest — Saturday, June 13, 2026

## TL;DR
- **Anthropic's "dynamic workflows" pattern gets a formal name and an open paper.** "Recursive Agent Harnesses" ([arxiv:2606.13643], June 11) explicitly cites Anthropic's recently-shipped dynamic workflows as the production precursor and frames **RAH** as harness-level recursion (parent agent generates a script that spawns full sub-harnesses with filesystem + code-execution + planning, in parallel, alongside structured function calls for small subtasks). On **Oolong-Synthetic at context up to 4M tokens**, Codex baseline 71.75 → **81.36% with RAH on Codex** and **89.77% with Claude Sonnet 4.5 backbone**. This is the closest published primitive yet to what Justin uses Claude Code's sub-agents for daily.
- **MiniMax open-sources the sparse-attention recipe that powered the M3 release.** [arxiv:2606.13392] — MiniMax Sparse Attention + the 428B-total / 23B-active **MiniMax-M3** release on HF — claims **28.4× attention-compute reduction at 1M context, 14.2× prefill speedup, 7.6× decode wall-clock speedup on H800**, and per-token compute "reduced to 1/20" via the blockwise Index-Branch + Main-Branch design. Released kernel is open-source. Direct successor to **Vortex** ([arxiv:2605.x, tracked]) — flagged below as `compare`.
- **Coding-agent harnesses are becoming a learned layer.** HarnessBridge ([arxiv:2606.12882], UCLA, June 11) replaces the manually-engineered harness with a **lightweight learnable controller** doing two bidirectional projections — observation (raw trajectory → compact decision state) and action (proposed action → executable transition / trajectory-grounded rejection). Reports matching or surpassing specialized harnesses on **Terminal-Bench 2.0** and **SWE-bench Verified** with substantially reduced token usage and trajectory length, and generalizes from training on smaller generators to commercial-scale models. Complements the **Self-Harness** result (harnesses-that-edit-themselves) already in the ledger — flagged as `compare`.
- **Computer-use evaluation gets a real-world hybrid-interface benchmark.** WeaveBench ([arxiv:2606.09426], 81 HF upvotes) is **114 tasks across 8 real-world work domains**, grounded in real user requests with publicly verifiable artifacts, requiring agents to span desktop GUI control + CLI + code editing + browser + external tools simultaneously. Best frontier model-runtime combination tops out at **41.2% PassRate** — gap-to-human is wide and the eval is hybrid-interface rather than pure-browser.
- **Population-level test-time scaling crosses IMO/USAMO gold threshold.** MaxProof on the new MiniMax-M3 ([arxiv:2606.13473], 69 upvotes) trains three proof-oriented capabilities (generation, low-FPR verification, critique-conditioned repair) into a single model, then at test time runs **the same model as generator + verifier + refiner + ranker** and tournament-selects across a population of candidate proofs. Result: **IMO 2025 35/42, USAMO 2026 36/42** — both above human gold-medal thresholds.

## Items

### 1. Recursive Agent Harnesses (RAH)
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.13643
- **Authors / org:** Elias Lumer, Sahil Sen, Kevin Paul, Vamse Kumar Subbiah
- **Focus area:** Agent orchestration / coding agents
- **What it is:** Names and studies the pattern sitting between "recursive language models" (recursion over model calls only) and the production pattern where a parent agent **writes and runs an executable script that spawns full sub-agent harnesses in parallel** — each child gets its own filesystem tools, code execution, and planning — and uses ordinary structured function calls for small subtasks. Authors quote: "production coding agents have begun to write code that spawns subagents at scale, most recently in Anthropic's dynamic workflows." On **Oolong-Synthetic (199 samples, context up to 4M tokens)**: Codex baseline **71.75 → 81.36% with RAH on Codex**, **89.77% with Claude Sonnet 4.5 backbone**.
- **Why it matters for Justin's agents:** This is the first paper to formalize exactly what Justin uses every day in Claude Code — a parent agent dispatching specialized sub-agents in parallel via scripts rather than tool-call chains. Two concrete takeaways: (a) the parent should be willing to **emit shell/Python that spawns harnesses, not just structured tool calls**; (b) on long-horizon work at 4M-token scope, harness-level recursion outperforms model-level recursion by ~10pp. For Justin's MCP-tool products, the implication is symmetric — expose primitives that subagents can call from generated scripts, not just from the orchestrator's tool list.
- **Action signal:** `try-now` — the pattern is reproducible today inside Claude Code without any new infrastructure; the paper just gives it a name and a benchmark to hill-climb against.

### 2. MiniMax Sparse Attention + MiniMax-M3 release
- **Source:** arXiv + Hugging Face
- **Link:** https://arxiv.org/abs/2606.13392 ; https://huggingface.co/MiniMaxAI/MiniMax-M3
- **Authors / org:** MiniMax AI (Xunhao Lai et al.)
- **Focus area:** Context engineering / frontier models
- **What it is:** Blockwise sparse-attention design — an **Index Branch selects Top-k key-value blocks**, a **Main Branch executes block-sparse attention** — with the kernel open-sourced. Headline numbers: **28.4× attention-compute reduction at 1M context, 14.2× prefill speedup, 7.6× wall-clock decoding speedup on H800**. The matching production model release **MiniMax-M3 (~428B total / ~23B active MoE, 1M context, native text + image + video)** claims **9× prefill / 15× decode speedups vs M2 at 1M context** and **per-token compute reduced to 1/20** via MSA.
- **Why it matters for Justin's agents:** This is the first first-party sparse-attention recipe shipped alongside a working 1M-context production model, and the speedups are large enough to move "long-context for agents" from "feasible if you pay for it" toward "default." For Justin's agent products this changes two things: (a) the **economics of keeping long conversation/tool-trace state in-context** rather than off-loading to memory tiers shifts in favor of in-context, at least for paying-API workloads; (b) the open kernel is the bridge other open models will use to ship 1M-token serving without bespoke infra. The 428B/23B-active size is **not local-fit** on M5 Max even at aggressive quant — this matters for API workloads, not laptop inference.
- **Action signal:** `compare` — direct successor to Vortex (already in ledger). MiniMax M3's reported 15× decoding speedup vs M2 is consistent with the 28.4× attention-compute reduction in the paper. Vortex previously reported 1.37× speedup on MiniMax-M2.7 (B200). Both effects compose with the model architecture rather than replacing it.

### 3. HarnessBridge — learnable bidirectional controller for LLM agent harness
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.12882
- **Authors / org:** Xiaoxuan Wang, Haixin Wang, Alexander Taylor, Jason Cong, Yizhou Sun, Wei Wang (UCLA inferred from author overlap)
- **Focus area:** Tools & connectors / coding agents
- **What it is:** A lightweight **learnable module** sitting between the LLM and the environment, replacing hand-engineered harnesses through end-to-end instruction tuning. Two bidirectional projections: **observation projection** (raw trajectory → compact, decision-relevant state) and **action projection** (proposed action → executable transition *or* trajectory-grounded rejection). Claims match-or-surpass-specialized-harness performance on **Terminal-Bench 2.0** and **SWE-bench Verified** with **substantially reduced token usage and trajectory length**; trained on smaller generators but generalizes to larger commercial models. Specific numerical results are deferred to the full PDF.
- **Why it matters for Justin's agents:** Pairs with #1 above and with Self-Harness from earlier in the ledger — the harness layer between model and tools is becoming first-class trainable infrastructure, not a hand-tuned configuration file. For MCP-tool products specifically, the lesson is that the **observation-compaction layer is a separable artifact** you can train independently and ship with the tools, instead of relying on the model to figure out how to read raw tool outputs. If the bidirectional rejection mechanism reproduces under independent test, it's a cleaner solution to "agent emits invalid action" than today's retry-on-parse-error loops.
- **Action signal:** `compare` — directly relevant to Self-Harness (harnesses-that-edit-themselves, Terminal-Bench 2.0 40.5→61.9 on MiniMax-M2.5). Self-Harness improves via edit-the-code; HarnessBridge improves via learn-the-controller. Both target the same bottleneck.

### 4. WeaveBench — long-horizon, real-world benchmark for computer-use agents with hybrid interfaces
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.09426
- **Authors / org:** Wanli Li, Bowen Zhou, Yunyao Yu, Zhou Xu, Yifan Yang, Dongsheng Li, Caihua Shan
- **Focus area:** Evaluation / tools (computer-use)
- **What it is:** **114 tasks across 8 real-world work domains**, grounded in actual user requests and publicly verifiable artifacts (deliverables, files, screenshots, logs, action traces — judged by a trajectory-aware judge, not just final-state). The "hybrid interfaces" framing is specifically that each task spans **visual desktop control + command-line execution + code editing + browsers + external tools** simultaneously — i.e., what real knowledge work looks like, not isolated browser tasks. Best frontier model-runtime combination peaks at **41.2% PassRate**.
- **Why it matters for Justin's agents:** Computer-use eval has been balkanized — OSWorld for desktop, WebArena for browser, SWE-bench for code, Terminal-Bench for shell — and frontier scores on each individually have been climbing. WeaveBench is the first eval that **rewards stitching them together** and reports a sober 41.2% ceiling. That number is the realistic upper bound when Justin is thinking about "agent that does my federal-data-engineer day job" — most of those tasks are multi-interface, not single-runtime. Useful as the leaderboard to watch for when interface-spanning generalist agents stop being a long way off.
- **Action signal:** `track` — no actionable artifact today, but the 41.2% ceiling is the headline number to revisit on every frontier release.

### 5. SpatialClaw — code-as-action interface for spatial reasoning
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.13673
- **Authors / org:** Seokju Cho et al. (NVIDIA + KAIST inferred from author overlap)
- **Focus area:** Tools & connectors / reasoning
- **What it is:** Maintains a **stateful Python kernel pre-loaded with input frames and a suite of perception + geometry primitives**; a VLM-backed agent writes **one executable cell per step conditioned on all prior outputs**. Result: **59.9% average accuracy across 20 spatial-reasoning benchmarks (+11.2pp over prior spatial agents)**, consistent across six VLM backbones from two model families with no benchmark- or model-specific adaptation.
- **Why it matters for Justin's agents:** Reinforces the through-line from HyperTool (yesterday's [arxiv:2606.13663]) and the broader code-block-as-action thread — when the action interface is "emit one Python cell," the model can dynamically observe intermediate results and adapt strategy across steps, rather than committing to a fixed tool sequence. The **stateful kernel + pre-loaded primitives** pattern is directly portable to non-spatial domains: ship a Jupyter-like environment with task-relevant utilities already imported, then let the agent write cells. Generalizable design principle for MCP-style tooling.
- **Action signal:** `track` — design-principle relevance is high; not a drop-in artifact for Justin's stack today.

### 6. MaxProof — population-level test-time scaling for math proof on MiniMax-M3
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.13473
- **Authors / org:** MiniMax (Jiacheng Chen et al.)
- **Focus area:** Reasoning & inference-time compute
- **What it is:** A single MiniMax-M3 model trained on **three proof capabilities** — generation, verification (engineered for low false-positive rate), and critique-conditioned proof repair — via "defense-in-depth" generative-verifier RL. At test time, the **same model serves as generator + verifier + refiner + ranker**, searches over a population of candidate proofs, and tournament-selects one. Results: **IMO 2025 35/42** and **USAMO 2026 36/42**, both above human gold-medal thresholds.
- **Why it matters for Justin's agents:** The structural lesson is **role multiplexing** — instead of training separate models for generate / verify / repair / rank, train one model with all four heads and switch at inference. Combined with population-level search, this gives a recipe for inference-time scaling that doesn't require multi-model orchestration plumbing. For Justin's MCP products: any tool whose output can be verified (compiled code, schema-valid JSON, tests-pass-or-not) becomes a candidate for the same recipe — single model, four roles, tournament across N candidates.
- **Action signal:** `track` — the recipe is reproducible but currently demonstrated only on math proof; watch for adaptations to code/data tasks.

### 7. FORT-Searcher — shortcut-resistant training data for deep search agents
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.12087
- **Authors / org:** Jia Deng, Yimeng Chen et al. (Renmin / industry partners inferred from author overlap with Ji-Rong Wen)
- **Focus area:** Evaluation / training methodology for tool-use
- **What it is:** Argues that prior search-agent training data inflates *structural* difficulty (more graph nodes, more hops) but doesn't actually force the agent to search — the intended search process can collapse through a cheaper identifying route. Formalizes **four shortcut risks: evidence co-coverage, single-clue selectivity, exposed constants, prior-knowledge binding** — and proposes **trajectory signatures** (solving cost, answer hit time, prior-shortcut rate) to diagnose realized search difficulty. Trains "FORT-Searcher" on shortcut-resistant synthesized tasks; claims best-overall performance among comparable-size open-source search agents on challenging deep-search benchmarks (numerical results deferred to PDF).
- **Why it matters for Justin's agents:** The general lesson — **structural complexity ≠ realized task difficulty** — applies to any synthetic agent-training data, not just search. The four shortcut categories are useful as a checklist when evaluating whether a benchmark is actually testing what its authors think it tests. Relevant for Justin's eval thinking: when reviewing any new agent benchmark, check whether "exposed constants" or "single-clue selectivity" would let a smart few-shot baseline shortcut the intended pipeline.
- **Action signal:** `track` — methodology lens, not an artifact to integrate.

## Conflicts & open questions
Cross-referenced against `_meta/claims-ledger.md`:
- **MiniMax Sparse Attention vs Vortex (sparse-attention serving for agents)** — `compare`. Vortex (already in ledger) reported **3.46× throughput vs full attention overall, 1.37× on 229B MiniMax-M2.7 (B200)**. MiniMax's own MSA paper reports **28.4× attention-compute reduction at 1M context, 14.2× prefill, 7.6× decode speedup on H800**, and the M3 release claims **15× decode vs M2 at 1M context**. The two papers measure different things (kernel-level compute reduction vs end-to-end serving throughput at typical agent batch sizes) and on different hardware (H800 vs B200), so they're complementary rather than contradictory — but the M3-vs-M2 number is the cleaner comparison for end-users and is the one to cite going forward.
- **HarnessBridge vs Self-Harness** — `compare`. Self-Harness (already in ledger: **40.5 → 61.9 on Terminal-Bench 2.0 with MiniMax M2.5**) improves by **letting the agent edit its harness code**. HarnessBridge improves by **learning a lightweight controller end-to-end** that replaces the hand-engineered harness. Both target the same bottleneck (harness layer between LLM and environment); HarnessBridge defers specific numbers to the PDF, so a head-to-head comparison on identical model + benchmark isn't yet possible. Open question: does the learned-controller approach scale better than the edit-the-code approach as harness complexity grows?
- **Recursive Agent Harnesses vs "The Illusion of Multi-Agent Advantage"** — open empirical question. Yesterday's [arxiv:2606.13003] showed automatically-generated MAS underperform CoT+Self-Consistency despite 10× cost. RAH is closer to **expert-designed** multi-agent (humans wrote the parent script template, the model fills in the dispatching) — the +10pp gain on Oolong-Synthetic at 4M-token context is consistent with the Illusion paper's caveat that expert-architected MAS still beats auto-MAS. Net read: multi-agent advantage is real **when the architecture is designed, not searched**, and is most visible at long-context scope.
