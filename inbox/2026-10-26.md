## TL;DR

- **Compaction loses the rules, not the work** (Compact-Bench 2610.31710; Compaction-Friendly 2610.31778): LLM summaries keep at most 16% of recurring details vs 79% for mechanical extraction, and conversation-only instructions ("don't do X") are dropped ~6x more than build specs. Keep constraints in CLAUDE.md/skill files and pin ids/paths mechanically.

- **Harness choice is model-specific** (2610.32483, 52,168 trajectories): rankings flip by model; TraceTrial (2610.32285) finds 31.1% of successful runs still break a harness rule.
- **Lessons that stick** (Self-Direction 2610.31846): per-mistake LoRA adapters +8.9-17.0 points on open Qwen agents; Phronix (2610.31789) validated capability store lifts cheap models from ~28% to ~89% on SWE-bench tasks.

- **Replay instead of re-reasoning** (mobile trace reuse 2610.31712: ~80% fewer tokens; HarnessMM 2610.32813: up to 87.9% fewer tokens).

### 1. Compact-Bench: Measuring What Context Compaction Costs Long-Horizon Coding Agents
- **Source:** arXiv (cross)
- **Link:** https://arxiv.org/abs/2610.31710
- **Authors/org:** Ruopei Sun, Jianfeng Cai, Kangwen Zhao, Wengang Zhou, Houqiang Li
- **Focus area:** context compaction cost for coding agents
- **What it is:** Compact-Bench pairs full-history and summary-only continuations from the same repository state (35 SWE-bench repairs, 146 agentic sessions, 106 production compaction chains). Across 14 summarizer backbones, compaction damages 5-64% of 22 full-history successes; Claude Opus 4.8 preserves the most repairs, DeepSeek-Flash damages the most. With Kimi-K3 summarizing, the Kimi Code prompt preserves 19/22 continuations while the Claude Code prompt retains the most recurring details (15.0%). LLM summaries keep at most 16.0% of recurring details vs 79.1% for mechanical extraction; production summaries keep 15.7% at the first boundary.
- **Why it matters for Justin's agents:** Long Claude Code / nightly-pipeline sessions compact constantly. Mechanical extraction of recurring details (paths, ids, commands) beats LLM summaries 79% vs 16% — pin those in a file or hook output rather than trusting /compact.
- **Action signal:** `try-now`

### 2. Benchmarks Are Surprisingly Compaction-Friendly
- **Source:** arXiv (cross)
- **Link:** https://arxiv.org/abs/2610.31778
- **Authors/org:** Jeanne Salle, Hardik Bhatnagar, Matthias Bethge, Sahar Abdelnabi, Maksym Andriushchenko
- **Focus area:** compaction strategies on frontier long-horizon tasks
- **What it is:** Fixes the OpenCode scaffold, implements five compaction strategies and runs three frontier models on PaperBench, ProgramBench and PostTrainBench. For the two 1M-context models the compaction threshold does not measurably change performance; GPT-5.3-Codex (smallest window) does worse at lower thresholds on PaperBench. No method beats default self-summarization; aggressive discarding costs some models up to 20 points. The first compaction summary on ProgramBench already drops about one third of anti-cheating rules, rising with each compaction; on SWE-chat sessions, instructions about how to work / what not to do are dropped ~6x more than build specs.
- **Why it matters for Justin's agents:** Pairs with Compact-Bench: compaction mostly survives because progress lives on disk, but constraints that exist only in the conversation ("don't push", "never touch the laptop") get dropped first. Keep such rules in CLAUDE.md / skill files, not in chat.
- **Action signal:** `try-now`

### 3. Knowing When to Stop: The Evidence-Action Gap in Coding Agents
- **Source:** arXiv (cross)
- **Link:** https://arxiv.org/abs/2610.31895
- **Authors/org:** Tianyu Chen, Xinran Zhao, Vijay Viswanathan, Shoubin Yu, Mingyuan Zhou, Tongshuang Wu
- **Focus area:** coding-agent over-persistence and escalation
- **What it is:** ImpasseBench injects twelve realistic environment blockers into solvable repair tasks and marks the step where evidence of needing outside help becomes sufficient. Across eight frontier models and 19,371 trajectories, nearly every run that needs help collects that evidence, yet a third still exhaust their budget, and every detected unsafe request comes after that point. An escalation tool cuts budget exhaustion from 34.0% to 6.7%; an external monitor nearly triples task success after environment restoration. Escalation tickets name the blocker but often omit the agent's progress and verification status.
- **Why it matters for Justin's agents:** Directly applicable to unattended jobs like the nightly pipeline: give agents an explicit escalate/handoff tool and require the handoff to include progress + verification state, otherwise they burn budget or try unsafe workarounds.
- **Action signal:** `try-now`

### 4. Who Verifies the Tools? How Warped Formatters Mislead Agents and Their Verifiers
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.32110
- **Authors/org:** William Jeffries
- **Focus area:** tool output formatting as a reliability bug
- **What it is:** In a production RAG research system, tool output formatters omitted search limits, result caps or identifier namespaces, misleading the agent and its verifier even though each tool computed correctly. Feeding the same results with omissions vs explicit details changed agent claims and verifier verdicts: in one test verifiers went from accepting incorrect answers 90/90 times to rejecting them 90/90. An audit prompt used with Codex and Claude Code rediscovered known defects plus twelve new ones, and found warped formatters in OpenClaw and Hermes (OpenClaw fix merged).
- **Why it matters for Justin's agents:** Cheap audit for MCP servers Justin writes: every tool result should state caps, truncation, search scope and id namespace. Run the paper's audit prompt over Mitamaton tools.

### 5. Tool-Calling LLM Agents Under Realistic MCP Faults: Scale Does Not Purchase Fault Tolerance
- **Source:** arXiv (cross)
- **Link:** https://arxiv.org/abs/2610.32555
- **Authors/org:** Antonio Ken Iannillo, Joshua Segun Owotogbe, Roberto Natella, Francesco Avallone, Kristina Kudryavtseva, Indika Kumara
- **Focus area:** MCP fault tolerance
- **What it is:** MCP-Injector is a protocol-aware fault-injection middleware on the MCP tool-call path (permanent, transient, intermittent faults, seedable), calibrated on incidents mined from 57,240 issue/PR threads across 1,774 open-source MCP repos. In 1,350 cells (gpt-oss 20B and 120B; custom plan-and-execute, OpenAI Agents SDK, LangChain), permanent-heavy faults cut task-completion score 60% (8.08 to 3.23/10). - **Why it matters for Justin's agents:** MCP resilience is a harness problem, not a model-size problem. Add retries/fallbacks and explicit error surfacing in the MCP client layer; MCP-Injector is a ready test rig.

### 6. Agentic AI Defense: Decode-Time Provenance Binding for MCP
- **Source:** arXiv (cross)
- **Link:** https://arxiv.org/abs/2610.31974
- **Authors/org:** Eric Yocam, Varghese Vaidyan, Paris Kalathas, Patrick Tague, Bruce DeBruhl, Yong Wang
- **Focus area:** MCP prompt-injection defense
- **What it is:** Shows cross-modal trust laundering: instructions hidden in an email-signature image (LSB, DCT or metadata steganography) bypass text scanners and enter a multi-agent MCP workflow once a tool decodes them. Proposes decode-time provenance binding: HMAC-authenticated trust labels, an MCP-maintained provenance ledger and context-taint tracking that block critical tool calls influenced by decoded content. Undefended pipeline: 100% attack success; keyword/regex defenses let 62.5% through; the mechanism blocks all 24 adaptive payloads. Audited trusted promotion raises legitimate-task completion from 67% to 100%.
- **Why it matters for Justin's agents:** Mitamaton reads email; any decoded attachment/image text should be tainted and kept away from send/delete tools. Taint-tracking at the MCP layer is the pattern.

### 7. Don't Forget What You Just Learned: Self-Directed Repair Turns Agent Mistakes Into Lasting Lessons
- **Source:** arXiv (new)

- **Focus area:** persistent lessons via per-mistake LoRA adapters

### 8. Phronix: The Capability-Centric Learning Paradigm for Agents

## Conflicts & open questions

- **Does compaction hurt?** Compact-Bench (2610.31710) reports 5-64% damage to repairs from a single summary-only continuation, while the compaction-friendly study (2610.31778) sees no measurable threshold effect for 1M-context models. Both agree constraints and recurring details are what get lost; the disagreement is about how much benchmark progress on disk masks it.
- **Self-improving harnesses, again.** Phronix (2610.31789), Self-Direction (2610.31846) and HarnessMM (2610.32813) report large gains from learned capabilities/lessons; RSIHub (2610.32253) finds evolution gains vary by setting and often fail to transfer to held-out tasks. Continues the Oct 21-23 thread (ARC-AGI-3 harness study).
- **Memory design.** MemCryst (2610.32295) and ActionRAG (2610.32752) report gains from structured memory/skills and graph memory; last week's Raw-RAG result (2610.30755, Oct 23) found naive retrieval over raw history hard to beat. ActionRAG's +5.4 is over retrieval baselines on MemoryAgentBench, the same benchmark family.
- **Multi-agent coordination.** Shared persistent documents beat debate (2610.31709), and failures concentrate after agents see peers' answers (2610.32060); but the helpful-agent problem (2610.31985) shows shared resources let benign agents bypass review. Open: whether shared-document coordination amplifies out-of-workflow favors.
