## Items

### 1. MAPLE: Memory-Augmented Planning with Language and Evolution
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2609.11636
- **Authors/org:** Kesheng Chen, Yamin Hu, Wenjian Luo
- **Focus area:** memory / planning / evolution
- **What it is:** LLM optimization agents usually treat each natural-language request in isolation. MAPLE keeps the optimization program, accepted plans, earlier updates, and candidate solutions so later NL revisions can reuse search state. Combines language-based problem construction with mathematical programming and evolutionary search. Introduces NLDO (15 trajectories, 180 updates across selection, scheduling, rostering, routing, cloud placement). Main eval: completes all trajectories; online scalar quality 0.951; Pareto hypervolume ratio 0.875. Ablations: maintaining executable state improves update validity and can preserve useful search across substantial revisions.
- **Why it matters for Justin's agents:** Direct pattern for Mitamaton day-admin: calendar/inbox constraints change mid-day; keep the *executable* plan + prior NL edits, not just chat summary. Also a template for Claude Code / MCP harnesses that evolve solver scripts across sessions instead of regenerating from scratch.
- **Action signal:** `try-now`

### 2. When Validation Stops Learning: Auditing Update Admission for Continual Embodied Agents
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2609.10873
- **Authors/org:** Qinzhen Ma, Ruihai Wu
- **Focus area:** continual learning / runtime guards
- **What it is:** Independent eval can reject harmful policy updates *and* starve useful continual learning. Argues update admission needs both error control and retained learning opportunity at a stated interaction budget. Shows range-based confidence gates cannot certify unchanged old-task behavior within otherwise substantial budgets; a paired-binomial construction lowers the sample burden when disagreements are rare. Also specifies certified historical-reference promotion and a round-level missed-opportunity metric. One-step pushing diagnostic (32 seeds): fresh paired checks admit 31.6% of a common update stream at 2,000 episodes/stage vs **zero** for the range-based gate; unconditional replay still learns better closed-loop. Physical-robot / VLA validation left open.
- **Why it matters for Justin's agents:** Mitamaton (and any on-device personalization loop) needs an admission policy for memory/skill updates — not a gate so conservative it freezes the agent. Audit missed-opportunity rate alongside false-admit rate before shipping “validate then write” curators.
- **Action signal:** `compare`

### 3. Agentic Share-of-Search: A Multi-Agent AI System for Competitive Decision-Making in LLM-Mediated E-Commerce
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2609.11190
- **Authors/org:** Spandan Ghose Chowdhury
- **Focus area:** multi-agent / ReAct / competitive visibility
- **What it is:** Seller-side multi-agent system for LLM-mediated ecommerce: defines Agentic Share-of-Search (ASoS), deploys query agents across leading AI shopping platforms, and runs a ReAct diagnostic agent that recommends prioritized merchandising interventions. 100-trial ablation feasibility study: recovers the ablated signal in 39% of trials (95% CI 30.0–48.8%, 5.5× chance), rising to 63.9% among high-correlation ablations.
- **Why it matters for Justin's agents:** Less core to Mitamaton day-admin, but useful as a concrete multi-agent + ReAct diagnostic pattern (query swarm → root-cause agent → ranked interventions) and a reminder that LLM-mediated discovery is becoming a first-class environment agents must measure.
- **Action signal:** `track`

### 4. How AI Coders Discuss, Disagree, and Reach Consensus: Challenges and Opportunities for LLM-Based Qualitative Coding
- **Source:** arXiv (cross-list from cs.HC)
- **Link:** https://arxiv.org/abs/2609.11109
- **Authors/org:** Jeongyeon Kim, John Mitchell
- **Focus area:** multi-agent debate / consensus
- **What it is:** Empirical study of multi-agent LLM qualitative coding: independent code → debate → reconcile. Accuracy depends on codebook length, data similarity, and agent disagreement. Counterintuitive result: **intense and unresolved** debates between agents associated with *higher* accuracy. LLMs emulate many human discussion behaviors but lack adaptive contextual responsiveness. Releases open-source AI discussion dataset + design recommendations for automated coding systems.
- **Why it matters for Justin's agents:** For Claude Code / multi-agent review loops, do not force early consensus — preserve disagreement traces as a quality signal. Contrasts with label-free Bayesian anchors (yesterday’s When Agents Disagree): sometimes the debate *is* the feature.
- **Action signal:** `compare`

### 5. Beyond Static Guarantees: Measuring the Static-Pass Dynamic-Fail Gap in Security-Sensitive and LLM-Generated Python Code
- **Source:** arXiv (cross-list from cs.CR)
- **Link:** https://arxiv.org/abs/2609.10762
- **Authors/org:** Jessica Pourleyli, Maitreyee Das Urmi, Glaucia Melo
- **Focus area:** agentic security eval / code gen
- **What it is:** Defines Static-Pass Dynamic-Fail (SPDF): code that clears static gates but remains exploitable at runtime. Three-stage agentic pipeline: Bandit+Semgrep → LLM CWE reasoning → autonomous exploit verification in isolated Docker. 1,355 Python samples (SecurityEval, RedCode, CyberNative). Of 654 Bandit-Semgrep-clean samples, LLM stage flagged 394 candidates across 235 files; dynamic verification confirmed/partially confirmed exploitability in **95 files** → inclusive pipeline rate **14.53%** (~1 in 7 statically clean). Confirmed rates among candidate file–CWE pairs: RedCode 33.7%, CyberNative 28.6%, SecurityEval 5.4%. Frequent confirmed classes (e.g. CWE-338, CWE-916) flagged by neither Bandit nor Semgrep.
- **Why it matters for Justin's agents:** Claude Code / MCP tool-writing and any Mitamaton-adjacent codegen should treat “static clean” as necessary not sufficient — add a cheap dynamic/agentic second gate before promoting generated Python into the harness.
- **Action signal:** `try-now`

## Conflicts & open questions
- **Update admission vs learn-anyway:** Validation-Admission ([`2609.10873`](https://arxiv.org/abs/2609.10873)) shows conservative range gates can admit *zero* useful updates and that unconditional replay still wins closed-loop — tension with Artificial Id / harness “validate before write” safety ([`2609.11911`](https://arxiv.org/abs/2609.11911)). For Mitamaton personalization: audit false-*reject* / missed-opportunity, not only false-admit.
- **Retain executable memory vs probe-and-curate:** MAPLE ([`2609.11636`](https://arxiv.org/abs/2609.11636)) bets on keeping the live program + candidate solutions across NL revisions; yesterday’s Grounding Agent Memory ([`2609.11060`](https://arxiv.org/abs/2609.11060)) argues post-task curators need environment-probing tools. Which memory write path for day-admin plans?
- **Debate-as-signal vs resolve-to-anchor:** AI Coders ([`2609.11109`](https://arxiv.org/abs/2609.11109)) finds intense *unresolved* multi-agent debate predicts higher coding accuracy; When Agents Disagree ([`2609.11709`](https://arxiv.org/abs/2609.11709)) pushes Bayesian backward reasoning as a label-free consensus anchor. Keep disagreement traces, or force an anchor before acting?
