## Items

### 1. JIT-Agent: Scaling Harness Intelligence via Just-in-Time Harness Evolution
- **Source:** arXiv (Hugging Face Daily Papers)
- **Link:** https://arxiv.org/abs/2608.25593
- **Authors / org:** Guibin Zhang / Leo Lu / Fangzhou Xie / Kang Zhu / Junhao Wang / Zhifei Xie / Zhaochen Yu / Zihang Liu / Zhongxiang Sun / Qiankun Li / Yue Liao / Heng Chang / Xiaobin Hu / Qibing Ren / Wangchunshu Zhou / Shuicheng Yan — NUS
- **Focus area:** Just-in-time harness synthesis
- **What it is:** A model trained to synthesize task-adaptive harnesses (memory, planning, action protocol, tool/skill orchestration) on the fly for arbitrary off-the-shelf agentic LLMs. Fixed four-module protocol; customize, repair, and self-evolve from an archive of prior harness configs. DeepSeek-V4-Flash + JIT surpasses GPT-5.6 on DeepSearchQA **(+9.1)** and OdysseyBench **(+4.3)**; GLM-5.2 gains up to **+20.2**. Competitive with OpenCode and Claude Code across DeepSeek V4, Mimo-V2.5, and Qwen3.6 families. Code: github.com/bingreeky/JIT. Submitted Aug 26; abs verified.
- **Why it matters for Justin's agents:** AutoSaddler (yesterday) patches a harness offline from failures. JIT-Agent *generates* the harness per task. That is the scalable version of "Claude Code skills + a planner markdown" if the 4-module protocol is real. Try as a harness helper in front of a frozen local model, not as a replacement for Claude Code this weekend. Archive-of-prior-harnesses is the compounding piece (same family as WikiSkill's wiki, without injecting it into the live agent).
- **Action signal:** `try-now` on the four-module split (M/P/A/F) as a directory layout; `compare` against AutoSaddler / PILOT before training a helper.

### 2. The Handoff Tax: Continuing Non-Native Trajectories in LLM Agents
- **Source:** arXiv (Hugging Face Daily Papers)
- **Link:** https://arxiv.org/abs/2608.24358
- **Authors / org:** Roy Ganz / Mor Shpigel Nacson / Adi Kalyanpur / Ron Litman
- **Focus area:** Mid-run model switching (Claude Code `/model`)
- **What it is:** Coding agents span dozens of model calls; users escalate LC→HC or downshift HC→LC mid-run, forcing the receiver to continue a *non-native* trajectory. Claude and GPT family pairs; vary direction, timing, and interface (full-trajectory transfer vs compaction vs trajectory removal, repo state preserved). Across both families, **full-trajectory escalation recovers less than half of the LC-to-HC quality gap** while paying a cost premium — the **handoff tax**. Downshift is the favorable cost-quality point. Preferred interface *reverses* with direction: reducing LC trajectory information *improves* escalation; removing the HC trajectory *hurts* downshift. Submitted Aug 25; abs verified.
- **Why it matters for Justin's agents:** Claude Code `/model` switches mid-task are not free. Operational rule: when escalating, prefer compact or drop the cheap trajectory and keep the repo; when downshifting, keep the expensive trajectory. Do not paste the full LC trace into Opus "for context." This is the missing eval for any Mitamaton router that swaps local 4B ↔ cloud Opus mid-day.
- **Action signal:** `compare` — add a 10-task escalate/downshift probe to the personal eval; default compact-on-escalate / keep-on-downshift.

### 3. VoiceMem: Streaming Dual-Brain Memory for Real-Time Interaction
- **Source:** arXiv (Hugging Face Daily Papers)
- **Link:** https://arxiv.org/abs/2608.26005
- **Authors / org:** Zhifei Xie / Jiaqi Lang / Ze An / Yifan Zhao / Dongchao Yang / Kai Li / Ziyang Ma / Mingbao Lin / Chunyan Miao / Shuicheng Yan — NTU Singapore
- **Focus area:** Streaming voice memory (Mitamaton voice)
- **What it is:** Parallel informational left brain (facts) + emotional right brain (affect/persona) with streaming memory I/O. Pipeline for memory-aware SLM training, long-horizon eval, and decoupled deployment with interchangeable backends. Under top-5 retrieval, left brain outperforms Mem0 at top-200 by **~30 points**. Right brain +4.29 aggregate on three persona benches vs previous best. Retrieval **134 ms**, inside standard VAD, so no extra conversational delay. Code: github.com/xzf-thu/VoiceMem. Submitted Aug 26; abs verified.
- **Why it matters for Justin's agents:** Yesterday's Gemini 3.5 Transcribe is the STT. VoiceMem is the memory that has to land *during* the utterance, not after. Split facts vs affect; keep retrieval inside VAD. Mitamaton voice notes should not dump into the same append-only notebook that Harness the Memory said hurts action — left brain is schema-entity, right brain is persona, both streaming. Decoupled Mem0-style backend means you can try the architecture without the training stack.
- **Action signal:** `try-now` — split Mitamaton voice memory into facts vs affect with a 134ms-class retrieval budget; `compare` against Mem0 / LightMem on a 20-turn voice log.
