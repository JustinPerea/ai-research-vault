# AI Research Digest — Thursday, June 25, 2026

## TL;DR
- **Agent memory consolidation continues.** Two complementary memory papers landed today: **Metis** (arxiv:2606.24151) shows hybrid text+code memory beats text-only by +20.6 pts task accuracy at -22.8% cost on AppWorld, and **EDV / Execute-Distill-Verify** (arxiv:2606.24428) attacks the "self-confirmation trap" by replacing single-agent reflection with multi-agent execution + third-party distillation + consensus-verified memory writes. EDV is the right architectural answer to yesterday's MEMPROBE finding that "the artifact itself doesn't contain what you need."
- **Coding agents — two orthogonal angles.** **Bayesian control for coding agents** (arxiv:2606.24453) reframes tool orchestration as cost-sensitive sequential hypothesis testing — the controller's belief state beats token-probability for uncertainty quantification, and the framework is highest-value precisely when verification is expensive but informative. **Kog Laneformer 2B** ships a from-scratch 2.3B coding model with novel "Delayed Tensor Parallelism," hitting 3,000 tok/s on 8× MI300X — fast, but HumanEval+ 45.1% is not yet competitive with Qwen2.5-Coder-7B at the same parameter class. The architecture is the interesting story.
- **Tool-use security.** **ToolPrivBench** (arxiv:2606.20023) measures whether agents pick higher-privilege tools when a lower-privilege alternative would suffice. Headline finding: over-privileged selection is common across mainstream agents, prompt-level controls fail under transient tool failures, and general safety training does not transfer to least-privilege decisions. Pairs directly with yesterday's MemClaw governance thesis: governance has to live in the *training*, not just the prompt.
- **Computer-use agents get autonomous reward signals.** **RL for Computer-Use Agents** (arxiv:2606.24515) uses a VLM-as-judge as a noisy binary reward channel, then derives a noise-corrected estimator for PPO. **+12.6 pts** over zero-shot on macOSWorld / Windows Agent Arena / OSWorld; **+5.1 pts** over uncorrected reward. The noise model is the actual contribution — VLM rewards have been tried before; explicit noise correction makes them finally PPO-stable.
- **Eval methodology + agent infra.** **Grading the Grader** (arxiv:2606.24839) shows iterative nudging raises agentic-data-analysis grading success from 36% → 97%, and 100% precision is achievable with a three-layer cascade. **CUGA** (IBM, HF blog, June 23) opens an Apache-2.0 production-grade agent harness with 24 working FastAPI examples — Intent Guards, Tool Approval, Playbooks built into the runtime. This is the open-source-friendly competitor to the closed Claude Tag / Slack-resident agents.

## Items

### 1. Metis: Bridging Text and Code Memory for Self-Evolving Agents
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.24151
- **Authors / org:** Zijie Dai, Siuhin He, Hui Li, Qihui Zhou, Jiajun Li, Mingcong Song, Guoping Long, Hongjie Si, Xin Yao, Lin Zhang, James Cheng, Xiao Yan
- **Focus area:** Agent memory
- **What it is:** A controlled comparison of text- vs code-based memory representations for self-evolving agents, followed by a hierarchical dual-representation system. Text memory stores execution plans, environment facts, and common pitfalls; recurring patterns get selectively *promoted* to executable tools. Evaluated on AppWorld. Headline: **+20.6 pts task accuracy over ReAct baseline at -22.8% execution cost**; outperforms other self-evolving agent systems across accuracy, efficiency, and construction cost.
- **Why it matters for Justin's agents:** This is the most direct attack to date on the "text-memory plateaus → migrate to a vector DB → still plateaus" cycle. The promotion criterion — recurring patterns get crystallized into tools — is the right shape for an MCP-stack agent that accumulates reusable scripts over time. Promotion-to-tool is also the part most MCP frameworks already half-support (you can register dynamic tools at runtime), so the integration cost is low.
- **Action signal:** `try-now` — pattern is small enough to retrofit into a custom Claude Code orchestration harness today, even without the reference impl. The AppWorld benchmark numbers give a credible target to beat. Pair with yesterday's MEMPROBE (arxiv:2606.24595) as the eval methodology.

### 2. EDV: Escaping the Self-Confirmation Trap via Execute-Distill-Verify
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.24428
- **Authors / org:** Shiding Zhu, Yudi Qi, Yajie Wang, Jiaze Li, Chao Song, Yaorui Shi, Yibo Miao, Hanqi Gao, Kai Zhang
- **Focus area:** Agent memory / agent orchestration
- **What it is:** Identifies the **self-confirmation trap**: single-agent experience learning reinforces the same agent's own mistakes as valid lessons. EDV decouples the loop into three roles: (a) **Execute** — multiple heterogeneous agents explore the same task in parallel; (b) **Distill** — a dedicated third-party agent comparatively analyzes all trajectories and proposes candidate experiences; (c) **Verify** — the executor group validates candidates by consensus before any write to memory. Consistent improvements across tau2-bench, Mind2Web, and MMTB. Code at https://github.com/shidingz/EDV.
- **Why it matters for Justin's agents:** This is the architectural fix that yesterday's MEMPROBE result implies. MEMPROBE showed task completion saturates while user-state recovery stuck at ~0.6 — meaning the agent succeeds without storing what was true. EDV's consensus-verify-before-write is exactly the gating mechanism MEMPROBE's "memoryless baseline beats" finding demands. For Justin's companion-app architecture, the three-role decomposition (different agents, third-party distillation, consensus gate) is the right pattern to layer in front of any memory store — vector, symbolic, or hybrid.
- **Action signal:** `try-now` — code is released; the three-role decomposition is implementable as a small orchestration wrapper over any existing memory backend. Pair the "verify by consensus" gate with MemClaw's policy-governed propagation (arxiv:2606.24535, yesterday) for a complete write-side governance stack.

### 3. RL for Computer-Use Agents with Autonomous Evaluation
- **Source:** arXiv (GLOW @ IJCAI 2026 workshop)
- **Link:** https://arxiv.org/abs/2606.24515
- **Authors / org:** Marta Sumyk, Oleksandr Kosovan
- **Focus area:** Tools & connectors / computer-use agents
- **What it is:** Desktop/GUI environments lack scalable reward signals — task completion is visually grounded and hard to encode in handcrafted rewards. The paper uses a **VLM-as-judge** that compares the final screenshot to the original instruction and emits a binary completion signal. Crucially, it models this signal as a **noisy binary reward channel** and derives a noise-corrected estimator for PPO. Results across macOSWorld, Windows Agent Arena, and OSWorld: **+12.6 pts success rate over zero-shot baseline, +5.1 pts over raw evaluator fine-tuning** — confirming the noise correction is the contribution, not the VLM-as-judge.
- **Why it matters for Justin's agents:** Computer-use agents are the connector layer between Justin's MCP stack and any closed app (e.g., a federal-system web portal with no API). The pattern of "use a VLM to bootstrap reward, then noise-correct" is the right shape for training small specialist computer-use models locally — and for evaluating screenshot-based MCP server outputs in CI. The noise-correction math generalizes to any LLM-as-judge pipeline where the judge itself is the bottleneck.
- **Action signal:** `track` — workshop paper, no public code yet. Most actionable angle is the noise-corrected reward estimator as a reusable component for any RL-on-VLM-judgment pipeline. Strongly pairs with Anthropic's existing computer-use Claude (and Gemini 3.5 Flash's 78.4 on OSWorld-Verified from May 19) as the open-research analog.

### 4. Bayesian Control for Coding Agents
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.24453
- **Authors / org:** Theodore Papamarkou, Vladislav Smirnov, Viktor Mazanov, Artem Vazhentsev, Preslav Nakov, Timothy Baldwin, Artem Shelmanov
- **Focus area:** Coding agents / reasoning & inference-time compute
- **What it is:** Reframes coding-agent tool orchestration as **cost-sensitive sequential hypothesis testing**. A controller maintains a Bayesian belief about code correctness and decides at each step whether to gather evidence (run tests, inspect), refine candidates, verify with an expensive tool, or stop. Evaluated across six code generators and nine benchmarks. The Bayesian belief state **outperforms token-probability and raw tool-success baselines for uncertainty quantification**. Largest gains when verification is expensive but informative.
- **Why it matters for Justin's agents:** This is the missing principled story under every Claude Code-style "decide when to run tests vs just write" decision. Today most of that gating is ad-hoc — vibes-driven prompt rules and "let the model decide." Bayesian control gives a calibrated belief that survives across long-running loops where token-probability collapses (overconfident on confabulated code, undercount on uncertain-but-correct edits). For Justin's federal-data-engineering scripts where verification (e.g., dry-run a pipeline against a sample partition) is expensive, the framework directly maps onto when to spend the verification budget.
- **Action signal:** `track` — paper is theoretical-leaning with broad benchmark coverage but no released code. Most immediately useful as the conceptual frame for replacing ad-hoc gating in custom Claude Code skills. Cross-reference with SelfCompact (arxiv:2606.23525, June 23): both frame "when to invoke an expensive operation" as a model-decision; SelfCompact decides when to *compact*, Bayesian control decides when to *verify*.

### 5. ToolPrivBench: Over-Privileged Tool Selection in LLM Agents
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.20023
- **Authors / org:** Kaiyue Yang, Yuyan Bu, Jingwei Yi, Yuchi Wang, Biyu Zhou, Juntao Dai, Songlin Hu, Yaodong Yang
- **Focus area:** Tools & connectors / agent safety
- **What it is:** Defines and measures **over-privileged tool selection** — an agent picking or escalating to a higher-privilege tool when a lower-privilege alternative would suffice. **ToolPrivBench**: eight domains, five risk patterns, tests both initial selection and escalation behavior. Headline findings: (a) over-privileged selection is *common across mainstream LLM agents*; (b) **prompt-level controls give only limited protection under transient tool failures** — agents escalate when a lower-privilege call returns an error; (c) general safety training does NOT reliably transfer to least-privilege decision-making. Proposes a "privilege-aware post-training defense" that substantially reduces unnecessary high-privilege use. Code at https://github.com/AISafetyHub/agent-tool-selection-bias.
- **Why it matters for Justin's agents:** For federal-data-engineering work the entire question of "which database role does the agent assume" is exactly this problem at production scale. The finding that prompt-level controls fail under transient errors is the smoking gun — `try-with-readonly-then-escalate-on-failure` is precisely the pattern most permission systems quietly encourage, and this paper says it generalizes into systematic over-escalation. For any MCP server exposing tiered tools, the lesson is: enforce least-privilege at the connector layer, not in the prompt.
- **Action signal:** `try-now` — code released; ToolPrivBench is small enough to run against Justin's actual MCP toolsets to find which ones bias toward over-escalation. Direct architectural complement to yesterday's MemClaw (arxiv:2606.24535) — MemClaw governs memory writes, ToolPrivBench-style discipline governs tool reach. Both are the access-control story for production agents.

### 6. Privacy-Preserving RAG via Multi-Agent Semantic Rewriting
- **Source:** arXiv (accepted, Elsevier Information Processing & Management)
- **Link:** https://arxiv.org/abs/2606.24623
- **Authors / org:** Yuanhe Zhao, Tianyu Zhang, Huafei Xing, Derek F. Wong, Jianbin Li, Tao Fang
- **Focus area:** Agent memory / tools & connectors
- **What it is:** A three-agent framework — privacy extraction, semantic analysis, reconstruction — that sanitizes RAG context **as offline preprocessing** before retrieval-time use, removing sensitive identifiers while preserving semantics. On LLaMA-3-8B under targeted attacks: **leak instances drop 144 → 1**; BLEU-1 0.122 vs SAGE baseline 0.117 (slight quality gain, not loss); **zero added latency at inference time** because the rewriting is done offline. Evaluated on ChatDoctor and Wiki-PII across six LLMs. Code at https://github.com/foursoils/Privacy-Preserving-RAG.
- **Why it matters for Justin's agents:** This is the right shape for any RAG corpus that mixes operational notes with personally identifying data — a category that includes most enterprise knowledge bases and absolutely includes federal-data-engineering ones. The "do it offline, accept zero inference-time cost" framing sidesteps the latency arguments that have killed previous privacy-RAG proposals. The 144→1 reduction is dramatic but is reported against targeted attacks — confirm whether the same numbers hold under prompt-injection-style retrieval attacks before deploying.
- **Action signal:** `track` — production-relevant for any RAG containing PII; the preprocessing approach is small enough to fold into a `rag-corpus-loader` MCP server. Watch for follow-ups extending to prompt-injection-resistant rewriting.

### 7. Autodata: An Agentic Data Scientist for Synthetic Data
- **Source:** arXiv / HF Daily Papers
- **Link:** https://arxiv.org/abs/2606.25996
- **Authors / org:** Ilia Kulikov, Chenxi Whitehouse, Tianhao Wu, Yixin Nie, Swarnadeep Saha, Eryk Helenowski, Weizhe Yuan, Olga Golovneva, Jack Lanchantin, Yoram Bachrach, Jakob Foerster, Xian Li, Han Fang, Sainbayar Sukhbaatar, Jason Weston (Meta FAIR)
- **Focus area:** Evaluation / reasoning & inference-time compute
- **What it is:** **Agentic Self-Instruct** — an agent system that functions as an autonomous data scientist, generating high-quality synthetic training+evaluation datasets, then **meta-optimizing itself** to improve its own data-creation pipeline. Tasks tested: CS research, legal reasoning, mathematical reasoning with objects. Reports improvements over classical synthetic-dataset creation methods, with meta-optimization providing "an even larger performance uplift." Concrete numbers are not in the abstract — full PDF needed for benchmark-by-benchmark comparison.
- **Why it matters for Justin's agents:** Meta-FAIR-grade authorship (Weston, Sukhbaatar, Foerster, Bachrach) lends weight to a thesis that's been circling for months — that the bottleneck on small agent fine-tunes is no longer compute, it's training-data curation. If Autodata generalizes, the right pipeline for a domain-specialist agent fine-tune is: (i) draft tasks with Autodata, (ii) fine-tune a small specialist, (iii) have the specialist propose new tasks back to Autodata. That's a complete recipe for a self-improving MCP-tool-specialist model.
- **Action signal:** `track` — top-tier authorship, but concrete benchmark numbers are missing from the abstract. Revisit once code or full PDF lands. Direct successor in spirit to last week's OpenThoughts-Agent (arxiv:2606.24855) which released the *open* data-curation pipeline.

### 8. Grading the Grader: Evaluating an Agentic Data Analysis System
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.24839
- **Authors / org:** Tian Zheng, Kai-Tai Hsu
- **Focus area:** Evaluation
- **What it is:** A practical post-mortem on evaluating LAMBDA (an agentic data analysis system) across 153 QRData tasks. Proposes a **three-layer grading cascade**: regex matching → LLM-based lenient assessment → human snippet inspection, used to distinguish *real* disagreements from grading artifacts. Headline numbers: **100% observed precision** (zero false positives across 70 cases) for both automated graders; **lenient grader achieves 97% recall vs human labels**; **keyword-anchored extraction +60 pts** to strict grader recall; **iterative nudging raises grading success 36% → 97%**, and **lenient-pass 16% → 46%**.
- **Why it matters for Justin's agents:** The number that should jolt every agent-eval pipeline is the 36% → 97% jump from iterative nudging — meaning a non-trivial fraction of "agent failure" results in current benchmarks are *grading failures*, not model failures. For Justin, this is the audit-ready answer to "are we actually measuring what we think we're measuring?" The three-layer cascade is the right reference design for any internal MCP-tool eval harness. The lesson — graders need their own templates, not just the original question re-injected — applies directly to LLM-as-judge configurations.
- **Action signal:** `try-now` — patterns generalize directly to LLM-as-judge MCP eval pipelines today, no code needed. Read full PDF for the cascade implementation details; the nudging mechanism is the most replicable pattern.

### 9. CUGA: Open-Source Agent Harness with 24 Working Apps (IBM Research)
- **Source:** Hugging Face blog (June 23, 2026)
- **Link:** https://huggingface.co/blog/ibm-research/cuga-apps
- **Authors / org:** IBM Research
- **Focus area:** Agent orchestration / tools & connectors
- **What it is:** **CUGA** (Configurable Generalist Agent) — an Apache-2.0 production agent harness handling planning, state, tool orchestration, and governance. Features: long-horizon planning with self-correction, declarative guardrails (Intent Guards, Tool Approval, Playbooks), multi-agent delegation, model-agnostic provider switching, three reasoning modes (Fast / Balanced / Accurate) for cost-latency tuning, interchangeable tool layer (OpenAPI / MCP / LangChain). Ships with **24 single-file FastAPI example apps** including: IBM Cloud advisor, Paper Scout, Wiki Dive, PDF/audio/video document RAG, **Ouroboros** (seven-agent lead-gen), and Meetup Finder (Playwright browser automation). `pip install cuga`. Repos: github.com/cuga-project/cuga-agent + cuga-project/cuga-apps.
- **Why it matters for Justin's agents:** The open-source analog to Claude Tag (yesterday's item 10) — same "agent at the center of a Slack-style productivity workflow" thesis but Apache-2.0 with all governance hooks exposed. The 24 example apps each as one FastAPI file is the smartest packaging choice for cargo-culting: pick the closest example, fork, replace tools. Intent Guards + Tool Approval + Playbooks at the runtime layer is exactly the discipline ToolPrivBench (item 5) and MemClaw (yesterday) say agents need. The multi-agent delegation primitive is the right substrate to layer EDV (item 2) on top of.
- **Action signal:** `try-now` — `pip install cuga`, run the Paper Scout or Ouroboros example to compare against Justin's current Claude Code + MCP stack. The Playbook + Intent Guard pattern is portable as a reference design even if Justin doesn't adopt the framework wholesale.

## Local-model corner

One model release today is local-runnable; another is mentioned as a benchmark target.

**Kog Laneformer 2B** (HF blog, June 24)
- **Model:** `kogai/laneformer-2b-it` — 2.3B-parameter instruction-tuned **coding** model, trained from scratch with novel "Delayed Tensor Parallelism" 8-lane architecture, 15 decoder layers w/ Grouped-Query Attention (32 query heads / 16 KV heads), Sliding Window Attention on 10 layers, **4,096-token context only**. Apache-2.0 (model code); Llama-2 community license on the tokenizer. Pretrain ~4T + mid-train ~2T + instruction-tune ~210M tokens, ~21 days × 192 H100s.
- **Memory fit:** Trivial — at fp16, ~4.6 GB weights; at Q4_K_M, ~1.5 GB. KV cache for 4K context is negligible. Fits inside any phone budget, let alone M5 Max + 64 GB.
- **Realistic tasks:** **HumanEval+ 45.1%, MBPP+ 51.6%** — these are *meaningfully below* Qwen2.5-Coder-7B (~80% HumanEval+) and even Qwen2.5-Coder-3B (~70%). The model's selling point is **latency**, not quality: 3,000 tok/s on 8× MI300X, 2,100 tok/s on 8× H200. Realistic use: drop-in code-completion sidecar where you want sub-second turnaround on autocomplete-class tasks and you accept lower quality than a 7B for that latency. **NOT** a replacement for a coding-agent backbone.
- **How to run:** `transformers` directly today; GGUF conversion via llama.cpp is straightforward but uncertain whether the Delayed Tensor Parallelism architecture survives the conversion cleanly. Wait for an official MLX-LM port before pinning to M5 Max for production.
- **Speed estimate on M5 Max:** No published benchmark. Extrapolating from Qwen2.5-3B at ~80 tok/s on M5 Max Q4, expect **120–180 tok/s** at Q4_K_M with 4K context — fast enough to feel instant for autocomplete-style use.

## Conflicts & open questions
Cross-referenced against `_meta/claims-ledger.md`:

- **Memory representation: text-only vs hybrid vs naive RAG.** Item 1 (Metis) advocates **hybrid text + code memory**, with selective promotion of recurring patterns into executable tools. This extends — and partially supersedes — EvoEmbedding's "naive RAG with evolvable embeddings beats agentic memory" (arxiv:2606.21649, June 22 digest). Both can coexist if EvoEmbedding solves the *retrieval* layer and Metis solves the *representation* layer, but Metis's headline "code memory captures execution semantics that text retrieval cannot" is the sharper rhetorical claim. The four-module framework from yesterday's survey (arxiv:2606.24775) treats Metis as a representation+storage contribution and EvoEmbedding as a retrieval one — consistent with both being right at their own layer.
- **The self-confirmation trap vs. consensus-verify gating.** Item 2 (EDV) targets the same architectural failure mode as DynamicMem (arxiv:2606.22877, June 23) and MEMPROBE (arxiv:2606.24595, yesterday): single-loop agent memory both *retrieves wrong* and *stores wrong*. Three independent papers now converge: the fix has to be a **gate on memory writes**, not just better retrieval. Status: trend confirmed across three different research groups in three days.
- **Tool-use safety: prompt-level guardrails are not enough.** Item 5 (ToolPrivBench) shows **prompt-level over-privilege controls fail under transient tool errors** — the agent simply escalates when the lower-privilege call fails. This directly extends yesterday's MemClaw thesis that production governance requires architectural primitives (scoped retrieval, temporal supersession, policy-governed propagation) rather than instructions in the system prompt. Open empirical question for tomorrow: do any of the existing MCP server frameworks enforce least-privilege at the *connector layer* (not just at the prompt or app layer)? If not, that's a high-leverage gap to fill.
- **Open question for the week:** does Bayesian control (item 4) generalize to *memory* operations (when to write, when to compact) the way it generalizes to *tool* operations (when to verify)? If yes, this is the principled umbrella that ties together SelfCompact, EDV's verify-gate, and the entire "model decides when to invoke expensive ops" pattern.
