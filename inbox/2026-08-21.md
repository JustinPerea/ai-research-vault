- **EnvHarness** [arxiv:2608.19880] (Google) wraps a frozen env with plug-in Stage/Contract/Chain components; EnvRigger diagnoses policy flaws from traces. Up to **+9.0** on held-out instances with **9.8% fewer steps**. The wrap-don't-rebuild counterpart to yesterday's SPADE.

## Items

### 1. EnvHarness: Awakening Static Worlds for Agent Learning
- **Source:** arXiv (Hugging Face Daily Papers)
- **Link:** https://arxiv.org/abs/2608.19880
- **Authors / org:** Chengsong Huang / Zifeng Wang / Rujun Han / Jun Yan / Yanfei Chen / Zoey CuiZhu / Ke Jiang / Peng Xia / Han Yu / Yufan Zhuang / Yifei Ming / Jiaqi Pan / Bhavana Dalvi Mishra / Jiaxin Huang / Burak Gokturk / Tomas Pfister / Chen-Yu Lee — Google
- **Focus area:** Environment wrapping + skill learning / RL signal
- **What it is:** A programmable plug-in layer that wraps a *static* environment to reshape behavior without changing underlying logic or the original verifier. EnvRigger treats the target policy as a black box, diagnoses flaws from trajectories, synthesizes EnvHarness components, and validates on fresh rollouts. Five benches / four domains: up to a **9.0-point** improvement on held-out instances with **9.8% fewer execution steps**, and a better RL optimization signal for policy–env co-evolution. Code: github.com/google-research/envharness. Submitted Aug 20; abs verified.
- **Why it matters for Justin's agents:** SPADE (yesterday) *writes* new Gym envs as code. EnvHarness *wraps* the env you already have (ALFWorld, SWE, WebShop, a personal sandbox) so you do not rebuild it. For Mitamaton this is "add Stage/Contract/Chain around the calendar+mail loop" rather than synthesizing a new world. Keep the verifier; change the curriculum.
- **Action signal:** `try-now` on the wrap-don't-rebuild idea; `compare` against SPADE if you are generating envs.

### 2. FACET: Preserving Source Intent and Executable State in Terminal Task Synthesis
- **Source:** arXiv (Hugging Face Daily Papers)
- **Link:** https://arxiv.org/abs/2608.18580
- **Authors / org:** Kou Shi / Zun Wang / Qisheng Su / Shiting Huang / Ziao Zhang / Zhen Fang / Qingnan Ren / Jin Liu / Yu Zeng / Yiming Zhao / Lin Chen / Zehui Chen / Feng Zhao — USTC
- **Focus area:** Terminal-task synthesis for coding agents
- **What it is:** Fine-grained Agentic Construction of Executable Tasks. Reconstructs related agent skills into coherent scenarios, then realizes and repairs the execution environment *before* generating instruction / solution / verifier, so all three share container state. Execution-based validation repairs artifact-specific failures without regenerating valid components. Fine-tuning on collected trajectories consistently improves Terminal-Bench 2.1 across model scales; ablations support environment-grounded construction over reverse/joint schemes. Code: github.com/StoKou/FACET-Terminal. Submitted Aug 19; HF Daily Aug 21; abs verified.
- **Why it matters for Justin's agents:** Terminal-Bench is the vault's coding-agent yardstick (StateM, PILOT, RST). FACET is the data engine that keeps instruction, env, solution, and verifier consistent — the failure mode RST [arxiv:2608.05466] also attacked. If a personal terminal set saturates, generate the next tasks environment-first, not instruction-first.
- **Action signal:** `compare` — against RST recursive synthesis; skip unless you are generating Terminal-Bench-like tasks.

### 3. MemTrapBench: Benchmarking Cognitive Traps in LLM Memory Use
- **Source:** arXiv (Hugging Face Daily Papers)
- **Link:** https://arxiv.org/abs/2608.20202
- **Authors / org:** Mengru Wang / Haozhe Luo / Zhenqian Xu / Zhixiang Cui / Haoming Xu / Qu Yang / Jizhan Fang / Junfeng Fang / Ningyu Zhang — ZJUNLP
- **Focus area:** Memory that distorts the current task
- **What it is:** Memory-induced cognitive traps: Reasoning Fixation and Belief Distortion — even faithfully recorded, semantically relevant memories can degrade the *current* task. Two model families × five memory frameworks: **all evaluated memory strategies underperform no-memory**, with even the strongest methods dropping **>10pp**. AdaptiveMem is an inference-time prompt skill that tells the model to avoid these traps; it mitigates MemTrapBench without hurting (sometimes improving) standard memory benches. Code: github.com/zjunlp/MemTrapBench. Submitted Aug 20; abs verified.
- **Why it matters for Justin's agents:** Yesterday's "Harness the Memory" said retrieving more hurts agentic action. MemTrapBench says retrieved calendar/history can *lock Mitamaton onto yesterday's strategy*. AdaptiveMem is a 1-page system prompt, not a new backend. Pair with the notebook-as-curated-state rule: retrieved memory is a hypothesis, not a mandate.
- **Action signal:** `try-now` — add an AdaptiveMem-style "treat retrieved notes as hypotheses" paragraph to Mitamaton; `compare` on a 20-item "yesterday's plan is now wrong" probe.

### 4. FlashPrefill V2: Block-Sparse Prefill Attention for Long-Context LLM Serving
- **Source:** arXiv (Hugging Face Daily Papers)
- **Link:** https://arxiv.org/abs/2608.19758
- **Authors / org:** Qihang Fan / Huaibo Huang / Zhiying Wu / Bingning Wang / Ran He — CASIA / Tencent
- **Focus area:** Local / long-context prefill
- **What it is:** Production-shaped follow-up to FlashPrefill: mean correction recovers pruned-block mass; PackGQA / warp specialization / pingpong aligned with FA3/4; FP8; native paged KV + continuous batching as an SGLang attention backend. NVIDIA **H20**, 128K: up to **47.26×** vs FA2 FP8 and **27.19×** vs FA2 BF16; still **30.49×** vs an FA3/4-aligned dense baseline in FP8. Code: github.com/qhfan/FlashPrefillv2. Submitted Aug 20; abs verified.
- **Why it matters for Justin's agents:** TwinKV [arxiv:2608.27128] (08-28 digest) repairs *eviction*. FlashPrefill V2 is the *prefill* complement for long Mitamaton / vault contexts. H20 numbers, not Apple Silicon — compare conceptually (mean-corrected block sparsity + paged KV) against MLX / llama.cpp prefill, do not expect a drop-in kernel.
- **Action signal:** `try-now` on the idea (prefill is the 64GB bottleneck TwinKV does not address); `compare` before changing the Mac serving config.
