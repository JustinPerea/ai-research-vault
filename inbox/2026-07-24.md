# AI Research Digest — Friday, July 24, 2026

## TL;DR
- **Autonomous loops:** BAAI's **AREX** (2607.21461) is a *dual-loop* self-improving deep-research agent — an inner research loop drafts an answer while an outer loop **audits it constraint-by-constraint and rewrites the search plan**. Reports "substantial" outperformance vs comparable-scale baselines on BrowseComp / WideSearch / DeepSearchQA / Humanity's Last Exam at both 4B dense and 122B-A10B MoE. Top HF Daily Paper today (38 upvotes).
- **Coding agents:** Two coding-agent benchmarks landed the same day — **Tencent WorkBuddy Bench** (2607.20911, tested on **Claude Code + CodeBuddy Code** across Code/Web/Office/Security) and **ICAE-Bench** (2607.21217, interactive project building with a User Agent simulator). Both explicitly retire the "fully-specified static task" evaluation shape.
- **Agent patterns:** **NVIDIA NOOA** (2607.20709) proposes agent-as-Python-object — docstrings *are* prompts, type annotations *are* contracts, method bodies of `...` are LLM-completed. Validated on SWE-bench Verified + Terminal-Bench 2.0 + ARC-AGI-3. First principled attempt to fuse tool schemas, harness scaffolding, and native language semantics into one substrate.
- **Learned-from-experience policies — pushback:** Meta's **Jaideep Ray** (2607.20668) shows human-authored text policies lift a frozen 7B agent by **+5.0 pts on TextWorldExpress**, but **policies distilled from the agent's own trajectories fail to beat fixed prompting** — even with richer traces, counterfactual evidence, or iterative GEPA search. Direct **CONFLICT** with the harness-evolution / auto-authored-skill cluster (SEED / MSCE / AgentBrew / GEPA).
- **Frontier post-training:** **SLAI T-Rex** (2607.20145) is the first open, full-parameter post-training case study on the **DeepSeek-V4** family on **Ascend SuperPOD**. **34.22% MFU** (2.93× baseline); the OR-specialized checkpoint beats GPT-5.4-Mini by 3.98 pp and base V4-Flash by 11.27 pp on operations-research zero-shot Pass@1 (71.81%). Frontier post-training is now a non-NVIDIA-substrate story too.

## Items

### 1. AREX: Towards a Recursively Self-Improving Agent for Deep Research
- **Source:** arXiv / Hugging Face Daily Papers (38 upvotes, #1 today)
- **Link:** https://arxiv.org/abs/2607.21461
- **Authors / org:** Shuqi Lu, Chaofan Li, Kun Luo, Zhang Zhang, Hui Wang, Hongwang Xiao, Zheng Liu, Lei Xiong, Jiahao Wang, Sen Wang, Xiyan Jiang, Wanli Li, Yuyang Hu, Hongjin Qian, Bingyu Yan, Ziyi Xia, Yingxia Shao, Kang Liu, Zhicheng Dou, Di He, Chaozhuo Li, Qiwei Ye, Zhongyuan Wang, Zheng Liu (24 authors, Beijing Academy of Artificial Intelligence + collaborators)
- **Focus area:** Long-running / autonomous loops (self-improvement); agent memory (compaction)
- **What it is:** A dual-loop self-improving research agent. The **inner loop** gathers evidence and drafts a provisional answer; the **outer loop** audits the answer *constraint-wise* against the original question and rewrites the search plan. The system also learns to autonomously compress interaction history while preserving verified evidence — memory management is a target of the outer loop, not a fixed policy. Released at two scales: a **dense 4B** and a **122B-A10B MoE** variant.
- **Numbers:** "Substantially outperforms comparable-scale baselines" on BrowseComp, WideSearch, DeepSearchQA, and Humanity's Last Exam. Headline percentages not surfaced in abstract; the 24-author list and MoE variant are the scale signals.
- **Why it matters for Justin's agents:** The dual-loop shape is directly transplantable to Justin's daily-digest and PR-watcher patterns — an inner "do the work" loop and an outer "audit that you did the right work" loop mapped onto the same trajectory. The **constraint-wise audit** is the concrete generalization of the *coverage-map* + *Frontier Task* primitives from SearchOS (2607.15257) into a research-agent frame.
- **Action signal:** `track` — repo/weights not yet confirmed on the abstract page; watch for MLX / GGUF conversion of the 122B-A10B MoE (~30 GB at 2-bit, ~61 GB at Q4 — 64 GB unified memory is the right target if a quant lands). `compare` — sits alongside PRO-LONG (2607.20064) as two different answers to "how does the agent manage its own log?" — PRO-LONG treats the full log as searchable memory; AREX **compresses while auditing**.

### 2. Tencent WorkBuddy Bench: Multi-Domain Coding-Agent Benchmark with Contamination-Resistant Task Construction
- **Source:** arXiv / HF Daily Papers (10 upvotes)
- **Link:** https://arxiv.org/abs/2607.20911
- **Authors / org:** Siqi Cai, Shaopeng Chen, Xiang Fei, Yong Mao, Zihan Xu + 31 others (Tencent WorkBuddy Bench Team)
- **Focus area:** Evaluation (coding agents)
- **What it is:** A four-subset coding-agent evaluation across **Code (repository-level engineering), Web (front-end dev), Office (business workflows), and Security (red/blue-team scenarios)**. Tasks are **reverse-engineered from real commits, PRs, or business scenarios** and rewritten to resist scraping, with contamination controlled through **dataset versioning rather than secrecy**. Deliberately avoids suite-wide averaging because scoring instruments differ across subsets.
- **Numbers:** Tested on **Claude Code and CodeBuddy Code** with a cross-model leaderboard reported. Open release includes task directories, environment images, harness, tests, reference solutions; project site at workbuddybench.com; code at github.com/Tencent/workbuddy-bench; dataset on Hugging Face.
- **Why it matters for Justin's agents:** Direct fit — Justin uses Claude Code, and WorkBuddy is one of the first benches that reports numbers *on the harness he actually runs* rather than raw model API. The **versioning-over-secrecy** contamination model is the right generalization for a public repo like this one: rotate task versions instead of holding tasks back. The four-subset separation also lets Security failures be measured independently from Code capability — matches the vault's "safety is a separate axis" thread (JANUS / NEXUS / OpenSkillRisk / ChannelGuard).
- **Action signal:** `try-now` — clone the repo, run the Security subset against a current Claude Code session, and use the observed failure modes as inputs to a NEXUS-style (2607.19356) intervention policy.

### 3. NVIDIA NOOA: Native Python Object-Oriented Agents
- **Source:** arXiv / HF Daily Papers (3 upvotes)
- **Link:** https://arxiv.org/abs/2607.20709
- **Authors / org:** Paul Furgale, Severin Klingler, James Nolan, Matt Staats, Gaia Di Lorenzo, Elisa Martinez Abad, Christian Schüller, Razvan Dinu, Alessio Devoto, Pascal Berard, Gal Kaplun, Elad Sarafian, Riccardo Roveri, Leon Derczynski, Ricardo Silveira Cabral (NVIDIA Labs)
- **Focus area:** Tools & connectors / agent architecture
- **What it is:** An agent programming model where an agent **is a Python object**. Methods represent actions; fields store state; docstrings *are* the prompts; type annotations *are* the tool contracts. Methods whose body is `...` are completed by an LLM-driven loop at call time; regular methods stay regular Python. Six model-facing capabilities are unified in one substrate: typed I/O, pass-by-reference over live objects, code-as-action, programmable loop engineering, explicit object state, and model-callable harness APIs.
- **Numbers:** Validated on **SWE-bench Verified + Terminal-Bench 2.0 + ARC-AGI-3**; specific pass rates not surfaced in the abstract.
- **Why it matters for Justin's agents:** This is the pattern that collapses several MCP-server design decisions into one representation. Instead of "define a JSON schema, write a Python handler, glue them via a manifest," NOOA lets a Python class *be* the tool spec. For Justin's MCP + Claude Code stack, the interesting piece is **pass-by-reference over live objects** — agents currently only get serialized snapshots of state; NOOA is designed to hand agents object handles. Composes with StructAgent (2607.11388) "wrapper > backbone" thesis by making the wrapper directly implementable in the host language.
- **Action signal:** `track` — pending code release and evidence that the pattern actually reduces harness code volume vs current MCP scaffolding. If NVIDIA open-sources this, prototype an MCP server as an NOOA class to test the "docstring-is-prompt" ergonomics.

### 4. From Agent Failures to Text Policies: What Works and What Breaks
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2607.20668
- **Authors / org:** Jaideep Ray, Ankit Goyal (Meta, based on prior Ray affiliation)
- **Focus area:** Agent orchestration (skill/policy learning); evaluation
- **What it is:** Investigates whether **TextGrad-style textual optimization** — which improves language-model systems via textual feedback — extends to *AI agents*. It empirically separates two questions: (a) do useful text policies exist for agents, and (b) can agents derive them from their own experience?
- **Numbers:** Human-authored policies **improve a frozen 7B agent by +5.0 success points on TextWorldExpress** (i.e., useful policy text exists). But policies derived from agent experience **do not reliably outperform fixed prompting**, even with richer traces, counterfactual evidence, or iterative **GEPA** search.
- **Why it matters for Justin's agents:** This is the negative-result counterweight to the whole harness-evolution / auto-authored-skill line. Justin's stack has been getting steadily more auto-generation-heavy (MSCE, AgentBrew, SEED, SkillOpt-style skills, GEPA-family search). Ray's result says the **generation-and-selection** stage of that pipeline is the actual bottleneck, not the *application* of text policies. Practical implication: keep the human-in-the-loop authoring step in the pipeline (e.g., Justin curates the skill notes before commit) rather than trusting the agent to author its own.
- **Action signal:** `compare` — direct **CONFLICT** with the harness-evolution primitive tracked since 2026-07-16 (Compound RELAI-VCL / QD-Handbook / Ralph-Loop AgentBrew / SEED hindsight-skill mining / GEPA). Extends the "Havranek/Irsova pre-registered negative on multi-agent debate" (2607.14713, from 2026-07-18 ledger) — the pattern is: on domain-realistic tasks, **automated generation of quality artifacts is the weak link, not the harness around them**.

### 5. SLAI T-Rex: Full-Parameter Post-training of the DeepSeek-V4 Family on Ascend SuperPOD
- **Source:** arXiv / HF Daily Papers (19 upvotes)
- **Link:** https://arxiv.org/abs/2607.20145
- **Authors / org:** Dongfang Li + 64 co-authors (SLAI team, targeting Ascend NPU)
- **Focus area:** Frontier models (post-training methodology); infrastructure
- **What it is:** First open case study of **full-parameter** continued pre-training + SFT on the **DeepSeek-V4 family** on Huawei **Ascend SuperPOD** hardware (NPU, not GPU). Hierarchical optimization framework targeting model parallelism, computation-communication coordination, and kernel efficiency. The specialization run targets operations research with ~10 K high-quality SFT samples across four task categories.
- **Numbers:** **Model FLOPs Utilization 34.22%, a 2.93× improvement over baseline**. The OR-specialized checkpoint hits **71.81% zero-shot Pass@1 on operations-research tasks**, beating **GPT-5.4-Mini by +3.98 pp** and **base DeepSeek-V4-Flash by +11.27 pp** on the same eval.
- **Why it matters for Justin's agents:** Not directly local-runnable — Ascend SuperPOD is nation-scale infra — but it's the first frontier-scale post-training report that *doesn't* assume H100/B200. That matters because it removes NVIDIA hardware as an implicit gatekeeper on which orgs can post-train frontier models, and it's the substrate story that pairs with the **inverse tool-recognition scaling** result from 2026-07-21 (Lomekwi) — SLAI T-Rex shows even large open MoEs can be domain-specialized affordably enough that "route new-tool-design through smaller specialized models" becomes a live workflow.
- **Action signal:** `track` — watch for a public checkpoint release. `compare` — sits alongside the FlashRT harness (2607.18171, 2026-07-22 digest) which optimizes *inference* on non-NVIDIA silicon (B200/MI355X). SLAI T-Rex is the training-side companion.

### 6. LLMs Get Lost in Evolving User Intent
- **Source:** arXiv / HF Daily Papers (4 upvotes)
- **Link:** https://arxiv.org/abs/2607.20734
- **Authors / org:** Jihoon Tack, Philippe Laban, Jennifer Neville
- **Focus area:** Context engineering / agent memory (dialogue state)
- **What it is:** A framework that converts static single-turn tasks into **multi-turn conversations where user intent evolves iteratively** — the user reveals, revises, and reshapes their goal mid-conversation while the underlying evaluation protocol is preserved. The paper argues static benchmarks miss the failure mode that dominates real usage: **the target moves while the agent is executing.**
- **Numbers:** "Substantial drops across model families" between static-setting performance and evolving-intent performance. Specific per-model numbers not surfaced in the abstract; 20 pages / 10 figures suggests a full model-family sweep is inside.
- **Why it matters for Justin's agents:** This is the same failure mode Justin hits when a Claude Code session's plan drifts as he types corrections — the model was optimizing against the *original* prompt, not the *revised* one. Composes directly with AppWorld-UL (2607.20536, ICML 2026: Claude Opus 4.7 only **48.6% success**; drops to 35.7% on compositional subset; 21.3% at scenario level) — together they form a two-paper convergence that **the single-turn benchmark suite is now the load-bearing measurement error** for agent capability.
- **Action signal:** `track` — the framework itself is the useful artifact. If the paper releases the conversion pipeline, apply it to Justin's own eval sets to sanity-check whether "wins" hold under evolving-intent conditions. `compare` — extends OmniaBench's contamination-controlled 1.4 pp frontier-model delta (2607.14989) with a *different* axis of hidden performance headroom.

### 7. ICAE-Bench: Evaluating Coding Agents as Interactive Project Builders
- **Source:** arXiv / HF Daily Papers (3 upvotes)
- **Link:** https://arxiv.org/abs/2607.21217
- **Authors / org:** Zhongyuan Peng, Dan Huang, Chuyu Zhang, Caijun Xu, Changyi Xiao, Shibo Hong, David Lo, Lin Qiu, Xuezhi Cao, Jiyuan He, Yixin Cao
- **Focus area:** Evaluation (coding agents)
- **What it is:** Benchmark that **retires "fully specified task" evaluation** for coding agents. Three distinguishing elements: (1) tasks derive from a **real open-source repository with executable behavior** — ground truth is the actual repo, not a spec; (2) a **User Agent** simulates the human without leaking the implementation; (3) evaluation combines **black-box tests** with multi-dimensional diagnostics measuring functional correctness, semantic similarity, structural fidelity, design quality, and interaction quality.
- **Numbers:** Detailed leaderboard not surfaced in the abstract; the design contribution is the primary artifact.
- **Why it matters for Justin's agents:** With WorkBuddy Bench (item 2) landing the *same day*, the field is now clearly moving off single-shot spec-following and onto interactive project construction. Both benchmarks stress the axis Justin's stack is weakest on: **the user is part of the loop and doesn't fully specify the task upfront**. The **structural fidelity** and **design quality** metrics matter because they penalize agents that write working-but-brittle code — exactly the failure mode that MCP-heavy loops accumulate over long sessions.
- **Action signal:** `compare` — pairs with WorkBuddy Bench (2607.20911) as a **two-paper convergence** that static coding-agent benchmarks are structurally undercounting real-world capability gaps. Also extends AppWorld-UL and LLMs-Get-Lost (items 6) into the coding domain.

### 8. FedAgentKE: Federated Semantic Knowledge Evolution for Heterogeneous Agents
- **Source:** arXiv (cs.MA)
- **Link:** https://arxiv.org/abs/2607.21361
- **Authors / org:** Weihao Li, Jun Bai, Ziyang Song
- **Focus area:** Agent memory (cross-framework knowledge transfer)
- **What it is:** Framework where **distributed agent frameworks collaboratively evolve transferable reasoning abstractions** through iterative semantic knowledge distillation, aggregation, and adaptation — **without sharing raw reasoning trajectories**. Addresses the fragmentation of local experience across isolated agent frameworks. The primitive is *semantic-abstraction transfer*, not trajectory replay.
- **Numbers:** "Consistent improvements under both cross-framework and cross-task settings" — no per-benchmark table surfaced in the abstract; 9-page format.
- **Why it matters for Justin's agents:** This is the missing primitive in the vault's memory-sharing story. mem0 / LangMem / MemCon / Oracle Agent Memory / Shared Selective Persistent Memory all assume a **single agent framework** owns the memory. FedAgentKE names the multi-framework case — e.g., a Claude Code session, an Obsidian-side pipeline, and a scheduled watcher all producing insights the others should benefit from without exchanging raw sessions. The **semantic-abstraction transfer** boundary is also the privacy story that lets shared memory work in a federated / cross-tenant setting (relevant to the Shippy 70-country deployment pattern from the 2026-07-18 ledger).
- **Action signal:** `track` — the shape is right but headline numbers are missing. Watch for a code release or follow-up with quantified transfer gains. `compare` — sits between SEED (2607.14777, on-policy self-distillation *within* one policy) and Shippy (allenai-shippy-2026-07-15, single-framework Soul+Skills+Config artifacts) as the **inter-framework** analog.

## Conflicts & open questions
Cross-referenced against `_meta/claims-ledger.md`:
- **CONFLICT — Ray Text Policies (item 4) vs the harness-evolution / auto-authored-skill cluster.** Ray reports that agent-derived text policies (even with counterfactual evidence and GEPA search) don't reliably beat fixed prompting on TextWorldExpress, while human-written policies give +5.0 pts. This is a direct tension with SEED (2607.14777) hindsight skill mining, MSCE (2607.16621) three-tier skill co-evolution, AgentBrew (2607.16851) Ralph-loop teacher-note synthesis, Compound RELAI-VCL (2607.14004) lifelong pass gains, and the GEPA family itself. Ray does *not* refute those wins — but sharpens the claim to: **the wins occur when the generation stage is scaffolded with external validation (environment-validated notes, cross-run regression control), not from raw self-authoring.** Vault primitive to adopt: **automated skill/policy generation without an external validator is the pipeline's weak link**.
- **CONFLICT — WorkBuddy + ICAE + AppWorld-UL + LLMs-Get-Lost vs static-benchmark leaderboards.** Four Jul 22–23 benchmarks all report the same failure shape: static single-turn / fully-specified evaluation is dropping real capability by large margins (Opus 4.7 at 48.6% on AppWorld-UL falls to 21.3% at scenario level; LLMs-Get-Lost sees "substantial drops"; ICAE + WorkBuddy retire single-shot spec-following outright). This isn't a new claim, but the *rate* at which convergent benchmarks are landing (two on the same day) sharpens it to: **any current SOTA agent number quoted without a multi-turn/evolving-intent variant should now be discounted.**
- Open empirical question: does AREX's outer-loop constraint audit generalize to coding agents (i.e., is it a substrate for a WorkBuddy-Security subset run) or is it specific to research-agent workloads?
- Open empirical question: SLAI T-Rex reports 34.22% MFU on Ascend — how does this compare to published H100 numbers on the same DeepSeek-V4 family? (Not answered in the abstract; would sharpen the "NPU vs GPU cost story" claim.)
