### 1. Who May Release an Agent's Promise? Standing over Commitments in Multi-Party Chat
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.21203
- **Authors/org:** Lan Wei, Bingyu Shen, Jiaqi Tang et al. (9 authors)
- **Focus area:** commitments / authority in multi-party assistant chat
- **What it is:** Defines *standing*: only the creditor (person owed) or someone they or operator policy authorize may release an assistant's promise. Across six models, small open models override the creditor (Qwen3.5-9B: 69%), larger ones drop promises on a peer's word (Qwen3.8-27B: 89%; gpt-6.1-sol: 83%), and nearly all act on a bystander's "go ahead after all". A self-kept commitment ledger stops override in 4 of 5 models; with a one-paragraph release policy it raises gpt-6-luna strict accuracy 49% → 83%. Code/prompts/labels released.
- **Why it matters for Justin's agents:** Mitamaton makes promises on Justin's behalf to other people — store commitments in an explicit ledger with creditor + release policy, not in chat context.
- **Action signal:** `try-now`

### 2. Approve What, Exactly? Effect Binding and Trusted Rendering for Agent Step-Up Authorization
- **Source:** arXiv (cross-list)
- **Link:** https://arxiv.org/abs/2610.21063
- **Authors/org:** Sai Varun Kodathala, Prashanth Pollishetty, Jaylen Cargill
- **Focus area:** approval binding / MCP elicitation / step-up auth
- **What it is:** Twelve attacks on agent approval paths (decoy recipients, amount cancellation, label spoofing, threshold splitting…) against AP2, Microsoft action-bound approval, and MCP elicitation. Audit of ten runtimes: no third-party verifiable approval record, post-approval argument changes in 4 of 8 measurable runtimes. ASU gateway renders the card from a canonical effect descriptor, has a phone passkey sign its digest, executes only the stored call (Tamarin-proved, 53 lemmas); trusted card cuts forged-narration attack success 0.54 → 0.03. Flooding still succeeds 0.45–0.60 against a modeled approver.
- **Why it matters for Justin's agents:** Direct design input for Mitamaton's iOS confirm sheet and any MCP elicitation flow: render from the executed call, bind the args, and sign on device.
- **Action signal:** `try-now`

### 4. MemCut: Every Secret Leaves a Trail in the Long-Term Memory of LLM Agents

## Conflicts & open questions

- **Tool-sequence memory: prescription or prior?** TRACER (2610.21267) wins big by ranking next tools from a trie of past sequences, while the tool-graph-memory audit (2610.21571) finds transition memory seldom helps and textual insights do better. Open: is the difference retrieval-as-filter (TRACER exposes candidates) vs memory-as-instruction (graph prescribes the next tool)?
- **Memory gains measured downstream vs in the store.** MemComposer (2610.21091), AiO-Mem (2610.21147) and Memorilla (2610.21375) report downstream QA/task gains; FEB-30 (2610.22209) shows QA evals hide an 80% failure rate on create/update/supersede, and MemCut (2610.21405) shows deletion leaves residual evidence. Open: which of these systems survive store-level and forgetting audits?
- **Compaction helps or hurts?** Mosaic (2610.22174) trains agents for compacted/forked multi-session runs; the context-engineering study (2610.20959) finds compaction makes investigator-type agents repeat steps. Yesterday's transparent-compact adds a third design. Open: decide compaction per agent behavior group.
- **Skill evolution vs skill drift.** SkillNEO (2610.20926) and FedSkillGit (2610.21348) improve skills continuously; CODA (2610.20845) shows drift erases 52–93% of co-evolved gains. Open: gate every evolved/merged skill with drift tests (paraphrase + corrupted skill) before publish, as FedSkillGit already gates on validation.
- **Which weak-to-strong signal?** LEASH (2610.22280) uses weak-model hidden states, SpecAgent (2610.21463) uses the strong model as a verifier, JevAgentHarness (2610.21412) uses per-choice calibrated confidence and shows naive delegation loses 19 points. Not compared head-to-head; hidden-state signals need open weights locally.
- **Guards and approvals are each bypassable.** INFUSE (2610.20776) finds guard models give limited protection; LinguaGuardBench (2610.22244) shows small guards flip with request language; Screwtape (2610.20941) evades action-only monitors on Claude Code transcripts; ASU (2610.21063) binds approvals but flooding still succeeds 0.45–0.60. Separately, hidden belief collapse (2610.22138) warns peer-check MAS can be silently poisoned while ARIA (2610.20780) and the steering agent (2610.22316) assume a supervisor sees the problem. Open: layered defense (scoped tools per FAOPs + bound approvals + monitor) rather than any single guard.
