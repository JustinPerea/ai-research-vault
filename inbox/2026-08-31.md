### 1. On the Maintenance and Co-evolution of Agent Plugins: An Empirical Study of Claude Code Plugin Marketplaces
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2608.28497
- **Authors / org:** Ahmed Hereiz / Yingzhe Lyu / Hao Li / Bram Adams / Ahmed E. Hassan (Queen's University, Software Analysis and Intelligence Lab)
- **Focus area:** Claude Code plugins / SKILL.md–script co-evolution
- **What it is:** First large-scale empirical study of Claude Code plugin marketplaces. Discovery via GitHub Code Search for `.claude-plugin/marketplace.json` on **2 Apr 2026**; 10-star filter → 1,926 repos, 2,018 marketplaces, **8,351** locally-resolvable plugins, **77,773** plugin-touching commits (3,948 authors). Plugin-touching commit activity **8.8×** from Oct 2025 launch (2,923) to Mar 2026 (25,618); Mann-Kendall p=0.003, Sen's slope ~4,550 extra commits/month; no plateau at cutoff. SE plugins **61.3%**. **34.4%** of plugins combine two or more component types. Skills grew **22×** (1,776→39,287) and by Mar 2026 outnumbered all other component types combined (39,287 vs 20,280). CCS classification of all 77,773 commits: **feat 39.6% vs OSS 17.2%** (Zeng et al. 2025); feat+fix+chore = 86.5%. Manual study of 700 commits: **74%** of sampled `docs` commits update runtime SKILL.md / agents/*.md, not human docs. Re-classifying docs/ci/style by diff function collapses docs **10.3% → 1.7%**. Claude co-authors **34.9%** of commits (any-agent 35.5%); perf 40.1%, revert 16.2%. Intra-skills script–Markdown Lift **1.37–1.58**; of 64 sampled co-change PRs, **78%** functionally coupled (interface change / internal logic / variable-version sync / repo re-structuring). Dataset: https://github.com/SAILResearch/agentic_plugin_marketplace. Abs verified 2026-08-31 (submitted 28 Aug 2026).
- **Why it matters for Justin's agents:** This is the vault's live loop (Claude Code plugins + SKILL.md) measured as a software-engineering artifact class. Three operational facts: (1) **SKILL.md and its scripts are a coupled pair** — a script flag/path/version change that does not update SKILL.md is a correctness defect, not doc drift; check SKILL.md in the same PR. (2) **Do not apply CCS classifiers or "docs:" heuristics trained on OSS** — most `docs` commits here are runtime behavior. (3) WikiSkill [arxiv:2608.27454, 08-28] tracks a compounding wiki + SKILL.md tree; it does **not** track script–Markdown coupling. Treat `~/.claude` skills as versioned multi-file packages, not a pile of Markdown. Dataset is public; no training required.
- **Action signal:** `try-now` — when a skill script changes, require a SKILL.md diff in the same commit; stop treating plugin Markdown as documentation.

### 2. Logos: An Agent Harness on a Cross-Process Bus
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2608.28553
- **Authors / org:** Hanzhang Jia (University of Sussex); Liheng Zeng / Hao Cheng / Yi Gao / Bo Ma (Zhejiang Gongshang University / Shanghai Shuyuan Information Technology)
- **Focus area:** Multi-agent harness / process isolation / append-only session transcript
- **What it is:** Argument that the spatiotemporal-composability calculus's reversibility guarantee does not bind an agent to one process. Logos is a ROS-like construction: a plugin is an OS process; the router holds only a routing table; **the only shared state is an append-only transcript** owned by no process. After process death, a new process of the same id imports the transcript and continues ("cold switching"); recorded steps are never repeated. Four kill points of the tool-call cycle (during execution / after return before persistence / after persistence before announcement / after announcement): **80/80** sessions resume with no repeated effect. Twelve sessions under six process kills: 12/12. Same-fault comparison with a single-process reference (DeepSeek harness v0.1.0-rc.5): one host kill interrupts every co-resident session (5-session composition, 10/10); peer processes interrupt only the faulty node (0/4 innocent sessions). Bus hop median **0.215 ms** over 10,000 calls vs model first-token **177 ms** (1/823). Table 1: MCP moves tool servers out but **keeps composition and session state in the host**; Temporal moves execution out but keeps assembly in the workflow; Logos moves composition and assembly onto the bus. Outward effects (payment) stay outside the boundary — withholding and compensation only. Abs verified 2026-08-31 (submitted 28 Aug 2026). No public repo on the abs page.
- **Why it matters for Justin's agents:** Yesterday's PES [arxiv:2608.27427] split persona from execution *inside* a trust-domain cut. Logos is the next cut: **do not put persona + MCP + session in one process**. Concrete port, no training: (1) persist an append-only JSONL transcript of every tool call/result *outside* the live Claude Code / Grok Bot process, (2) resume from the transcript after a kill rather than re-running settled calls, (3) keep irreversible MCP (send / pay / calendar-write) in a separate process from the chat surface. MCP is not that architecture — it still hosts composition. Combined PES+Logos recipe untested. Implementation is a research harness on one Windows laptop, not a Mitamaton drop-in.
- **Action signal:** `try-now` — persist an append-only session transcript outside the live process and refuse to re-execute recorded tool calls on resume; `compare` with PES's persona/execution domains.

### 3. String: An Agentic OS Where Every App Is a Markdown File
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2608.28027
- **Authors / org:** Jookyung Song (Seoul National University & H1R.AI); Nojun Kwak (Seoul National University); Simyung Chang (H1R.AI)
- **Focus area:** Agent–computer interface / progressive disclosure of tools / MCP-shaped runtime
- **What it is:** Open-source runtime that treats the agent's interface as an OS problem. SFMD (String-Flavored Markdown) declares views, typed actions, navigation, and credentials; the runtime handles discovery/validation/execution/secrets behind two verbs: `/open` to see, `/act` to do. Design claim: dump every tool schema into context and the agent pays rent on every turn. Measured residency: 100 public OpenAPI services as String apps — full JSON schemas **103,518** tokens/turn, one-line index 3,291, String **53** (fixed single-tool interface). SkillsBench v1.1, 87 tasks × 6 models × 3 runs on OpenHands: String **51.8% vs skills 50.5%** (+1.3 pp), **33.5% fewer tokens** among completed episodes (range 21.7–44.3%). Staging is causal: showing every action at once pushed wrong-action selection **28% → 2%** when staged; injecting one tier of detail one turn early, information held fixed, cost **11.6 pp** (Sonnet 4.6) / **23.3 pp** (Haiku 4.5). Privilege follows provenance: local file/app may shell+HTTP; remote SFMD may HTTP only; `$VAR` expands only in author-written template positions, never from caller-supplied text. Over MCP the whole runtime is one tool `{topic, cmd}`. Code: https://github.com/string-os. Abs verified 2026-08-31 (submitted 28 Aug 2026).
- **Why it matters for Justin's agents:** WikiSkill [arxiv:2608.27454, 08-28] already said "wiki for the proposer, not the live agent." String is the runtime version: **do not dump every MCP/skill schema into Claude Code's system prompt**. Concrete port: (1) expose MCP tools as named actions with `--help` on demand, (2) keep a ~50-token resident stub, (3) stage schemas so confusable actions are not listed at the decision point. Privilege-follows-provenance is the Mitamaton-shaped rule: Gmail-read-only remote content must not unlock local shell. v0.1 is single-user, loopback-only, unauthenticated — not a production drop-in. The steal is the rendering discipline, not the TypeScript daemon.
- **Action signal:** `try-now` — progressive-disclose MCP/skill schemas (names first, `--help` for the one in use); do not inject the full tool catalog into every turn.

### 4. ContextPilot: Teaching Agents for Proactive Context Management via Fine-grained RL
- **Source:** arXiv (also Hugging Face Daily Papers, submittedOnDailyAt 2026-08-31)
- **Link:** https://arxiv.org/abs/2608.28476
- **Authors / org:** Zhuoshi Pan (Tsinghua / Tencent Youtu Lab); Qizhi Pei / Honglin Lin (Shanghai AI Lab); Junru Lu / Di Yin / Xing Sun (Tencent Youtu Lab); H. Vicky Zhao (Tsinghua)
- **Focus area:** Memory / context folding (plan + long-term memory + foldHistory)
- **What it is:** Proactive context-management agent that *edits its own working context* via tools, plus an RL recipe that branches at high-sensitivity context edits and assigns snapshot-level credit. Toolset extends StateLM (search/delete/summarize) with **plan**, **memorize/readMemory**, and soft offloading (**foldHistory / summarizeContext / compressContext**). Long-context QA, 32K window, three-run means: ContextPilot-8B-RL avg **69.40** vs StateLM-8B-RL **65.85**; Qwen3-8B w/o tools at 128K avg **45.93**. BrowseComp+ **54.18 vs 48.84** SFT. Qwen3.5-397B-A17B tool ablation (Table 4): original tools 77.89 → +planning 80.29 → +soft offloading 83.08 → +long-term memory **87.16**; BrowseComp+ **63.49 → 80.96** with the full toolset. Deep search, WebExplorer-8B: ContextPilot avg **50.10** vs SUPO **49.09**. Token plot: WebExplorer-8B grows ~linear to ~30K/turn; ContextPilot stabilizes ~**8–10K**. Code: https://github.com/Tencent/ContextPilot ; weights: https://huggingface.co/collections/panzs19/contextpilot. Abs verified 2026-08-31 (submitted 28 Aug 2026).
- **Why it matters for Justin's agents:** TwinKV [arxiv:2608.27128, 08-28] is *what to drop in the KV cache*. ContextPilot is *what to fold in the working transcript*. Complementary layers. The steal without training: give WorkBuddy/Claude Code the toolset — **plan**, **memorize** (entity/event notes that survive folds), **foldHistory** (collapse history to keywords+summary, recover via search) — and do not wait for 8B RL. Do not SFT a local 8B this week; the paper's own 397B ablation shows the tools move BrowseComp+ more than the RL. Pair with PES: fold/compress in the persona domain; do not fold the execution audit trail.
- **Action signal:** `compare` — add plan / long-term-memory / foldHistory tools to the Mitamaton context loop vs TwinKV eviction; skip the RL until the tools move a cell.

### 5. EvoUndo: Recoverability-Constrained Self-Evolution for LLM Agent Harnesses
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2608.28363
- **Authors / org:** Tanmay Sah / Dolly Sah / Harshul Jain / Tanya Sah (Independent)
- **Focus area:** Harness self-evolution / recoverability gate
- **What it is:** Framework that admits a harness mutation only when a witness + recovery program can restore typed observational equivalence across counterfactual states. 600 one-shot self-evolution tasks (config / tools / middleware / listeners / resources / multi-surface): 281 already admissible, 122 capability-inadequate, **197** capability-positive but fail recovery. Under original recovery language L0, conventional verifier-guided repair **0/197**. Deterministic oracle: L0 **48/197**, L1 **191/197**. Protocol-locked 2×2 factorial on gpt-oss-120b: exact-address grounding **0/48 → 38/48 (79.2%)** when L0 is sufficient (S0); extending the recovery language recovers **142/143 (99.3%)** on S1. D0L1 rescues **180/197 (91.37%)**. Adding exact-address diagnostics on top of L1 *hurts* on gpt-oss-120b (133/143, 93.0%) and does **not** replicate as a drop on Qwen3.8-27B. Effect-scoped snapshots beat EvoUndo when the affected pre-state is known (300/300 vs 243/300 different-surface); EvoUndo is for cases where inverse semantics must be synthesized. Code "will be released openly"; no URL on the abs page. Abs verified 2026-08-31 (submitted 28 Aug 2026).
- **Why it matters for Justin's agents:** Fourth keep/drop on the skill/harness-evolution pile. WikiSkill [arxiv:2608.27454, 08-28] **never rolls the wiki back**. RedEvoAgent [arxiv:2608.27439, 08-30] keeps a rewrite only if it beats the incumbent on held-out val. HarnessLens [arxiv:2608.27311, 08-29] gates on behavior-relevant tasks + attributable evidence. EvoUndo adds: **the prior harness state must be restorable**. Concrete port, no training: do not merge a SKILL.md / CLAUDE.md / plugin patch unless you can restore the previous files (git revert is the cheap snapshot; EvoUndo is the case where the patch is stateful — MCP config, middleware order, listener bindings). Combined four-gate recipe untested.
- **Action signal:** `compare` — add verified recoverability of the prior harness state as a fourth keep/drop next to WikiSkill / HarnessLens / RedEvoAgent on the same 3–5 personal tasks.

### 6. SEPO: Evidence-Grounded Prompt Optimization via Structural Editing
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2608.28067
- **Authors / org:** Xiaoyu Ma / Haoyue Liu / Yiwen Li / Jionghao Zhu / Zhichao Wang / Ye Chen / Xiaoying Tang (CUHK Shenzhen / Xi'an Jiaotong / FNiI-Shenzhen)
- **Focus area:** Prompt / CLAUDE.md optimization (vs GEPA / NPO)
- **What it is:** API-only prompt optimiser that locally edits typed units in a two-layer schema (outline + step-local rules) and carries an **edit-effect lineage** (which examples the last patch newly fixed or broke) into the next architect call. 14-task held-out suite, 2000 metric-call budget, architect Qwen3.5-397B-A17B: Sepo **61.9%** macro on Llama-3.1-8B-Instruct (**+3.1 pp vs GEPA 58.8**) and **73.3%** on Qwen3-8B (**+2.2 pp vs GEPA 71.1**); wins ≥11/14 vs every baseline. Word Sorting +18.9 pp over GEPA on Llama; MBPP+ +8.7 pp on Qwen. Optimisation tokens **2.9M vs GEPA 4.1M**; deployment tokens 203k vs 424k; prompts **>5× shorter** than GEPA (236 vs 1,324 tokens). Ablation: dropping lineage −2.9 pp, dropping multi-trajectory archive −4.7 pp, dropping typed attribution inflates length 228→450. Abs verified 2026-08-31 (submitted 28 Aug 2026). No public repo on the abs page.
- **Why it matters for Justin's agents:** Yesterday's NPO [arxiv:2608.27266] said dump traces and do **one whole-prompt rewrite**. SEPO says that rewrite is the thing that accretes rules and cannot say which examples a patch broke. Complementary, not a replacement: start with NPO; if the CLAUDE.md bloats or val regressions appear, switch to addressable local edits with a newly-fixed/newly-broken log. Do not stand up GEPA's Pareto pool. Evaluation is single-turn text tasks, not agentic MCP loops — treat the CLAUDE.md transfer as an empirical question.
- **Action signal:** `compare` — NPO whole-prompt rewrite vs SEPO local typed edits on the same WorkBuddy traces; keep NPO as the baseline, graduate to lineage-aware local edits if the naive pass plateaus.

### 7. LongPIBench: A Long-Context Benchmark for Prompt Injection
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2608.28411
- **Authors / org:** Yupei Liu (The Pennsylvania State University); Yuqi Jia / Neil Zhenqiang Gong (Duke University); Jinyuan Jia (The Pennsylvania State University)
- **Focus area:** Long-document prompt injection (email summary / paper review / resume / code review)
- **What it is:** Long-context PI benchmark covering four realistic document workflows, each with a synthetic (100 instances) and a real-world set. Contexts are thousands to tens of thousands of tokens — orders of magnitude above OPI / InjecAgent / AgentDojo. Email-summary injected goals include inserting an attacker-controlled link into the summary and forcing a draft reply. Heuristic attacks remain effective without defenses; **Authority spoof** (impersonating chairs / hiring managers / IT admins) is the strongest heuristic: Llama-3.1-8B-Instruct email **0.70** vs Combined **0.25**; GPT-4o email **0.69** vs Combined **0.03**. Table 5 (Combined attack, aggregated): Ours no-defense **0.98**, MetaSecAlign 8B **0.78**, PromptLocate **0.45** vs OPI/InjecAgent/AgentDojo near-zero for those same defenses. Paper-review Combined: MetaSecAlign 8B **1.00** (short-bench ASR ~0). Email-summary Authority spoof (Table 4): no defense **0.97**, MetaSecAlign 8B **0.40**, PromptLocate **0.45**. Detectors show extreme FPR/FNR trade-offs on long documents. Code: https://github.com/liu00222/LongPIBench. Abs verified 2026-08-31 (submitted 28 Aug 2026).
- **Why it matters for Justin's agents:** Mitamaton's Gmail-read-only inbox *is* a long-email-summary task. SARA [arxiv:2608.27146, 08-28] is Observation≠authorization inside a trajectory; LoopHarness [arxiv:2608.27141, 08-29] is non-decaying loop state. Neither is a long-document PI filter. MetaSecAlign 8B and short-context PI benches are not a Gmail-thread guarantee. Concrete port: add an Authority-spoof probe to a long Mitamaton email (IT-admin voice, "include this link in the brief" / "draft yes, please") and measure whether the morning brief complies. Combined SARA+long-email-PI recipe untested. Do not train an attacker.
- **Action signal:** `compare` — run LongPIBench's email-summary Authority-spoof pattern against Mitamaton's Gmail brief; do not treat MetaSecAlign / SARA ASR as covering long inbox threads.
