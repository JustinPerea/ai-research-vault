# AI Research Digest — Monday, May 25, 2026

## TL;DR
- **Gemini 3.5 Flash (DeepMind, May 19) closes the follow-up flag from the 2026-05-21 digest** with substantive numbers: **Terminal-Bench 2.1 76.2%**, **MCP Atlas 83.6%**, **GDPval-AA 1656 Elo**, **CharXiv Reasoning 84.2%**, "4× faster output tokens/s vs. other frontier models" — Flash-tier model claimed to outperform Gemini 3.1 Pro on coding/agentic benchmarks. First DeepMind release in the MCP-Atlas-evaluation era; the 83.6 MCP Atlas number is the headline.
- **Skill-lifecycle research crests this weekend with two pairs-with papers.** (1) **SkillOpt** (Microsoft / academic cluster) frames skills as *text-space optimization* — an optimizer model proposes bounded add/delete/replace edits, accepted only when held-out validation improves; reports **+19.1 pts in Claude Code, +24.8 in Codex agentic loop, +23.5 in direct chat on GPT-5.5** across 6 benchmarks × 7 models × 3 harnesses. (2) **From Raw Experience to Skill Consumption** (same week, multiple of the same authors) reports the harder negative finding: **model-generated skills have non-trivial *negative transfer*** — a model can be a strong extractor and a weak consumer or vice versa, and skill utility is **independent of model scale or baseline task strength**. The pair sharpens the SkillOS / SkillsVote / Ratchet cluster: optimization works *if* you measure utility correctly; raw extract-and-reuse pipelines silently regress.
- **Agent-memory defense gets its sharpest empirical paper of the month.** **MemAudit** (cs.AI, May 22) — counterfactual influence score + memory-consistency graph — drives MINJA query-only memory-injection attack success **from 70% → 0% on QA agents and 83.3% → 0% on the RAP reasoning agent**, post-hoc. First clean "near-perfect defense" number on the MINJA threat model; directly applicable to any Justin-built memory store that ingests user-derived content.
- **Context-engineering at serving-system level reappears.** **Parallel Context Compaction** (cs.LG, May 22) replaces serial LLM-based summarization with parallel compaction across 8B–120B dense and MoE backbones, evaluated on HotpotQA / LoCoMo. Measured wins are wall-time + throughput (not accuracy) — operationally relevant for the long-horizon-agent-serving case Justin's MCP companion stack is in. Sits next to [arxiv:2605.04050] LCM and [arxiv:2605.21850] ACC on the harness/training/serving triangle.
- **Two harness-side production primitives released with code or near-code:** **DART** (semantic-recoverability runtime for structured tool agents — verifies that downstream consumers' commitments remain valid after partial rollback) and **Co-ReAct** (step-level rubric injection into ReAct decision points; GitHub code released). Both close real gaps in the open agentic-harness stack — DART on transactional rollback, Co-ReAct on per-step decision quality.

### 2. SkillOpt: Executive Strategy for Self-Evolving Agent Skills
- **Source:** arXiv (cs.AI, submitted May 22, 2026); top of Hugging Face Daily Papers (84 votes)
- **Link:** https://arxiv.org/abs/2605.23904
- **Authors / org:** Yifan Yang, Ziyang Gong, Weiquan Huang, et al.
- **Focus area:** Agent memory / Long-running autonomous loops / Coding agents
- **What it is:** Frames agent skills as *external state of a frozen agent* and applies text-space optimization to them — analogous to weight-space training but with prompts as the parameter. **Mechanism:** a separate optimizer model converts scored rollouts into bounded edits (add / delete / replace) on skill documents; **edits are only accepted when they improve held-out validation scores**. Stability primitives named: *textual learning-rate budget, rejected-edit buffer, epoch-wise slow/meta update* — borrowed deliberately from gradient-descent literature. **Evaluated across 52 configurations**: 6 benchmarks × 7 target models × 3 execution harnesses. Headline gains on **GPT-5.5**: **+23.5 pts in direct chat, +24.8 pts in Codex agentic loop, +19.1 pts in Claude Code**. Outperforms human-authored skills, one-shot LLM-generated skills, Trace2Skill, TextGrad, GEPA, and EvoSkill across all 52 configurations. Skills optimized on one model/harness transfer to others without re-optimization.
- **Why it matters for Justin's agents:** The most aggressive numerical confirmation yet of the **disciplined skill-edit thesis** the ledger has been tracking — held-out validation gating is the same primitive that [arxiv:2605.22148] Ratchet's outcome-driven retirement and [arxiv:2605.18401] SkillsVote's Post-Execution gating converge on, but SkillOpt formalises it as gradient-style optimization rather than threshold-based curation. (a) **The +19.1 in Claude Code** is the direct operational number for Justin's daily workflow — a textual-optimizer that improves a skill library inside the Claude Code loop by ~19 pts on whatever benchmark mix they used is the strongest publicly-reported lift on a Claude Code substrate to date. (b) **Skill transfer across models/harnesses without re-optimization** says the optimizer's output is portable, not bound to the model that produced the gradient signal. Operationally: a SkillOpt-tuned skill library produced overnight on a GPT-5.5 / Codex run could be dropped into Justin's Claude Code or MCP companion stack and retain most of the lift. (c) Pairs as a `compare` against item #3 below — SkillOpt is the *optimization* side of the story; Skill Consumption is the *measurement* side, and the two have to be read together to avoid silent negative transfer.
- **Action signal:** `try-now` `compare` — wait for code; the validation-gated edit loop is portable enough to prototype on a SkillOS-shaped repository today and A/B against the unvalidated baseline. Pair-read with item #3.

### 3. From Raw Experience to Skill Consumption: A Systematic Study of Model-Generated Agent Skills
- **Source:** arXiv (submitted May 22, 2026)
- **Link:** https://arxiv.org/abs/2605.23899
- **Authors / org:** Zisu Huang, Jingwen Xu, Yifan Yang, et al. (overlap with SkillOpt author cluster)
- **Focus area:** Agent memory / Evaluation
- **What it is:** Companion empirical study to item #2 above; same author cluster. Decomposes the skill lifecycle into **experience generation → skill extraction → skill consumption** and evaluates each link separately across **five agentic task domains**. **Headline findings:** (a) Model-generated skills are beneficial *on average* but exhibit **non-trivial negative transfer** — some skills actively hurt the consuming agent; (b) **a model can be a strong extractor and a weak consumer, or vice versa** — the two roles do not co-vary; (c) skill utility is **independent of model scale or baseline task strength** — bigger models neither produce nor consume skills better. **Proposed fix:** a **meta-skill** that guides extraction toward features tied to actual downstream utility — consistently improves skill quality across domains and substantially reduces negative transfer.
- **Why it matters for Justin's agents:** This is the critical companion read to SkillOpt — the **measurement substrate** that lets SkillOpt's gradient signal be meaningful. The ledger's [arxiv:2605.12978] "Useful Memories Become Faulty When Continuously Updated by LLMs" already established consolidation-decay (54% of solved ARC-AGI problems re-fail). This paper extends the same negative finding from memory consolidation to *skill extraction itself*: even before any update / decay step, ~half the skill-pipeline literature has been silently averaging over wins and active regressions. (a) The **scale-independent finding** is the load-bearing result — bigger frontier models are *not* a fix for skill-quality issues, which means Justin can't defer this problem until Opus 5 / GPT-6. (b) The **strong-extractor ≠ strong-consumer** finding means **the SkillOS-style "extractor-curator-executor" decomposition needs role-specific model selection**: the model that mines skills from rollouts is not necessarily the model that should consume them. Practical implication: pair a cheap-fast extractor (Haiku-class) with a careful-consumer (Opus-class) at the right phases. (c) The **meta-skill-as-extractor-guide** result is the same load-bearing mechanism [arxiv:2605.22148] Ratchet's ablations identified ("meta-skill authoring guidance + outcome-driven retirement are load-bearing"). Three independent papers in 30 days converge: **the dominant primitive in skill curation is "tell the agent how to evaluate skills before it writes any"**.
- **Action signal:** `try-now` `compare` — implement the meta-skill primitive in Justin's MCP harness; A/B against the no-meta baseline using domain-specific outcome metrics. Pair-track with SkillOpt (item #2) and Ratchet — this is the structurally important member of the trio because it names the *measurement* failure mode the other two assume away.

### 4. Parallel Context Compaction for Long-Horizon LLM Agent Serving
- **Source:** arXiv (submitted May 22, 2026)
- **Link:** https://arxiv.org/abs/2605.23296
- **Authors / org:** Musa Cim, Burak Topcu, Chita Das, Mahmut Taylan Kandemir (Penn State cluster — Das and Kandemir are long-time systems / memory-architecture authors)
- **Focus area:** Context engineering
- **What it is:** Standard long-horizon-agent serving uses **sequential LLM-based summarization** to compact context as histories grow, which "stalls agent inference for tens of seconds" and produces unpredictable output volumes despite prompt-level length instructions. **Parallel Context Compaction** runs the compaction step concurrently rather than serially; gives operators **fine-grained predictable control over summary volume**. **Evaluated on 8B–120B dense and MoE models** across HotpotQA and LoCoMo. **Headline:** at matched decoding volume, parallel compaction *reduces end-to-end wall time and improves compaction throughput over the sequential baseline*. (Note: paper reports systems wins, not accuracy wins — accuracy is preserved, not increased.)
- **Why it matters for Justin's agents:** Sits at serving-system level on the **harness / training / serving triangle** that the [arxiv:2605.04050] LCM (inference-time hierarchical compression), [arxiv:2605.21850] ACC (training-time trajectory distillation), and now-this (serving-time parallel compaction) papers form. Justin's long-running MCP / companion-app workloads hit exactly the failure mode named in the abstract — single-shot summarization that stalls the agent for tens of seconds, with unbounded output. **The "predictable output volume" guarantee is the operationally interesting claim** — Justin's existing harnesses guess at summary length via prompt hints, which is exactly the unpredictability the paper names. Composes orthogonally with [arxiv:2605.20630] IBM MCP-pipeline caching on the same MCP-workload latency axis.
- **Action signal:** `track` `local-fit` — wait for code; tested up to 120B dense + MoE which covers Justin's local M5 Max workload range (Qwen3-30B-A3B class). The systems wins (wall-time + throughput) are exactly what matters on a 64 GB box where a 30-second compaction stall is a felt UX issue.

### 5. MemAudit: Post-hoc Auditing of Poisoned Agent Memory
- **Source:** arXiv (cs.AI, submitted May 22, 2026)
- **Link:** https://arxiv.org/abs/2605.23723
- **Authors / org:** Zhewen Tan, Yilun Yao, Huiyan Jin, + 9 others
- **Focus area:** Agent memory / Evaluation
- **What it is:** Defense paper against **MINJA** (query-only Memory INJection Attack) — adversaries inject harmful records into the memory store by *normal interaction*, no direct memory-bank write access required, and the poisoned records get retrieved later to compromise the agent. **MemAudit** combines two detection signals: (a) **counterfactual memory-influence score** — measures each memory's causal contribution to harmful outputs by ablation; (b) **memory-consistency graph** — flags structurally anomalous memories on the cross-memory relation graph. **Headline numbers (post-hoc audit setting):** **QA-agent attack success 70% → 0%; reasoning-agent (RAP) attack success 83.3% → 0%**.
- **Why it matters for Justin's agents:** Highest-signal defensive paper of the week. Any Justin-built memory store that ingests user-derived content (a companion app, an MCP-backed personal RAG) inherits the MINJA threat surface — the attacker doesn't need privileged write access, only a normal conversational channel. (a) The **70%→0% / 83.3%→0% numbers are the cleanest defense-paper numbers in the ledger to date** — most prior agent-defense papers report 15-40 pp reductions, not collapse to zero. (b) **Counterfactual influence score is the same mechanism family the Anthropic Natural Language Autoencoders work used** — interpret-the-cause-of-the-output as the audit primitive. Different mechanism (NLA decodes activations; MemAudit ablates memory entries), same epistemics. (c) The **post-hoc auditing framing** is operationally important — MemAudit isn't an inference-time defense, it's a periodic audit pass over the memory store. That maps cleanly to Justin's planned Obsidian-vault-ingest workflow: run MemAudit nightly over the cumulative memory store, quarantine flagged entries.
- **Action signal:** `try-now` — wait for code; the counterfactual-influence-score primitive is implementable today using existing agent harnesses (ablate-and-re-evaluate is harness-level, no model changes), and even a partial-recall implementation is high-value vs. the current zero-defense baseline.

### 6. DART: Semantic Recoverability for Structured Tool Agents
- **Source:** arXiv (submitted May 22, 2026)
- **Link:** https://arxiv.org/abs/2605.23311
- **Authors / org:** Ke Yang, Panpan Li, Zonghan Wu, Kejin Xu, Huaxi Huang, Xiaoshui Huang
- **Focus area:** Tools & connectors / Long-running autonomous loops
- **What it is:** Frames the **transactional rollback gap** in tool-using agents: when a structured tool call fails mid-task, current options are (a) full replay (safe, wasteful) or (b) local checkpoint restore (efficient, may be semantically invalid because downstream consumers have already acted on upstream outputs). **Core observation:** *"controller legality does not imply semantic validity"* — a control-flow-valid rollback can still violate downstream commitments. **DART** is a modular runtime that: localizes the failed instance; certifies semantically-recoverable boundaries; aligns checkpoints to those boundaries; selects admissible restore points while preserving downstream work under dependency + effect constraints. Evaluated across **3 LLM-driven domains plus external validation on a LangGraph-based substrate**. **Headline:** recovers *all* commitment-sensitive cases where baseline local recovery fails; five-domain safety audit shows zero unsafe admitted rollbacks (qualitative, not quantitative — paper reports recoverability coverage, not accuracy delta).
- **Why it matters for Justin's agents:** Direct gap-filler for any Justin-built MCP harness that orchestrates multiple stateful tool calls (database writes, third-party API commits, filesystem operations). The named failure mode is real and currently unhandled — most open agent harnesses (Claude Code included) full-replay on tool failure because the semantic-validity question isn't tractable per call. (a) The **LangGraph substrate validation** is operationally important — DART is being tested on the framework most likely to land in production multi-agent stacks, which is the right portability signal. (b) Pairs as a `compare` against [arxiv:2605.15077] AsyncFC's symbolic-futures concurrency model — AsyncFC is the *forward-path* parallelism primitive (decouple decode from execution); DART is the *recovery-path* primitive (decouple rollback from full-replay). Both are harness-side, both presume structured tool schemas, both compose. (c) The "controller legality ≠ semantic validity" frame is the right vocabulary for the dependency-tracking work [arxiv:2605.04050] LCM's hierarchical-summary-DAG implicitly does; DART makes the same dependency graph the rollback substrate too.
- **Action signal:** `track` — wait for code; the LangGraph integration is the easiest adoption path. The qualitative coverage result needs quantitative recovery-delta numbers before adoption; first useful benchmark to run on Justin's MCP stack is whether DART changes mean-time-to-recovery on a controlled-failure workload.

### 7. Co-ReAct: Rubrics as Step-Level Collaborators for ReAct Agents
- **Source:** arXiv (submitted May 22, 2026); code on GitHub
- **Link:** https://arxiv.org/abs/2605.23590
- **Authors / org:** Jiazheng Kang, Bowen Zhang, Zixin Song, et al.
- **Focus area:** Tools & connectors / Inference-time compute
- **What it is:** **Injects a rubric at each ReAct decision step** to guide the next Reason-or-Act choice — rather than the agent's own internal judgment alone. The rubric generator is **trained via GRPO with list-wise Spearman rank-correlation reward** against multi-judge expert consensus rankings (not binary preferences). Evaluated on **DeepResearchBench** and **SQA-CS-V2**; consistent improvements across **open-source 8B/14B and closed-source baselines**. Code released on GitHub.
- **Why it matters for Justin's agents:** Small but immediately portable contribution. (a) The **8B / 14B open-source evaluation** is the local-fit angle — Qwen3-14B-class and 8B-class models fit trivially on M5 Max, and step-level rubric injection is a harness-side change requiring zero fine-tuning. (b) The **GRPO + Spearman list-wise reward** training recipe is interesting separately — most ReAct-tuning work uses binary preference; ranking-aware reward is the better signal when the goal is *choice among similar candidates* rather than *one correct vs. one wrong*. (c) Composes with [arxiv:2605.18401] SkillsVote's Post-Execution gating — SkillsVote evaluates skill *outcomes*; Co-ReAct evaluates per-step *decisions* before they're taken. The same supervisory-LLM-as-rubric pattern at different temporal granularities.
- **Action signal:** `try-now` `local-fit` — code is live; clone, run against an existing Qwen3-14B-MCP setup, measure decision quality on a controlled trajectory. The rubric-injection layer is light enough to integrate without harness changes.

### 8. EVE-Agent: Evidence-Verifiable Self-Evolving Agents
- **Source:** arXiv (submitted May 21, 2026)
- **Link:** https://arxiv.org/abs/2605.22905
- **Authors / org:** Yamato Arai, Yuma Ichikawa
- **Focus area:** Agent memory / Long-running autonomous loops
- **What it is:** Addresses the **"unjustified self-training" failure mode** in self-evolving agents — without evidence verification, agents drift toward plausible-sounding-but-unsupported outputs as their own data become the training signal. **Mechanism:** extends the proposer–solver framework with three components — (a) proposer generates question, answer, *and verbatim evidence span*; (b) **evidence verifier scores spans by the marginal accuracy gain when the evidence is provided**; (c) verifier signal feeds the training loop, rewarding genuinely useful supporting text. **Zero oracle answers / human labels / external annotations required.** Headline qualitative claim: "substantially improves evidence-grounded correctness over prior self-evolving search agents" — auditable curriculum where every training example carries inspectable source spans.
- **Why it matters for Justin's agents:** Niche but on-trend. (a) The **marginal-accuracy-gain-from-evidence** signal is a concrete numerical proxy for what [arxiv:2605.04018] BRIGHT-Pro / RTriever already pointed at — *evidence quality is the load-bearing variable in retrieval-augmented agents, not raw retrieval depth*. EVE-Agent makes that proxy self-supervised. (b) Composes with item #5 MemAudit on the agent-memory-integrity axis: MemAudit audits *existing* memory for poisoning post-hoc; EVE-Agent prevents *new* skill / memory entries from being learned without evidence backing. Defense-in-depth pair. (c) Pairs as the **measurement counterpart** to item #2 SkillOpt's optimization: SkillOpt accepts edits that improve held-out validation; EVE-Agent's evidence-marginal-gain score is a candidate definition of *what* "improvement" means when validation labels are scarce.
- **Action signal:** `track` — paper is light on quantitative benchmarks (no headline pp number reported in the abstract); useful as a measurement primitive once code lands. Track for whether the evidence-marginal-gain score replicates as a portable training signal in independent setups.

## Local-model corner

Two items have direct M5 Max relevance today:

- **Co-ReAct (item #7)** — open-source code, evaluated on 8B / 14B open models. **Memory fit on M5 Max:** Qwen3-14B at Q4_K_M sits at ~8.5 GB weights + working KV; trivial on 64 GB unified. The rubric-injection layer is harness-side (no extra weights), so net memory cost is the base model only. **Realistic tasks:** any ReAct loop where step-level decisions matter — code-edit-vs-search choice, tool-call-vs-recurse choice, web-search-query refinement. The DeepResearchBench gains were on closed-source baselines too, so the rubric-injection primitive is model-agnostic. **How to run:** clone the GitHub repo, point it at a llama.cpp or MLX Qwen3-14B backend, swap the harness loop wrapper. **Speed estimate:** Qwen3-14B Q4 on M5 Max runs ~28–32 tok/s in MLX; per-step rubric pass adds a forward through a smaller rubric model (paper doesn't fix the rubric-model size — Justin can pick).

- **Parallel Context Compaction (item #4)** — evaluated up to 120B (covers Justin's local range up to Qwen3-30B-A3B and 70B-class Q4). **Memory fit:** the compaction pass uses the same backbone as the agent, so no additional weights. The parallel mechanism *should* compose with MLX's `mx.distributed` primitives or llama.cpp's `--parallel` flag when code releases. **Realistic tasks:** any Justin-run long-horizon agent that currently stalls 10–30s on summary regeneration — companion-app multi-day context, long MCP-tool trajectories. **Speed estimate:** systems wins are the headline; +X tok/s end-to-end won't be quoted until code lands, but the abstract specifies wall-time reduction at *matched* decoding volume, which is the metric that matters.

The SkillOpt (#2), Skill Consumption (#3), MemAudit (#5), DART (#6), EVE-Agent (#8) results are **model-agnostic** — they don't require specific weights, they're optimization / governance / defense layers that wrap a frozen agent. SkillOpt's +19.1 in Claude Code result is the most operationally relevant local-applicable number even though Claude Code is API-backed; the optimizer transfers across harnesses, so applying it to a local-model MCP loop is mechanically identical.

## Conflicts & open questions
Cross-referenced against `_meta/claims-ledger.md`:

- **Gemini 3.5 Flash MCP Atlas 83.6% (item #1)** vs. **Fara1.5-27B "more than 90%" Online-Mind2Web (microsoft-research-2026-05-21-magenticlite-fara15)** — both are May 2026 top-tier agentic-capability numbers but on **different benchmarks** (MCP Atlas vs. Online-Mind2Web). No direct conflict, but flagged as **compare** — the open question is whether either benchmark generalizes to the other's coverage; cross-evaluation has not been published. The 90 vs. 83.6 numbers are headline-comparable but operationally non-substitutable.

- **SkillOpt scale-independent claim** (item #2 reports skill optimization yields gains across 7 target models, transfer preserved) vs. **Skill Consumption scale-independent finding** (item #3 reports skill utility independent of model scale or baseline task strength). These are **consistent, not contradictory** — both point to **skill quality being a property of the optimization / extraction process, not the model substrate**. Worth flagging as the **converging-evidence open question**: *if* scale doesn't matter for skill utility, the skill-curation pipeline becomes a more important investment than choosing a bigger base model — concrete implication for Justin's stack composition decisions.

- **Open empirical question raised today:** the SkillOpt + Skill Consumption pair argue that **held-out-validation-gated skill edits + utility-grounded extraction** are the load-bearing primitives. The ledger has [arxiv:2605.22148] Ratchet (outcome-driven retirement, +0.328 MBPP+ rolling-mean), [arxiv:2605.18401] SkillsVote (Post-Execution gating, +7.9 pp Terminal-Bench), [arxiv:2605.06614] SkillOS (curator-executor split). Four independent recent works pointing at the same primitive cluster — the field has converged faster than any prior agent-memory subarea. Open question: **is there a single canonical implementation that subsumes all four**, or are the different validation signals (held-out scoring, outcome-driven retirement, post-execution gating, curator-executor split) actually orthogonal? No paper has yet run all four in a head-to-head ablation.
