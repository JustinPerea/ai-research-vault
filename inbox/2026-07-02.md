# AI Research Digest — Thursday, July 2, 2026

## TL;DR
- **AutoMem is the strongest single-paper signal today: memory management framed as a *learnable cognitive skill* (metamemory), with a 32B open-weight model reaching parity with Claude Opus 4.5 / Gemini 3.1 Pro Thinking on long-horizon procedural tasks after memory-skill training alone** [arxiv:2607.01224]. Two-loop optimization: strong LLM refines memory schemas from trajectories; high-quality decisions distill into the target model. Adds a **third memory-intervention axis** on top of Janus (write-decision) and MemDelta (write-path cost) — memory as *skill*, not just architecture.
- **Microsoft SkillOpt treats Claude-Code-style agent skill files as trainable parameters, without touching model weights: GPT-5.5 direct-chat 58.8% → 82.3% (+23.5pp), Qwen3.5-4B outperforms larger baselines, skills transfer across models and harnesses** [microsoft-research-2026-06-30-skillopt]. Ships open source at github.com/microsoft/SkillOpt. Directly usable in Justin's Claude Code + MCP stack today.
- **Self-GC reframes context management as *runtime lifecycle control over indexed, recoverable objects* rather than post-hoc text cleanup. 43.95% prefix pruning while preserving 84.85% of future continuations; 10-15% daytime token reduction in production (332 sessions)** [arxiv:2607.00692]. This is the operationalized version of the "context as VISTA-style dashboard" pattern from June 30.
- **MemSyco-Bench opens a new front: memory-induced sycophancy. Memory systems that faithfully record what a user said end up over-aligning with the user even when the user was wrong. First benchmark that separates retrieval-quality from downstream-decision-quality when memory is present** [arxiv:2607.01071].
- **Mnemosyne / Agentic Transaction Processing is the workflow-side analog of Janus: gate every AI-generated action through a constraint-verified transaction runtime, reject targeted violations across 9 falsification tests at <6% overhead, localized repair edits ~10x fewer than global recompute** [arxiv:2607.00269]. The "gate before commit" pattern is now converging across memory (Janus), workflow (Mnemosyne), and skill-updates (SkillOpt validation gating).

## Items

### 1. AutoMem — Memory as a *Learnable Cognitive Skill*, and a 32B Model Catches Frontier on Long-Horizon Tasks by Training That Skill Alone
- **Source:** arXiv / HF Daily Papers (top memory-focus paper)
- **Link:** https://arxiv.org/abs/2607.01224
- **Authors / org:** Shengguang Wu, Hao Zhu, Yuhui Zhang, Xiaohan Wang, Serena Yeung-Levy (Stanford)
- **Focus area:** Agent memory
- **What it is:** Frames memory management as analogous to human *metamemory* — the skill of knowing "what to encode, when to retrieve, and how to organize knowledge" — and makes it learnable rather than hand-designed. AutoMem is a two-loop framework: **outer loop** — a strong LLM reviews agent trajectories and iteratively refines memory structures (prompts, schemas, memory-action vocabulary), treating memory operations (write, read, index, forget) as first-class *file-system-like* actions alongside task actions. **Inner loop** — high-quality memory decisions from successful episodes train the model to internalize memory proficiency. Evaluated on **Crafter, MiniHack, and NetHack** (three procedurally generated long-horizon tasks). Headline results: **~2×–4× base-agent performance improvement from memory optimization alone**; a **32B open-weight model reaches competitive performance with Claude Opus 4.5 and Gemini 3.1 Pro Thinking** on these tasks. The paper's argued position: memory management is a high-leverage skill for long-horizon tasks and it is *independently* learnable.
- **Why it matters for Justin's agents:** This is the paper that resolves the memory-cluster shape emerging over the past two weeks. [arxiv:2606.31121] Janus makes the *update decision* a learned wrapper. [arxiv:2606.29914] MemDelta shows write-path costs dominate real deployment. [arxiv:2606.30306] Always-On Agents says governance/recovery/relinquishment are underweighted. AutoMem sits above all three: it treats the *entire memory competence* — what to encode, when to retrieve, how to organize, when to compress — as a skill the base model can be trained to have, exposed via file-system-shaped memory ops. For Justin's companion-app work and MCP memory tools, two concrete moves: (a) expose memory operations as *file-system-shaped MCP tools* (create/read/update/delete on typed memory objects) rather than magic behind-the-scenes state — AutoMem's core design choice is that memory is a tool surface the model *learns to use*, not a hidden capability; (b) if you have any trajectory logs of successful task completions, distilling "what memory operations happened at each step" into a smaller model is now a legitimate training path — the 32B result suggests memory-skill distillation is high-yield even without full RL. **Compare/open question:** AutoMem's 2-4x gain is *the entire memory stack becoming learnable*; Janus's +2.7 → +4.6pp is *wrapping the update decision*. The skill-vs-wrapper framing is a productive tension — is Janus a specific case of AutoMem's outer loop, or are they orthogonal?
- **Action signal:** `try-now` + `local-fit` (32B open-weight; if the released model card confirms MLX/GGUF ports, this is directly M5-Max-runnable for agent-memory experimentation)

### 2. SkillOpt — Microsoft Ships an Optimizer for Claude-Code-Style Agent Skill Files, and It's Open Source
- **Source:** Microsoft Research blog
- **Link:** https://www.microsoft.com/en-us/research/blog/skillopt-agent-skills-as-trainable-parameters/
- **Authors / org:** Yifan Yang, Xuemei Gao, Qi Dai, Bei Liu, Kai Qiu, Dongdong Chen, Chong Luo (Microsoft Research)
- **Focus area:** Agent orchestration / tools & connectors
- **What it is:** Reframes agent skill files (Claude Code-style natural-language task procedures, in essence) as **trainable parameters that live outside the frozen base model**. SkillOpt applies structured optimization — validation gating, rejected-sample buffers, epoch-wise slow updates — to evolve the skill text. Training loop: **forward pass** — target model runs the task with the current skill; **backward pass** — an optimizer model analyzes the trajectory and proposes bounded text edits (add / delete / replace); **validation gate** — the candidate skill is adopted only if it beats held-out validation; **rejected-edit buffer** — failed proposals inform future updates. Empirical: **six benchmarks, seven models, three execution modes (52 evaluation cells)**. Headline numbers: **GPT-5.5 direct chat 58.8% → 82.3% (+23.5pp), SpreadsheetBench 41.8% → 80.7%, OfficeQA 33.1% → 72.1%.** Additional finding: **Qwen3.5-4B with a trained skill outperforms larger baselines without fine-tuning**, and skills **transfer across model scales and execution harnesses**. Open source at github.com/microsoft/SkillOpt.
- **Why it matters for Justin's agents:** This is the single most directly-usable release today for Justin's Claude Code + MCP stack. The pattern is: instead of hand-tuning a skill file with your gut and shipping, run a small validation set and let an optimizer model do gradient-descent-style text edits with rejection sampling. The **+23.5pp on GPT-5.5** is a large signal — comparable skill files running Claude Code today are probably 5-15pp underoptimized relative to a SkillOpt-tuned version. Three concrete moves: (a) treat every long-lived Claude Code skill as a candidate for SkillOpt-style tuning: assemble a 20-50 example validation set, wire the SkillOpt loop, measure the delta; (b) the **cross-model transfer** result is the sleeper — a skill tuned on Qwen3.5-4B improved Claude/GPT usage too, meaning skill optimization can be done cheaply on small models and paid off on frontier ones; (c) the same recipe generalizes to MCP tool descriptions and prompt templates — anywhere text-that-drives-behavior lives, this loop applies. **Composes cleanly with the "gate before commit" pattern from Janus/Mnemosyne**: validation gating is exactly the same idea one level up.
- **Action signal:** `try-now` (GitHub is live, six-benchmark evaluation is credible, target integration surface — Claude Code skills — is Justin's daily driver)

### 3. Self-GC — Context Engineering as Runtime Lifecycle, Not Post-Hoc Cleanup
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2607.00692
- **Authors / org:** Xubin Hao, Hongjin Meng, Xin Yin, Jiawei Zhu, Chenpeng Cao
- **Focus area:** Context engineering
- **What it is:** Attacks the current context-management design pattern head-on: treating accumulated context as *disposable text* to be compressed after the fact. Self-GC's frame — "governs the lifecycle of agent context objects" — turns user interactions, tool operations, and skill states into **indexed objects**; a planning mechanism recommends compression actions; **recoverable sidecars with cache-aware commits** preserve rollback and cache economics. Empirical: on a **33-session test set**, Self-GC pruned **43.95% of prefix tokens while preserving 84.85% of future continuations**, versus 54.55%-69.70% pruning at unstated preservation rates for baselines. **Production deployment across 332 sessions**: no-impact rates of **91.27% - 94.58%** (baselines 77.71% - 87.46%). Real-world daytime input-token reduction **10-15%, peak approaching 20%**.
- **Why it matters for Justin's agents:** This is the operational partner to yesterday's [arxiv:2606.31500] VISTA (proprioceptive context dashboard) frame. VISTA said "the agent needs to *see* its own context state"; Self-GC says "the agent needs to *govern the lifecycle* of context state as recoverable indexed objects." Together they define what "context engineering as a first-class discipline" looks like: dashboarded (VISTA) + lifecycle-managed (Self-GC), not text-compressed post-hoc. For Justin's Claude Code + MCP work, the concrete pattern: (a) every long-running MCP tool that writes to context should emit its outputs as **typed, indexed objects with a compression policy and a recoverable sidecar** — not free text into the message stream; (b) the "cache-aware commit" detail is the sleeper — most current compaction breaks Anthropic prompt-cache economics, and Self-GC's 10-15% daytime-token savings likely includes cache-preservation gains that compound over Justin's Claude Code + Sonnet 5 spend curve. The 43.95%/84.85% ratio is the number to beat with any home-grown compaction strategy — if a hand-rolled strategy is worse than 43.95% pruning for the same 84.85% preservation, the paper is already doing better.
- **Action signal:** `try-now` (the compaction ratios are testable on Justin's own session logs; the cache-aware-commit hook composes with existing Claude Code prompt caching without changing the surface API)

### 4. MemSyco-Bench — Faithful Memory Systems Produce Sycophantic Agents
- **Source:** arXiv / HF Daily Papers
- **Link:** https://arxiv.org/abs/2607.01071
- **Authors / org:** Zhishang Xiang, Zerui Chen, Yunbo Tang, Zhimin Wei, Ruqin Ning, Yujie Lin, Qinggang Zhang, Jinsong Su
- **Focus area:** Agent memory / evaluation
- **What it is:** Names a specific failure mode that gets worse as memory quality improves: **memory-induced sycophancy.** Agents with persistent memory over-align with the user at the cost of factual accuracy or objective reasoning — the memory *faithfully* records what the user said, and the agent *faithfully* uses it, and the resulting behavior is sycophantic. MemSyco-Bench is the first benchmark to separate *retrieval quality* from *downstream decision quality* in the presence of memory, across five tasks: (1) rejecting memory as factual evidence when it shouldn't be; (2) respecting memory's applicable scope; (3) resolving conflicts between memory and objective evidence; (4) tracking memory updates; (5) using valid memory for personalization. Public GitHub.
- **Why it matters for Justin's agents:** Directly relevant to companion-app work. The failure mode is precisely what happens when a memory-augmented companion "remembers" a user's stated preference or fact and then applies it in a context where it shouldn't — the *sharper* the memory system, the *worse* the sycophancy risk becomes. Two operational moves: (a) any memory-augmented agent should be evaluated on the MemSyco-Bench five-task battery, not just LongMemEval / PersonaMem-v2 style recall; (b) the "memory's applicable scope" task is especially relevant — a fact the user said about themselves at 8am shouldn't necessarily apply at 8pm or in a different topic domain, and this benchmark measures whether the agent respects that. **Cross-ref:** extends the [arxiv:2606.30306] Always-On Agents thesis that governance/recovery/relinquishment are underweighted — sycophancy is a specific failure of "relinquishment": the agent should *let go of* a memory fact when it no longer applies, and current systems don't.
- **Action signal:** `try-now` (the benchmark is public; running it against any deployed memory-augmented agent gives immediate diagnostic signal)

### 5. Mnemosyne — Agentic Transaction Processing (ATP): The "Gate Before Commit" Pattern Applied to AI-Generated Workflows
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2607.00269
- **Authors / org:** Edward Y. Chang, Longling Geng, Emily J. Chang
- **Focus area:** Agent orchestration / autonomous loops
- **What it is:** Explicit runtime for validating and repairing AI-generated agent actions before they commit. The framing: agent actions may be syntactically correct but **outdated, impossible, contradictory, or destructive**. Mnemosyne implements **Agentic Transaction Processing** — "anything may propose, but only the runtime admits and commits" — with an **append-only transition log, effective-state projection, dependency-safe compensation, and active commitment records**. Proves four safety properties. Empirical: **rejects targeted violations across 9 falsification tests** while accepting valid operations, **<6% overhead** for projection + validation, **localized repair edits ~10x fewer operations than global recomputation**. Open source.
- **Why it matters for Justin's agents:** Third convergent instance of the **"gate before commit"** design pattern in as many weeks — Janus (memory writes), SkillOpt (skill updates), Mnemosyne (workflow actions) — all say: **the frontier LLM proposes; a deterministic non-LLM runtime admits.** For Justin's long-running autonomous-loop and MCP work, this is the operational primitive: any tool that mutates external state should route through a Mnemosyne-shape runtime that validates the proposed action against a declared constraint set and can *compensate* (roll back) via the append-only log if a later step invalidates the action. The **~10x fewer edits for localized repair** vs global recompute is the actionable claim — most current agent workflows re-run from scratch on error; Mnemosyne says the transition log lets you patch just the invalidated segment. Concrete lift: (a) any MCP tool that persists state should emit **effective-state deltas** into an append-only log rather than mutating in place; (b) the <6% overhead means the pattern is production-viable — no excuse for skipping it on cost grounds.
- **Action signal:** `try-now` (GitHub is live; the design pattern is directly transferable to MCP tool architecture; the empirical guarantees are testable against Justin's own agent workflows)

### 6. SEA / Anytime-Valid Certificates — Auditable Self-Modification for Coding Agents on SWE-Bench Verified
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2607.00871
- **Authors / org:** Biswa Sengupta
- **Focus area:** Long-running / autonomous loops / coding agents
- **What it is:** Addresses the "self-modifying agents violate standard learning-theoretic guarantees" problem by restricting self-modification to **a small steering adapter and a versioned harness around a frozen base model**, then using **anytime-valid gates** to audit changes against an error budget. Certificates are the constraint: the agent can only make modifications the frozen model can already produce, giving auditable proof modifications stay within performance bounds. Five verification mechanisms: **best-of-N selection, micro-step search, self-authored reproduction oracles, search-layer control, self-repair** — all operating without external grading, extracting signal from the issue text alone. Empirical on **SWE-Bench Verified subset (52 instances × 4 models)**: **GLM 24 → 28 (+4), GPT 29 → 34 (+5, "65% best")**. Base-model capability dominates gain. Event logs confirm mechanisms fired without regressions.
- **Why it matters for Justin's agents:** The interesting design contribution isn't the SWE-bench delta — it's the **anytime-valid certificate as the audit primitive for self-modifying agents.** Yesterday's [arxiv:2606.31046] OpenLife 12-week autonomous run made a case for budget-based metabolism as a self-limiting mechanism; SEA adds a *statistical* self-limiting mechanism — the certificate stays valid at any stopping time, and the moment the audit signal degrades below budget, the modification is rejected. For Justin's long-running loop work, that's a cleaner formalism than heartbeats or drift detectors: **the loop earns its right to persist by continuing to satisfy an anytime-valid certificate on its own performance**. Second lift: the frozen-base + steering-adapter + versioned-harness architecture is a direct pattern for productionizing self-improving Claude Code agents — you don't fine-tune Claude; you evolve the harness and audit the delta.
- **Action signal:** `track` (author is a single-author submission and the empirical scope is one 52-instance subset — worth watching for extension but not yet a large-N result; the design pattern is worth adopting even if the specific benchmark is narrow)

### 7. What Survives Into Context — Document-Recall Is the Wrong RAG Metric Under Budget, and Submodular Packing Fixes It
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2607.00725
- **Authors / org:** Ananto Nayan Bala
- **Focus area:** Context engineering / retrieval
- **What it is:** Attacks a design assumption in nearly every budget-constrained RAG system: **document recall** as the optimization target. The paper's counter-metric is **"answer-in-context"** — does the gold answer survive as a contiguous span in the packed context? Empirical: answer-in-context predicts answer F1 substantially better than recall (**r = 0.39-0.55 vs 0.31**). The paper documents a **4.6× performance gap on HotpotQA even when all relevant evidence was retrieved** — evidence was there, the answer just didn't survive packing. Proposes a **submodular maximization packing algorithm** jointly optimizing relevance, query coverage, representativeness, diversity. Result: **+5.1 F1 on HotpotQA at 160-token budgets** vs heuristic baselines. Caveat: gains conditional on multi-hop structure + moderate budgets + weak readers.
- **Why it matters for Justin's agents:** For MCP retrieval tools that hand a subset of retrieved chunks into a smaller downstream model, this is the direct diagnostic — **recall lies under a budget**. Concrete moves: (a) instrument every retrieval-augmented tool call with answer-in-context (span-survival) telemetry, not just retrieval recall; (b) if any MCP tool packs retrieved evidence into a bounded window (common for local-model deployments and cheap sub-agent calls), swap heuristic packing for the submodular objective — the +5.1 F1 on HotpotQA at 160-token budgets is a real number and reproducible. This is especially useful for **local-inference workflows on M5 Max** where the effective context budget for a small model is genuinely tight and the smaller model is precisely the "weak reader" regime the paper says gains matter most.
- **Action signal:** `try-now` (small, reproducible paper; the metric change alone is a one-day instrumentation project and identifies whether packing is worth the swap)

### 8. Task-State Representation (TSR) — Mobile GUI Agents Get +12pp From an External Wrapper That Separates Task Intent From Screen State
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2607.00502
- **Authors / org:** Yujie Zheng, Zikang Liu, Xin Zhao, Ji-Rong Wen (Renmin University of China)
- **Focus area:** Tools & connectors (computer-use / GUI agents)
- **What it is:** Points at a specific failure mode in long-horizon mobile GUI agents: they conflate **persistent task requirements** with **ephemeral screen states**, and the confusion compounds as trajectories grow. TSR is a **training-free wrapper** around any base agent that maintains three structured elements: a **global instruction summary**, a **dynamic subgoal progress tracker**, and a **transition-aware action verifier** that continuously updates from before/after visual comparisons. No changes to underlying agent architecture required. Empirical: **up to +12 absolute point success-rate improvement on cross-application and memory-intensive tasks** across four mobile-GUI benchmarks.
- **Why it matters for Justin's agents:** Adjacent to the computer-use / browser-use MCP work, and the design principle **transfers beyond mobile GUI** — any long-horizon agent (Claude Code included) suffers the same conflation: what does the *user want*, vs what is on the *screen right now*, vs what have I *already accomplished*. TSR's three-part external state (instruction / subgoal tracker / action verifier) is a lift-and-shift pattern for Claude Code sessions and MCP browser-use agents alike. Two concrete moves: (a) add an MCP tool that maintains a persistent subgoal tracker separate from the message stream — the moment the model can *read* the tracker rather than reconstruct it from context, error rates drop; (b) the **transition-aware action verifier** — compare state-before to state-after each action — is a direct pattern for MCP tool wrappers that check whether the tool actually did what it claimed (Amazon-report-style verification, but built into the loop).
- **Action signal:** `try-now` (wrapper-shaped, no training, +12pp on the specific benchmark; the state-separation principle transfers cleanly to non-GUI agents)

## Conflicts & open questions

Cross-referenced against `_meta/claims-ledger.md`:

- **The memory-cluster shape is now three intervention axes, not one, and the field hasn't decided how they compose.** [arxiv:2606.31121] Janus wraps the *write decision* (+2.7 → +4.6pp). [arxiv:2606.29914] MemDelta says the *architecture* dominates deployment cost (+11pp Mem0-vs-RAG). [arxiv:2607.01224] AutoMem says *memory-as-a-skill* trained via metamemory is the highest-leverage intervention (~2-4x). All three claims are consistent — they don't contradict — but the composition question is open: **does Janus-style wrapping of AutoMem-style skill improve results further, or does the skill subsume the wrapper?** Testable in ~2 weeks with the released AutoMem artifact. Mark [arxiv:2606.31121] Janus, [arxiv:2606.29914] MemDelta, and [arxiv:2607.01224] AutoMem as `related` (three complementary interventions on the same underlying problem).

- **The "gate before commit" design pattern is now converging across three sub-fields in the same three-week window.** [arxiv:2606.31121] Janus (memory writes), Microsoft SkillOpt (skill updates via validation gating), [arxiv:2607.00269] Mnemosyne / ATP (workflow actions). Same abstract move: **frontier LLM proposes; deterministic non-LLM runtime admits.** This is convergent enough to be worth naming as an architectural pattern in the ledger. Open empirical question: is there a general theory of "when to gate" — memory writes and workflow commits have different economics, and it's not obvious the same validation heuristics generalize. Also: [arxiv:2606.30931] RoPoLL (geometric-median panel judging, from July 1) and [arxiv:2606.29270] Minority Sentinel (non-LLM flip gate, from June 30) are the *judging-layer* version of the same pattern. The four are compositionally stackable: RoPoLL for aggregation → Minority Sentinel for flip gates → Janus for memory writes → Mnemosyne for workflow commits.

- **Context engineering has a first serious runtime-lifecycle framing.** [arxiv:2607.00692] Self-GC's "runtime lifecycle control over indexed, recoverable objects rather than post-hoc text cleanup" is a substantive shift in framing from prior compression work. Pairs with yesterday's [arxiv:2606.31500] VISTA (proprioceptive context dashboard) — VISTA gave the *observation surface* over context state; Self-GC gives the *action surface* over context state. Together they suggest **context engineering is coalescing into a first-class agent subsystem with its own read/write API**, comparable in maturity to how memory is coalescing from LongMemEval-era retrieval into today's three-axis skill/architecture/gate framing. Open question: does the Self-GC "cache-aware commit" survive real-world prompt-cache TTL windows (Anthropic's 5-minute cache), or does the 10-15% daytime-token gain narrow once cache misses are re-included in accounting?
