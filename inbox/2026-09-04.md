### 1. Fresh Memory, Stale Plans: Dependency-Scoped Validation for Distributed LLM-Agent Memory
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2609.03340
- **Authors / org:** Evan Chen, Shiqiang Wang, Christopher G. Brinton
- **Focus area:** Memory / multi-agent — PlanFence dependency-scoped validation
- **What it is:** PlanFence: plans cite exact public records used; executor validates only records that can affect the pending external action, replanning once or blocking when validation is incomplete. In 30 controlled live workflows with a post-plan revision, freshness-only executors act on the obsolete plan every time; PlanFence completes all without an invalid action. Controlled results on safety/systems cost, not general task accuracy.
- **Why it matters for Justin's agents:** Direct sequel to yesterday's Memory Trust Gap [2609.01852]: fresh shared state ≠ valid authorizing plan. Steal for Mitamaton multi-agent admin: cite plan dependencies; revalidate before Gmail/calendar side effects. Soft conflict with Civilization Framework authority-from-memory [2609.03425].
- **Action signal:** `try-now`

### 2. Do GUI Agents Know When Not to Act? Enabling Conflict-Aware Termination for Multimodal GUI Agents
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2609.03438
- **Authors / org:** Zhaoyuan Huang, Tianjie Ju, Pengzhou Cheng, Zheng Wu, Yansi Li, Chuanbiao Song, Jun Lan, Huijia Zhu, Weiqiang Wang, Zhuosheng Zhang
- **Focus area:** GUI / computer-use — conflict-aware termination
- **What it is:** CONFLICTGUI benchmarks instruction-internal and instruction–GUI conflicts. Agents that succeed on feasible tasks show severe execution-biased overcompliance under conflict. ### 3. Speculative Macro Commit for Faster Tool-Using Agents
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2609.03236
- **Authors / org:** Zeyu Liu, Souvik Kundu, Peter A. Beerel
- **Focus area:** Tools / runtime — Speculative Macro Commit (SMC)
- **What it is:** Two-tier runtime: large authoritative actor + faster speculative drafter executing future action chains on an isolated environment snapshot. Mines multi-action skeletons into a macro library; commits remaining pre-executed steps when actor's next tool call matches. ### 5. Plan Pointers and Record-Directive Form in Budgeted Verification of Inherited Agent Memory
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2609.03450
- **Authors / org:** Kazuki Nakayashiki
- **Focus area:** Memory / inheritance — Plan Pointers + record-directive form
- **What it is:** When an agent inherits budgeted memories and may pull ≤1 archived source before acting, directive form (bare id vs criterion vs both) steers retrieval. - **Why it matters for Justin's agents:** Inherited memory for Claude Code / Mitamaton handoff is format-sensitive. Prefer criterion directives; avoid id+criterion cancel patterns. Soft conflict with PlanFence (validate deps) and Memory Trust Gap (don't trust store blindly).
