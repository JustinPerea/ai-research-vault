### 1. Whose Memory Is It? Scope-Aware Commit Rules for Long-Term LLM Memory
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.09008
- **Authors/org:** Hongyu Gu, Xinchang Li
- **Focus area:** agent memory / commit rules
- **What it is:** Persistent memory turns a rejected plan, a simulated tool result or another speaker's belief into a durable 'fact' once it is stored as a plain sentence. The authors call the missing context discourse ownership (which world, branch or speaker licenses a proposition) and find LLMs already carry a causally active ownership signal that memory interfaces throw away. CASK (Causally Anchored Scoping Keys) is a commit rule that keeps the stable relations expressing ownership, so shared-world facts enter durable memory while provisional content stays in its original scope. On controlled long-conversation conflicts and tool-agent traces it improves memory admission and stops provisional content contaminating later answers.
- **Why it matters for Justin's agents:** Same failure AgentMemGate flagged yesterday, now with a principled commit boundary: tag every memory write with its owner/branch before it becomes durable, and let only shared-world facts through.
- **Action signal:** `try-now`

### 2. Stale, Misattributed, or Late: Where Personal Memory Fails Before Generation
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.10265
- **Authors/org:** Haonan Deng, Park Sinchaisri
- **Focus area:** personal memory / evaluation
- **What it is:** Measures personal-memory failures before generation using a Personal Fact Memory reference layer. Serving only the active value of each correctly keyed slot eliminates stale exposure; without update resolution 70.3% of prompts expose a superseded value. Participant-aware BM25 matches the reference ranker within 0.02 once retrievers share the active store. The hard part is assigning revisions to the right slot: four LLM key assigners beat a rule extractor on key recall but give lower clean-retrieval rates, and open-domain merge recall on LongMemEval never exceeds 0.062. Same-name speakers in LoCoMo cannot be told apart; prompt prefill, not retrieval, dominates turn latency.
- **Why it matters for Justin's agents:** For a personal day-admin agent: keyed slots with explicit supersession beat fancier retrieval. Invest in slot assignment/merge and speaker identity, and test the memory block itself, not just final answers.
- **Action signal:** `try-now`

### 3. Relevance Is Not Sufficiency: What Actually Closes the Evidence Gap in Long-Term Memory QA
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.09348
- **Authors/org:** Yufeng Li, Shuxin Li, Zhenhua Xu et al. (10 authors)
- **Focus area:** long-term memory retrieval
- **What it is:** Top-ranked memories can each be relevant yet jointly miss a fact the answer needs, especially on multi-session and temporal questions. Recasts retrieval as building a sufficient memory set: Budgeted Flat Reconstruction first uses Formal Concept Analysis (FCA-MS) to decompose the question into information requirements and pick a covering subset, then keeps acquiring unseen records via deeper text search or entity/session views until budget runs out. Over a flat store it beats same-store adaptations of recent agent-memory systems on LoCoMo and LongMemEval-S; on LongMemEval-S judged accuracy rises 72.4% → 82.2% with Turn Hit 91.4%.
- **Why it matters for Justin's agents:** Cheap upgrade to a flat memory store: decompose the question into required facts and retrieve until each is covered, instead of top-k by similarity.
- **Action signal:** `try-now`

### 7. RunningTab: Direct Workspace Interaction with Environment-Side Tabs
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.10444
- **Authors/org:** Jinheon Baek, Soyeong Jeong, Yumin Choi et al. (5 authors)
- **Focus area:** workspace agents / context bookkeeping
- **What it is:** For agents that build deliverables directly from workspace files via a terminal (direct workspace interaction), nothing tracks what the task still requires, what was read, and what was listed but never opened. ### 10. RippleCP: Measuring Counterfactual Checkpoint Advantage in Coding Agents
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.09088
- **Authors/org:** Mayur Akewar, Ravi Ranjan
- **Focus area:** coding-agent checkpoints

### 25. When the Governor Becomes the Disturbance: Control-Generated Disturbance and Cost-Aware Backoff in Governed Tool-Using Agents
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.09037
- **Authors/org:** Veronique Ziegler
- **Focus area:** governed tool-using agents

## Conflicts & open questions

- **Fix memory at write time or read time?** CASK (2610.09008) and Stale, Misattributed, or Late (2610.10265) put the decisive step at construction (scope-tag commits; active value per keyed slot), while BFR (2610.09348) and ExperienceIndex (2610.10091) win at retrieval (sufficient sets; artifact experience). 2610.10265 also finds ranker choice barely matters once the store is clean. Open: how much of BFR's +9.8 pts survives on a store with supersession already resolved?
- **Are self-improvement gains real?** FreeEvolve (2610.09197, +13.6 held-out), SkillForge (2610.09832, up to 7.8% relative) and UniSkill (2610.10164) report gains, but the winner's-curse study (2610.09239) shows selection-set gains overstated by 13-20 pts with small selection sets and even in GEPA/MIPROv2, and Agent Plasticity (2610.08902) finds in-regime gains transfer only partially. FreeEvolve reports held-out metrics; others should be read for held-out sets and uncertainty.
- **Skills: curate or verify per configuration?** Agent Skills' utility (2610.08875) shows the same Skill flips from help to hurt across model+harness configurations on 36.78% of tasks, so SkillSandbox (2610.10088) verdicts and SkillForge (2610.09832) fitness scores, each measured in one setup, may not transfer to a different model or harness. Untested.
- **Can prompting make agents verify tool results?** Loud Failures, Quiet Failures (2610.10062) finds a 'check each result' prompt line does not move detection, while yesterday's When Tools Lie (2610.08097) restored accuracy with *mandatory* reflection, and Caddie (2610.09858) gets +25 pts from a trained critic. Reconciliation: optional self-checks fail; enforced checks (a step the harness requires, a separate critic, Humanize's deterministic gates in 2610.08900) work.
- **Where can small local models be trusted?** Not Every Call Needs a Frontier Model (2610.09021) finds the best local model matches hosted ones at 4 of 5 call sites but small models fail unsafely at actuation (87.2% actuation on unowned devices; a 4B worse than its 2B sibling), and AO-DA (2610.09772) protects an 8B but not a 4B under pollution. Small models look fine for routing/classification and risky for actions without a hard ownership/permission check.
- **Security vs utility:** Secure-CUA (2610.09469) claims secure-by-design at a ~1.6-pt utility cost, and multi-aspect runtime verification (2610.08928) reports zero attack success with no observed false positives, but CredLeakBench (2610.08871) finds most mitigations hurt genuine tasks, WebMirage (2610.09240) defeats three agent-level defenses, and the governor study (2610.09037) shows aggressive supervision can itself block completion. Benchmarks used to score both sides are themselves shaky: shipped AppWorld/WorkArena verifiers accept wrong side effects (2610.09142).
