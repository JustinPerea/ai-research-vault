# AI Research Digest — Sunday, May 17, 2026

## TL;DR
- **Harness choice now beats model choice on real long-horizon agent tasks.** WildClawBench (Shanghai AI Lab cluster, 60 human-authored bilingual real-runtime tasks, avg ~8 min and 20+ tool calls per task) reports **Claude Opus 4.7 top at 62.2%**, every other model below 60%, and **up to 18-point variance for the same model across harnesses** (OpenClaw, Claude Code, Codex, Hermes). Directly extends [arxiv:2605.15184]'s "harness dominates retrieval" finding from yesterday into the broader "harness dominates absolute task success" regime.
- **MSR's DELEGATE-52 follow-up names a clean fix: run delegated work as Python.** Philippe Laban / Tobias Schnabel / Jennifer Neville reaffirm **19–34% artifact-fidelity degradation over 20 delegated iterations** for frontier models — but **Python workflows degrade <1% on average**. Sharpens [arxiv:2604.15597] DELEGATE-52 with a concrete production-pattern recommendation.
- **A 10th orthogonal memory failure mode lands: multimodal/visual.** NVIDIA's MemLens (789 questions, 5 memory abilities, 32K–256K cross-modal context) shows **multi-session reasoning below 30%** and **image-ablation drops two frontier VLMs below 2% on 80.4% of vision-dependent questions** — current multimodal memory pipelines do not preserve visual evidence across sessions. Adds the visual axis to a memory-failure-mode taxonomy that now spans nine prior text-only failure modes.
- **Two new context-engineering tricks worth porting today.** InsightReplay (Xin Eric Wang cluster) periodically replays critical insights near the active generation frontier; **+1.65 avg / +9.2 max points across 24 settings** (8B/30B Qwen3.5, R1-Distill, Gemma-4 × AIME, HMMT, GPQA-D, LiveCodeBench-v5) — a clean operational counterpart to [arxiv:2605.12922]'s channel-transition finding. OpenDeepThink (Berkeley/Codeforces cluster) parallelizes reasoning via Bradley–Terry aggregation; **+405 Codeforces Elo for Gemini 3.1 Pro in ~27 minutes of LLM-call rounds**.
- **Eval methodology says the eval methodology is the bottleneck.** TRAIL (Holistic Evaluation and Failure Diagnosis) reports **+38% Category F1 / 3.5× localization / 12.5× joint localization-categorization** over prior baselines, plus SOTA on GAIA and SWE-Bench — and explicitly argues "evaluation methodology, not model capability, is the bottleneck" because the same frontier models score much higher inside its top-down/bottom-up framework than as standalone judges. 7th consecutive agent-eval-credibility paper.

### 1. WildClawBench: A Benchmark for Real-World, Long-Horizon Agent Evaluation
- **Source:** arXiv (cs.AI, submitted May 11, surfaced on HF Daily Papers May 15, 2026)
- **Link:** https://arxiv.org/abs/2605.10912
- **Authors / org:** Shuangrui Ding, Xuanlang Dai, Long Xing, Shengyuan Ding, Ziyu Liu, JingYi Yang, Penghui Yang, Zhixiong Zhang, Xilin Wei, Xinyu Fang, Yubo Ma, Haodong Duan, Jing Shao, Jiaqi Wang, Dahua Lin, Kai Chen, Yuhang Zang (17 authors, Shanghai AI Lab / Intern Large Models cluster — Dahua Lin and Kai Chen are well-known Shanghai AI Lab leads)
- **Focus area:** Evaluation / Agent orchestration / Coding agents
- **What it is:** First agent benchmark to run **real CLI harnesses on real systems** rather than synthetic sandboxes. 60 human-authored, bilingual (Chinese/English), multimodal tasks across six thematic categories; tasks average ~8 minutes wall-clock and 20+ tool calls each; native CLI harnesses (OpenClaw, Claude Code, Codex, Hermes Agent) operating on actual tools (not mock APIs). Hybrid grading: deterministic checks + environment auditing + LLM/VLM judging. Headline numbers: **Claude Opus 4.7 tops at 62.2% success**; every other model below 60%; **up to 18-point variance for the same model across harness choice**.
- **Why it matters for Justin's agents:** Two specific implications for Justin's stack. (a) The 18-point harness variance is the single biggest production-relevant finding of the week — **the harness is now empirically the dominant variable on real-world long-horizon tasks**, not the model. For Justin's Claude Code / MCP workflow that means harness selection and tool-presentation design should be the first-class optimization target, not model upgrades. (b) Opus 4.7 ceiling at 62.2% on real 8-minute / 20-tool-call tasks is a concrete bound for Justin's MCP companion-app reliability budget — even with the best current frontier model on the best harness, expect 4 of 10 long-horizon production runs to fail. The bilingual multimodal task set also makes this the cleanest current benchmark to evaluate any custom MCP harness Justin builds; the "Claw" suffix in benchmark naming is now sticky (Claw-Eval [arxiv:2605.15040] Orchard, ZeroClaw harness, OpenClaw, WildClawBench).
- **Action signal:** `try-now` `compare` — quantitative extension of [arxiv:2605.15184] (harness dominates retrieval on memory recall) into the broader "harness dominates absolute success on real long-horizon tasks" regime. Pairs with [arxiv:2605.05716] More Is Not Always Better (component interference) and [arxiv:2605.04050] LCM-Volt > Claude Code as three independent papers now pointing at the harness layer as the production frontier.

### 2. Further Notes on Our Recent Research on AI Delegation and Long-Horizon Reliability
- **Source:** Microsoft Research blog (May 15, 2026)
- **Link:** https://www.microsoft.com/en-us/research/blog/further-notes-on-our-recent-research-on-ai-delegation-and-long-horizon-reliability/
- **Authors / org:** Philippe Laban (Senior Researcher), Tobias Schnabel (Principal Researcher), Jennifer Neville (Partner Research Manager) — Microsoft Research; same authors as the original DELEGATE-52 paper.
- **Focus area:** Long-running / autonomous loops / Evaluation
- **What it is:** Author follow-up to [arxiv:2604.15597] "LLMs Corrupt Your Documents When You Delegate" (DELEGATE-52). Re-reports the headline finding — **frontier models degrade artifact fidelity 19–34% over 20 delegated iterations** on chained transformation-and-inversion tasks — and adds the contrast that **Python workflows degrade <1% on average** under the same protocol. Substantial clarification block: the original paper is "a stress test for long-horizon delegated execution with limited human verification between steps", measures semantic content degradation specifically (not formatting/style), and is "a diagnostic tool, not a comprehensive reliability measure". Authors explicitly note: "current production systems can mitigate these effects through verification loops, orchestration, and domain-specific tooling."
- **Why it matters for Justin's agents:** Two operationally important updates over the original. (a) The **Python-workflow-degrades-<1%** number is new and is the right design pattern: convert long-horizon delegated artifact transformations into Python pipelines wherever possible (deterministic, replayable, single-step verifiable), and reserve LLM-as-mutator for irreducibly natural-language steps. This is the same pattern as [arxiv:2605.12975] PyRAG (multi-hop RAG as Python program synthesis with deterministic feedback) and [arxiv:2605.05138] Executable World Models — three independent results pointing at Python as the durable-state substrate. (b) The "verification loops, orchestration, and domain-specific tooling" line is MSR effectively endorsing the [arxiv:2605.06455] PrefixGuard / [arxiv:2605.04785] AgentTrust runtime-supervision stack as production mitigation.
- **Action signal:** `compare` — directly extends ledger entry [arxiv:2604.15597] DELEGATE-52 with new numbers (Python <1% degradation) and a named mitigation pattern. Confirms the 19–34% degradation claim hasn't been retracted or weakened.

### 3. MemLens: Benchmarking Multimodal Long-Term Memory in Large Vision-Language Models
- **Source:** arXiv (cs.CV / cs.AI, May 14, 2026)
- **Link:** https://arxiv.org/abs/2605.14906
- **Authors / org:** Xiyu Ren, Zhaowei Wang, Yiming Du, Zhongwei Xie, Chi Liu, Xinlin Yang, Haoyue Feng, Wenjun Pan, Tianshi Zheng, Baixuan Xu, Zhengnan Li, Yangqiu Song, Ginny Wong, Simon See — **NVIDIA** (per HF Daily attribution; Yangqiu Song is HKUST, Simon See is NVIDIA Solution Architecture)
- **Focus area:** Agent memory / Evaluation
- **What it is:** First benchmark of multimodal long-term memory in vision-language models across multi-session conversations. **789 questions** spanning five memory capabilities: information retrieval, cross-session reasoning, temporal reasoning, knowledge updating, refusal-when-no-evidence. Context windows from **32K to 256K tokens** with cross-modal token counting. Three key findings: (a) **long-context VLMs excel initially but degrade as conversations grow** — the same memory-decay signature as text-only LongMemEval-V2 surfaces in the multimodal regime; (b) memory-augmented agents maintain text consistency but **suffer from visual fidelity loss under storage-time compression** — i.e. summarizing an image into text and storing the text loses the visual evidence; (c) **multi-session reasoning consistently underperforms with most systems below 30%** accuracy, and **removing evidence images drops two frontier VLMs below 2% accuracy on 80.4% of vision-dependent questions** — proving the questions actually require the images. Proposed direction: hybrid long-context + structured multimodal retrieval.
- **Why it matters for Justin's agents:** For companion apps that ingest screenshots, photos, and PDFs alongside text, this is the cleanest evidence yet that **text-only memory summarization breaks the visual evidence pipeline**. Concrete implementation pattern: **store image references (paths/CDN URLs) as first-class memory entries alongside the text summary**, not as text-only descriptions — the <2% performance on image-ablated questions is the cost of storing only the description. Pairs with [arxiv:2605.15184] grep-beats-vector: if storage is files + grep over markdown shards, image references are native; if storage is vector embeddings of text descriptions, the visual signal is destroyed at write time. The **<30% multi-session ceiling** is the multimodal analogue to [arxiv:2605.06527] STALE's 55% implicit-conflict ceiling and [arxiv:2605.14498] GroupMemBench's 46% multi-party ceiling — the agent-memory abstraction continues to leak everywhere it's stress-tested.
- **Action signal:** `track` `compare` — **10th orthogonal memory failure mode** (visual/multimodal) alongside STALE / Belief Memory / scale-conditioned / MEMOREPAIR / Memory Curse / DeMem / MEME / consolidation-decay / multi-party belief tracking. NVIDIA co-author signal raises the chance of a reference implementation or a follow-up benchmark.

### 4. Stateful Reasoning via Insight Replay
- **Source:** arXiv (cs.CL, May 14, 2026)
- **Link:** https://arxiv.org/abs/2605.14457
- **Authors / org:** Bin Lei, Caiwen Ding, Jiachen Yang, Ang Li, Xin Eric Wang (**UCSC / Penn State / UConn cluster** — Xin Eric Wang is UCSC, same author cluster as [arxiv:2605.14271] HarnessAudit; Ang Li is Penn State)
- **Focus area:** Context engineering / Reasoning
- **What it is:** Mechanism for keeping early-CoT insights accessible during long reasoning chains. InsightReplay **periodically extracts critical insights from the active reasoning trace and replays them near the active generation frontier** — i.e. it surfaces earlier reasoning steps into the recent-token window so attention can re-anchor on them. Tested on **24 settings**: 2 model scales (8B, 30B) × 4 model families (Qwen3.5, DeepSeek-R1-Distill, R1-Distill-Qwen, Gemma-4) × 4 tasks (AIME, HMMT, GPQA Diamond, LiveCodeBench v5). Headline numbers: **+1.65 average / +9.2 max point improvement over standard CoT** across all 24 settings; the max gain was R1-Distill-32B on LiveCodeBench v5.
- **Why it matters for Justin's agents:** This is the operational implementation of the [arxiv:2605.12922] "channel-transition" finding from last week — that paper showed task-defining tokens become inaccessible to attention while still encoded in residual stream, and recommended **periodic goal re-anchoring**. InsightReplay is exactly that recommendation, with measured gains across 24 settings and across model families. For Justin's MCP loops that produce long-horizon reasoning traces (research agents, multi-step coding agents), the implementation is harness-side, not model-side: at fixed intervals or at attention-trough triggers, insert a "previously you established that <insight>" block near the active generation frontier. Composable on top of any harness; no fine-tuning required. The +9.2 max gain on LiveCodeBench v5 is the directly Justin-relevant number — long-context coding agents are the failure mode this targets.
- **Action signal:** `try-now` — runtime pattern, no fine-tuning, immediately portable to MCP-based coding agents. Mechanistic complement to [arxiv:2605.12922] channel-transition / GAR; pairs with [arxiv:2605.04050] LCM (LCM compresses old context; InsightReplay re-promotes critical fragments back to near the cursor — different compression direction on the same axis).

### 5. Case-Based Calibration of Adaptive Reasoning and Execution for LLM Tool Use (CAST)
- **Source:** arXiv (cs.AI / cs.CL, May 14, 2026)
- **Link:** https://arxiv.org/abs/2605.15041
- **Authors / org:** Renning Pang, Tian Lan, Leyuan Liu, Piao Tong, Sheng Cao, Xiaosong Zhang (affiliations not on abstract; Xiaosong Zhang is a known UESTC name in the tool-use literature)
- **Focus area:** Tools & connectors
- **What it is:** Framework that calibrates an agent's tool-use reasoning depth from **historical execution trajectories rather than exemplar reuse**. CAST extracts signals from past trajectories (complexity profile + failure pattern), uses them to design fine-grained rewards for an RL phase, and trains the agent to **autonomously decide when deeper reasoning is warranted vs. when a direct call suffices**. Headline numbers: **+5.85 percentage points execution accuracy** on BFCLv2 and ToolBench; **26% average reduction in reasoning length**.
- **Why it matters for Justin's agents:** The 26% reasoning-length reduction at +5.85pp accuracy is the rare positive-on-both-axes result in tool use — most prior work trades accuracy for tokens or vice versa. For Justin's MCP stack this maps to two concrete patterns: (a) bank past tool-call trajectories per MCP server, label them by complexity and outcome, and use them as a calibration corpus before a new release ships; (b) reward shaping based on **failure profiles, not just success/failure binary**, gives the agent a cheap when-to-reason-deeply signal. Pairs with [arxiv:2605.07112] Switchcraft (pre-call routing by query) and [arxiv:2605.07990] (tool-choice readable from logits) as a third axis on the tool-use efficiency frontier — Switchcraft picks the model, the logit-gap monitor catches misfires, CAST controls reasoning depth within a single agent run.
- **Action signal:** `try-now` — concrete pattern reusable in any MCP harness with trajectory logging. The corpus-of-past-trajectories framing fits naturally with the [arxiv:2605.13880] PREPING "warm the cache before user shows up" pattern from yesterday's digest.

### 6. OpenDeepThink: Parallel Reasoning via Bradley–Terry Aggregation
- **Source:** arXiv (cs.CL, May 15, 2026)
- **Link:** https://arxiv.org/abs/2605.15177
- **Authors / org:** Shang Zhou, Wenhao Chai, Kaiyuan Liu, Huanzhi Mao, Qiuyang Mang, Jingbo Shang (**Berkeley + UCSD cluster** — Huanzhi Mao is BFCL co-author, same author cluster as yesterday's [arxiv:2605.15077] AsyncFC and [arxiv:2605.14445] FrontierSmith; Jingbo Shang is UCSD)
- **Focus area:** Reasoning & inference-time compute
- **What it is:** Test-time compute scaling via population-based parallel reasoning. Multiple reasoning candidates are sampled in parallel, **ranked by pairwise Bradley–Terry aggregation of LLM-judge comparisons** (replacing noisy pointwise scoring), and evolved across generations: **top candidates preserved, 75% mutated using natural-language critiques from comparisons, bottom 25% discarded** each generation. Releases **CF-73**, a curated set of 73 expert-rated Codeforces problems with International Grandmaster annotation. Headline number: **Gemini 3.1 Pro gains +405 Codeforces Elo across 8 sequential LLM-call rounds (~27 minutes wall-clock)**. Gains concentrated in objectively verifiable domains; **reversals observed in subjective domains** (an important honesty caveat). Transfers across model scales without retuning.
- **Why it matters for Justin's agents:** For Justin's coding-agent work, +405 Elo on Gemini 3.1 Pro is a competitive-programming-class capability uplift achievable at the harness layer with no training — the cost is just 8 rounds of parallel LLM calls. Concrete implementation: a Bradley–Terry ranker over n parallel candidate solutions can sit as a subagent in front of any code-generation MCP. The **subjective-domain reversal caveat** is the operational ceiling — for product/UX/writing tasks, the same machinery hurts performance. So the pattern is task-class-gated: enable parallel-and-rank for code, math, formal-verification tasks; disable for open-ended creative tasks. Pairs with [arxiv:2605.08083] AutoTTS (controller synthesis over pre-collected trajectories) — AutoTTS picks the test-time-scaling strategy, OpenDeepThink is one such strategy.
- **Action signal:** `track` `compare` — independent test-time compute mechanism distinct from [arxiv:2605.08083] AutoTTS, [arxiv:2605.05138] Executable World Models, [arxiv:2605.13037] MAP, [arxiv:2605.13301] SU-01. Five test-time-scaling mechanisms now on the table for code and reasoning workloads.

### 7. π-Bench: Evaluating Proactive Personal Assistant Agents in Long-Horizon Workflows
- **Source:** arXiv (cs.AI / cs.CL, May 14, 2026)
- **Link:** https://arxiv.org/abs/2605.14678
- **Authors / org:** Haoran Zhang, Luxin Xu, Zhilin Wang, Runquan Gui, Shunkai Zhang, Haodi Lei, Zihao He, Bingsu He, Chicheng Qin, Tong Zhu, Xiaoye Qu, Yang Yang, Yu Cheng, Yafu Li (affiliations not on abstract; Yu Cheng is a frequent CUHK/MSRA-Asia author)
- **Focus area:** Evaluation / Tools & connectors
- **What it is:** First benchmark to evaluate **proactive** behavior (identifying unstated user needs) in personal-assistant agents — distinct from task completion of explicit instructions. **100 multi-turn tasks across 5 personas**, including hidden intents and cross-session dependencies; measures both proactivity and task completion as separable competencies. Headline findings: (a) **task completion and proactivity are separable competencies** — agents that succeed at one can fail the other; (b) **prior interactions significantly improve agents' ability to anticipate intents in subsequent tasks** (i.e. memory matters specifically for proactivity, not just task completion); (c) "proactive assistance remains challenging" across current frontier models. 44-page paper.
- **Why it matters for Justin's agents:** Directly addresses the companion-app use case at the eval layer. Two specific implications: (a) **separating proactivity from task-completion in eval** means Justin should split his companion-app evals into "does it do what the user asked" vs. "does it surface relevant unstated needs" — these have different failure modes and probably need different fine-tunes/prompts; (b) **prior-interaction-improves-proactivity** is the operational counterpart to all of this month's memory work — memory pays off specifically on the proactivity axis, not the task-completion axis, which means the cost of a complex memory system has to be justified primarily by proactive-behavior metrics. The hidden-intent and cross-session-dependency task design also makes π-Bench a candidate evaluation target for any new MCP companion-app feature Justin ships.
- **Action signal:** `track` `try-now` — bench is small enough (100 tasks, 5 personas) to run inside a CI loop. Sits alongside [microsoft-research-2026-05-11-socialreasoning-bench] (whether agents act in users' best interests) and [arxiv:2605.12493] LongMemEval-V2 (multi-session memory) as the third leg of the companion-app eval triangle: capability / alignment / proactivity.

### 8. Self-Distilled Agentic Reinforcement Learning (SDAR)
- **Source:** arXiv (cs.LG / cs.CL, May 15, 2026)
- **Link:** https://arxiv.org/abs/2605.15155
- **Authors / org:** Zhengxi Lu, Zhiyuan Yao, Zhuowen Han, Zi-Han Wang, Jinyang Wu, Qi Gu, Xunliang Cai, Weiming Lu, Jun Xiao, Yueting Zhuang, Yongliang Shen (affiliations not on abstract; Yueting Zhuang is **Zhejiang University**, well-known cluster)
- **Focus area:** Agent orchestration / Reasoning & inference-time compute
- **What it is:** Stable recipe for combining RL with **on-policy self-distillation (OPSD)** in multi-turn LLM agents. Direct combination is unstable; SDAR treats **OPSD as a gated auxiliary objective while keeping RL as the primary optimization backbone**, with a **sigmoid gate that strengthens positive signals and softly attenuates negative ones** — fixing the compounding-instability failure mode of naive token-level distillation. Headline numbers across Qwen2.5 and Qwen3 model families: **ALFWorld +9.4% over GRPO baseline**, **WebShop accuracy +10.2%**, **Search-QA +7.0%**.
- **Why it matters for Justin's agents:** Not a near-term integration for Justin (it's a training recipe, not a runtime pattern) but it's an important data point for **what the open-source agentic-RL frontier looks like in May 2026**. The +9.4% ALFWorld number is competitive with [arxiv:2605.06078] BEACON (92.9% via milestone reward shaping), [arxiv:2605.06642] StraTA (93.1% via top-down strategy), and [arxiv:2605.05413] Constant-Context Skill Learning (89.6%) — four mechanistically distinct techniques now clustered near the ALFWorld near-90% plateau. The asymmetric-treatment-of-positive-vs-negative-signals pattern is also relevant for any RL fine-tunes Justin might commission for specialized MCP agents.
- **Action signal:** `track` — training recipe, not runtime. Joins the ALFWorld plateau cluster; awaits independent ablation showing the sigmoid gate is the load-bearing component.

## Conflicts & open questions
Cross-referenced against `_meta/claims-ledger.md`:

- **Item 1 (WildClawBench) vs. [arxiv:2605.15184] (Grep vs. Vector)**: not a conflict — the grep-vs-vector paper measured **memory backend** variance; WildClawBench measures **full-task** variance across harness choice. - **Open empirical question from item 3 (MemLens)**: does the [arxiv:2605.15184] grep-beats-vector finding extend to multimodal memory? MemLens's "removing evidence images drops to <2%" suggests that storing image *references* in a grep-able filesystem (not text descriptions in a vector index) is the correct write pattern, but there's no direct head-to-head yet. Worth running grep-with-image-refs vs. text-only-vector on MemLens's 789 questions.
- **Open empirical question from item 4 (InsightReplay)**: does insight replay compose with [arxiv:2605.04050] LCM's hierarchical context compression? Mechanistically they should — LCM compresses old context into a summary DAG with lossless pointers, InsightReplay re-promotes critical fragments back near the cursor. No paper has run both together yet.
