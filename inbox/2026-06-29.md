## Items

### 1. Supersede — The Memory-Update Gap Is Not a Storage Problem
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.27472
- **Authors / org:** Vedant Patel
- **Focus area:** Agent memory
- **What it is:** Targeted diagnosis of a single failure mode in long-conversation agents: when a fact *changes* (user moves, price updates, plan revised), can the agent overwrite the prior belief? Patel isolates the knowledge-update subset of LongMemEval and runs a clean A/B: full-context-replay vs bounded self-maintained memory. On a frontier model (gpt-5.4), the bounded condition drops from **92% → 77%** (paired McNemar p<0.005). Scaled to 24× conversation length, accuracy collapses **68% → 28%**. The damning ablation: doubling the memory budget yields **28% → 28%** (n=25) — the policy, not the budget, is the bottleneck. Then a positive result: GRPO on Qwen2.5-3B with a custom supersession environment lifts held-out unseen-conversation supersession from **9.0% → 16.7%** in a single run. Code, env, model, and dataset open-sourced.
- **Why it matters for Justin's agents:** This is the cleanest experimental separation yet between *retention* and *update* in agent memory — and the result aligns with the cluster signal building since [arxiv:2606.14571] StreamMemBench ("bottleneck is use/transfer not storage") and [arxiv:2606.14470] GitOfThoughts ("memory helps only at ≥0.8 cosine similarity, i.e., near-duplicates"). Companion-app pattern: memory writes that *replace* prior beliefs (preferences, addresses, plans) need their own policy, not just an upsert into the same vector index that handles new-fact storage. Two practical moves for Justin's stack today: (a) tag every memory write with `update_targets: [prior_memory_id, ...]` so the retrieval layer can decide whether the new fact *supersedes* or *augments*, and (b) include a small held-out supersession set in any memory eval — most existing memory benchmarks reward recall, not update fidelity, so memory architectures that look great on LoCoMo can be silently catastrophic at managing change.
- **Action signal:** `compare` (extends [arxiv:2606.14571] StreamMemBench + [arxiv:2606.14470] GitOfThoughts; together they map the *use/update* failure mode that storage-focused architectures like [arxiv:2606.11680] HORMA, [arxiv:2606.06036] MRAgent, [arxiv:2606.05894] EMBER do not address)

### 2. Delayed Verification Destabilizes Multi-Agent Belief — and the Threshold Is the Inverse Golden Ratio
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.27409
- **Authors / org:** Igor Itkin
- **Focus area:** Agent orchestration
- **What it is:** Multi-agent LLM systems use verifier/critic agents to catch hallucinations — but verification is *delayed*. During the lag, false claims propagate. Itkin formalizes this as a delayed consensus problem on an agent graph with a small set of "grounded corrector" nodes, then does spectral analysis to extract closed-form stability thresholds. Three sharp results: (a) the *worst* regime is when communication delay equals verification delay; (b) at delay = 2 the critical verifier strength is exactly the **inverse golden ratio (1/φ ≈ 0.618)** — below it, oscillation; above it, convergence; (c) the corrector-placement objective is supermodular, so a greedy algorithm achieves **(1 - 1/e)** of optimal node assignment for a fixed verifier budget. Validated across five open models; the predicted oscillation patterns appear empirically. Final wrinkle: grounded factual answering eliminates the instability entirely — the effect is specific to *signed-belief* tasks (claims that can be true *or* false, not just retrieved-or-not).
- **Why it matters for Justin's agents:** This is the first multi-agent paper with a number you can put on a whiteboard. Concrete production implications: (1) any "agent network → critic → relay → critic" pipeline where verification rounds don't match message rounds is the *exact* regime the paper says is least stable; pin the two delays so they don't coincide. (2) Greedy corrector placement is trivially implementable — if Justin's agent products grow to N>3 cooperating agents (companion + tool subagents + memory writer), the bound says you don't need to optimize, you just need to seed the highest-degree nodes with grounded verifiers first. (3) The grounded-factual-answering escape hatch is the practical out: for tool-use chains where every claim either does or doesn't ground in a function-call return value, this whole class of instability disappears. The takeaway is *not* "add more critics" — it's "put corrector nodes where they break the longest belief-propagation path, and never let verification lag the chatter."
- **Action signal:** `try-now` (greedy placement + delay-pinning are mechanical; companion app's planner-executor architecture is the right test case)

### 3. ATOD — Anneal From SFT to RL, Reweight by Turn-Level Disagreement
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.27814
- **Authors / org:** Qitai Tan, Zefang Zong, Yang Li, Peng Chen
- **Focus area:** Agent training / long-running loops
- **What it is:** Small-LM agents need fast skill imitation (cheap) *and* reward-driven improvement (expensive); the standard "SFT then RL" sequence wastes the SFT phase's signal once RL begins. ATOD anneals: imitation dominates early, RL gradually takes over on the same trajectory budget. Inside each multi-turn rollout, Turn-level Disagreement-Uncertainty Reweighting upweights *high-value turns* — the steps where the teacher and student diverge most, which are the steps where the gradient signal is densest. On ALFWorld / WebShop / Search-QA, **+3.03 pts vs on-policy distillation, +23.62 pts vs GRPO** average success, with three student sizes all surpassing their teachers by **+2.16 pts**.
- **Why it matters for Justin's agents:** The +23.62-pt margin over GRPO is the headline, but the structural insight is the one to internalize: in multi-turn agent rollouts the gradient signal is *not* uniformly distributed across turns — a small number of critical decisions carry most of the success/failure mass. The Turn-level Disagreement-Uncertainty Reweighting recipe is portable to any agent fine-tuning setup where you have a strong teacher and a weak student (precisely the "frontier-model-as-teacher → local-model-as-deployment-runtime" pattern Justin's M5 Max stack uses). Pairs naturally with [arxiv:2606.27009] Semantic Early-Stopping (yesterday's coverage): stop the loop when the embeddings stop moving, *and* train the loop on the turns where the teacher and student disagree most.
- **Action signal:** `track` (training-time recipe; valuable if Justin starts fine-tuning a local 3-8B agent, but not immediately deployable)

### 4. Gemini 3.5 Flash — Computer Use as a Built-In Tool
- **Source:** Google blog (DeepMind / Gemini)
- **Link:** https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-computer-use-gemini-3-5-flash/
- **Authors / org:** Google DeepMind
- **Focus area:** Tools & connectors / computer-use agents
- **What it is:** Computer use is now a *first-party tool* in the Gemini API for Gemini 3.5 Flash — observe a screen, output click/type/navigate actions, run across browser, mobile, and desktop targets in one API surface. Google claims "best performance yet" on OSWorld but doesn't include the number in the post (the ledger pegs Gemini 3.5 Flash at 78.4 OSWorld-Verified as of [arxiv:2606.24515] coverage on Jun 25). Two safeguards land as defaults, not aftermarket: required-confirmation gating on sensitive actions, and **automatic task termination on detected prompt injection**. Available via Gemini API (ai.google.dev), Gemini Enterprise Agent Platform (GCP console), and a Browserbase-hosted demo.
- **Why it matters for Justin's agents:** Two structural changes worth noting independent of the model quality. First: "computer use as a built-in tool" is a different surface than the screenshot+function-call recipe most open CUA stacks (Holo3.1, OpenWebRL, ATOD-trained agents) currently use — it shifts the screenshot-loop *inside* the provider, so latency, retries, and grounding logic become Google's problem. For Justin's companion product, that's the right tradeoff *if* the agent's primary computer-use surface is web (which Browserbase implies); for desktop-native automation (Obsidian, Claude Code) you still want local stacks. Second: the prompt-injection auto-termination is the first commercial CUA to surface this as a marketed default — the threat-model bar just moved for *every* CUA vendor. If Justin's stack runs any agent that fetches+acts (Slack→file, email→shell), this is now the floor of what users will expect to see in a feature-comparison table. Track for benchmark numbers; the post is light on detail. Don't migrate yet — the Holo3.1 Q4 + local-MCP path remains the right local-fit; this is what to use when sovereignty doesn't matter and you want frontier-tier reliability per click.
- **Action signal:** `track` (waiting for published OSWorld number and latency/pricing)

### 5. Internalizing the Future — World-Model Planning as Q-Value-Like Successor-Estimation
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.27483
- **Authors / org:** Xuan Zhang, Zhijian Zhou, Lingfeng Qiao, Yulei Qin, Ke Li, Xing Sun, Xiaoyu Tan, Chao Qu, Yuan Qi
- **Focus area:** Reasoning & inference-time compute / agent training
- **What it is:** LLM agents react more than they plan; the paper trains a single autoregressive model to *predict future states* and *estimate success probability* — a textual analog of Q-values. Critical empirical finding: naive SFT on traces with foresight tokens produces a **format-capability gap** — agents *write* foresight text but it doesn't condition action selection. The fix is a three-stage pipeline: (1) World Model Agentic Mid-Training (WM-AMT) injects the predictive capability into the base policy; (2) Format-Eliciting SFT (FE-SFT) structures how that capability surfaces in outputs; (3) Foresight-Conditioned RL (FC-RL) calibrates and refines it against task rewards. Outperforms training baselines on search and math-reasoning tasks.
- **Why it matters for Justin's agents:** The format-capability gap is the *named, replicable version* of a problem every agent author has hit: the model writes the "thought" but the action is still reactive. The three-stage pipeline argues the answer is not better prompts but staged *capability acquisition first, format last*. Translates to Justin's stack as: when distilling agent behavior from Claude Opus traces to a small local model, the order matters — instill foresight via mid-training on world-model objectives *before* SFT on output format, otherwise the small model learns the surface mimicry and not the underlying state-prediction. Closely related to ATOD (item 3) — both papers are arguing the agent-training community's "SFT then RL" default is leaving structure on the table.
- **Action signal:** `track`

### 6. QueenBee Planner — Communication Topologies Are a Learnable Skill, Not a Fixed Wiring Diagram
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.27492
- **Authors / org:** Congjia Tian, Yuhang Yao, Jiaming Cui
- **Focus area:** Agent orchestration / multi-agent
- **What it is:** Treats inter-agent communication as a *learned* design skill. An outer LLM planner generates **temporal communication DAGs** — who sends what to whom, in which round, who merges, who emits the final answer — and refines them across execution traces using three operations: Preserve, Modify, Avoid. Safeguards against the obvious failure mode of an LLM judging its own design choices: held-out acceptance gates, variance-aware credit, motif-level attribution, transfer trust, insight falsification, structural deduplication. On Count-Frequency aggregation the best learned topology cuts RMSE from **12.53 → 7.87** *and* reduces messages, model calls, and token cost simultaneously (the rare case where the cost-vs-quality frontier moves in one direction across both axes). Similar gains on Silo-Bench-style distributed coordination.
- **Why it matters for Justin's agents:** Most production multi-agent setups (LangGraph DAGs, CrewAI flows, Claude Code subagent dispatch) hardcode their communication topology *once*, at design time. QueenBee says that's leaving meaningful headroom on the table — and unlike most "let-the-LLM-design-the-system" claims, it does the legwork of preventing the planner from declaring itself the winner. For Justin's MCP-and-subagent stack the actionable lift is **motif-level attribution**: when a multi-agent run succeeds or fails, the credit should attach to a *substructure* of the communication graph (which two agents talked, what they exchanged), not to the whole run or to individual agents — that's the granularity at which improvement actually transfers. Plain code, not RL — feasible to lift the pattern without GPU access. Pairs structurally with item 2 (Itkin): QueenBee learns the topology, Itkin tells you where to put the grounded correctors *in* that topology.
- **Action signal:** `track` (motif-level attribution is the immediately portable idea; the full topology search loop is heavier)

### 7. Glite ARF — Deterministic Python Verifiers Beat Prose Rules for Parallel Coding Agents
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.27416
- **Authors / org:** Vassili Philippov, Pavel Katunin, Dmitry Andreev, Igor Ostanin, Anton Nikolaev
- **Focus area:** Coding agents / agent orchestration
- **What it is:** Open-source Python framework for running many LLM coding agents in parallel on a research project while keeping reproducibility. Three-role split: human picks hypotheses, coding agents execute within fixed parameters, deterministic Python verifiers enforce process rules (task isolation, work immutability, no off-task drift). The slogan: "the rules of the research process live in code that fails loudly when violated" — not in prose system prompts that the agent can creatively reinterpret. Real-world deployment: BEA 2026 Vocabulary-Difficulty Task, **1st place (closed track), 2nd place (open track)** across Spanish/German/Mandarin, **+29.9% (closed) / +35.9% (open) RMSE reduction over baseline**, across 273 tasks / 146 runs / 129 feature sets, **~$498 total LLM spend, ~1% framework wall-clock overhead**.
- **Why it matters for Justin's agents:** Two pieces are directly portable to Justin's Claude Code + MCP stack. First: *enforce process rules in code, not in prompts*. Most Claude Code workflows use a CLAUDE.md plus careful prompting to keep an agent on task; this paper says the right pattern is a deterministic verifier (a Python check, a CI-style hook, a Cedar policy eval — equivalent shape) that fails loudly when the agent strays. Second: the deployed-cost shape — $498 total, 1% overhead, 273 tasks — is the realistic numerical envelope for "many parallel coding agents on a single multi-day research goal" right now. That's a useful planning number for any indie shipping coding-agent infra. Pairs with [arxiv:2606.27009] Semantic Early-Stopping (cheap deterministic signal as runtime gating) and [hf-blog-2026-06-23-ibm-cuga] CUGA (declarative guardrails as native primitive); all three are converging on the same prescription: deterministic, code-enforced governance beats prompt-encoded governance.
- **Action signal:** `try-now` (Python framework, MIT-style permissive use implied; mechanical to lift the verifier pattern even if not adopting the whole framework)

## Conflicts & open questions
Cross-referenced against `_meta/claims-ledger.md`:

- **Memory cluster — storage architectures vs. use/update bottleneck:** Supersede ([arxiv:2606.27472]) joins [arxiv:2606.14571] StreamMemBench and [arxiv:2606.14470] GitOfThoughts as a third independent data point that **the bottleneck is what the policy does with memory, not how memory is stored**. The storage-architecture cluster ([arxiv:2606.11680] HORMA, [arxiv:2606.06036] MRAgent, [arxiv:2606.05894] EMBER, [arxiv:2606.03463] DMF, [arxiv:2606.06090] MAGE) does not specifically address supersession; running any of those head-to-head on Patel's LongMemEval-supersession subset would be the cleanest cross-check. Three "bottleneck is policy not storage" papers in 15 days is a pattern.
- **Multi-agent supervisor architectures vs. delayed-verification instability:** Itkin's instability result ([arxiv:2606.27409]) directly tensions the implicit assumption in [deepmind-blog-2026-06-18-ai-control-roadmap] (Securing the Future of AI Agents) that "trusted AI supervisor monitors agent reasoning" is structurally stable. Itkin shows: if the supervisor's verification cadence matches the agents' communication cadence (the natural implementation), you sit at the *worst* point of the stability surface. Open empirical question: does the AI Control Roadmap's million-trajectory empirical refinement implicitly pin the two delays apart? The DeepMind post doesn't say; the Itkin paper would predict oscillation in any deployment that doesn't.

Open question — *foresight-vs-format gap:* [arxiv:2606.27483] Internalizing the Future names a phenomenon ("the model writes the thought but the action is still reactive") that may already be lurking in every CoT-trained agent that "thinks before tool-calling." Does the same gap explain part of the disappointing transfer of [arxiv:2606.14470] GitOfThoughts' worked-example memory? Worth one targeted experiment if Justin builds a long-context agent: ablate the thought-block and check whether action quality moves.
