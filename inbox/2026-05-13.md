# AI Research Digest — Wednesday, May 13, 2026

## TL;DR
- **Memory benchmarks doubled down.** Two new memory evaluations dropped in 24 hours — **MEME** finds all current memory systems collapse to **3% Cascade / 1% Absence accuracy** under dependency-reasoning queries (only Claude Opus 4.7 file-based agent partially recovers, at **~70× cost**), and **LongMemEval-V2** extends LongMemEval to 451 questions over up to **500 trajectories / 115M tokens** with "experienced colleague"-style premise-awareness probes. ## Items

### 1. MEME: Multi-entity & Evolving Memory Evaluation
- **Source:** arXiv (cs.AI, May 12, 2026)
- **Link:** https://arxiv.org/abs/2605.12477
- **Authors / org:** Seokwon Jung, Alexander Rubinstein, Arnas Uselis, Sangdoo Yun, Seong Joon Oh (affiliations not on abstract page; first/last author handles consistent with Tübingen / NAVER AI)
- **Focus area:** Agent memory / Evaluation
- **What it is:** New benchmark for LLM agent memory in persistent multi-entity environments. Six task types, including three the authors argue are unscored elsewhere: **Cascade** (dependency reasoning across linked memories), **Absence** (recognizing missing information), and **Deletion** (state after a memory is removed). 100 controlled episodes × 6 memory systems × 3 paradigms. Headline: **all evaluated systems collapse on dependency reasoning under default configuration** — Cascade 3% / Absence 1% average accuracy. None of prompt tuning, deeper retrieval, noise reduction, or stronger LLMs substantially helps. A **file-based agent on Claude Opus 4.7** partially closes the gap, but at **~70× the baseline cost** — i.e. solvable in principle but not affordable in production today.
- **Why it matters for Justin's agents:** This is the most cleanly named failure mode in agent memory benchmarks since STALE. **Cascade and Absence are exactly the workloads a personal-companion memory layer is supposed to handle**: "remember that Alice's preference depended on Bob's mention" (Cascade); "notice that we never resolved that earlier thread" (Absence); "Charlie was removed from the project, so don't surface their context" (Deletion). The fact that file-based-agent-on-Opus-4.7 is the only thing that works *and costs 70× a baseline* tells you (a) the structure of the answer is right — memory wants to be a file system with an agent, not a vector index; (b) the cost is currently load-bearing, not optional. Worth instrumenting on internal evals immediately even with a small set of synthetic episodes.
- **Action signal:** `try-now` `compare` — directly extends the failure-mode taxonomy that's been growing all month: [arxiv:2605.06527] STALE (implicit conflict), [arxiv:2605.05583] Belief Memory (partial observability), [arxiv:2605.07313] scale-conditioned, [arxiv:2605.07242] MEMOREPAIR (cascade repair), [arxiv:2605.08060] Memory Curse, [arxiv:2605.10870] DeMem (decision-distortion). MEME is the 7th orthogonal axis and the first one specifically targeting *dependency / absence / deletion* — which MEMOREPAIR addresses on the repair side but no benchmark previously measured on the recall side.

### 2. LongMemEval-V2: Evaluating Long-Term Agent Memory Toward Experienced Colleagues
- **Source:** arXiv (cs.AI, May 12, 2026) / HF Daily Papers
- **Link:** https://arxiv.org/abs/2605.12493
- **Authors / org:** Di Wu, Zixiang Ji, Asmi Kawatkar, Bryan Kwan, Jia-Chen Gu, Nanyun Peng, Kai-Wei Chang (UCLA NLP-style author cluster)
- **Focus area:** Agent memory / Evaluation
- **What it is:** Extension of LongMemEval framed around **specialized web environments and "experienced colleague" capability** — five memory abilities (static state recall, dynamic state tracking, workflow knowledge, environment-specific gotchas, premise awareness) tested across **451 manually-curated questions over histories up to 500 trajectories / 115M tokens**. Authors propose two reference memory methods: **AgentRunbook-R** (RAG-based) and **AgentRunbook-C** (coding-agent-based, builds and queries an executable runbook). Headline: AgentRunbook-C **72.5%** average vs. RAG baseline **48.5%** and coding-agent baseline **69.3%**. Coding-agent-with-runbook gets you a ~24 pp jump over RAG, ~3 pp over the unstructured coding agent. Marked Work-in-Progress.
- **Why it matters for Justin's agents:** The "experienced colleague" framing is the right product target for an applied agent — not "answers a question about its memory" but "knows the workflow well enough to skip the steps a new hire would miss." The benchmark explicitly tests *workflow knowledge* and *environment-specific gotchas*, which are the two highest-value memory modes for an MCP-driven internal-tools agent and exactly what RAG-only systems get worst. **115M-token histories at 500 trajectories** is also realistic for a 6-month-old companion app, not a synthetic stress test. AgentRunbook-C's structure (file-based, executable, coding-agent-managed) converges with the MEME finding — the answer to long-term memory is a managed file system, not an embedding index.
- **Action signal:** `try-now` `compare` — pairs with MEME above (both vote for file-based managed memory over vector retrieval). Sharpens [arxiv:2605.06614] SkillOS — SkillOS proposed a Markdown skill repository as memory; AgentRunbook-C is essentially the same idea operationalized as a runbook. Sharpens [arxiv:2605.05242] Direct Corpus Interaction — DCI was about retrieval; AgentRunbook is about persistent constructed knowledge.

### 3. δ-mem: Efficient Online Memory for Large Language Models
- **Source:** arXiv (cs.CL, May 12, 2026) / HF Daily Papers
- **Link:** https://arxiv.org/abs/2605.12357
- **Authors / org:** Jingdi Lei, Di Zhang, Junxian Li, Weida Wang, Kaixuan Fan, Xiang Liu, Qihan Liu, Xiaoteng Ma, Baian Chen, Soujanya Poria (Poria's group, SUTD-style cluster)
- **Focus area:** Agent memory / Context engineering / Local & open models
- **What it is:** A **lightweight memory mechanism that augments a frozen full-attention backbone with a compact online state of associative memory** — no weight modification, no fine-tuning. The state is a fixed-size matrix (the paper headlines **8×8**); the mechanism uses this state to produce **low-rank attention corrections** at generation time. Reported numbers: **1.10×** strongest non-δ-mem baseline on a generic evaluation, **1.31× on MemoryAgentBench**, **1.20× on LoCoMo**. Backbone capabilities preserved.
- **Why it matters for Justin's agents:** Two operationally interesting properties. First, **no backbone retraining** — you keep whatever frozen model you already serve, you add a small state that updates online, and you get memory. Second, **8×8 is tiny** — this is not a "stuff KV cache full of compressed past tokens" approach; it's a learned associative-memory side-channel that lives outside the cache. If the authors release weights/code for a model Justin actually runs (Qwen3 family, Gemma 3, Llama 3.x), this is the cheapest memory-layer integration on the radar — strictly fewer moving parts than mem0/LangMem-class systems. Caveat: the abstract doesn't make clear whether δ-mem itself requires training to produce the state encoder/decoder, or whether it's training-free at inference time. The 1.31×/1.20× claims need independent reproduction against best-tuned RAG.
- **Action signal:** `track` `local-fit` — watch for the weights/code drop. If it's a training-free post-hoc adapter, it's plug-and-play on llama.cpp / MLX once someone wires it in. Mechanistically orthogonal to KV-cache eviction [arxiv:2605.09649] from yesterday — δ-mem compresses *episodic memory*, KV eviction compresses *attention substrate*. Both could compose on the same M5 Max long-context serving setup.

### 4. Continual Harness: Online Adaptation for Self-Improving Foundation Agents
- **Source:** arXiv (cs.AI, May 11, 2026) / HF Daily Papers
- **Link:** https://arxiv.org/abs/2605.09998
- **Authors / org:** Seth Karten, Joel Zhang, Tersoo Upaa Jr, Ruirong Feng, Wenzhe Li, Chengshuai Shi, Chi Jin, Kiran Vodrahalli (Princeton / DeepMind-adjacent author handles)
- **Focus area:** Long-running / autonomous loops / Agent orchestration
- **What it is:** A **reset-free self-improving harness** for embodied / world-model agents — iteratively refines **prompts, sub-agents, skills, and memory** through online interaction, starting from a "minimal environment interface" with no curated knowledge, no hand-crafted tools, no domain scaffolding. Demonstration: a Continual Harness instance called **GPP becomes the first AI system to complete Pokemon Blue, Yellow Legacy on hard mode, and Crystal without a lost battle**. On Pokemon Red and Emerald, the harness "substantially reduces button-press cost" relative to the minimalist baseline and **recovers a majority of the gap to a hand-engineered expert harness**. 28-page paper, 19 figures, 5 tables — suggests serious empirical work.
- **Why it matters for Justin's agents:** Most "self-improving agent" papers are stress-tested in ALFWorld / WebShop / SciWorld, which are bounded multi-step tasks. Pokemon Crystal hard-mode-no-loss is a **long-horizon, partially observable, irrecoverable-mistake** task — closer to "run my background agent on real workflows for a week" than to anything in the standard agent-RL eval suite. Two practical takeaways for Justin: (a) the recipe of **co-evolving prompts + sub-agents + skills + memory** in one harness validates the architecture pattern Claude Code agents informally fall into; (b) "minimal environment interface → expert performance" is the right operating point for autonomous loops that have to bootstrap into a new tool/API surface without a curated runbook. The "reset-free" framing is the long-running-loop word for "doesn't need to be babysat between episodes."
- **Action signal:** `track` `compare` — concrete proof of a self-improving autonomous loop without hand-curated knowledge; the right reference architecture to compare future harnesses against. Relates-to [arxiv:2605.06614] SkillOS (skill curation) and [arxiv:2605.03042] ARIS (autonomous research) — Continual Harness is the *embodied / world-model* leg of the same family. Watch for repo / code release; "first to beat Pokemon X" is the kind of headline that travels and accelerates adoption.

### 5. ToolCUA: Towards Optimal GUI-Tool Path Orchestration for Computer Use Agents
- **Source:** arXiv (cs.AI, May 12, 2026)
- **Link:** https://arxiv.org/abs/2605.12481
- **Authors / org:** Xuhao Hu, Xi Zhang, Haiyang Xu, Kyle Qiao, Jingyi Yang, Xuanjing Huang, Jing Shao, Ming Yan, Jieping Ye (Alibaba / Fudan author cluster)
- **Focus area:** Tools & connectors / Computer use / Coding agents
- **What it is:** Training recipe for **computer use agents that mix GUI actions with tool calls** — the core argument is that pure-GUI agents waste effort doing visually what a single API call would accomplish, and pure-tool agents miss the cases where only the GUI exposes the necessary state. Three stages: (1) **Interleaved GUI-Tool Trajectory Scaling Pipeline** synthesizes mixed-modality trajectories from existing GUI-only and tool-only data; (2) **Tool-Bootstrapped GUI RFT** (SFT + RL warm-up); (3) **Online Agentic RL** with a **Tool-Efficient Path Reward** that explicitly penalizes inefficient sequencing. Headline: **46.85% accuracy on OSWorld-MCP, +66% relative over baseline, +3.9% over GUI-only configurations**. Claimed SOTA at scale.
- **Why it matters for Justin's agents:** This is the production pattern for **Claude-Cowork-style desktop agents + MCP tool servers** — the agent should prefer the API when it exists and fall back to GUI clicks when it doesn't. The Tool-Efficient Path Reward is the explicit training signal that previous "computer-use" papers (Anthropic CUA, OSWorld baselines) didn't have. The 3.9 pp over GUI-only is the **direct measurement of the value of having tools at all** in a desktop agent — modest in absolute terms but the right axis to track as MCP server inventory grows. Caveat: OSWorld-MCP is single-machine; "production" computer use also has to deal with auth, screen sharing, and cross-app state, none of which ToolCUA addresses.
- **Action signal:** `track` `compare` — extends [arxiv:2605.10787] ComplexMCP (which showed top-tier models <60% on 300+ MCP tools) by training specifically for the hybrid action space. Pairs with [arxiv:2605.07112] Switchcraft (route-by-classifier) — ToolCUA does the dispatch inside one model; Switchcraft does it across models. Watch the OSWorld-MCP leaderboard.

### 6. Counterfactual Trace Auditing of LLM Agent Skills
- **Source:** arXiv (cs.AI, May 11, 2026)
- **Link:** https://arxiv.org/abs/2605.11946
- **Authors / org:** Xiaolin Zhou, Jinbo Liu, Li Li, Ryan A. Rossi, Xiyang Hu (Adobe Research / ASU author handles)
- **Focus area:** Evaluation / Agent orchestration / Coding agents
- **What it is:** Framework for **evaluating skills by behavior delta, not pass rate**. Pairs agent traces with-skill vs. without-skill on the same task, segments each trace into goal-directed phases, aligns the phases across pairs, and emits **Skill Influence Pattern (SIP) annotations** describing concrete behavior changes — e.g. *literal template copying*, *off-task artifact creation*, *excess planning*, *task recovery*. Run on **49 Claude SWE tasks**. Headline: **pass rate moves only +0.3 pp on average — but 522 SIP instances appear across the same paired traces**. High-baseline tasks show the most skill effects but are already saturated; mid-baseline tasks show the most *recoverable* improvement but at substantially higher compute cost. Code released.
- **Why it matters for Justin's agents:** This is the missing eval methodology for **SkillOS / Markdown-skill-repo / persistent-skill-runbook** designs. If you've ever added a Claude Code skill and watched the pass-rate needle not move while the agent *clearly* behaves differently, this paper names the four ways that happens (template-copying = bad, off-task artifacts = bad, excess planning = mixed, task recovery = good) and gives you a counterfactual auditing protocol to measure them. **The right question to ask of a new skill is not "did pass rate go up" but "what fraction of SIPs are task-recovery vs. template-copying."** Directly upgrades the eval discipline around any skill-curation system.
- **Action signal:** `try-now` — code-released, immediately wireable into a personal coding-agent eval. `compare` — sharpens [arxiv:2605.06614] SkillOS (which reported aggregate gains) by exposing that aggregate gains hide both helpful and harmful behavior changes. Also a methodological cousin of [arxiv:2605.10448] Evidence-Supported Bounds — both are post-hoc trace-level reporting layers on top of existing benchmarks.

### 7. Rollout Cards: A Reproducibility Standard for Agent Research
- **Source:** arXiv (cs.AI, May 12, 2026)
- **Link:** https://arxiv.org/abs/2605.12131
- **Authors / org:** Charlie Masters, Ziyuan Liu, Stefano V. Albrecht (Edinburgh)
- **Focus area:** Evaluation
- **What it is:** Argues that **rollout records, not reported scores, are the reproducibility unit for agent research**. Introduces a "rollout card" publication bundle that preserves the actual trajectories + the evaluation rules applied to them. Two empirical findings: (1) **audit of 50 popular training and evaluation repositories** — **none report how many runs failed, errored, or were skipped** alongside their headline scores; (2) **37 distinct ways reporting rules alter task-success rate, token accounting, or timing** on identical evidence; re-grading the same rollouts under different rules produces score swings up to **20.9 absolute percentage points** — sometimes flipping model rankings. Released rollout-card exports across tool use, SWE, web, multi-agent, safety, and search; reference implementation integrated into Ergon (open-source RL gym).
- **Why it matters for Justin's agents:** **Agent benchmark numbers without rollout-level evidence are now untrustworthy by default.** The Edinburgh team's finding that **no popular repo reports failure/skip counts** means almost every leaderboard number Justin reads is over-stating real performance by an unknown amount, and the 20.9-pp swing from reporting-rule alone means cross-paper comparisons need to normalize the reporting rule before any claim can be made. Practical move: when evaluating a new model or harness internally, treat the *trajectory store* as the artifact, not the success rate; require failure / error / skip counts in any internal report. Also: any time a vendor reports a number on a public benchmark without a rollout export, halve the number in your head.
- **Action signal:** `try-now` `compare` — third leg with [arxiv:2605.10448] Evidence-Supported Bounds (yesterday — outcome-evidence labeling on top of existing benchmarks) and [arxiv:2605.04624] AuditRepairBench (rank instability under evaluator reconfiguration). Three independent reproducibility-side papers in a week converging on the same conclusion: **the agent-benchmark layer needs rebuilding**, and the right move is to ship traces + rules, not aggregate scores.

### 8. Intermediate Artifacts as First-Class Citizens: A Data Model for Durable Intermediate Artifacts in Agentic Systems
- **Source:** arXiv (cs.AI / cs.MA, May 12, 2026)
- **Link:** https://arxiv.org/abs/2605.12087
- **Authors / org:** Josh Rosen and Seth Rosen
- **Focus area:** Agent orchestration / Long-running loops / Tools & connectors
- **What it is:** Position-with-data-model paper arguing that agent systems should **persist intermediate work products as typed, structured, addressable, versioned, dependency-aware, authoritative artifacts** rather than throwing them away after each step. Distinguishes intermediate artifacts from chat transcripts, "memory," hidden reasoning state, and narration — those are *records of* work; artifacts *are* work. Proposes a systems-level data model with explicit update semantics and lineage tracking. **Stated thesis:** "The claim is not that artifacts make models smarter. It is that durable intermediate artifacts make AI-generated work more inspectable, revisable, and maintainable over time." 18 pages, 1 figure, 3 tables.
- **Why it matters for Justin's agents:** This is the **product-level abstraction** behind two trends Justin has been tracking: (a) Shepherd's typed-event execution trace ([arxiv:2605.10913], May 11) — Shepherd makes *the trace* a first-class data structure, this paper makes *the side-effects of the trace* (drafts, plans, files, partial solutions) first-class; (b) the "managed file system as memory" pattern that MEME, LongMemEval-V2, and SkillOS all converge on. For a companion-app or coding-agent product, the practical translation is: **don't store the chat log as the source of truth**; store typed artifacts (this draft, this plan, this skill, this scratchpad) with versions and lineage, and let the chat reference them by ID. That's the abstraction that lets a long-running agent be inspected, edited, and resumed — which is the thing that makes background autonomy actually shippable.
- **Action signal:** `track` — position paper, no code released. Practically useful as design framing right now. `compare` — converges with [arxiv:2605.10913] Shepherd (trace as data structure) and [arxiv:2605.06614] SkillOS (Markdown SkillRepo as durable artifact) — three independent designs landing on "the agent's external state needs to be a typed, addressable, versioned data structure, not a log."

## Conflicts & open questions
Cross-referenced against `_meta/claims-ledger.md`:
- **MEME vs. existing memory papers — no direct contradiction, but a sharp empirical floor.** MEME's 3% Cascade / 1% Absence result is the **first quantitative baseline** showing that *every* current memory paradigm — including the explicitly-cascade-aware Belief Memory [arxiv:2605.05583] and MEMOREPAIR [arxiv:2605.07242] — collapses on dependency reasoning under default config. Open empirical question: **do Belief Memory and MEMOREPAIR move the MEME numbers when actually evaluated on it?** The authors did not test those systems per the abstract. This is the missing experiment that would either confirm or refute the implicit promise of those two papers.
- **Counterfactual Trace Auditing vs. SkillOS aggregate gains.** [arxiv:2605.06614] SkillOS reported aggregate gains across multi-turn agentic and single-turn reasoning tasks. Counterfactual Trace Auditing finds that on Claude SWE tasks, skills move pass rate only +0.3 pp aggregate while producing 522 distinct behavior changes — meaning aggregate gains can hide both task-recovery (good) and template-copying / off-task-artifact (bad) effects in roughly comparable measure. **Not a contradiction — a refinement.** Open question: re-evaluate SkillOS under Counterfactual Trace Auditing protocol to see which SIPs dominate.
- **MEME / LongMemEval-V2 file-based-agent finding converges with AgentRunbook-C, SkillOS Markdown repo, and Intermediate Artifacts data model.** Four independent papers in three days argue the persistent agent-state layer should be a managed *typed file system*, not a vector index or chat-log replay. No conflict — strong convergence; the field appears to be settling on this design point.
