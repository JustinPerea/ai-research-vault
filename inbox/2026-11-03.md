## TL;DR
- **Memory is delivered, not used** (2611.01718): on 8,000 SWE-bench Verified episodes, three memory systems move resolve rate <0.4 pts; most deliveries irrelevant or restating visible context. Pair with 2611.03289: top-k retrieval logs cannot identify any memory's value.
- **Keep tool records out of the context** (2611.00442): typed side-channel delivery 92.3% vs 45.7% correct turns; in-context synthesis collapses past ~74 rows and costs ~200x per correct answer beyond 100.
- **App-scoped memory for vague phone tasks** (2611.00191): MemU-Bench: best model 16.4% SPL without history; AppMem lifts GPT-5.5 from 15.7% to 66.9%.
- **Memory is an injection channel** (2611.01700): cross-session injections persist after the attack content is removed and steer decisions with no visible anomalies.
- **Compaction keeps the rule but not compliance** (2611.03223): most post-compaction violations occur with the rule still in context; compacted runs violate >2x full-history runs.
- **Write skill descriptions contrastively** (2611.00544): Skill++ at 731 skills: all-required-skills selected 76.3% vs 36.4%; transfers to Codex CLI. Zep (2611.01386) ships verified-trace skill compilation over MCP: +4.5-18.8 pts.
- **MCP poisoning is a model problem today** (2611.03555): 22.9% ASR over 9,720 real-execution cells; frameworks all ~23-26% with no defense; Claude Opus 4.8 8/530. Tool updates (2611.01976) bypass in-context defenses at 97.6%.
- **Exit 0 is not success** (2611.01930): 7 of 8 harnesses close stdin; 11.5% of tested CLI calls exit 0 without acting; RECEIPT cuts false success claims 73.5%.
- **Hard guards for exact limits** (2611.01043): code guard executed 0 unauthorized actions vs up to 269/470 for models alone; LeanGuard (2611.02332) blocks every forbidden call on Tau-Bench with Qwen 0.8B-27B.
- **Try to refute writes before executing** (2611.02950): BlackSwan +14.9/+25.2 pts on AppWorld, +12.7 on WebShop.
- **Parallel coding agents collide** (2611.00314): contradictory tasks: Claude Code + Opus 4.8 drops 62% to 16%; a chat channel barely helps. Boundary Contracts (2611.01265) double acceptable patches 9 to 18 of 40.
- **Self-evolved harnesses forget** (2611.03219): Meta-Harness SWE-Bench 94.0% to 32.0% after evolving on FeatureBench.

### 1. Who Schedules Agent Memory? A Sidecar Approach to Long-Horizon Tasks
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.00779
- **Authors/org:** Zhuang, Qijia, Liu, Rui, Ren, Yuxiang
- **Focus area:** memory scheduling decoupled from the main agent loop
- **What it is:** MemSidecar splits memory scheduling from execution. Hooks push bound memory to the main agent when execution events match predefined conditions; Foresight runs an independent agent that predicts likely queries, retrieves in parallel and caches results. 41.23% (Hooks) and 44.34% (Foresight) on MCP-Persona with lower cost and latency.
- **Why it matters for Justin's agents:** Hook-triggered memory delivery maps onto Claude Code-style hooks: the main agent should not have to stop and decide to look things up.
- **Action signal:** `compare`

### 2. Pulse: Long-Horizon Tasks Need Streaming Personalization
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.00988
- **Authors/org:** Zhuang, Qijia, Liang, Jialiang, Ren, Yuxiang
- **Focus area:** streaming personalization during long tasks
- **What it is:** Pulse runs a lightweight memory agent beside execution that watches for emerging personalization needs and preference conflicts and intervenes from user and project memories; RL learns when and how to intervene. 71.9% on pi-Bench and 46.4% on MCP-Persona, best among compared methods.
- **Why it matters for Justin's agents:** Preferences retrieved only from the first request get missed mid-task; a day-admin agent needs a watcher that re-applies them as the plan unfolds.
- **Action signal:** `compare`

### 3. Delivered, Not Used: Evaluating Agent Memory at Its Point of Use
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.01718
- **Authors/org:** Xu, Changran, Li, Zeju, Xu, Qiang
- **Focus area:** evaluating memory at the point of use
- **What it is:** MemUse audits each memory delivery in recorded trajectories against what the agent could already see, then follows later actions. On 8,000 SWE-bench Verified episodes from three memory systems, resolve rates stay within 0.4 pts of no memory, yet most delivered entries were irrelevant, most relevant ones went unused, and in two systems most restated visible content. 23.2% of episodes with beneficial use still failed.
- **Why it matters for Justin's agents:** Outcome scores hide whether memory did anything. Log deliveries and check use before tuning a memory layer.
- **Action signal:** `try-now`

### 4. Memorix: Managing Memory Selections for AI Agents
- **Source:** arXiv (cross)
- **Link:** https://arxiv.org/abs/2611.00060
- **Authors/org:** Zhang, Jing, Song, Xiaguannan, Du, Dong, Feng, Erhu et al.
- **Focus area:** precomputed, versioned project memory for agents
- **What it is:** Memorix computes what an agent should read once per project: an immutable versioned Store, a View separating selection from composition, and Quests/Profiles that keep the view fresh. On SWE-ContextBench and LibEvolutionEval: up to 1.5x resolved rate, correct library version on every version-conditioned task, up to 100x lower amortized cost and 38x faster builds.
- **Why it matters for Justin's agents:** A reproducible, pinned context bundle per project beats per-task splicing of files, and makes failures replayable.
- **Action signal:** `compare`

### 5. Top-$k$ Retrieval Leaves Memory Value Undetermined
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.03289
- **Authors/org:** Behnam, Arman
- **Focus area:** what retrieval logs can and cannot tell about memory value
- **What it is:** Proves top-k retrieval leaves every memory's value undetermined from its retrieval log no matter how many episodes; on 14 memory benchmarks no value was determined in any of 55 configurations. LEDGER estimates only determined Shapley values with confidence intervals, merges identical-history memories and retrieves to make future logs informative: determined fraction 0.001 to 0.797 on pooled HotpotQA, -2.6 acc there, +2.7 on LoCoMo.
- **Why it matters for Justin's agents:** Do not prune or rank memories by usage-success heuristics from top-k logs; they carry no identifiable signal.
- **Action signal:** `track`

### 6. MemShift: Separating Detection from Repair in LLM-Derived Personal Memory
- **Source:** arXiv (cross)
- **Link:** https://arxiv.org/abs/2611.02338
- **Authors/org:** Xu, Zichuan, Zhang, Haochen, Dong, Yuyang, Onizuka, Makoto et al.
- **Focus area:** detecting vs repairing stale derived personal memory
- **What it is:** MemShift benchmarks five shifts (source revision, deletion, redefinition, writer switch, export) in derived personal-memory values, scoring detection and repair separately with a deterministic scorer. On four open-weight LLMs, detection only helps as much as repair allows; LLM-written programs over typed records close most of the gap to exact recomputation.
- **Why it matters for Justin's agents:** Values like 'important contacts' should be recomputed by code over typed records, not re-derived in free text by the model.
- **Action signal:** `compare`

### 7. Chain on Demand: Deferred Evidence Organization for Long-Term Conversational Memory
- **Source:** arXiv (cross)
- **Link:** https://arxiv.org/abs/2611.02480
- **Authors/org:** Lu, Di, Li, Zechen, Xue, Hao
- **Focus area:** query-time evidence organization for conversational memory
- **What it is:** Chain on Demand keeps the raw turn-level memory unchanged and, per query, builds a temporary evidence chain from anchors chosen for relevance, diversity and new term coverage, then restores each anchor's same-session neighborhood. 82.2% on 1,540 non-adversarial LoCoMo questions (76.3% on all 1,986) and 86.6% on LongMemEval-S.
- **Why it matters for Justin's agents:** Store raw turns and organize at read time instead of committing to write-time summaries that may drop what a future query needs.
- **Action signal:** `compare`

### 8. Scalaris: A Scalable Enterprise Memory Architecture for Conversational AI Assistants

### 9. MemU-Bench: Benchmarking GUI Agents on Long-Horizon User Interactions

- **Link:** https://arxiv.org/abs/2611.00191
- **Authors/org:** Liu, Yizhou, Lu, Zhengxi, Tang, Fei, Qiu, Yiwen et al.

### 10. MemHarmBench: Evaluating Cross-Session Prompt Injection in Memory-Persistent AI Agents
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.01700
- **Authors/org:** Wang, Zhihua, Feng, Yunhao, Gao, Yifeng, Pan, Rui et al.
- **Focus area:** cross-session prompt injection via persistent memory
- **What it is:** MemHarmBench plants malicious instructions, checks they persist in memory, removes the attack content and runs a new legitimate session. Victims split into users, workspace owners and external stakeholders. Released on GitHub.
- **Why it matters for Justin's agents:** Anything written to long-term memory from untrusted content is a delayed injection channel; memory writes need provenance and review.

### 12. Do Agents Still Follow the Rules? Benchmarking Rule Compliance under Agent Context Compaction

### 13. Fidelity Collapses with Table Size, Not Turn Count: Delivery Architecture in a Deployed Tool-Using Agent
- **Source:** arXiv (cross)
- **Link:** https://arxiv.org/abs/2611.00442
- **Authors/org:** Hoang, Tung Thanh
- **Focus area:** tool result delivery architecture and data fidelity
- **What it is:** In a production award-travel agent, keeping records in session state and delivering rows via a typed side channel (BYPASS) scored 92.3% fully correct turns vs 45.7% for feeding full records through context (paired +46.6 pp). In-context synthesis collapses past ~74 rows; thresholds range from under 10 rows (GPT-4o-mini) to ~198 (Gemini 2.5 Pro). Beyond 100 rows each correct in-context answer costs ~200x.

### 14. Skill++: Towards Lifelong Agents via Routing-Aware Skill Refinement
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.00544
- **Authors/org:** Zhang, Hanrong, Liang, Minghao, Wu, Jiawei, Chen, Yankai et al.
- **Focus area:** routing interference in growing skill libraries
- **What it is:** As similar skills are added, a router choosing by name+description can lose earlier skills. Skill++ rewrites only each new skill's name and description to state what it supports, how it differs from its nearest predecessor and what it excludes. With 731 skills over ten sessions, all required skills selected for 76.3% of queries vs 36.4%; gains carry to the Codex CLI harness.
- **Why it matters for Justin's agents:** Skill descriptions are routing keys. Write them contrastively against neighbors as the library grows.

### 27. RECEIPT: Measuring and Repairing the Return Assumption of LLM Agents in Web Service Operations
- **Source:** arXiv (cross)
- **Link:** https://arxiv.org/abs/2611.01930
- **Authors/org:** Yang, Boyang, Yang, Ziyao, Zhang, Yu, Chai, Duo et al.

- **What it is:** Measures the 'return assumption': 7 of 8 harnesses close stdin when no terminal is attached, causing 11.5% of tested CLI invocations to exit 0 without acting; an unanswered prompt multiplies token use by 2.9. ### 29. CAREFUL-Bench: Effect-Aware, Judge-Free Evaluation of Multi-Turn LLM Function Calling

### 30. LEANGUARD: Lean-Verified Guardrails for Tool-Using Agents

### 32. Dependence-Aware Risk Assessment and Optimal Design of AI-Agent Safeguard Systems
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.00386
- **Authors/org:** Li, Yijia, Xu, Maochao, Zhao, Peng

## Conflicts & open questions

- **Memory value is hard to see.** MemUse (2611.01718) finds memory barely moves SWE outcomes and mostly goes unused, and LEDGER (2611.03289) proves top-k logs cannot identify memory value, while Scalaris (2611.02612), Chain on Demand (2611.02480), AppMem (2611.00191) and Pulse (2611.00988) report large benchmark gains. Gains look real on recall-shaped tasks; use-level audits are still missing for most systems. Continues the Nov 4 'recall is not use' thread.
- **Write-time vs read-time organization.** Chain on Demand defers organization to query time; Memorix (2611.00060) precomputes per-project views ahead of time. Both reject per-task ad hoc splicing; they disagree on when to commit structure.
- **Self-improving harnesses.** Exo (2611.00463) and ParetoSaddler (2611.02079) report cost/quality gains, but continual evolution forgets earlier task types (2611.03219). Regression gates look mandatory.
- **Advisory metadata does not protect.** CAREFUL-Bench (2611.02978) finds MCP-style effect hints ignored; MCP poisoning (2611.03555) finds frameworks add no defense. Enforcement belongs in deterministic gates (2611.01043, 2611.02332).
