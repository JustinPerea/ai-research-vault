## Items

### 1. StateM: 95.3% Terminal-Bench 2.1 via Harness Scaling
- **Source:** arXiv (Hugging Face Daily Papers)
- **Link:** https://arxiv.org/abs/2608.15089
- **Authors / org:** Ziheng Qin / Yaxin Lu / Zhangyang Atlas Wang / Kai Wang
- **Focus area:** Long-horizon harnesses + Terminal-Bench
- **What it is:** Bets that long-horizon failures (lost mutable state, unrecalled lessons, skipped procedures, premature stop) are execution-system bugs, not weight bugs. StateM organizes a run around durable states, phase-local context, checked transitions, recoverable runbooks, and versioned procedural practices. Terminal-Bench 2.1: GPT-5.5 xhigh **92.1%** vs **83.1%** reference (GPT-5.6 Sol Ultra 91.9% as a published peer). Runbook transfers unchanged to GPT-5.6. GPT-5.6 Sol xhigh + StateM: **95.3% raw** over 445 trials, **all 89 tasks succeeded at least once**. Frozen profile: GPT-5.6 Luna **76.7 → 85.4**, above the **84.9%** Sol xhigh reference. Same runtime + runbook + golden rules: **<$38** adaptation lifts DeepSeek-V4 Flash **82.7 → 88.1** (standard timeouts) and **89.1** on an 88-task common core; final-score API usage **~$15** vs **$574.68** GPT reference; total DeepSeek **$52.22**. BusinessBench: family-specific runbooks +0.55 macro / +1.34 micro; two mechanism-matched families **+10.04**. Submitted Aug 15; HF Daily Aug 18; abs verified this run.
- **Why it matters for Justin's agents:** This is the sharpest "harness > backbone" measurement since StateAct (2026-07-28) and it lands on Terminal-Bench 2.1, the vault's coding-agent yardstick. Three portable pieces: (1) **phase-local context** — do not carry the whole trajectory into every tool turn, (2) **checked transitions** — a state change has a predicate, (3) **runbooks that transfer across models** (5.5 → 5.6 unchanged; Luna frozen profile beats the Sol reference). The $15-vs-$575 line is the reason to try this on DeepSeek-V4 Flash / local 30B-A3B *before* buying more Opus. Compare, do not merge, with later PILOT [arxiv:2608.26530] live-steer — StateM is stateful runbooks, PILOT is a mid-run supervisor channel.
- **Action signal:** `try-now` — steal phase-local context + a 1-page recoverable runbook for the Mitamaton / Claude Code daily loop; `compare` against PILOT once you have a 10-task Terminal-Bench-like set.

### 2. UI-Mate: Open-Weight Foundation GUI Agents with In-Context Demonstrations
- **Source:** arXiv (Hugging Face Daily Papers)
- **Link:** https://arxiv.org/abs/2608.15930
- **Authors / org:** Zihan Ding / Longxu Dou / Qi Gao / Xiangwu Guo / Shengchao Hu / Zilong Huang / Zihang Jiang / Lei Ke (plus UI-Mate team)
- **Focus area:** Computer use + open-weight agents
- **What it is:** Foundation GUI agent combining a closed-loop environment-grounded training stack (task gen → env → rollout → filter → SFT → online RL) with **in-context demonstration learning** that turns multimodal demos into subtask workflows and re-plans from the live UI. New bench OSWorkerBench: 100 long-horizon office tasks / 41 apps, instruction-only and demo-guided (33-task self-demo from strong-agent rollouts, 45-task variant-demo from related human recordings). UI-Mate-27B: **77.0% OSWorld-Verified**, **66.2% WindowsAgentArena** (open-weight SOTA per authors). OSWorkerBench **41.0% strict / 76.9% progress**, **+17.7 / +24.5** vs Qwen3.6-27B base. 33-task self-demo: one demonstration lifts strict **17.2 → 35.4** and progress **67.9 → 81.1**. Submitted Aug 16; abs verified this run.
- **Why it matters for Justin's agents:** Two uses. (1) **Open-weight computer-use ceiling** — 77% OSWorld-Verified at 27B is a local-or-cheap-host candidate for the GUI fallback StateAct [arxiv:2607.22798] said should be rare. (2) **One demonstration nearly doubles strict success** on long-horizon office tasks — Mitamaton should accept a screen recording / click trace as a skill, not only a paragraph of instructions. 27B dense is tight on 64 GB at high context; Q4/Q5 is the experiment, not BF16.
- **Action signal:** `compare` — UI-Mate-27B vs Gemini 3.5/3.7 Flash computer-use vs Claude-in-Chrome on a 10-task personal GUI set; try the one-demo skill format even if you never host the 27B.

### 3. Agentic Transaction: Towards ACID-Compliant Agent Systems
- **Source:** arXiv (Hugging Face Daily Papers)
- **Link:** https://arxiv.org/abs/2608.13900
- **Authors / org:** Zhaoyan Sun / Xiaoxiao Wang / Guoliang Li
- **Focus area:** Long-running loops + reliability / state
- **What it is:** Reinterprets ACID for agents: Semantic Atomicity, Consistency, Isolation, Durability. Instantiated as an ACID-compliant data agent — transactional explore-execute-validate cycles, transactional skill hubs, confidence-divergence validation, semantic-dependency isolation, transaction-aware semantic state. Authors report **+10.6%** over SOTA agents **including Claude Code** on "widely used benchmarks" (names not in the abs). Submitted Aug 14; abs verified this run.
- **Why it matters for Justin's agents:** Keep the vocabulary, discount the +10.6% until the bench list is public. Semantic atomicity ("the whole day-admin act commits or it doesn't") and isolation ("two Mitamaton tools don't clobber the same calendar event") are the right names for bugs Justin will actually hit. Pair with Aug 13's runtime contract (evidential commit) — ACID says *what* a commit is; the runtime contract says *who is allowed to commit*.
- **Action signal:** `track` until the benchmark table is on the abs/PDF; reuse the four semantic guarantees as a design checklist now.
