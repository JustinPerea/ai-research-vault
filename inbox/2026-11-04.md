- **Measure memory by task utility, not importance** (2611.03930): answer-bearing memories +0.33 paired reward over controls; task-blind summaries and structured records gain less than Raw; no effect on the SWE/sci-coding tasks tested.

### 1. What Is This Memory Useful For? Measuring Task-Conditioned Utility in Long-Term Agent Memory
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.03930
- **Authors/org:** Chih-Hsuan Yang, Anjir Ahmed Chowdhury, Feng Yan, Rajeev Thakur
- **Focus area:** task-conditioned utility of long-term agent memories
- **What it is:** Task-blind writer stores a memory; a frozen reader answers a later task with and without it under identical filler, with a cost ledger. On LongMemEval-V2 web-agent recall tasks, answer-bearing memories beat matched controls by +0.33 mean paired reward; task-blind summaries and structured records gain less than Raw even at fixed context; generic retrieval misses most answer-bearing memories; no measurable effect on the SWE and scientific-coding benchmarks tested. Public Conditional Memory Utility Dataset.
- **Why it matters for Justin's agents:** Score memory compression by the task utility it preserves plus its cost, not by an importance score. Summarizing before storing can throw away the answer-bearing bits.
- **Action signal:** `compare`

### 2. WASP-Mem: Let Agent Organize Procedural Memory. Human Spend Effort on Diagnosis
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.04003
- **Authors/org:** Peizhi Niu, Ge Shi, Vaibhav Gorde, Sarthak Ghosh et al.
- **Focus area:** agent-synthesized procedural memory as a wiki
- **What it is:** WASP-Mem distills execution traces and feedback into persistent, interlinked wiki pages. On TheAgentCompany: +4.6-6.1% checkpoint pass rate over the strongest baseline across three models with 57-61% less storage. Human-defined schemas and dedup rules hurt; one round of human diagnosis beats four rounds of self-judgment by 7.0-10.9%.
- **Why it matters for Justin's agents:** Let the agent organize its own procedure notes and spend human time labeling why failed runs failed. That maps directly onto skill/notes files in a Claude Code-style harness.
- **Action signal:** `try-now`

### 4. One Assistant, Many Memories: Benchmarking Real-World Group Assistance When Recall Is Not Enough
- **Source:** arXiv (cross)
- **Link:** https://arxiv.org/abs/2611.04867
- **Authors/org:** Zhanghao Hu, Linhai Zhang, Qian Zhao, Qi Zhu et al.
- **Focus area:** group-chat memory benchmark from a deployed assistant
- **What it is:** GroupAssistBench: 80,299 real messages in 50 groups (cost >$53K), testing recall (L1) and use for open-ended service requests (L2) over single, distributed and conflicting memories. The best memory system rivals full context on recall but falls far behind on use. Relating retrieved memories and binding remembered facts as response constraints both help.
- **Why it matters for Justin's agents:** Recall scores overstate memory quality. Evaluate whether remembered facts actually constrain the response, especially when several people's facts conflict.
- **Action signal:** `compare`

### 7. You don't need long context
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.05306
- **Authors/org:** Peter Belcak, Saurav Muralidharan, Jindong Jiang, Yonggan Fu et al.
- **Focus area:** frequent compaction instead of long context
- **What it is:** Later tokens cost more (up to 7x on frontier open-weight models). With frequent compaction, frontier models lose little to no accuracy on long-horizon and long-input tasks; SWE performance does not collapse even at one action per context. Proposes semantic state space models (SSSMs).
- **Why it matters for Justin's agents:** Supports aggressive compaction in agent loops and on local models where long context is costly.
- **Action signal:** `try-now`

### 8. Why Pay for Long Reasoning When Rewrite Do Trick? Causal Effects of Reasoning History Compaction on Future Generation and Agent Cost
- **Source:** arXiv (cross)
- **Link:** https://arxiv.org/abs/2611.03852
- **Authors/org:** Anton Hristov
- **Focus area:** rewriting reasoning history to cut future tokens
- **What it is:** Rewrites prior reasoning into compact state records before pending tool results are revealed, then compares continuations. On the open-weight models tested, accepted compact histories usually shorten later reasoning; in software-agent runs compaction can reduce total spend, but quality and rewrite-inclusive time depend on target and compressor.
- **Why it matters for Justin's agents:** Compacting the agent's own earlier thoughts, not only tool output, is a cheap cost lever, but it needs per-model evaluation.
- **Action signal:** `compare`

### 9. Length Is Cheap, Competition Is Not: Attention Predicts Context Rot in Retrieval
- **Source:** arXiv (cross)
- **Link:** https://arxiv.org/abs/2611.04169
- **Authors/org:** Yinuo Liu
- **Focus area:** context rot as attention competition
- **What it is:** On five open 0.5B-3B models, neutral filler costs nothing up to 32K tokens (0.97-1.00), but evidence-formatted distractors drop accuracy to 0.16-0.33, and one rival value for the queried key multiplies loss 9-110x. Attention mass left on the evidence explains up to 58% of loss variance vs at most 8% for log length. Probe and 126K trials released.
- **Why it matters for Justin's agents:** For context assembly, the danger is similar-looking stale facts (old memory versions, near-duplicate records), not sheer length. Dedupe and supersede before injecting.
- **Action signal:** `try-now`

### 10. The Agent Board: Kanban for Machines; Durable Coordination for Agents That Outlive the Conversation
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.04100

### 23. Voluntary Servitude: Weaponized Safety Warning Mechanisms for Controlling AI Agents

### 34. Silent Instrument Errors Reorder Agent Leaderboards
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.04399
- **Authors/org:** Yangze Liu (Shandong University)
- **Focus area:** silent grader/logging errors in agent leaderboards

## Conflicts & open questions

Compaction looks safe for the working loop; compressing stored memories is where answer-bearing detail disappears. Measure both per task.
