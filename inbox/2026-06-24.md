## Items

### 1. Are We Ready For An Agent-Native Memory System?
- **Source:** arXiv / HF Daily Papers
- **Link:** https://arxiv.org/abs/2606.24775
- **Authors / org:** Wei Zhou, Xuanhe Zhou, Shaokun Han, Hongming Xu, Guoliang Li, Zhiyu Li, Feiyu Xiong, Fan Wu
- **Focus area:** Agent memory / evaluation
- **What it is:** Systematic data-management-style evaluation of 12 representative memory systems plus 2 baselines across 5 workloads / 11 datasets. Decomposes agent memory into four modules: representation+storage, extraction, retrieval+routing, maintenance. Headline finding: *no single architecture dominates across all scenarios* — effectiveness depends on alignment between memory structure and workload bottleneck. Localized maintenance > global reorganization on cost-performance curves. Code at https://github.com/OpenDataBox/MemoryData.
- **Why it matters for Justin's agents:** This is the right field-survey to anchor any companion-app memory architecture decision on. Treats memory as a data system, not a single design pattern, and gives the four-module decomposition language to talk about which knob is being turned. The "no dominant architecture" finding is the polite version of "stop picking systems by GitHub stars — pick by workload bottleneck."
- **Action signal:** `try-now` — clone the benchmark to A/B mem0/LangMem against EvoEmbedding-style RAG on Justin's actual companion-app workload shape. Saves weeks of comparison work.

### 2. Governed Shared Memory for Multi-Agent LLM Systems (MemClaw + ArgusFleet)
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.24535
- **Authors / org:** Yanki Margalit, Nurit Cohen-Inger, Erni Avram, Ran Taig, Oded Margalit (Ben-Gurion University + IBM Research, inferred)
- **Focus area:** Agent memory / agent orchestration
- **What it is:** Formalizes the **fleet-memory problem** with four failure modes (unauthorized leakage, stale propagation, contradiction persistence, provenance collapse) and four counter-primitives (scoped retrieval, temporal supersession, provenance tracking, policy-governed propagation). Implemented as **MemClaw**, a *production* multi-tenant memory service; evaluated via **ArgusFleet** harness. Reports 100% reconstruction of depth-4 derivation chains, zero cross-fleet leakage, sub-second per-hop provenance latency. Most useful contribution: two real architectural failures found in production — sub-tenant scope bypass on direct GET-by-id (disclosed + remediated), and a pipeline-ordering conflict where a synchronous near-duplicate gate rejects contradictory writes before the async contradiction detector sees them.
- **Why it matters for Justin's agents:** Direct successor to last week's GateMem (arxiv:2606.18829) — same problem space, but written *from* a production deployment rather than from theory. The two disclosed failure modes are exactly the kind of subtle bug that takes down a federal-data-engineering pipeline: scope-bypass and async/sync ordering. The four primitives are the right language for the agent-memory access-control story in any system Justin ships.
- **Action signal:** `compare` — extends and partially supersedes GateMem (arxiv:2606.18829). The thesis "long-context retrieval alone is insufficient for production multi-agent memory" directly contradicts EvoEmbedding's "naive RAG with the right embeddings beats agentic memory" (arxiv:2606.21649, June 22). Both can be right if EvoEmbedding solves the representation layer and MemClaw solves the governance layer — but the rhetoric clashes head-on.

### 3. ReM-MoA: Reasoning Memory Sustains Mixture-of-Agents Scaling
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.24437
- **Authors / org:** Heng Ping, Arijit Bhattacharjee, Peiyu Zhang, Shixuan Li, Wei Yang, Ali Jannesari, Nesreen Ahmed, Paul Bogdan
- **Focus area:** Agent orchestration / agent memory / reasoning
- **What it is:** Mixture-of-Agents (layered multi-LLM inference) consistently degrades, plateaus, or saturates with depth in prior variants. ReM-MoA adds two pieces: a **Ranked Reasoning Memory** that persistently stores+ranks reasoning traces from all layers (a Reviewer Agent does the comparative ranking), and **Curated Diversified Memory Routing** that exposes each agent to distinct mixes of successful + failed traces to preserve exploration diversity. Optional multi-domain Reviewer-distillation pipeline pulls supervision from frontier models. Five reasoning benchmarks (math, formal logic, code, knowledge, commonsense); ReM-MoA "outperforms prior MoA variants across both depth and width scaling, and its advantage widens with depth."
- **Why it matters for Justin's agents:** This is the missing piece for any subagent-fan-out pattern. Justin's Claude Code workflows already burn tokens on layered planner→executor→reviewer chains, and the depth-degradation curve is the exact reason most fan-outs cap at 2 layers. The "expose each agent to different success+failure trace mixes" routing rule is small enough to retrofit into a custom orchestration harness without weight changes.
- **Action signal:** `track` — paper claims qualitative depth advantage but the linked abstract doesn't give per-benchmark numbers; revisit when code or full PDF lands. The mechanism is reusable as a pattern in MCP orchestration even before the reference impl ships.

### 4. MEMPROBE: Probing Long-Term Agent Memory via Hidden User-State Recovery
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.24595
- **Authors / org:** Enze Ma, Yufan Zhou, Wei-Chieh Huang, Jie Yang, Huanhuan Ma, Zixuan Wang, Chengze Li, Chunyu Miao, Philip S. Yu, Zhen Wang
- **Focus area:** Agent memory / evaluation
- **What it is:** Evaluates long-term memory as **a post-interaction artifact**, not via downstream task success. Each simulated user has a hidden, taxonomy-anchored "user-state bank"; the agent assists across a trajectory of leak-controlled tasks; then the bank is reconstructed from the agent's resulting memory under full-store and top-k access. 50 simulated users × 31 hidden dimensions = 1,550 recovery targets. 5 memory systems tested. Key finding: **task completion nearly saturates (even for a memoryless baseline) while category-balanced recovery sits at ~0.6 and drops further under top-k retrieval** — successful assistance and recoverable memory are distinct capabilities.
- **Why it matters for Justin's agents:** This is the eval methodology Justin's companion-app should be measured by. Standard chat-style success metrics will tell you the agent "works" while the actual user model rots — which is exactly the failure mode that kills companion-app retention. MEMPROBE makes that failure mode quantifiable. The leak-controlled scenario design (only implicit signals leak into memory) maps onto how companion-app users actually behave.
- **Action signal:** `compare` — directly affirms DynamicMem (arxiv:2606.22877, June 23) ">93% of failures are memory retrieval, not generation." Both papers reach the same conclusion from opposite directions — DynamicMem says retrieval is the failure mode; MEMPROBE says the artifact itself doesn't contain what you need. Triangulates with the Item 1 survey: the gap is in the maintenance + retrieval modules, not representation.

### 5. Qwen-AgentWorld: Language World Models for General Agents
- **Source:** arXiv / HF Daily Papers (top trending, 37 upvotes)
- **Link:** https://arxiv.org/abs/2606.24597
- **Authors / org:** Qwen team (33 authors; Yuxin Zuo, Zikai Xiao, Li Sheng, Fei Huang et al.)
- **Focus area:** Frontier models / agent orchestration / local models
- **What it is:** Two open language-world models — **Qwen-AgentWorld-35B-A3B** and **Qwen-AgentWorld-397B-A17B** — trained to simulate agentic environments across 7 domains using long chain-of-thought reasoning. Training: CPT on 10M+ environment trajectories + augmented professional corpora → SFT for next-state-prediction reasoning → RL with hybrid rubric+rule rewards. Evaluated on **AgentWorldBench** (built from real interactions of 5 frontier models on 9 benchmarks); claims to "significantly outperform existing frontier models." Two deployment modes: (a) decoupled environment simulator for cheap agentic RL training (claimed to beat real-env training), (b) unified agent foundation model where world-model training acts as a warm-up.
- **Why it matters for Justin's agents:** Two angles. **(a) Local-fit:** 35B-A3B is the MoE class that fits comfortably on M5 Max with active-parameter inference speed. If this checkpoint actually outperforms general chat models on agentic tasks, it's the new default for any local-agent stack. **(b) Strategic:** "world-model warm-up improves downstream agent performance" is a non-trivial training-stage claim — if it generalizes, every future agent fine-tune should start from a world-model checkpoint. Watch for the open-weights release.
- **Action signal:** `local-fit` — pending HF weights drop. Verify the 35B-A3B variant lands as MLX or GGUF before committing; the 397B-A17B is too big for M5 Max but useful as a frontier reference if API access opens.

### 6. NatureBench: Can Coding Agents Match the Published SOTA of Nature-Family Papers?
- **Source:** arXiv / HF Daily Papers (27 upvotes)
- **Authors / org:** Yuru Wang, Lejun Cheng, Yuxin Zuo, et al. (17 authors, Frontis AI)
- **Link:** https://arxiv.org/abs/2606.24530
- **Focus area:** Coding agents / evaluation
- **What it is:** 90 cross-discipline tasks distilled from peer-reviewed Nature-family publications, each with a per-task containerized environment auto-built by the **NatureGym** pipeline (the env-fragmentation fix that prior research-agent benchmarks lacked). Strict web-search-disabled protocol. **Best of ten frontier agent configurations matches published SOTA on only 17.8% of tasks** (g>0.1 criterion). Post-mortem: agents win primarily by **methodological translation** — converting scientific tasks into familiar supervised-prediction problems — not by genuine invention. Failures: wrong method choice + insufficient compute budget, not task misunderstanding. Benchmark + NatureGym + public leaderboard with maintainer-side reproduction all released.
- **Why it matters for Justin's agents:** This is the cleanest "where are coding agents actually weak" benchmark released this quarter. The 17.8% ceiling under web-search-off is a sharp data point against the "frontier coding agents are nearly here" narrative — they are nearly here on bounded refactor + bug-fix work, not on open-ended methodology selection. For Justin's federal-data-engineering work, the failure-mode breakdown (wrong method, not wrong understanding) is the audit checklist: when an agent fails on a novel pipeline design, the leverage point is method retrieval / pattern library, not better prompting.
- **Action signal:** `track` — benchmark + reproducer are released; useful as a regression eval for any high-autonomy coding-agent stack Justin's evaluating. Pair with last week's CLI-Universe (arxiv:2606.22883) for terminal-vs-research-task coverage.

### 7. Block-GTQ: RoPE-Aware Bit Allocation for KV-Cache Quantization
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.24033
- **Authors / org:** Fengfeng Liang, Yuechen Zhang, Jiaya Jia (JIA-Lab)
- **Focus area:** Context engineering / local models
- **What it is:** Existing KV-cache quantizers treat each cached key as a flat vector — wrong under RoPE, where a key's contribution decomposes into position-dependent two-dimensional frequency blocks. **Block-GTQ** computes a label-free per-block energy score and greedily allocates integer bit-widths by marginal gain. Built on TurboQuant-MSE. Results: at 2–3 b/dim K-only quantization, MAE drops 32–80% per layer vs uniform TQ-MSE (wins all 367/367 layer comparisons). On Llama-3.1-8B-Instruct K2V2: NIAH avg 70.6 → 97.4, LongBench-EN 36.87 → 53.31. On AIME with DeepSeek-R1-Distill-Qwen-7B at K3V2 (no fp16 recent-key buffer): 51.7/37.5 vs fp16 54.2/37.9, while uniform TQ-MSE collapses to 0/0. Packed-cache serving path on Qwen2.5-3B + H800: **3.24× KV compression, 1.34× faster than fp16 FlashAttention2 at 128K, peak memory 56.31 GB → 19.85 GB, feasible at 256K/512K where fp16 OOMs**. Code at https://github.com/JIA-Lab-research/blockgtq.
- **Why it matters for Justin's agents:** The single most directly local-impactful paper in this digest. KV-cache headroom is the actual binding constraint on M5 Max for long-context agent loops — 3.24× compression at near-fp16 quality on Qwen2.5-3B-class models means real 128K-token MCP sessions become feasible inside the 64GB unified memory budget. The benchmarks are on Llama-3.1-8B and Qwen2.5-3B, both of which already run well on M5 Max via llama.cpp Metal.
- **Action signal:** `try-now` — clone repo, evaluate on M5 Max with Qwen2.5-3B-Instruct first to validate the headroom math, then port to llama.cpp Metal if the upstream impl is CUDA-only. The 256K/512K-feasible claim is the killer feature for any long-running agent.

### 8. SAFARI: Scaling Long-Horizon Agentic Fault Attribution via Active Investigation
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.24626
- **Authors / org:** Chenyang Zhu, Jiayu Yao, Kushal Chawla, Youbing Yin, Nathan Wolfe, Pengshan Cai, Jingyu Wu, Spencer Hong, Sangwoo Cho, Shi-Xiong Zhang, Daben Liu, Sambit Sahu, Erin Babinsky
- **Focus area:** Long-running / autonomous loops / agent orchestration
- **What it is:** Current methods diagnose agent failures by loading the full trajectory into an LLM context window — suffers attention dilution and just fails when the trace exceeds context. **SAFARI** replaces linear context loading with a **tool-augmented diagnostic loop**: specialized tools to read+search trajectory segments, plus a persistent Short-Term Memory (STM) for cross-turn reasoning. Decouples diagnostic accuracy from the model's native context window. Results: **+20% over SOTA on Who&When at 1M token budget; +19% on TRAIL GAIA subset at 25K token budget; 0.58 precision when fault sits 5× beyond native context** — where traditional evaluators "fail entirely."
- **Why it matters for Justin's agents:** Justin's scheduled-routine runs (this one!) are exactly the long-horizon trajectory shape SAFARI is built for. When a 4-hour autonomous loop fails, the standard "feed the whole transcript to Claude and ask what went wrong" approach hits the same context-window wall SAFARI is calling out. The tool-augmented diagnostic loop pattern — read+search tools over the trajectory + persistent STM — is the right shape for a `claude-code` fault-attribution skill. Pairs cleanly with OpenRath Sessions (arxiv:2606.19409, June 23) and FlashRT Capsules (arxiv:2606.20537, June 19): Sessions give you the artifact, Capsules give you the snapshot, SAFARI gives you the diagnostic loop.
- **Action signal:** `try-now` — pattern is implementable today as a custom subagent over a trajectory file even before code release. The "fault 5× beyond context" precision number is the key data point for any system that has to debug its own past runs.

### 9. OpenThoughts-Agent: Data Recipes for Agentic Models

Strong scaling — outperforms alternative open datasets at every training set size under matched compute. **Everything released**: training sets, pipeline, experiment logs, models — openthoughts.ai.
- **Why it matters for Justin's agents:** Two angles. **(a)** The 32B-class Qwen3 checkpoint with this fine-tune is the most credible *generalist* open agent model right now — pairs with last week's CLI-Universe-Qwen3-32B (arxiv:2606.22883, terminal specialist). Comparable size, complementary specialization. **(b)** The 100-ablation pipeline-decomposition is the right reference architecture for anyone training an MCP-specific agent model from open weights. Trumps closed-source training-data folklore.

## Conflicts & open questions
Cross-referenced against `_meta/claims-ledger.md`:

- **Memory governance vs naive RAG.** Item 2 (Governed Shared Memory / MemClaw) explicitly states "long-context retrieval alone is insufficient for production multi-agent memory." This directly contradicts EvoEmbedding's "naive RAG with evolvable embeddings surpasses dedicated agentic memory systems" thesis (arxiv:2606.21649, June 22 digest). Both can be right if EvoEmbedding solves the *representation* layer and MemClaw solves the *governance* layer — but as stated, the rhetoric is incompatible. Item 1's survey (arxiv:2606.24775) is the most authoritative referee available, and it lands with "no single architecture dominates" — which is closer to MemClaw's "governance matters" framing than to EvoEmbedding's "representation is enough."
- **Memory failure mode triangulated.** Item 4 (MEMPROBE) finds "task completion nearly saturates while category-balanced recovery stays at ~0.6 and drops further under top-k" — this directly affirms DynamicMem's ">93% of failures are memory retrieval, not generation" (arxiv:2606.22877, June 23 digest). Two independent benchmarks now confirm: the *artifact* is the problem, not the model. Status: confirmed.
- **Open question for tomorrow:** Does ReM-MoA (item 3) replicate when the Reviewer Agent is a smaller model than the base solvers? The paper's framing suggests the Reviewer needs to be at least as strong — if so, this is a closed-source-frontier-only technique, not a local-stack pattern. Worth checking the full PDF when it's available.
