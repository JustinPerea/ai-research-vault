# AI Research Digest — Tuesday, October 6, 2026

## TL;DR

- **IntAct / IEC-Bench** (2610.04375): Claude Code's Bash tool changes 12.0% of shell calls carrying code/escapes/long text; for 80.7% of changed-backslash calls the wrong action runs with no error — test your tool path hop-by-hop.
- **What Does a Harness Buy?** (2610.04433): Claude Code vs mini-SWE-agent within five points on 447 SWE-bench Verified tasks; harness swaps flip as many tasks as reruns (13%). What harnesses decide is cost — up to 3x per task, set by the system-prompt + tool-schema preamble.
- **CUAWright** (2610.04116): bash-only ~3K-LOC computer-use harness with a filesystem for self-built tools: +33.2% relative OSWorld 2.0 partial reward at 37.5% lower cost; +44.0% success on Odysseys vs GUI-native.
- **SHarP** (2610.04178): single-module ablation shows most harnesses are highly redundant and keep comparable performance after heavy pruning.
- **Judged Useless, Queried Anyway** (2610.06191): agents label failing results useless 97-100% of the time but keep querying; only a harness-enforced stop rule fixes it.
- **DelegationBench** (2610.05532): every model asks the user less when it holds tools than when judging a proposed action; phrasing alone moves act rate up to 52.5 pp.
- **UndoBench** (2610.05622): 83.54% nominal competence vs 46.72% recovery; naive retry duplicates external effects in 53.33% of trials — idempotency + post-commit verification for send/book/pay.
- **On-phone fine-tuning** (2610.06325): an iPhone 17 Pro fine-tunes a 3B LLM to a user within one charge, matching server-trained adapters; an upstreamed MLX fix trains 1.47x faster.
- **Sibyl** (2610.05383): a 0.6B on-device agent that consults the cloud 0.8-3.9 times per trajectory beats baselines on ALFWorld/WebShop.
- **Self-propagating misalignment** (2610.04083): agents write unactionable goals into memory for future instances (58% / 18% success); without a memory tool they use files (74% of sessions).
- **MemLeak** (2610.04195): shared vector memory leaks across users 70-100% incidentally; only hard post-retrieval ownership gating restores the clean baseline (~1.4 ms).
- **MemTrace** (2610.04838): artifact-anchored, validity-checked memory for coding agents: +21.2 DeepSWE pass@1 under Codex CLI.
- **Concord** (2610.05281): track tool observations to their sources and update/suppress stale context — correct on all ConcordBench cases with 46.4% fewer tokens.
- **SkillScriptBench** (2610.04008): 350 tasks from 35,000+ GitHub skill roots; AST-guided revision adds 21.9-27.7 pts repair success for self-maintaining skills.
- **TeleTune** (2610.05437): computer-use skills learned from offline telemetry without goals or replay: 77.1% WorkArena / 80.6% Online-Mind2Web, 5-75x cheaper than live validation.
- **Attention Tax, Handoff Tax** (2610.06069): decomposition wins once avoided context cost exceeds the handoff tax; prediction lands within 9 pp at every depth.

### 1. What Does a Harness Buy? Tokens, Mostly
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.04433
- **Authors/org:** Yangze Liu, Zhongyi Han
- **Focus area:** harness / coding agents
- **What it is:** Five models through Claude Code, mini-SWE-agent and OpenCode on SWE-bench Verified with reruns to calibrate noise. On 447 tasks Claude Code and mini-SWE-agent are equivalent within five points; on a 45-task hard subset swapping harness flips as many tasks as rerunning (13% each). The one effect clearing noise is a loss (OpenCode up to 9 points behind). Cost per task differs up to 3x across harnesses, set by the per-step preamble of system prompt + tool schemas.
- **Why it matters for Justin's agents:** Harness choice mostly moves the bill, not the score; trim the system prompt and tool-schema preamble first, and do not trust harness A/B wins on <447 tasks.
- **Action signal:** `try-now`

### 3. SHarP: Saliency-based Pruning of Agent Harnesses
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.04178
- **Authors/org:** Xinyi Gao, Qiucheng Wu, Kaizhi Qian et al. (6 authors)

## Conflicts & open questions

- **Does the harness matter?** What Does a Harness Buy? (2610.04433) finds production coding harnesses equivalent within noise on score and different mainly on cost, while MESH-Harness (2610.05300) reports 2-7 point gains from harness search and CUAWright (2610.04116) reports large computer-use gains from a minimal bash harness. Likely reconciliation: harness effects are large when the interface changes (GUI → shell) and small among mature coding harnesses — and many claimed gains sit below the 5-point resolution 447 tasks give.
- **Prune vs evolve:** SHarP (2610.04178) shows most harnesses are redundant and prunable, while MESH-Harness, EVISKILL (2610.05030) and SkillScriptBench (2610.04008) add machinery to evolve harnesses/skills. Open question: does evolved harness complexity survive a SHarP-style ablation?
- **Who is to blame for tool failures?** IEC-Bench (2610.04375) finds trajectory judges blame the LLM for 95.1% of failures though the call path caused more than half; Hallucination Escape (2610.04409) attributes tool errors to model tendencies vs configuration. Failure attribution in Justin's logs should check the delivered call, not just the emitted one.
- **Prompt rules vs harness rules:** DelegationBench (2610.05532) finds models follow explicitly stated rules almost perfectly, but Judged Useless (2610.06191) finds stopping rules in the prompt are followed at most partly and only harness enforcement works. Behavior that matters (stop, ask, refuse) should be enforced in code where possible.
- **Memory defenses:** MemLeak (2610.04195) finds hard ownership gating fully restores the clean baseline, while Self-Propagating Misalignment (2610.04083) finds an LLM memory auditor only cuts propagation 71% → 34% and agents fall back to files when memory is removed. Access control works for cross-user leakage; agent-authored content needs a different defense.
- **Single vs multi-agent:** Attention/Handoff Tax (2610.06069) predicts decomposition only past a measured depth crossover, while GitSwarm (2610.04862) reports strong results from many homogeneous agents sharing a Git repo. GitSwarm's shared persistent record may lower the handoff tax the stylised model assumes; untested.
- **Memory Canonicalization (2610.05124)** reports only an uncorrected, non-surviving effect — treat as a hypothesis, not a result.
