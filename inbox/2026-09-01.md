### 1. Measure Before You Manage: Evaluating Agent Working Memory in Coding Agents
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2608.31057
- **Authors / org:** Le Chen / Baixi Sun / Xiaolong Ma / Chih-Hsuan Yang / Sheng Di / Franck Cappello / Rajeev Thakur (Argonne); Zishen Wan (Columbia); Feng Yan (University of Houston)
- **Focus area:** Memory / context accounting for coding agents
- **What it is:** Argument that coding-agent working memory is semantically heterogeneous and must be measured before it is managed. Across **55** archived full-context trajectories (eight repos; SWE-bench Lite–derived under a local Docker-free evaluator): **1,350** in-context objects after dropping 306 disk-only — tool outputs **585** (**55.5%** pooled volume, **40.2%** retention-weighted cost), artifacts **165** (**28.3% / 38.9%**), instructions **110**, agent state **490**. Artifact median size **624** proxy tokens vs tool-output **73**; mean residency **10.71** vs **8.61** steps. Structural compression probe: compressed/raw **0.150** artifacts vs **0.673** tool outputs. Object-aware (OA) compression vs FIFO/LRU/uniform compression: calibration (n=15) mean Δ repeated-calls OA−FIFO **−1.633** (Holm p=0.0146); held-out (n=8) no contrast survives Holm. Retrieval (Generative Agents–style) follow-up: none of four GA–baseline contrasts survives Holm. Four reporting levels: stored state, delivered context, management work, task/process outcome. Abs verified 2026-09-01 (submitted 31 Aug 2026). No public code/data release claimed.
- **Why it matters for Justin's agents:** Yesterday's ContextPilot [arxiv:2608.28476, 08-31] is *what to fold* in the working transcript; TwinKV [arxiv:2608.27128, 08-28] is *what to drop* in KV. This paper is the measurement layer both skipped: typed residency accounting and a warning that calibration gains and equal token budgets do not imply held-out wins or matched delivered context. Concrete port, no training: (1) tag Claude Code / WorkBuddy context objects as instruction / artifact / tool-output / agent-state, (2) report volume *and* retention-weighted cost, (3) when comparing condensers, report auxiliary calls + wall time + delivered-state medians, not just a budget label. Primary endpoint is repeated tool calls (process), not official SWE-bench repair — do not read as a repair win.
- **Action signal:** `try-now` — add typed working-memory accounting to Claude Code session logs; refuse to declare a memory policy “better” from a calibration-only contrast or a shared nominal budget alone.

### 2. Token-Efficient Data Reasoning Agents via Adaptive Structuring of Unstructured Data
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2608.31082
- **Authors / org:** Milad Rezaei Hajidehi / Qitong Wang / Stratos Idreos (Harvard University)
- **Focus area:** Memory / tools / unstructured-doc reasoning cost
- **What it is:** “Agentic data cracking”: whenever the answer agent opens a document, a cracking sub-agent forks from the already-loaded context (KV-prefix / prompt-cache reuse) and extracts grounded RDF-style cracked objects (subject–relation–object + cardinality + unit + evidence) likely useful for related future queries. Catalogue surfaces subject–relation pairs before open; miss falls back to raw document. FanOutQA + one human-verified related prior question per test item (Claude-Haiku-4.5): mean cost **$0.26 → $0.12 (−53%)**; mean prefill **189K → 87K**; LLM-judge accuracy **42% vs 43%** (p=0.39). Ideal pre-structured store **28×** cheaper. Median **$0.246 → $0.072** (**3.4×**); P10 paired ratio **9×** cheaper; P90 **1.24×** (no-reuse overhead). Case study (20 Hitchcock questions then 10 tests): **$0.81 → $0.27**. 4K cracking decode budget ≈ **12%** overhead / ~150 objects. Abs verified 2026-09-01 (submitted 31 Aug 2026).
- **Why it matters for Justin's agents:** Mitamaton already pays to open Gmail threads, PDFs, and calendar dumps. Cracking says: while the prefill is paid, extract reusable structure so the next related question is a catalogue hit, not another million-token open. Complements ContextPilot fold tools (working transcript) and TwinKV (KV eviction) with a *corpus* store that survives model swaps — cracked objects are plain text, not model-bound KV. Concrete port: after any large document tool result, run a bounded extract of entities/relations into a shared store; expose catalogue + structured-read MCP tools before `open`. Do not pretreat FanOutQA Wikipedia locality as identical to personal inbox locality — measure reuse on real Mitamaton query logs.
- **Action signal:** `try-now` — add a post-open “crack” step (bounded decode) into a reusable entity/relation store for Gmail/docs; require catalogue lookup before re-opening the same source.

### 3. A Universal Context-Reuse Layer for Cross-Model KV Sharing
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2608.30963
- **Authors / org:** Yi Li / Dongming Jiang / Yi Zhao / Bingzhe Li (University of Texas at Dallas)
- **Focus area:** Local / multi-model serving / KV reuse across model boundaries
- **What it is:** Cross-model KV sharing: translate source-model KV into a target-consumable cache so heterogeneous models (scale, family, tokenizer) avoid full target prefill on shared context. Within-family Qwen2.5-7B→1.5B on LongBench2: native 1.5B **27.59%** → handoff **34.48%** (+6.89 pp); native 7B **45.69%**. Handoff latency **34.5 ms** vs 1.5B prefill **158.7 ms** (8K–16K); **53.8 vs 288.3 ms** (16K–32K). Cross-family Qwen2.5-1.5B→Gemma-2-2B: up to **67.04%** prefill-cost reduction at 4K; handoff perplexity competitive across horizons. Llama3.1-70B→Qwen2.5-7B: handoff **44.0%** accuracy / **138 ms** vs native Qwen **45.7% / 899 ms** and native Llama **44.0% / 7,328 ms**. Demo video linked on abs. Abs verified 2026-09-01 (submitted 31 Aug 2026).
- **Why it matters for Justin's agents:** TwinKV [arxiv:2608.27128] repairs eviction *within* one model. This is the next cut for a Claude Code ↔ local Qwen ↔ router stack: when context already exists on model A, do not always re-prefill model B from tokens. Relevant to Handoff Tax [arxiv:2608.24358, 08-27] mid-run model switches. Caveat: requires a learned transport module per pair; latency numbers exclude source prefill; not a drop-in for Apple Silicon without a serving stack that can host the translator. Compare conceptually against prompt-cache / prefix reuse before building translators.
- **Action signal:** `compare` — for any 4B↔27B/35B or cloud↔local handoff path, measure native re-prefill vs translated-KV quality/latency on a fixed long Mitamaton context; keep TwinKV as within-model eviction.

### 4. CAST: Critique-Aware Supervision for Training Reliable Long-Horizon Tool-Calling Agents
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2608.30147
- **Authors / org:** Amir Saeidi / Zehua Zhang / Rishitosh Singh / Naman Ahuja / Vivek Gupta / Chitta Baral (Arizona State University); Ali Payani / Gaowen Liu / Jayanth Srinivasa (Cisco Research)
- **Focus area:** MCP / tools / long-horizon reliability (critique before irreversible actions)
- **What it is:** CAST converts sparse trajectory rewards into action-level verification (hallucination / domain violation / wrong tool) via an agentic annotator, trains CAST-Critic, then optimizes CAST-Policy on critique-enriched successful trajectories. Train on τ-Bench Retail (500 tasks × 5 trials). Table 1 (selected): Retail Policy-4B pass^1 **26.1%** / pass^4 **16.5%** vs Base-4B **7.2% / 6.1%** and RFT-4B **27.6% / 12.2%**; Policy-8B pass^4 **14.8%** vs Base **5.2%**. OOD Telehealth Policy-4B pass^4 **30.0%** vs Base **10.0%**; Telecom Policy-8B+Critic-8B pass^4 **27.8%** vs Base **5.6%**. Appendix: GPT-OSS-120B Retail pass^4 **5.9%**. Prompted GPT-4.1 as critic *hurts* (high false-positive rate **46.8%** vs Critic-4B **13.6%**). Abs verified 2026-09-01 (submitted 30 Aug 2026).
- **Why it matters for Justin's agents:** SARA [arxiv:2608.27146, 08-28] is Observation≠authorization at the harness boundary. CAST is the *trained* step-local critique layer that intercepts refunds/exchanges/writes before execution — the Mitamaton shape for calendar-write / send / pay. Steal without full RL: (1) log proposed irreversible MCP calls with a structured yes/no + rationale from a small critic, (2) require user-contract support before execute, (3) if training, prefer critique-enriched successes over raw RFT. Do not treat Retail pass^4 as a Gmail guarantee; OOD gains are real but smaller and critic-dependent.
- **Action signal:** `compare` — CAST-style action critique in front of irreversible MCP tools vs SARA’s provenance gates on the same personal tasks; start with a prompted/small critic, graduate to fine-tune only if false-positive rate stays low.

### 5. Aspire: Can Models Self-Evolve from Vague Goals?

- **Link:** https://arxiv.org/abs/2608.31111
- **Authors / org:** Yuhao Wu / Jingyuan Zhang / Jiajun Shi et al. (ByteDance Seed; SUTD; M-A-P; TokenWave.AI) — full list in Contributions
- **Focus area:** Harness / weight self-evolution under vague goals
- **What it is:** Aspire benchmark: agent gets only a natural-language capability goal; **520** expert-authored hidden items across **6** goals; sealed evaluation. RQ1: vague goals vs explicit PostTrainBench tasks — Claude Opus 4.8 vague **27.07** vs official Max **32.90**; GPT-5.6 vague **29.58** vs official **36.23**. Adaptive-feedback (30 cells): **28** evaluate a checkpoint, **2** beat base, **1** retained (Terra mathematics **20.10** vs **17.86**). RQ3 harness evolution (weights fixed): best GPT-5.6 Sol successor **27.22** task macro vs original Qwen-Agent **28.64**; Qwen3.5-4B Creator produces no valid harness. Agents train/edit routinely; retained target-aligned gains are rare. Project: https://self-developing-agents.github.io/ Abs verified 2026-09-01 (submitted 31 Aug 2026).
- **Why it matters for Justin's agents:** Direct stress test of the vault’s self-evolution pile. WikiSkill [arxiv:2608.27454] never rolls the wiki back; RedEvoAgent / HarnessLens / EvoUndo add keep/drop gates. Aspire says: under *vague* goals with hidden eval, weight self-evolution mostly fails to retain gains, and harness successors stay below an engineered reference. Operational rule for Claude Code skill evolution: do not promote a SKILL.md / weight / harness patch on “the train job finished” or on a narrow self-eval checklist — require held-out personal tasks and rollback (EvoUndo) when Δ≤0. Aspire is the empirical cold water, not a recipe to copy.

### 6. Learning to Evaluate Before Improving: Automatic Rubric Induction for Automatic Research Agents
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2608.31076
- **Authors / org:** Xuehai Wang / Haowei Qin / Tongxin Liu / Junkai Li / Buqiang Xu / Jintian Zhang / Yijun Chen / Zirui Xue / Shumin Deng (Zhejiang University et al.)
- **Focus area:** Harness evolution / evaluation-first agent control
- **What it is:** AutoSciRub induces a task-specific executable rubric *before* research execution (skeleton → literature grounding → task-data exploration → criterion synthesis), then uses criterion-level verify + targeted revision. ResearchClawBench (40 tasks): cross-model under Codex avg **+2.08** (GPT-5.4 **+2.38**, GLM-5.2 **+1.87**, MiniMax-M3 **+1.99**); cross-harness under DeepSeek-V4-Flash avg **+2.95** (Claude Code **+2.14**, OpenClaw **+3.11**, OpenScience **+3.60**). AstaBench E2E Discovery 20-task subset: avg **+16.8** (Claude Code **+19.36**, Codex **+12.61**, OpenClaw **+18.38**). Ablation (OpenClaw): base **17.25** → skeleton **17.61** → grounded rubric **18.31** → full **20.36**. Rubric-guided revision **+2.05** vs rubric-free self-refine **+0.77** over three rounds. Code: https://github.com/zjunlp/AutoSciRub. Abs verified 2026-09-01 (submitted 31 Aug 2026).
- **Why it matters for Justin's agents:** HarnessLens [arxiv:2608.27311, 08-29] gates harness patches on behavior-relevant tasks. AutoSciRub is the sibling move for *open-ended* work: induce the success criteria before the agent spends the budget, then revise against unmet criteria. Steal for Mitamaton / vault digests / research agents: (1) expand a vague user ask into atomic verifiable criteria grounded in available data, (2) run, (3) verify criterion-by-criterion, (4) revise only the gaps. Do not confuse ResearchClawBench’s absolute score band (~20) with “solved science” — the lift is the signal.
- **Action signal:** `compare` — evaluation-first rubric induction vs HarnessLens post-hoc targeted verification on the same 3–5 personal open-ended tasks; try the plugin pattern (rubric layer around an existing harness) before rewriting the agent.

### 7. On the Design of Qwen3.8-Next Architecture: Evaluation, Efficiency, and Training Stability
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2608.30320
- **Authors / org:** Qwen Team (core: Zihan Qiu / Zekun Wang / Xiao Li / Yanpeng Li / Yang Xu / Yixuan Wang / Huaqing Zhang / Rui Men / Bo Zheng / Dayiheng Liu et al.)
- **Focus area:** Local / open models — frontier MoE architecture recipe
- **What it is:** Architecture + ablation report for **Qwen3.8-Flash-Next**: sparse MoE **125B** total / **6B** activated / **+51B** n-gram embedding tables held off-accelerator. Token mixing: Gated DeltaNet hybrid with **1 full-attention layer per 4**; CPT replaces full attention with **Qwen Sparse Attention (QSA)** (micro-block indexer). **Gated Residual (GR)** widens residual to 4 branches with elementwise sigmoid read gate. Optimizer: **Muon** on 2D linear maps (+ AdamW on embeddings/router/GR low-rank). Claims vs 397B-A17B predecessor: leads on **8/14** pretrain benches, trails rest by ≤**2.6** points, at ~**1/3** activated params, ~**1/3** tokens, ~**1/9** training FLOPs. QSA at 1M context: kernel **7.6×** prefill / **4.9×** decode vs dense. FlashQLA kernels: https://github.com/QwenLM/FlashQLA. Abs verified 2026-09-01 (submitted 30 Aug 2026). This digest does **not** treat the paper as a confirmed public weight drop (no HF card verified this run).
- **Why it matters for Justin's agents:** Continues the open MoE thread after Thomson / Qwen3.6-35B notes. The stealable pieces for a local stack are the *recipe axes*: GDN hybrid schedule, QSA for long prefill, GR for stability at higher LR/batch, Muon hyperparameter shift (larger batch, no batch warmup). 6B activated is the right size class for 64 GB unified memory *if/when* weights ship; 51B host n-gram tables are a serving dependency, not a pure on-device footprint. Until weights are public, track the architecture; do not reserve Mac RAM for a phantom checkpoint.
- **Action signal:** `track` — watch for Qwen3.8-Flash-Next open weights; if they land, compare 6B-act MoE vs current Qwen3.6-35B-A3B / Thomson-Small on personal coding + day-admin cells before swapping the local slot.
