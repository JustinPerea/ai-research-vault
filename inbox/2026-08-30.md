### 1. Persona–Execution Separation (PES)
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2608.27427
- **Authors / org:** Yisen Xi (Independent Researcher, Beijing)
- **Focus area:** Personas / shells + execution audit (MCP-shaped bridge)
- **What it is:** Architecture pattern for agents that must both evolve (instructions, tone, skill bindings) and leave an audit trail of state-changing work. A single trust domain does not do both cheaply: under LLM representational indistinguishability, persona edits and execution-semantics changes are the same substrate (prompt text), so any single-domain fix re-introduces typed change objects, an external gate, and a stable audit anchor — PES rebuilt at higher coupling cost. PES puts the **expression surface** in a permissive domain (persona singly-homed, free drift of surface instructions/tone) and the **execution surface** in a restrictive domain (faceless SOP loop, gated, audited). One employee identity. Governed contract bridge: (1) status summaries flow back, (2) data bodies stay except a graded DLP-masked E2 exception, (3) identity stays continuous. Enforcement: MCP-with-ACL tool calls, deny/ask/allow approval matrix, DLP, audit; fail-closed. Applicability only when multi-user deployment, execution audit, and expected persona churn hold jointly. Development/pilot case (FIA Workbench, financial digital-employee platform): five decisions over one month (2026-07-19 → 2026-08-17), each with a rejected alternative. Mechanism check on the shipped implementation: **R = 0.00** (zero execution-side re-validation under L1–L5 persona perturbation, five model configs: deepseek-v4-flash / v4-pro / qwen3.8-max / kimi-k3 / glm-5.3). V2 isolation passed on four configs; qwen3.8-max did not converge on the SOP (0/4 clean). A recovered pre-separation build was decoupled from the persona **by omission, not by construction** — wiring the persona in changed execution 2/2. Implementation is not public. Abs verified 2026-08-30 (submitted 27 Aug 2026).
- **Why it matters for Justin's agents:** Mitamaton's whole product is personas/shells on top of irreversible MCP (Gmail-read-only is the current contract; calendar-write / send / pay are the ones that will need a ledger). Yesterday's SARA splits Observation from authorization *inside* a trajectory; LoopHarness keeps a non-decaying risk register *across* trajectories. PES is the third cut: **who the agent is** vs **what it is allowed to commit**. Concrete port, no training: (1) WorkBuddy / shell prompt lives only in the chat surface, (2) MCP tools that change state are faceless — they take a work-order schema, not the persona text, (3) summaries of "calendar hold placed" may return; the event body and attendee list do not, except a DLP-graded exception, (4) do not "mirror" the persona into the execution prompt so the backstage sounds like the shell. The qwen3.8-max non-convergence is the same backbone-dependent warning as yesterday's Qwen3.6-35B manager-worker regression: verify the model will actually commit to the SOP's terminal action before you bet the audit trail on it.
- **Action signal:** `try-now` — split Mitamaton's persona/shell store from the MCP execution path this week; do not project the shell into tool-call context.

### 2. RedEvoAgent: Automatic Red-Teaming Agent with Experience-Driven Skill Evolution
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2608.27439
- **Authors / org:** Junjie Zhang / Hui Liu / Kecheng Chen / Haoliang Li (City University of Hong Kong); Xianbo Mo / Changsheng Chen (Shenzhen MSU-BIT University)
- **Focus area:** Skill evolution (validation ratchet) + Claude Code / Codex threat model
- **What it is:** Product-level agent harnesses (named: Claude Code, Codex) make jailbreaks more than unsafe text — they can trigger tool use and persistent state. Trajectory-retrieval attackers (RedCodeAgent) reuse misleading experiences, burn context, and are hard to audit. RedEvoAgent distills cross-case attack trajectories into a **concise Markdown attack skill** in the attacker system prompt. Experience = isolated tool-effectiveness profile on the train split + annotated rollouts. **Deciding-Tool Attribution** labels the tool immediately before the first successful target query, so co-occurrence is not treated as credit. **Validation ratchet:** a candidate skill rewrite is kept only if it strictly beats the incumbent on an independent val split; rejected candidates go into a rejection context. Frozen target, frozen attacker model, frozen toolbox; only `s` evolves. Eval: Agent Security Bench (400 cases, split 80/40/280) and AgentHarm (208 cases, 40/20/148); targets MiniMax-M2.5 / DeepSeek-V4-Flash / Qwen3.5-35B × Claude Code or Codex; attacker GPT-4o mini, budget B=20, R=4 SkillOpt-style rounds. Headline cells (Table 1): Claude Code / MiniMax / ASB **93.2 ASR** vs FlipAttack 91.8 / RedCodeAgent 76.4 / MAJIC 74.2; Codex / MiniMax / ASB **92.8** vs FlipAttack 81.1. Claude Code / DeepSeek / AgentHarm **74.3** HarmScore vs FlipAttack 67.9 (RedCodeAgent 37.5 — retrieved trajectories *hurt*). Skill ablation (Table 2): evolved skill, MiniMax / ASB / Claude Code **93.2 ASR / 1.8 tool calls** vs No-Skill 77.5/3.0. Experience ablation: dropping the tool-effectiveness profile **93.2 → 76.9**. Zero-shot transfer of the MiniMax+Claude-Code skill, no re-evolution: Codex destination **90.5 vs 80.8** No-Skill. Abs verified 2026-08-30 (submitted 27 Aug 2026).
- **Why it matters for Justin's agents:** Two reads, both operational. (1) **Threat:** the vault's live loop (Claude Code) is literally a target harness in the tables. SARA's Observation≠authorization and LoopHarness's non-decaying register are defenses *inside* the target; this paper is the attacker that evolves a SKILL.md against that harness. Minimum: treat a growing `~/.claude` skill corpus as an attack surface, not only as a productivity layer. (2) **Ratchet reuse, sign flipped:** WikiSkill keeps a skill if val score rises and **never rolls the wiki back**; HarnessLens verifies on behavior-relevant tasks behind an attributable-evidence gate; RedEvoAgent keeps a rewrite only if it beats the incumbent on held-out val and records failed rewrites so the distiller does not repeat them. The portable primitive for a WorkBuddy maintainer is incumbent-relative held-out gating + a rejection log, not "the wiki only grows." Do not train an attacker.
- **Action signal:** `compare` — put RedEvoAgent's incumbent-relative ratchet next to WikiSkill's full-val-set keep and HarnessLens's behavior-relevant gate on the same 3–5 personal tasks; separately, assume Claude Code is in the red-team literature now.

### 3. Naive Prompt Optimization: Rethinking the Need for Complex Prompt Search
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2608.27266
- **Authors / org:** Yuan Chang / Xiaoqi Chen (Purdue University)
- **Focus area:** Prompt / CLAUDE.md optimization (vs GEPA / GRPO)
- **What it is:** Prompt optimization is being built as a search problem (OPRO, ProTeGi, MIPRO, GEPA's Pareto pool). NPO is the dumb baseline: **one lineage**, teacher sees a sliding window of prompts + **full rollout traces + rewards**, rewrites once, no beam, no Pareto. Student held at Qwen3-8B; teachers Qwen3-8B / DeepSeek-V4-Flash-preview-0424 / GPT-5.5. Constrained decoding isolates decision quality from format failures. IFBench / HotpotQA rollout budgets **3,500 / 6,800**, slightly under GEPA's 3,593 / 6,871, with larger reflection minibatches (50/10 and 40/20 vs GEPA's 3). NPO **matches or beats GEPA** and **benefits more from stronger teachers**; GEPA+GPT-5.5 is often on par with GEPA+Qwen3-8B. Optimized prompts applied **verbatim** to other students: strongest within family (Qwen 8B → 14B/32B; Llama-3.1-8B → 70B), still positive but noisier cross-family. 22 TextArena games, 408 episodes: NPO ≈ GEPA, GRPO wins some games that resist prompting. Gold-answer overlap with the HotpotQA val set stays negligible (training-set overlap grows, as expected). Abs verified 2026-08-30 (submitted 27 Aug 2026).
- **Why it matters for Justin's agents:** GEPA is in the vault (and NPO cites AI4AI [arxiv:2608.12307] as the teacher-builds-a-harness neighbor). This paper is permission to **not** stand up a candidate pool to edit CLAUDE.md / SKILL.md. Recipe: dump the last W traces from a WorkBuddy eval, ask Opus/GPT-5.5 to rewrite the prompt, keep the best val score. Transfer is the second fact: a prompt tuned on local Qwen3-8B is the thing you try on 32B before you retune. The TextArena split is the caveat — some interactive loops want GRPO/LoRA, not a prompt. Do not train. Responsible-use note in the paper: the same cheap teacher pass can optimize a small local model for malicious tasks; keep the teacher's refusal in the rewrite prompt.
- **Action signal:** `try-now` on a single-lineage CLAUDE.md rewrite from traces; `compare` against GEPA only if the naive pass plateaus.

### 4. SWE-Prime: Fewer Trajectories, Better Performance
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2608.27449
- **Authors / org:** Dewu Zheng / Yanlin Wang / Jianxing Yu / Zibin Zheng (Sun Yat-sen University); Ruizhe Ye / Yang Ye / Ensheng Shi / Xilin Liu / Yuchi Ma (Huawei Cloud); Hongyu Zhang (Chongqing University)
- **Focus area:** Coding-agent SFT data quality (trajectory + segment)
- **What it is:** Coding-agent SFT usually keeps every *successful* trajectory. Success still contains bad supervision: skip-observe edits, failed tool calls, adjacent identical tool calls, git-history leakage of the gold patch, and over-broad diffs. SWE-Prime is two-stage. Stage 1 scores trajectories on observe-edit-verify, tool success percentile, adjacent-call redundancy, git-hack detection, and file×line scope vs the reference patch, then HDBSCAN-clusters issues (Qwen3-Embedding-8B) and takes the top per cluster. Stage 2 chunks remaining traces into **semantic segments** with boundary-aware windows, scores contribution / learnability / risk, and applies loss **only** to assistant tokens in segments ≥ threshold (all tokens remain as context). Pool: SWE-rebench OpenHands trajectories from Qwen3-Coder-480B-A35B, **32,161** resolved of 67,074. Frozen recipe after a one-model sweep: **10%** retention, segment threshold **7**. On SWE-Bench Verified / Pro, the 10% subset **beats full resolved-trajectory SFT**, relative gains vs that full pool of up to **24.2%** (Verified) and **12.2%** (Pro). Table 1 cells vs raw / full-SFT / SWE-Prime (Verified overall): Qwen3-30B-A3B-Instruct-2507 **25.2 / 36.8 / 39.6**; GLM-4.7-Flash **40.4 / 41.4 / 51.4**; Qwen3-Coder-30B-A3B **44.8 / 51.0 / 53.2**. Random-10% is near-useless or negative. Dropping Stage 2 loses the rest of the lift. SWE-Prime also cuts average turns vs full-SFT. Abs verified 2026-08-30 (submitted 27 Aug 2026).
- **Why it matters for Justin's agents:** Not a "fine-tune OpenHands this weekend" item. The filter is the primitive, and it is the coding-side twin of HarnessLens's attributable-evidence gate: **do not SFT (or distill, or promote a trace into a SKILL.md) on every green run.** Git-hacking detection is the one to steal immediately for any personal SWE eval — if the agent read the fix out of `git log` / `git show`, the trace is poison. Segment-level loss-masking (keep the context, don't train on the thrash) is the same idea as "gate the skill on the behaviors it claims to touch." The 30B-A3B rows are the local-fit hook; Thomson item 5 is a different 35B-A3B and **lost** coding, so do not conflate them.
- **Action signal:** `compare` — score personal coding traces with observe-edit-verify + git-leak + adjacent-redundancy before promoting them into a skill or an SFT mix; skip full-pool SFT.

### 6. CritICL: Inference-Time Weak-to-Strong Generalization from Small Language Model Failure Modes
- **Source:** arXiv (also Hugging Face Daily Papers)
- **Link:** https://arxiv.org/abs/2608.27455
- **Authors / org:** Yufan Wu / Zhengyi Hu / Lang Wei / Ruichen Li / Qifan Yang / Ting Zhu (The Ohio State University); Yinghui He (Princeton University)
- **Focus area:** Local-model inference-time (failure-mode ICL, no extra samples)
- **What it is:** Test-time scaling (self-consistency, self-reflection, LLM-as-judge) spends generations. CritICL's claim: **failure-mode distributions are stable across scale inside a family**, so critiques of weak-model mistakes are reusable ICL for the strong model. Stage 1 builds CritBank offline (weak CoT, keep incorrects, frontier LLM labels + critiques). Stage 2: **CritICL-static** uses a family-level failure-mode profile; **CritICL-dynamic** predicts per-query failure modes then retrieves. Weak CritBank: Qwen2.5-1.5B/3B/7B-Instruct; targets Qwen2.5-32B/72B-Instruct. Also Llama 1B/3B/8B → 70B. Table 1 overall Pass@1, Qwen 32B: CritICL-static **49.8** vs 5-shot fixed 46.0 vs Consistency@7 49.5; Qwen 72B: **59.2** vs 5-shot fixed 56.3 vs Consistency@5 59.0. MATH token cost on 32B (Table 2): CritICL-static **1 gen, 3,768 tokens** vs Consistency@7 5,440 vs Self-Reflection 7,533. Aggregate weak profile matches the 72B failure ranking better than any single weak model (Spearman **0.91** Qwen, **0.88** Llama); cross-family transfer is real but weaker. Code (from the HF Daily Papers record fetched this run): https://github.com/umwyf/CRITICL. Abs verified 2026-08-30 (submitted 27 Aug 2026). Dropped 08-28 and 08-29 as math ICL when the harness pile filled the slots; kept today as the cheap local inference-time leftover.
- **Why it matters for Justin's agents:** The 1.5B→72B transfer is the local-stack trick: log the 1.7B/4B's failure modes once, retrieve critiques for the 27B/35B (or for Opus, same-family only if you have a weak Claude, which you do not — so this is a **Qwen-family** tool). Static profile = one generation, which is the point versus self-consistency. Do not spend the weekend on MATH; the steal is the retrieval key (failure mode, not embedding similarity) for personal eval misses. Pair with NPO: NPO rewrites the prompt from traces; CritICL injects *other people's* (the small model's) mistakes as ICL. Complementary, not a replacement for a SKILL.md.
- **Action signal:** `try-now` — build a tiny CritBank from local Qwen 1.7B/4B misses on the personal eval and ICL the 27B/35B with CritICL-static; skip dynamic (extra generation) until static moves a cell.
