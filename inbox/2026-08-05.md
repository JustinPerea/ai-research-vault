Gains reverse on fact-consolidation tasks — scoped to temporal reasoning over things that go stale.

## Items

### 1. SkillJack: Persistent Skill Backdoors in Self-Evolving Agents
- **Source:** arXiv (Hugging Face Daily Papers)
- **Link:** https://arxiv.org/abs/2608.03509
- **Authors / org:** Zonghao Ying / Xiangfan Wu / Huiyu Wu / Xing Zheng / Huangsheng Cheng / Xiaorong Shi / Jing Guo — Tencent (AI-Infra-Guard)
- **Focus area:** Agent skills + security (experience-to-skill pipeline)
- **What it is:** First attack that hijacks the agent's *own* skill-extraction loop rather than runtime retrieval. Three named properties: **sanitization whitewashing** (malice is rewritten into a clean-looking skill), **cross-layer promotion** (a transient trajectory becomes a persistent capability), **persistence isolation** (the attack survives deletion of the source records). SkillX + Anything2Skill, 150 trajectories, four policy-risk categories. SkillX: safety detection **98.5% on poisoned trajectories → 11.4% on extracted skills**. ASR 56.2% (SkillX) / 89.2% (Anything2Skill). **80.0%** of skill-mediated attacks persist after the original poisoned records are deleted; some skills fire on benign queries. Code: https://github.com/Tencent/AI-Infra-Guard/research/skilljack
- **Why it matters for Justin's agents:** Claude Code / Mitamaton skill evolution (WikiSkill-style proposer, Trace2Skill, "write a SKILL.md from this session") is the exact pipeline. Scanning transcripts is not enough — the compiled `SKILL.md` is the artifact that needs a provenance stamp and a re-scan. Minimum viable: (1) every auto-written skill records source session IDs, (2) deleting a bad transcript does **not** retire the skill unless you also delete/gate the skill, (3) re-run a safety prompt on the *skill text*, not the raw trace. Do not let a web-browsing or email-reading session write skills without a human gate.
- **Action signal:** `try-now` — add a skill-write gate + source-session field to `~/.claude/skills` this week; the attack is architectural, not model-specific.

### 2. Skill-Use: Can LLMs Actually Use Skills in Agentic Harnesses?
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2608.04828
- **Authors / org:** Jinyi Han / Yuanjian Xu / Ying Liao / Xinyi Wang / Zishang Jiang / Zixiang Di / Fanyang Lu / Zhichao Hu et al.
- **Focus area:** Agent skills + harness evaluation (progressive disclosure)
- **What it is:** Evaluates whether an agent can *recognize and apply* a skill on its own under progressive disclosure (name + short description only; must retrieve the full procedure). Three facets: **Trigger** (did it invoke the right skill), **Compliance** (did it follow the procedure), **Boundary** (did it avoid forbidden operations). SU score combines the three and credits execution only after trigger. 79 real skills × 177 executable tasks across nine domains, real files, isolated Docker, trajectory rubric. Eight LLMs × two harnesses. Strongest configuration: **SU 0.613**. Triggering and compliance are independent bottlenecks; scores and model rankings **shift with the harness**.
- **Why it matters for Justin's agents:** This is the first eval that matches Anthropic's SKILL.md progressive-disclosure contract rather than "dump the full skill in the system prompt" (WikiSkill's eval setup). The 0.613 ceiling plus harness-conditioned rankings is the reason not to treat "Opus 5 is good at skills" as portable to Claude Code vs a custom Mitamaton harness. Measure Trigger separately from Compliance on Justin's own 10–15 skills.
- **Action signal:** `compare` — score Trigger / Compliance / Boundary on the existing `~/.claude/skills` set under Claude Code vs a thinner custom harness; do not collapse them into pass-rate.

### 3. The Personalization Mirage: How LLMs Fabricate User Profiles, and Why Self-Monitoring Misleads
- **Source:** arXiv (Hugging Face Daily Papers)
- **Link:** https://arxiv.org/abs/2608.04570
- **Authors / org:** Yushi Sun / Yanjie Zhang / Rui Sheng
- **Focus area:** Personalization + memory faithfulness
- **What it is:** Names **over-inference (OI)**: fabricating user attributes beyond the evidence. MirageBench: 150 personas (stereotypical / counter-stereotypical / neutral), 6 personalization tasks on an "imagination gradient", four-way faithfulness taxonomy with an independent judge (Cohen's κ = 0.863 four-class / 0.900 binary vs blind human on 400 claims), 12 models × 7 families, 143,616 judged claims. Every model over-infers **35–49%** of claims (mean 41.6%, claim-weighted 41.8%). **Self-Monitoring Inversion:** models' self-assessed OI is negatively rank-correlated with judge-measured OI (ρ = −0.60, p = 0.044; wide bootstrap CI). Within a single model, self-audit still ranks that model's own claims moderately (AUROC 0.58–0.83). OI is task-dependent (27–59%); in a multi-turn pilot, inferred attributes accumulate approximately linearly with little revision.
- **Why it matters for Justin's agents:** Mitamaton will write "Justin prefers X" notes from thin evidence. The operational rule: **external verification, not the model's confidence, is the memory-quality signal.** A self-audit prompt ("how sure are you this is a real preference?") is actively misleading for *choosing* a backend. Prefer typed, evidence-linked memories (source session + quote) over free-text user models, and do not let inferred attributes accumulate turn after turn without a revision pass.
- **Action signal:** `compare` — add a 20-claim OI probe (calendar, food, work-hours, tooling prefs) to the Mitamaton eval and score against a human-labeled evidence file, not against the model's self-rating.

### 4. Caching for the Future: Scrub Jay Episodic Memory Principles for Agent Memory Systems
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2608.04746
- **Authors / org:** Kartikey Singh Bhandari / Aarya Wadhwani / Dhruv Kumar / Pratik Narang
- **Focus area:** Agent memory (perishable facts / temporal decay)
- **What it is:** Persistent agents contaminate retrieval with outdated facts because every memory is treated as equally durable. ScrubJay-MEM encodes each memory as a jointly-bound What–Where–When tuple with an auto-classified perishability πᵢ and a utility horizon τᵢ, retrieves by query-adaptive scoring, and revises retroactively at O(1) LLM calls per update. Temporal Generalization Test (TGT) with held-out retention intervals and a Generalization Gap (GenGap) metric. ScrubJay-MEM is the only retrieval-based system with substantially positive GenGap (**+0.108**). On MemoryAgentBench EventQA-64k it improves F1 by **+2.66** over Mem0 and **+3.09** over Qwen3-Embedding-4B under a matched LLM backbone. A decay ablation collapses GenGap **5.7×**, so type-conditioned decay is load-bearing. Gains narrow under stronger backbones and **reverse on fact-consolidation tasks** — scoped to temporal reasoning over perishable facts.
- **Why it matters for Justin's agents:** Calendar times, restaurant picks, "current project," standup hours — Mitamaton's most-used memories *go stale*. PAST-Bench (2026-08-04) already showed the biggest Hermes+ lift is *replacing* outdated state; ScrubJay-MEM is a concrete store-side mechanism for that. Do not put perishability on every vault note (code facts, license text, skill procedures should not decay). Put it on dated prefs and world facts, and keep a consolidation path for things that should become permanent.
- **Action signal:** `try-now` — add a `perish_after:` / `as_of:` field to Mitamaton preference notes and drop expired rows from retrieval before touching embeddings.
