## Items

### 1. Ouroboros: A Self-Developing Frontier Coding Agent with Reviewed Core Evolution
- **Source:** arXiv (Hugging Face Daily Papers, surfaced Aug 11; placed on submitted date)
- **Link:** https://arxiv.org/abs/2608.08311
- **Authors / org:** Anton Razzhigaev / Andrei Gritsaev / Andrei Kaznacheev / Nikita Dragunov / Roman Yampolskiy / Andrei Kuznetsov
- **Focus area:** Self-developing coding harness
- **What it is:** Harness whose tools, prompts, context assembly, and core code improve through reviewed commits that then *are* the runtime. Recursive free evolution: improvement is itself a task and can schedule the next cycle. Experience-driven: ordinary work and social interaction expose bugs and inefficient context construction that become reviewed structural changes. Frozen-snapshot campaigns (not the live agent): Terminal-Bench 2.1 Opus 5 **86.74%** (best reported); OSWorld-Verified **90.69%** (exceeds prior best); five-rollout CL-Bench normalized reward **0.2301** SOTA. Hope: 161-day public free-evolution deployment under governed human communication across seven surfaces — humans surface faults and proposals, the agent decides which changes to pursue. Safety is a primary design problem because the agent may rewrite its own code and select new model APIs. Benchmarks freeze a snapshot; Hope continues on a separate lineage.
- **Why it matters for Justin's agents:** This is PILOT / WikiSkill taken to "the harness is a git repo the agent commits to." Two portable constraints, not a "let Claude Code rewrite Claude Code" invitation: (1) **reviewed** commits — a human or a frozen validator is on the merge, (2) **benchmark lineage ≠ live lineage** — never eval the agent that is currently mutating. Hope's 161 days is the existence proof that a long-running self-edit loop can be operated, not a recipe to copy without the guardrail story. For Mitamaton: allow skill/prompt PRs; do not allow the day-admin agent to change its own tool-authorization code.
- **Action signal:** `compare` — against Claude Code's current "edit the skill, I will review" loop; do not turn on recursive free evolution.

### 2. Mitigating Over-Personalization in LLMs via Structured Memory
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2608.08300
- **Authors / org:** Hakeem Hannoon / Andrew Zhao / Mihir Narayan / Sharvin Goyal / Ivaxi Sheth
- **Focus area:** Personal agent memory (presentation, not contents)
- **What it is:** Two failure modes of memory-augmented assistants: **cross-domain leakage** (work memories leak into personal answers and vice versa) and **memory-induced sycophancy** (stored user beliefs raise agreement). Inference-time-only change: how memories are *presented*, not what is stored. Seven models on PersistBench. Unstructured all-in-context list vs structured formats that partition by domain. Strongest method: **−8.8%** leakage on average vs baseline, utility preserved.
- **Why it matters for Justin's agents:** Completes yesterday's Personalization Mirage [arxiv:2608.04570]: Mirage says models fabricate attributes; this says even *true* memories, dumped as a blob, leak across domains and make the model a yes-man. Mitamaton should already have domains (work / health / calendar / social). The try-now is a prompt-layout change: inject only the matching domain plus a one-line "other domains exist but are withheld." Do not put the whole user wiki in the system prompt.
- **Action signal:** `try-now` — partition `wiki/` or memory notes by domain and inject one domain per Mitamaton turn; measure leakage on 10 cross-domain questions.

### 3. The Replay Gap: Static Evaluation of Model Switching in LLM Agents Scores the Wrong World
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2608.08239
- **Authors / org:** Ashritha Gonuguntla (independent)
- **Focus area:** Agent evaluation (routers / mid-run model swap)
- **What it is:** Agentic routers are scored like single-turn routers: replay a log, splice in another model's recorded outputs, assume the rest of the trajectory is unchanged. This paper forks *live* SWE-bench agent trajectories, rebuilds the environment, continues each fork with a different model, and compares to same-model control forks. Six paired runs, ~900 rollouts. Swaps exceed matched control floors by **+0.25 to +0.66** normalized edit distance (CIs exclude zero); rewrite **61–94%** of post-fork actions; **74–77%** of early swaps diverge at the first post-fork action vs 6–35% of controls; **3%** of replayed states remain valid. All five observed outcome flips are in swap arms (upgrades rescue, a downgrade loses the sole solve); **0 / 359** control forks flip. A log-stitching replay evaluator mispredicts every success-relevant outcome call and predicts patches with **0.00–0.11** similarity to what actually happened. Extra: temperature-0 "determinism" is serving-stack dependent (FP8 controls diverge on >90% of forks; AWQ stays near-identical). Under tight budgets the stronger model more often exhausts steps without submitting. Harness + trajectories released.
- **Why it matters for Justin's agents:** Any "route this Claude Code step to local Qwen to save money" idea cannot be validated by splicing Qwen into an Opus log. You have to actually fork the environment. Also a warning for the vault's harness-compare habit: if the compare is log-replay rather than live fork, the number is about the wrong world. Serving-stack footnote matters on the 64 GB box — "temp 0" is not a reproducibility guarantee under MLX / llama.cpp quant.
- **Action signal:** `compare` — if you A/B Opus vs local Qwen inside one Mitamaton / Claude Code task, fork live; do not score a spliced transcript.

## Conflicts & open questions
- **Conflict flagged:** Ouroboros's headline Terminal-Bench / OSWorld numbers are *frozen-snapshot, Opus 5* scores for a self-editing harness. They do not license "let the live agent keep editing" as the thing that produced 86.74%. The paper itself splits Hope (live) from benchmark lineage. Any later citation that collapses those two is a misread.
- **Convergent with Structured Memory + Mirage (Wed):** presentation and fabrication are different bugs. Fixing layout (today) does not fix over-inference (Wed).
- **Open question vs PILOT** [arxiv:2608.26530]: PILOT steers a *frozen* worker mid-run; Ouroboros lets the harness rewrite itself between runs. Complementary, uncompared.
