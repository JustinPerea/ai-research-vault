# AI Research Digest — Tuesday, June 2, 2026

## TL;DR
- **First MCP-native benchmark for personalized tools.** **[arxiv:2606.02470] MCP-Persona** (Shanghai Jiao Tong / Shanghai AI Lab; ICML 2026 camera-ready) builds the first benchmark for MCP tools that interact with *individual user accounts and local databases* (Reddit, Xiaohongshu, Lark/Feishu, Slack) rather than generic information-seeking endpoints. **SOTA agents "significantly struggle"** on real personalized tool use — a separate failure axis from the tool-retrieval-at-scale failure mode in [arxiv:2605.10787] ComplexMCP (May 12). The two benchmarks now define the production-realistic MCP eval space.
- **Lifecycle skill attacks formalize the second class of persistent agent compromise.** **[arxiv:2606.02540] SkillHarm** (Ohio State / Stanford / Amazon) automatically constructs poisoned-skill attacks — **86.3% ASR for Fixed-Payload Poisoning, 69.3% for Self-Mutating Poisoning** across 879 attack samples × 71 skills, with 12 risk types organized by agent-workflow component. Companion to yesterday's **[arxiv:2605.31042] ClawTrojan** (95.5% ASR via stored-and-replayed file injections) — together they document the *agent-as-its-own-attack-surface* failure mode: skill packages and workspace files are the durable carriers, single-step defenses are blind to both.
- **Unified Context Evolution posts the biggest single-paper ALFWorld jump this season.** **[arxiv:2606.02304] UCE** (CUHK-led) treats agent experience as a typed external library — Memory / Strategy / Workflow / Skill — and gradient-freely scores, retrieves, and prunes units across tasks. **ALFWorld 75.4% → 96.3% (+20.9 pts), WebShop 45.1% → 61.3% (+16.2 pts)**, transferable across backbones without retraining. Pushes the ALFWorld near-90% cluster ([arxiv:2605.06078] BEACON 92.9 / [arxiv:2605.06642] StraTA 93.1 / [arxiv:2605.05413] CC-Skill 89.6 / **UCE 96.3**) into clear new lead, mechanism = *typed-knowledge externalization* rather than reward shaping or in-weights skill compression.
- **Two strong pieces of orchestration evidence — multi-agent for computer use, online RL for web.** **[arxiv:2606.01533] Multi-Agent Computer Use** (Koh / Salakhutdinov / Fried, CMU) makes the manager-LLM emit a DAG of subagent tasks with continuous revision: **3.4–25.5% over single-agent baselines on OSWorld / Online-Mind2Web / WebTailBench / Odysseys + ~1.5× wall-clock speedup** on Odysseys. **[arxiv:2606.02031] OpenWebRL** (Microsoft) trains a 4B web agent end-to-end via online multi-turn RL on live browsers using only **0.4K initialization trajectories + 2.2K RL tasks**: **67.0% Online-Mind2Web, 64.0% DeepShop** — the strongest 4B open web agent result on these benchmarks.
- **DRIFT introduces the diagnostic primitive the long-horizon-collapse cluster has been missing.** **[arxiv:2606.02060]** (claim-centric audit that tracks agent claims, checks support in trajectory evidence, marks unsupported / conflicting spans) reports **up to +30 pts on span-level error localization** over baselines across **2,790 real trajectories × 2 frameworks × 3 backbones × 3 benchmarks**, plus releases TELBench (1,000 instances) for first-error-span localization. Where LongDS-Bench / DELEGATE-52 / citation-eval *measure* late-turn collapse, DRIFT *localizes* it — gives the per-step blame signal the cluster has been hand-waving.

### 1. MCP-Persona — First MCP-Native Benchmark for Personalized Tools
- **Source:** arXiv (submitted June 1, 2026; ICML 2026 camera-ready)
- **Link:** https://arxiv.org/abs/2606.02470
- **Authors / org:** Wenhao Wang, Peizhi Niu, Gongyi Zou, Xiyuan Yang, Jingxing Wang, Haoting Shi, Yaxin Du, Jingyi Chai, Xianghe Pang, Shuo Tang, **Yanfeng Wang**, **Siheng Chen** (Shanghai Jiao Tong + Shanghai AI Lab — Siheng Chen's federated/MAS cluster)
- **Focus area:** Tools & connectors / Evaluation
- **What it is:** Existing MCP benchmarks (ComplexMCP, BFCL, AceBench, MCP-Universe) target *generic information-seeking* endpoints — public APIs that any user can hit identically. MCP-Persona is the first benchmark explicitly built around the *personal-tool* class: MCP servers that interact with **individual user accounts and local databases** — Reddit (account-scoped feeds + DMs), Xiaohongshu / Rednote (posts + saves), Lark/Feishu (calendar + chat + docs), Slack (channels + messages + files). The harder structural property: many tasks depend on *what the user actually did* in account state, not on a static knowledge base, so the eval substrate has to model per-user history. Headline qualitative finding: SOTA agents "significantly struggle" on real personalized tool use. (Specific per-model numbers are in the paper PDF; the abstract states the qualitative result but not the leaderboard split, so the magnitude headline is provisional pending PDF read.)
- **Why it matters for Justin's agents:** (a) **This is the benchmark Justin's MCP-companion-app work has been operating without.** Every MCP server Justin builds for his agent products is by construction a personal-account tool (your calendar, your notes, your Slack, your repo). Generic MCP benchmarks have been measuring the wrong thing for this workload class — they reward read-the-public-web behaviors and miss the account-state-aware behaviors that actually matter for companion apps. MCP-Persona is the first benchmark whose task distribution matches the production workload. (b) Sits as a structurally distinct second axis next to **[arxiv:2605.10787] ComplexMCP** (May 12: first MCP-native at scale, 300+ tools across 7 stateful sandboxes; failure modes = tool retrieval degrades / overconfidence / abandonment-over-recovery). ComplexMCP measures *scaling* failure modes in the tool space; MCP-Persona measures *personalization* failure modes in account state. Both are production-realistic, neither subsumes the other. (c) For Justin's federal-data-engineering hat: the *per-account-scoped data access* property is also the structural shape of any enterprise-MCP deployment (per-user permissions on shared corporate data) — MCP-Persona is the closest public proxy for that class of eval. (d) ICML 2026 camera-ready + public benchmark + GitHub release means external reproductions arrive within weeks.
- **Action signal:** `try-now` `compare` — register a baseline run for any in-house MCP harness against MCP-Persona when code drops; cross-reference with [arxiv:2605.10787] ComplexMCP in the ledger as the two-axis production-MCP-eval cluster (scale + personalization).

### 2. SkillHarm — Lifecycle-Aware Skill-Based Attacks (86.3% / 69.3% ASR)
- **Source:** arXiv (submitted June 1, 2026)
- **Link:** https://arxiv.org/abs/2606.02540
- **Authors / org:** Yuting Ning, Zhehao Zhang, Yash Kumar Lal, Boyu Gou, Junyi Li, Weitong Ruan, Chentao Ye, **Rahul Gupta**, **Diyi Yang**, **Yu Su**, **Huan Sun** (Ohio State + Stanford + Amazon — Yu Su / Huan Sun = Mind2Web / SeeAct lineage)
- **Focus area:** Tools & connectors / Long-running autonomous loops
- **What it is:** Agent skills (Anthropic Skills, Claude Code SKILL.md files, OpenAI Apps, community skill packages) are now persistent first-class artifacts that get installed once and invoked across many sessions — the same threat-model shape that made browser extensions and PyPI packages such reliable supply-chain attack surfaces. SkillHarm builds **AutoSkillHarm**, an *automated* skill-poisoning pipeline using natural-language-driven coding agents, and a benchmark of **879 attack samples × 71 skills × 12 risk types** organized by agent-workflow component (data pipelines / system environments / agent autonomy). **Two attack vectors:** **Fixed-Payload Poisoning** (direct compromise — skill ships with a static malicious payload) hits **86.3% ASR**; **Self-Mutating Poisoning** (delayed harm — skill embeds logic that persistently modifies the agent's state, triggering harm in later sessions) hits **69.3% ASR**. Key sharp finding: many *apparent* attack failures are not the agent resisting — the agent simply hasn't engaged with the poisoned file yet. The defensive surface is even thinner than the raw ASR suggests.
- **Why it matters for Justin's agents:** (a) **Read with [arxiv:2605.31042] ClawTrojan from yesterday, this is the second 4-day-old paper documenting a class of stored-and-replayed agent attack that single-step defenses fundamentally miss.** ClawTrojan = workspace-file injection that the agent writes during one session and re-reads in a later session (95.5% ASR). SkillHarm = skill-package injection installed once and replayed every time the skill is invoked (86.3% / 69.3% ASR). The two papers cover the two natural carriers of multi-session persistence in modern agent harnesses (workspace files; installed skill packages) — together they establish *agent-as-its-own-attack-surface* as a measured 2026 failure mode, not a hypothetical one. (b) The Self-Mutating variant is the more architecturally interesting half — the payload **rewrites the skill itself in place during execution**, so an integrity check at install time is bypassed by definition. The defensive primitives that work for this class are runtime origin-tagging (DASGuard from yesterday's ClawTrojan paper) and the out-of-band-metadata channel ([arxiv:2605.29082] Redpanda); in-prompt guardrails and skill-install-time-static-analysis don't. (c) **For Justin's Skill-publishing work:** the threat model for any Claude Code Skill / MCP server published to a community catalog is now quantified. The 86.3% number is the right pressure on a "default-trust community skills" assumption — that assumption is no longer defensible. (d) Pairs cleanly with item 1 (MCP-Persona) — MCP-Persona measures *capability* failures on personal-account tools, SkillHarm measures *security* failures on the skill/tool layer. Two distinct production-MCP eval axes published the same day.
- **Action signal:** `try-now` `compare` — add SkillHarm to the agent-security cluster in the ledger as the skill-package counterpart to ClawTrojan's workspace-file attack; implement skill-origin tagging on any community-skill install path in the harness; verify install-time hashing of skill files matches at every invocation.

### 3. UCE — Typed Evolvable Context Units: ALFWorld 75.4 → 96.3, WebShop 45.1 → 61.3
- **Source:** arXiv (submitted June 1, 2026)
- **Link:** https://arxiv.org/abs/2606.02304
- **Authors / org:** Zixuan Zhu, Yitong Hu, Yong Dai, **Junfeng Fang**, Chunyang Jiang, Senkang Hu, Yuzhi Zhao (CityU HK + collaborators — Junfeng Fang = NUS / NExT lab agent-systems lineage)
- **Focus area:** Agent memory / Context engineering
- **What it is:** A **gradient-free** framework that externalizes agent experience into an evolving library of **typed Evolvable Context Units (ECUs)** with four explicit categories: **Memory** (specific past events), **Strategy** (general approach patterns), **Workflow** (procedural sequences), **Skill** (parametric primitives). Three coupled mechanisms: (1) **typed knowledge decomposition** — every new experience is parsed into the four ECU types rather than dumped as raw trajectory; (2) **quality tracking** — each ECU carries a score that updates based on whether retrieving it in later tasks correlated with success or failure; (3) **adaptive scheduling** — the system allocates future *generation* effort toward types/topics with weak coverage. Crucially, the library transfers across backbones without retraining the actor. **Numbers:** **ALFWorld success 75.4% → 96.3% (+20.9 pts), WebShop task score 45.1% → 61.3% (+16.2 pts)**.
- **Why it matters for Justin's agents:** (a) **The ALFWorld 96.3% is the highest published single-paper score in the four-paper ALFWorld near-90% cluster.** Prior members: **[arxiv:2605.05413] Constant-Context Skill Learning** (89.6%, procedural context in *weights*), **[arxiv:2605.06078] BEACON** (92.9%, milestone-level temporal reward shaping), **[arxiv:2605.06642] StraTA** (93.1%, top-down strategy abstraction). UCE's mechanism is fourth-axis-distinct (typed-knowledge externalization, no retraining), which means it should *compose* with the other three rather than replace them — open empirical question whether stacking ECU + BEACON + StraTA breaks the ALFWorld ceiling entirely. (b) The **typed-knowledge schema (Memory / Strategy / Workflow / Skill) is publishable on its own as a vocabulary** — most existing agent-memory systems use one bag-of-everything store and force the retrieval layer to disambiguate. UCE's claim that *typing* the writes (not just the retrieval index) is the source of the gains has independent evidential support: yesterday's **[arxiv:2605.31075] TaskMem** argued for *learned write policy* on streaming multimodal input, **[arxiv:2605.21463] Mem-π** (May 21) argued for *learned when-and-what* on text, and now UCE adds the *typing* axis. Together the three papers point at "what to memorize is the unsolved primitive" as the dominant 2026 memory-design insight. (c) **Gradient-free + cross-backbone transferable** is the load-bearing operational property — the ECU library is essentially a portable, model-agnostic skill/memory database that survives model swaps. For Justin's stack where the backbone moves between Claude Opus 4.8, local MLX Qwen, and frontier providers across the year, this is the right architecture. (d) The cross-backbone-transferability property is the structural complement to **[arxiv:2605.30785] AdaCoM** (yesterday: external context manager LLM for a frozen agent) — UCE supplies the *knowledge base* that an AdaCoM-style external manager would draw on. The two paper architectures plug together.
- **Action signal:** `try-now` `compare` — prototype a typed ECU store (Memory / Strategy / Workflow / Skill tables) in the agent harness; cross-reference with the four-paper ALFWorld near-90% cluster + the three-paper write-policy cluster in the ledger.

### 4. Multi-Agent Computer Use — Manager-DAG + Parallel Subagents (3.4–25.5% over Single-Agent)
- **Source:** arXiv (submitted June 1, 2026)
- **Link:** https://arxiv.org/abs/2606.01533
- **Authors / org:** **Jing Yu Koh**, **Ruslan Salakhutdinov**, **Daniel Fried** (CMU — VisualWebArena + Mind2Web lineage; Koh is also the OSWorld and Online-Mind2Web author)
- **Focus area:** Agent orchestration / Tools & connectors
- **What it is:** Standard computer-use agents (Claude Computer Use, OpenAI Operator-class) run as a single linear executor — see the screen, choose one action, see the result, repeat. This bottlenecks at any task whose subparts are independent (open three tabs, compare prices across them, fill the cheapest into a form). The CMU system uses a **manager model** to decompose the task into a **DAG** with explicit dependencies, **dispatches parallel subagents** to execute nodes whose deps are satisfied, and **continuously revises the DAG** based on what new screens reveal. Information retention across subagents is forwarded through the manager + DAG structure, addressing the partial-observability problem of CUA work. **Numbers:** **3.4–25.5% improvements over single-agent baselines on OSWorld, Online-Mind2Web, WebTailBench, Odysseys** — Odysseys (multi-step long-horizon web) gets the biggest jump *and* a **~1.5× wall-clock speedup** from the parallelism.
- **Why it matters for Justin's agents:** (a) **First paper to ship a credible multi-agent answer to computer-use specifically** — most prior multi-agent work has targeted text-based research/reasoning (WideSearch, Uno-Orchestra, DecomposeR). Computer use is the harder substrate because the manager has to reason about *screen state* not just text state. (b) The fact that **OSWorld and Online-Mind2Web both move under the same recipe** is the cross-benchmark evidence — these two suites have different failure-mode distributions (OSWorld = OS-level long tasks with file system, Online-Mind2Web = web-only browsing) and a manager-DAG architecture clearing both is stronger evidence than either alone would be. (c) Pairs structurally with **[arxiv:2605.30824] DecomposeR** from yesterday (typed-DAG plans as RL target for deep research) — both papers argue the *DAG as first-class plan structure* is the right abstraction at the orchestration layer, in two different task domains. The DAG-as-plan thesis is now a multi-paper cluster. (d) For Justin's MCP work: the manager-decomposes-into-DAG pattern is **directly implementable as an MCP server today** — the MCP server exposes a `decompose(task) → DAG` endpoint and a `dispatch(DAG_node)` endpoint, and the agent runs the inner loop. The 1.5× wall-clock speedup on Odysseys is the right scale of latency win for any user-facing companion-app workflow.
- **Action signal:** `try-now` — implement a manager-DAG + parallel-subagent dispatcher on top of an MCP harness; cross-reference with [arxiv:2605.30824] DecomposeR, [arxiv:2604.27221] WideSearch, [arxiv:2605.05007] Uno-Orchestra as the DAG-as-plan-structure cluster.

### 5. DRIFT — Span-Level Error Localization in Deep-Research Agent Trajectories (+30 pts)
- **Source:** arXiv (submitted June 1, 2026)
- **Link:** https://arxiv.org/abs/2606.02060
- **Authors / org:** Jiaming Wang, Ziteng Feng, Jiangtao Wu, Ruihao Li, **Qianqian Xie**, Yuxiang Ren, He Zhu, Xueming Han, Fanyu Meng, **Junlan Feng**, **Jiaheng Liu** (China Mobile + Wuhan U / Yale lineage — Junlan Feng is a long-running NLP-systems author; Qianqian Xie = FinGPT)
- **Focus area:** Evaluation / Reasoning & inference-time compute
- **What it is:** Existing agent evals score the final output — they don't tell you *where* in a long trajectory things went wrong. DRIFT is a **claim-centric audit framework** that (1) extracts every claim the agent emits along its trajectory, (2) checks whether each claim is supported by the evidence in the agent's *own* tool/search outputs, (3) marks the spans where unsupported or conflicting claims propagate into the answer path. **Eval setup:** **2,790 real trajectories × 2 agent frameworks × 3 backbones × 3 benchmarks**, plus a derived **TELBench** of 1,000 instances for first-error-span localization. **Numbers:** **+30 pts on span-level error localization and first-error accuracy** over baselines.
- **Why it matters for Justin's agents:** (a) **DRIFT supplies the per-step blame signal that the long-horizon-collapse cluster has been hand-waving over.** Yesterday's **[arxiv:2605.30434] LongDS-Bench** measured that long-horizon errors account for 52–69% of total failures with a ~47-point early-to-late decline; **[arxiv:2604.15597] DELEGATE-52** measured 25% content corruption in long delegated edits; **[arxiv:2605.06635] AST-parser citation-eval** measured 42% factual-accuracy drop as tool-call depth scales 2 → 150. All three measure *that* collapse happens. DRIFT gives the diagnostic primitive for *where* the collapse happens — without per-span localization, the cluster has been measuring an aggregate failure rate with no actionable signal. (b) The **claim-centric** framing is structurally close to **[arxiv:2605.03042] ARIS** (May 10: 5-pass scientific editing pipeline + claim auditing in the "Assurance" layer) — ARIS bakes claim auditing into the runtime; DRIFT bakes it into post-hoc evaluation. The two together suggest *claim-as-the-unit-of-eval* is converging as the standard rather than answer-as-the-unit. (c) Pairs with **[arxiv:2605.29087] Trace-Answer Dissociation** (May 31: 50% latent-correct rate in think mode vs. 11–15% no-think; correct answer present in 84% of "Unfaithful Capitulation" instances) — Trace-Answer Dissociation argued the answer and the trace decorrelate; DRIFT supplies the audit primitive that can *quantify* this per-trajectory. (d) **For Justin:** instrument any long-running deep-research / data-analysis loop to emit claim-evidence pairs; you can run DRIFT-style local audits without the full TELBench training pipeline and get a much sharper internal eval than "did the final answer pass."
- **Action signal:** `try-now` `compare` — implement claim-extraction + evidence-support audit as a post-hoc trajectory analyzer; update LongDS-Bench / DELEGATE-52 / citation-eval cluster in the ledger to note DRIFT as the diagnostic primitive that fills the localization gap.

### 6. OpenWebRL — 4B Web Agent via Online Multi-Turn RL (67.0% Mind2Web / 64.0% DeepShop)
- **Source:** arXiv (submitted June 1, 2026; 36 pages)
- **Link:** https://arxiv.org/abs/2606.02031
- **Authors / org:** Rui Yang, **Qianhui Wu**, Yuxi Chen, Hao Bai, **Wenlin Yao**, **Hao Cheng**, **Baolin Peng**, Huan Zhang, Tong Zhang, **Jianfeng Gao** (Microsoft Research + UIUC + UCLA — Jianfeng Gao's MSR group, prior CUA-Gym lineage)
- **Focus area:** Tools & connectors / Local & open models for Apple Silicon
- **What it is:** A full open recipe for training a small visual web agent end-to-end via **online multi-turn RL on real live websites** (not simulated, not from cached HTML). Five components: scalable live-browser infrastructure, supervised initialization, multimodal context management, trajectory-level success judging, efficient multi-turn policy optimization. Strikingly small training budget: **0.4K initialization trajectories + 2.2K RL training tasks** trains a **4B-parameter model** to **67.0% on Online-Mind2Web and 64.0% on DeepShop** — competitive with much larger closed-source CUAs. Paper systematically ablates the design choices.
- **Why it matters for Justin's agents:** (a) **4B + open recipe + 67% Online-Mind2Web is the size class that fits comfortably on M5 Max.** The implication is that running a *trainable* web agent locally (not just inferring from a frozen one) is now operationally tractable — the online-RL training loop can run against a live browser in a container on the same M5 Max that serves inference. This is the cleanest path Justin has to a privately-trained companion-app web layer. (b) Joins the CUA cluster — **[arxiv:2605.29119] PRO-CUA** (May 31: decoupled on-policy environment interaction from policy optimization using PRM step-level feedback), **[arxiv:2605.25624] CUA-Gym** (env side), and **MagenticLite / Fara1.5** (Microsoft May 21 small-model agentic system). OpenWebRL is the *full end-to-end recipe* the cluster has been building toward, and notably it comes from the same Microsoft lineage as Fara1.5 + CUA-Gym. (c) The **2.2K RL task budget** is the sharpest data-efficiency point in the cluster — most prior open CUA work needed 50K-500K trajectories. The implication is the training cost curve is now low enough that fine-tuning a domain-specific web agent (federal-data-portal navigation, internal-Slack workflows, etc.) is a weekend project not a quarter project. (d) Limitation: the 67% Online-Mind2Web vs. CMU's Multi-Agent Computer Use system (item 4) is not directly comparable — Multi-Agent uses a frontier backbone and orchestrates many calls; OpenWebRL trains a 4B model end-to-end. **Open empirical question:** does running OpenWebRL-4B *under* the Multi-Agent-Computer-Use DAG manager compose, or does the 4B's individual ceiling cap the orchestration?

Cross-reference with PRO-CUA, CUA-Gym, Fara1.5 in the ledger as the CUA-training cluster.

### 7. eMoT — Evolving Memory-of-Thought with Symbolic Anchoring (100% Game-of-24)
- **Source:** arXiv (submitted June 1, 2026)
- **Link:** https://arxiv.org/abs/2606.02054
- **Authors / org:** Xiang Li, Jiwei Wei, Ke Liu, Yitong Qin, Jinyu Guo, **Malu Zhang**, **Peng Wang**, **Yang Yang** (UESTC — Yang Yang's reasoning-with-memory lab)
- **Focus area:** Agent memory / Reasoning & inference-time compute
- **What it is:** A framework that treats reasoning traces as *evolving memory* with three coupled mechanisms: (1) **memory corrosion** — high-utility reasoning sub-traces are reinforced across repeated tasks while low-utility traces decay, so the in-memory reasoning library self-curates; (2) **symbolic anchoring** — Python is used as a deterministic backstop for any subproblem where neural reasoning is unreliable (arithmetic, combinatorics, parsing); (3) **consistency-driven refinement** — the system actively reconciles the neural answer against the symbolic outcome, refusing to commit when they diverge. **Numbers:** **Game of 24: 100% accuracy, +17.6 pts over baseline.** Consistent gains across GSM8K, ASDiv, SVAMP, MGSM with a lightweight backbone (specific model unnamed in abstract).
- **Why it matters for Justin's agents:** (a) **Mechanistically third-axis-distinct from yesterday's memory papers and complementary to them.** [arxiv:2605.31075] TaskMem = learned *write policy* on streaming input. [arxiv:2605.30785] AdaCoM = external *context manager* for a frozen agent. eMoT = *utility-decay-driven self-curation* of reasoning traces inside the memory. The three together cover write-time, manage-time, and decay-time as separable memory axes — none of the three subsumes the others. (b) The **symbolic-anchoring + consistency-refinement** combination is the most aggressive published version of the *neuro-symbolic verifier* pattern this season. It pairs naturally with yesterday's **[arxiv:2605.30738] MAVEN** (intermediate verification scaffold lifting GPT-OSS-120b 48% → 71% on tool-use math/physics) — MAVEN verifies tool outputs, eMoT verifies reasoning chunks; the two could compose into a single agent that verifies both layers. (c) The 100% on Game of 24 (a small, well-structured benchmark) is less interesting on its own than the **+17.6 pts margin** and the consistency-driven-refinement mechanism — the mechanism transfers; the benchmark ceiling does not. (d) The **memory-corrosion** primitive (high-utility-reinforcement / low-utility-decay across repeated tasks) is a direct counter to **[arxiv:2605.08060] Memory Curse** (May 11: expanded accessible history degrades cooperation). The Curse and TaskMem and now eMoT all target *what gets carried forward*; eMoT's specific contribution is making the decay rate a function of *observed task utility* not raw recency.
- **Action signal:** `track` `compare` — promising mechanism cluster, magnitude-on-real-agent-tasks (vs. Game of 24 and grade-school math) is the next experiment; cross-reference with TaskMem, AdaCoM, Memory Curse in the ledger as the four-axis write/manage/decay/policy memory cluster.

## Local-model corner

One on-axis open release today: **JetBrains Mellum2** (HF blog, June 1).

- **Model:** **Mellum2** — **12B total / 2.5B active** Mixture-of-Experts, text + code (no multimodal), **Apache 2.0**. JetBrains explicitly positions it as a "focal" model — a sub-agent component for routing, orchestration, RAG context compression, summarization, retrieval post-processing, planning, validation, transformation, and code completion. Not a full agent base.
- **Memory fit:** 12B total at Q4_K_M GGUF ≈ **6.5–7 GB on disk**; the MoE active set (2.5B per token) means runtime memory pressure during decode is closer to a 2.5B dense model. KV cache for moderate context windows (32K, untested public claim) lands in the low single-digit GB. **Total ~12–18 GB of unified memory under MLX with a comfortable working context.** Leaves ~45 GB free on a 64GB M5 Max — enough headroom to run Mellum2 *alongside* a larger reasoning model (Qwen3-30B-A3B, Gemma-4-26B-A4B) and a local MCP server on the same machine.
- **Realistic tasks:** **Sub-agent / focal roles only** — JetBrains is explicit that this is not a flagship reasoner. Practical fits per their framing: (a) **context compression in front of a remote frontier executor** (the AdaCoM-architecture role from yesterday — small local manager, big remote actor), (b) **classification / routing** in an MCP gateway (which tool to invoke; which backend to escalate to), (c) **retrieval post-processing** (rerank → summarize → forward to executor), (d) **inline code completion** (its strongest published fit — JetBrains has the IDE distribution to validate this). NOT a fit for: long-horizon planning, deep reasoning, or autonomous agent loops.
- **How to run:** **MLX** is the right path on Apple Silicon — `mlx_lm` ships standard MoE support; community GGUFs from the launch will surface on Hugging Face under `JetBrains/mellum-2` within days. `llama.cpp` GGUF runs identically. Inference speed is the load-bearing claim: JetBrains reports ">2× faster than similar-sized models" — on M5 Max, a 2.5B-active MoE typically benchmarks in the **120–180 tok/s decode** range; specific Mellum2-on-M5-Max numbers are not yet public.
- **Pairing with yesterday's AdaCoM (item 2 of 2026-06-01) and today's UCE (item 3):** Mellum2 is **exactly the right size to be the small local LLM** that AdaCoM proposes as an *external context manager for a frozen remote executor*, and is also a plausible *retrieval/scoring head* over a typed-ECU library (item 3) that lives on disk. The architecture is now a published full stack: **typed-ECU store (UCE) on local disk + Mellum2 as the local context manager (AdaCoM role) + remote Claude Opus 4.8 as the frozen executor.** First full week the components for that stack have all been published.
- **Caveats:** Training-token count, exact context length, and per-benchmark numbers are not in the launch post — they're in the technical report (arxiv:2605.31268) which has not been verified for this digest. The "competitive with similar-sized open models" framing is qualitative and the specific benchmark splits should be confirmed before treating the model as the strongest in class.

- **Open empirical question: does typed-ECU memory (UCE) inherit the Memory Curse?** **[arxiv:2605.08060] Memory Curse** (May 11) — expanded accessible history degrades cooperation in 18 of 28 settings via erosion of forward-looking cooperative intent. The Curse was demonstrated on unstructured-history memory. UCE provides structured, typed, scored-and-pruned memory — which *should* mitigate the Curse by definition (the pruning step removes the lexical traces that drive the cooperative-intent erosion), but neither UCE nor TaskMem nor Mem-π tests on the Memory Curse benchmark. This is the second time in two days this open question has surfaced — pulling forward yesterday's open question on TaskMem as a duplicate of the same gap. Suggested experiment: run UCE + TaskMem + eMoT on a cooperation game from the Memory Curse benchmark with matched memory budgets; if structured-typed memory still degrades cooperation, the Curse is mechanism-agnostic.

- **Open empirical question: can OpenWebRL-4B (item 6) and Multi-Agent Computer Use (item 4) be composed?** OpenWebRL trains a 4B web agent end-to-end (67% Online-Mind2Web); Multi-Agent Computer Use is a manager-DAG architecture over a frontier backbone (3.4–25.5% over single-agent). The natural composition is: Multi-Agent Computer Use's manager dispatches OpenWebRL-4B as the parallel-subagent worker. Whether the 4B's per-call ceiling caps the orchestration's gains, or whether the parallelism amortizes the per-call limit, is the next experiment — and the test that would tell us whether *small specialist + DAG orchestration* beats *single frontier model* on web CUAs. Neither paper ran this composition.
