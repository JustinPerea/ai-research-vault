### 1. Agent-Controlled Forgetting for Tool-Using Agents: Reversible Context Curation in Practice
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.10590
- **Authors/org:** Jan-Peter Franke
- **Focus area:** tool-use / context curation
- **What it is:** Tool-using agents carry observations whose useful content is often much smaller than the payload. Agent-controlled forgetting lets the acting model select prior tool results, replace each with a short note at its original position, and keep the exact original in a recoverable archive. A Python harness exposes batch archival and explicit recovery without task-specific training, while protecting user instructions and assistant messages. In an exploratory OpenTelemetry debugging case followed by an unrelated implementation task: 231,951 provider prompt tokens vs 912,492 under retained history (50% fewer cumulative input tokens; about USD 1.28-1.44 vs about 4.38). Both arms passed the two-case primary behavioral oracle.
- **Why it matters for Justin's agents:** Directly applicable to Claude Code / MCP tool traces: archive bulky tool results out of context with a short note and recover on demand, instead of letting the history balloon.
- **Action signal:** `try-now`

### 2. Curating Always-Loaded Context for LLM Agents: A Capacitated Assortment Model with Censored Feedback
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.11007
- **Authors/org:** Zexuan Liu, Yuning Yang, Tiancheng Zhao
- **Focus area:** context files / AGENTS.md
- **What it is:** At session start LLM agents load a fixed context file (e.g. AGENTS.md); every loaded token is charged again each later round, and growing files can degrade performance, yet curators usually append. Formulates curation as a capacitated assortment problem: instructions consume tokens under finite attention; adding one never raises compliance of others; retained instructions incur per-session setup cost. Proves an upper bound on optimal file size regardless of candidate count, and that appending every positive-standalone-value instruction can be arbitrarily worse than an optimal subset.
- **Why it matters for Justin's agents:** Stop treating AGENTS.md / CLAUDE.md as append-only. Budget always-loaded instructions and drop low-value ones; the math says appending everything useful is wrong.
- **Action signal:** `try-now`

### 3. What to Admit and How to Present: Governing Persistent Memory in LLM Agents
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.11188
- **Authors/org:** Chang Liu, Deliang Ding
- **Focus area:** memory admission / presentation
- **What it is:** Persistent memory improves personalization but can induce sycophancy and cross-domain leakage. Separates two governance decisions: admission (what recalled info enters working context) and presentation (how admitted info is expressed). Two inference-time designs without retraining: factor-compiled admission (FC) assessing whole entries, and permission-semantic admission (PS) decomposing entries into typed units; both use deterministic policies. On an external benchmark (four tasks times 300 samples), FC and PS cut pooled judge-assessed failure rates vs verbatim injection by 6.7 and 8.8 pp.
- **Why it matters for Justin's agents:** Pair with yesterday's CASK: decide what memory is allowed into the turn, then how it is phrased — not just what gets stored.
- **Action signal:** `try-now`

### 5. DeltaReplay: Task-Relative Memory Reuse for Mobile GUI Agents
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.11707
- **Authors/org:** Yudong Bai, Yihong Chen, Quanming Yao et al. (4 authors)
- **Focus area:** mobile GUI agent memory
- **What it is:** Memory-augmented mobile GUI agents store successful trajectories, but a stored trajectory rarely matches a new task exactly (different parameters, partial overlap, or no relevant record). Forcing irrelevant memory misleads; discarding useful memory wastes experience. DeltaReplay is a step-level reuse framework that decides how to use existing memory without modifying it, via page-level consistency and action-level generality over a transition-graph of trajectories.
- **Why it matters for Justin's agents:** For iOS/GUI agents: reuse memory at the step level relative to the new task, not whole-trajectory replay.
- **Action signal:** `compare`

### 6. Use and Disuse: Intent-Structured Experience Consolidation for Memory and Learning in LLM Agents
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.12124
- **Authors/org:** Xiangyi Zeng, Baihang Liu, Xutong Wang et al. (6 authors)
- **Focus area:** experience consolidation
- **What it is:** Hippocam is a hierarchical memory and continual-learning architecture inspired by goal-selective maintenance and gradual consolidation. Structures ongoing work as nested intents: active context stays on the current intent; completed intents consolidate into task-relevant outcomes and state rather than full working details. A recursive prefix consolidation mechanism repeatedly consolidates experience into reusable knowledge for long-term autonomous operation.

### 7. MemoWM: How World Models Change What Agents Need to Remember
- **Source:** arXiv (cross-list)
- **Link:** https://arxiv.org/abs/2610.10778
- **Authors/org:** Bingfan Zeng, Zhisheng Chen, Chenbo Sang et al. (9 authors)
- **Focus area:** world-model conditioned memory
- **What it is:** Long-term agents face growing storage as they accumulate experience. World models capture reusable regularities that can cut per-experience storage. MemoWM allocates memory conditioned on a world model: shared predictions compress retained info and reconstruct omitted content; a task-aware rule balances reconstruction-error impact vs storage cost. Across five long-term agent-memory benchmarks: 42.42% average answer accuracy (+2.62 pp over strongest baseline) while cutting average experience-specific storage 53.9% vs MIRIX.
- **Why it matters for Justin's agents:** If you already have a predictive model of recurring user/world patterns, store only the residual that the prior cannot predict.
- **Action signal:** `track`

### 8. Real Long-Term Memory for AI: A 50-Million-Token Window That Is Faster and Cheaper Than Recompute
- **Source:** arXiv (cross-list)
- **Link:** https://arxiv.org/abs/2610.10845
- **Authors/org:** Sietse Schelpe
- **Focus area:** KV-cache persistence
- **What it is:** Tests galahad-kv, a public package that saves KV state of about 16k-token blocks to encrypted local NVMe and loads it back byte-exact without recompute. On 50M tokens of public text via vLLM on one H100 with Gemma 4 12B and 31B: 100/100 probed blocks loaded with no recompute at depths 0 to 50M; load 2.8 to 4.3x faster than recompute and 8.8 to 12.3x less GPU energy; GPU memory stayed flat. The 12B model answered facts planted millions of tokens earlier at 82% (per abstract).
- **Why it matters for Justin's agents:** Practical local persistent KV layer for long-lived agents — worth a try on a local GPU stack if you keep a large always-on context. As tested, 12B/31B need discrete VRAM; smaller open models would be the 64 GB unified-memory fit.
- **Action signal:** `compare`

### 9. Gated Memory: Admission-Controlled Memory Formation for Conversational AI
- **Source:** arXiv (cross-list)
- **Link:** https://arxiv.org/abs/2610.11270
- **Authors/org:** Preeti Saraswat, Divya Neelagiri, Ajay Manoj
- **Focus area:** memory admission gate
- **What it is:** Personalized conversational AI extracts facts into persistent vector stores, but the formation stage (first write) has almost no principled attention. Critical signals (permanent attribute vs transient situation) exist only in the original utterance and are lost once extraction produces a subject-relation-object triple. ### 10. REMORY: Learning Residual Memory for Context Compaction
- **Source:** arXiv (cross-list)
- **Link:** https://arxiv.org/abs/2610.11287
- **Authors/org:** Hanchen Xia, Baoyou Chen, Yutang Ge et al. (8 authors)
- **Focus area:** residual memory / compaction
- **What it is:** Long-horizon agents compact history to fit a finite window, but a textual summary alone may not support every later decision. REMORY supplements the summary with a bounded sequence of soft memory tokens that help a frozen LLM approximate the continuation it would produce with full history — an analogue of a residual connection along the sequence. On SummHay, improves source attribution at nearly unchanged insight coverage using only 5.2% of input positions; gains on Qwen3.8-27B and GLM-5.3-Flash agent benchmarks.
- **Why it matters for Justin's agents:** If you summarize agent history, keep a small learned residual alongside the text summary rather than summary-only.
- **Action signal:** `track`

### 14. Harness Evolution Hits a Ceiling: When Weight Training Should Begin
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.11655
- **Authors/org:** Yuan Tian, Bing Hu, Hao Wang et al. (5 authors)
- **Focus area:** harness vs weight training
- **What it is:** Improving a long-horizon agent means evolving the harness around a frozen model or training weights. Labels failed trajectories by the first signal that fires into process failures (blocked calls, loops, exhausted budgets) vs content failures (delivered but poor plan). Harness evolution repairs process failures (behavior can later be trained into weights); content failures need weight training. On DeepPlanning, self-evolving harness lifts Qwen3.5-4B from 0.16 to 0.30 and 9B from 0.32 to 0.44 held-out.
- **Why it matters for Justin's agents:** Diagnose failures before choosing the lever: fix the harness for loops and blocked tools; only train weights when the plan content itself is wrong.

### 31. Who Verifies the Verifier? Co-Evolving Inspectable Graders with Self-Improving Agents
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.11464
- **Authors/org:** Xing Zhang, Guanghui Wang, Yanwei Cui et al. (7 authors)
- **Focus area:** co-evolving graders
- **What it is:** Self-improving loops need a verifier; on open-ended tasks a hand rubric or bare LLM judge invites reward hacking. ### 36. One Word Opens the Gate: The Option-Channel Attack on Typed Decision Models as Agent Guardrails

## Conflicts & open questions

- **Admission at write vs read?** Gated Memory (2610.11270) and Governing Persistent Memory (2610.11188) put decisive governance at formation/admission; Agent-Controlled Forgetting (2610.10590) and REMORY (2610.11287) act at context-curation/compaction time; MemoWM (2610.10778) and DeltaReplay (2610.11707) decide what to reuse relative to a predictive prior or new task. Open: one pipeline that gates writes, then budget-curates always-loaded context, then forgets bulky tool payloads.
- **Harness evolution vs weight training vs winner's curse?** Harness as Only Mutable Surface (2610.10629) and AgentEvolver (2610.11613) want harness-only self-evolution; Harness Evolution Ceiling (2610.11655) says process failures are harness and content failures need weights; yesterday's winner's-curse (2610.09239) and today's Who Verifies the Verifier (2610.11464) say unanchored verifiers overstate gains. Open: can a hash-chained harness admission gate plus anchored graders make AgentEvolver's 82% SWE-bench Pro claim trustworthy?
- **Skills: conflict vs contrast vs morph?** One Skill Too Many (2610.11647) shows co-installed near-duplicates silently drop constraints; SkillContrast (2610.11650) reranks by differing text; SkillMorph (2610.11858) localizes faults inside a skill. Untested: whether SkillContrast reduces the conflict rate measured by 2610.11647.
- **Soft classifiers vs schema gates for safety?** Option-Channel Attack (2610.12292) and BRANCH (2610.10742) show typed/multi-scanner guards fail under polarity and ensemble attacks; NOMOS (2610.11030) compiles policies to deterministic schema gates; ObligationBench (2610.11773) says even good ban-checkers miss required actions. Prefer compiled gates + obligation checks over yes/no classifiers.
- **Time budgets again:** On the Clock (2610.10833) confirms yesterday's AgentTime (2610.09944): prompt-only budgets fail; the clock belongs in the harness.
- **Computer-use judges:** AgentHorizon (2610.11050) shows instruction-swapped negatives expose false successes — same spirit as TestJack (2610.10619) for coding benchmarks.
