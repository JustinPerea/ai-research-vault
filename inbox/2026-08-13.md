### 2. AI4AI at Test-Time: Strong-to-Weak Capability Transfer via Harnesses
- **Source:** arXiv (Hugging Face Daily Papers)
- **Link:** https://arxiv.org/abs/2608.12307
- **Authors / org:** Cheng Qian / Wenting Zhao / Liangwei Yang / Heng Wang / Jielin Qiu / Heng Ji / Silvio Savarese / Huan Wang / Shelby Heinecke
- **Focus area:** Agent harnesses + local / small models
- **What it is:** Asks whether strong-to-weak transfer can happen *at test time* — a stronger builder writes an inference-time harness that a weaker frozen target then uses, no parameter updates. Four Theory-of-Mind benchmarks; builder uses 5% of data as val to iteratively refine the harness, then evaluate on the full test set. Average target performance **0.49 → 0.91**. Ablation/analysis: gains come from **offloading unstable reasoning into deterministic code, benchmark-specific routing, and strict answer-format enforcement**, not from longer CoT or broader sampling. Builder reasoning effort improves harness quality monotonically; weaker targets gain the most. Submitted Aug 12; abs verified this run.
- **Why it matters for Justin's agents:** This is the cleanest "Opus writes the harness, Qwen-4B/9B runs it" result of the week and maps onto the 64 GB local stack. Weekend experiment: pick 10 Mitamaton / personal-eval tasks, let Opus (or Gemini 3.7 Flash) emit a SKILL.md + a tiny checker script, freeze both, run Qwen3.5-4B / 9B against the checker. The paper's warning is also the design rule — if the harness is just "think harder," expect nothing; if it is code + router + format gate, expect the jump.
- **Action signal:** `try-now` — one builder pass, one frozen local target, no fine-tune.

### 3. Agent Safety Should Be a Runtime Contract
- **Source:** arXiv (Hugging Face Daily Papers)
- **Link:** https://arxiv.org/abs/2608.11274
- **Authors / org:** Albus W. Ng / Yi Han / Jusheng Zhang / Wenhao Wang
- **Focus area:** Agent security + harness design
- **What it is:** Position paper: RLHF / DPO / Constitutional AI are structurally insufficient for agents that execute code, mutate files, send messages, and write databases. Safety is a **runtime contract** with two faces — **preventive** (sandboxes, permission gates, output filters, trajectory monitors) and **evidential** (submission gated on tests, log captures, file diffs, citation grounding). Evidence: survey of **52** documented agent/LLM safety incidents; false-completion audit (**31** non-contested core cases); trajectory-schema audit of **12** public agent systems/harnesses; title-level audit of **28,560** NeurIPS/ICML/ICLR 2023–2025 papers showing a pooled **8–12×** imbalance of training-time vs deployment-time safety work. Formalizes an Agent Trajectory Schema + Evidence Chain; supplementary JSON released. Submitted Aug 11; abs verified this run.
- **Why it matters for Justin's agents:** This is the architectural sentence to put above Mitamaton's side-effecting tools (mail, calendar write, file mutate): *the unit of safety is the trajectory-with-checkable-evidence, not the model.* Minimum viable port: (1) permission gate on send/create/delete, (2) refuse to mark a day-admin task done unless a diff / sent-item / calendar-ack exists, (3) keep that evidence out of the model's mouth — the harness checks it. Complements later SARA [arxiv:2608.27146, 2026-08-28] (authorization ≠ induction) by naming the *evidential* half those papers often skip.
- **Action signal:** `try-now` — add an evidential submit-gate to the 3–5 side-effecting Mitamaton tools; leave the full schema as a later refactor.

### 4. ToolHazard: Scaling Adversarial Environments for Agent Security
- **Source:** arXiv (Hugging Face Daily Papers)
- **Link:** https://arxiv.org/abs/2608.11878
- **Authors / org:** Yutao Mou / Pengfei Yang / Zhe Yin / Zhangchi Xue / Xiaotian Luan / Dingyao Yu / Tong Zhang / Shikun Zhang / Wei Ye
- **Focus area:** Agent security (indirect prompt injection) + eval
- **What it is:** Existing IPI evals rely on hand-built or reused environments, stochastic LLM-simulated tools, and predefined injection sites. ToolHazard is a synthesis loop — Environment Simulator + Attacker Agent + User Simulator — that builds executable stateful environments, discovers injection points, writes environment-specific payloads, and constructs state-grounded long-horizon tasks. ToolHazard-Bench stress-tests agents under complex workflows and diverse environmental attacks. Findings: substantial vulnerabilities; **injection timing and placement change attack effectiveness**. Alignment data generated by the framework improves security on ToolHazard-Bench **and AgentDojo** while preserving benign utility. Submitted Aug 12; abs verified this run.
- **Why it matters for Justin's agents:** This is the generator you want *before* you trust a "we're safe, we prompt-filter tool output" claim. Two portable facts: (1) *when* the injection lands matters as much as *what* it says — a calendar-update payload at the end of a long Mitamaton session is a different attack than one in turn 1; (2) synthetic alignment data can transfer to AgentDojo, so a small personal-tool attack set is worth generating even if you never train. Use as the eval companion to item 3's runtime contract, not as a replacement for it.
- **Action signal:** `compare` — generate a 10-payload personal-tool attack set (mail/calendar/files) and score the current Claude Code / Mitamaton loop; do not fine-tune on it until the runtime gates exist.
