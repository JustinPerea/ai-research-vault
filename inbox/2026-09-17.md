### 2. Contiguity, Not Importance: Budgeted Repair of Stale KV Caches After Document Edits
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2609.17983
- **Authors/org:** Mingyang Mao, Wyatt Mackey, Xiaomin Lin
- **Focus area:** KV cache / context edits
- **What it is:** Budgeted in-place repair of stale KV caches after edits to retrieved knowledge, working memory, or user state. A contiguous edit-local window recovers ≥0.94 of the post-edit answer margin, beats attention-, KV-deviation- and structural selectors, and is 13–21× faster than full re-prefill; the edge vanishes when answer-bearing text moves downstream.
- **Why it matters for Justin's agents:** If a cached profile/memory block is edited, refresh a contiguous window after the edit, not just the edited span; fall back to full re-prefill when dependent text is not adjacent. Directly applies to prefix-cached memory blocks in a local model stack.
- **Action signal:** `try-now`

### 3. The Other Half of the Memory Wall: Serving 35B MoEs from SSD with Trained Routing Prediction
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2609.18063
- **Authors/org:** Yu Lin, Yiming Wang, Runyuan Cai, Hanze Liu, Xiaodong Zeng
- **Focus area:** local MoE serving / SSD offload
- **What it is:** Edge0 streams a 35B MoE from SSD using a per-layer prerouter that predicts next-layer routing one token ahead (the prediction is the routing, so nothing is dropped), plus an unmerged recovery LoRA for int4 + routing loss. On a single 24GB machine it serves 35B at 20 tok/s in 3 GiB peak active memory, within a few points of the fp16 teacher; an 8B tier too. Framework, checkpoints and adapters open source.
- **Why it matters for Justin's agents:** Another SSD-offload path for 35B-class MoEs on consumer hardware; compare against existing Mac expert-offload setups for always-on local agents.

## Conflicts & open questions
- **Self-evolving skills vs poisoned self-evaluation:** EvoSkill-GUI ([`2609.17653`](https://arxiv.org/abs/2609.17653)) and CHASE ([`2609.18366`](https://arxiv.org/abs/2609.18366)) improve agents by editing skills/harnesses from feedback; Trusting Trust Revisited ([`2609.17817`](https://arxiv.org/abs/2609.17817)) shows that same loop can be steered into insecure instructions that persist after clean re-evolution. Any skill write path needs eval-set provenance and human-readable diffs.
- **Step-level guards vs trace-level policy:** ContrAgent ([`2609.18128`](https://arxiv.org/abs/2609.18128)) gates per call with temporal contracts; Compositional Policy Violations ([`2609.18820`](https://arxiv.org/abs/2609.18820)) argues per-step checks cannot catch cumulative/authority violations. Likely complementary (LTLf over the full trace covers some CPV types) — untested together.
- **Memory first or control first?** The SwiftSage extensions ([`2609.19128`](https://arxiv.org/abs/2609.19128)) find execution-time reflection dominates and memory helps only once the loop is stable, while LGM ([`2609.18461`](https://arxiv.org/abs/2609.18461)) and Memory Has Geometry ([`2609.17969`](https://arxiv.org/abs/2609.17969)) push richer memory structure. Different benchmarks; no head-to-head.
- **Verify the write, not the screen:** ERPBench ([`2609.17885`](https://arxiv.org/abs/2609.17885)) shows saves without correct values; MIRAGE ([`2609.19059`](https://arxiv.org/abs/2609.19059)) shows plausible answers without real evidence use. Outcome-only evals overstate both computer-use and memory reliability.
- **Same-substrate judges:** the independence-graded audit ([`2609.18272`](https://arxiv.org/abs/2609.18272)) warns against auditors sharing the auditee's model family/toolchain; GraphEcho ([`2609.17695`](https://arxiv.org/abs/2609.17695)) shows repeated evidence being mistaken for corroboration. Both argue for counting independent sources/judges.
