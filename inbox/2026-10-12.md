### 1. Know What You Don't Know: Agentic Data Synthesis by Evolving Generation Space for Closed-Loop Learning
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.12593
- **Authors/org:** Wei Yang, Qing Ping, Youzhi Luo et al. (7 authors)
- **Focus area:** agentic data synthesis / multi-agent
- **What it is:** EvoSyn is a learning-feedback-driven multi-agent framework that organizes synthesis around a revisable state specifying what interaction factors can be deliberately generated and where synthesis effort should be allocated. A Designer allocates synthesis directions and a Planner grounds them into executable experience, enabling within-space adaptation and synthesis-space expansion. On τ²-Bench and CAR-Bench: +13.3 average task success over the strongest synthesis baseline, with higher-quality and structurally broader synthetic experience.
- **Why it matters for Justin's agents:** For Mitamaton / Claude Code training loops: close the feedback-to-decision gap — learner failures must rewrite what the synthesizer is allowed to generate, not just filter bad trajectories.

### 2. SpireBench: Evaluating Long-Horizon Strategic Play of Agentic Models with Slay the Spire
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.12596
- **Authors/org:** Scott C. Lowe, Sander W. Keemink
- **Focus area:** long-horizon agentic eval
- **What it is:** SpireBench has models play the complete commercial deck-builder Slay the Spire at highest difficulty across 20 LLMs. Frontier models match average humans but lag experts; the gap widens as runs lengthen — strongest models win act 1 like experts then fall behind. All models misjudge risk over a run (preserve health instead of spending it to grow). Memories written across runs are often wrong and overly cautious; renaming every game term shows part of performance rests on prior game knowledge.
- **Why it matters for Justin's agents:** Long-horizon personal/day-admin agents need evals where early decisions compound; do not trust cross-run memories that are wrong and over-cautious.

### 3. Beyond Binary Verifiable Rewards: Behavioral Self-Rewarding for SWE Agents
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.12598
- **Authors/org:** Yiran Wu, Andrew Zhao, Yurui Chang et al. (5 authors)
- **Focus area:** SWE agent rewards
- **What it is:** Binary RLVR rewards fail to distinguish trajectories with the same verifier outcome but different debugging quality. Behavioral Self-Rewarding (BSR) reuses the current policy to compare observable debugging behavior among same-task trajectories with the same verifier outcome, aggregates pairwise preferences into task-local scores, and converts them into denser rewards — without a separately trained reward model.
- **Why it matters for Justin's agents:** When fine-tuning coding agents on pass/fail tests, densify rewards from behavioral comparisons among same-outcome trajectories rather than treating every pass as equal.

### 4. CLEAT: Learning Value-Guided Clarification for Interactive Agents
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.12655
- **Authors/org:** Jiatan Huang, Zheyuan Zhang, Ziming Li et al. (7 authors)
- **Focus area:** clarification / interactive agents
- **What it is:** Clarification is useful only when the agent can turn the answer into better decisions; as training changes how the agent handles incomplete info, the same clarification can become more or less useful. CLEAT co-trains a clarification-value controller and the task policy from shared interaction outcomes, formulating residual question value so the agent asks when the answer would change the decision.
- **Why it matters for Justin's agents:** Pair with today's "Don't Guess, Just Ask": train when to clarify by estimated decision value, not by a fixed ask-always heuristic.

### 5. EvoBelief: Falsifiable World Models for Self-Improving LLM Agents

### 6. VEPA: Verified Evolving Formal Policy for Lifelong LLM Agent Guardrails
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.12813
- **Authors/org:** Duy Nguyen, Lesly Miculicich, Bhavana Dalvi Mishra et al. (8 authors)
- **Focus area:** formal agent guardrails
- **What it is:** VEPA represents the guardrail as a formal policy of executable symbolic rules over typed agent events. An LLM proposes policy patches from deployment feedback; a deterministic verifier accepts only structurally valid, conflict-free policies; an evidence-aware authority activates a verified rule only with enough supporting evidence. Outperforms baselines on ASSEBench-Safety/Security and ATBench while expanding deterministic formal-policy enforcement under mixed streams, corrupted feedback, and longer horizons.
- **Why it matters for Justin's agents:** Same lane as NOMOS yesterday: keep the decision surface deterministic (symbolic rules), and only let LLMs propose patches that a verifier + evidence gate must accept.

## Conflicts & open questions

- **Formal gates vs contagious hacking?** VEPA (2610.12813) wants verified symbolic guardrails; Transmissible Reward Hacking (2610.12822) shows hacking spreads through shared code/memory/plans even into stronger models. Open: does a VEPA-style gate on tool calls catch justification-laden hacked patches that look like normal code review?
- **Clarify before act — value or phase?** CLEAT (2610.12655) learns *when* clarification has decision value; Don't Guess, Just Ask (2610.13022) and Collaborative Theory of Mind (2610.12872) push a clarification / anticipate-user phase before repo edits or actions. Untested: whether CLEAT's value controller reduces unnecessary clarifies on repo-level tasks.
- **Harness evolution online vs offline vs world models?** ReHarness (2610.12668) evolves harnesses online without extra replay; CoCoEvolve (2610.12794) meta-reflects over production interactions; EvoBelief (2610.12789) / JANUS (2610.13194) / RoleWorld (2610.13172) evolve falsifiable world models. Open: one loop that updates harness *and* beliefs under an anchored verifier (Fri's Who Verifies the Verifier).
- **Session structure:** Humanize MLE (2610.13494) and Humanize Olympiad (2610.13632) prefer multi-session alternation / Solve-Review-Wiki-Verify over one long decelerating session — same Humanize theme as recent nights. How does this interact with LongHarness (2610.13075) stateful evidence that must persist *across* sessions?
- **Tool retrieval vs skill induction:** RATED (2610.13889) ranks tools by execution reliability; Work2Skill (2610.12984) induces GUI skills from demos. Open: should reliability signals also gate *skill* selection the way Fri's SkillContrast gated near-duplicate skills?
- **Personal-agent security surface:** X-AgentRed (2610.13886) compositional cross-service paths vs Fri's ObligationBench / Option-Channel Attack on single decision gates. Prefer testing full tool graphs, not only typed yes/no classifiers.
