# AI Research Digest — Wednesday, July 29, 2026

## TL;DR
- **Filesystem-Based Memory** [arxiv:2607.26637] is the first systematic study of the default Claude Code / Obsidian memory medium: a directory of markdown the agent itself reads, writes, and reorganizes. Organization reliably **halves retrieval cost** on large stores — but **no measured agent converts organization into better answers**, and the store's shape is as sensitive to the *tool set* as to the model. Directly names the vault's live architecture as a design space rather than an assumption.
- **Keep It InMind** [arxiv:2607.24368] (HF Daily) isolates the implicit-association blind spot: a tree-nut allergy should change a macaron answer, but the two texts share no retriever cue. With the fact in context the backbone hits **84.0%**; six vector / graph / agentic memory systems top out at **14.4%** even when they recall the same facts on demand at up to **100%**. Routing — which facts must stay visible — is the open problem, not embedding dimension.
- **OmegaUse-OfficeVal** [arxiv:2607.27155] is the Mitamaton-shaped office-suite eval: **100 practitioner-derived tasks**, mean **2.32 human hours**, code-based verifiers, and per-task labor-time + price-proxy so you can compare LLM inference cost to human cost. Frontier models are cheaper and faster; they have **not yet approached human deliverable quality**.
- **SkillRise** [arxiv:2607.26784] trains one policy that alternates task-solving and curating an evolving skill document passed to the next (different) task. Strongest Pass@1 on ALFWorld / WebShop / ScienceWorld, **+2.3 to +8.5 pp** over the strongest baseline, with test-time scaling *across* related tasks rather than repeated sampling of one task.
- **CodeNib** [arxiv:2607.25431] (HF Daily) is the serving layer Claude Code is missing: reusable lexical + dense + structural views per commit, served as ranked search / symbol nav / bounded context. Graph and vector updates **8.7× / 25.4×** faster than independent rebuild; selected-context policies preserve localization with **50–87% fewer trajectory tokens** than paired grep/read.

## Items

### 1. Filesystem-Based Memory for LLM Agents: Organization, Evolution, and Sustainability
- **Source:** arXiv (Hugging Face Daily Papers)
- **Link:** https://arxiv.org/abs/2607.26637
- **Authors / org:** Sizhe Zhou / Sheldon Yu / Hui Wei / Junda Wu / Siru Ouyang / Yizhu Jiao / Shijia Pan / Julian McAuley / Yu Zhang / Tong Yu / Jiawei Han
- **Focus area:** Agent memory + filesystem / Obsidian-shaped stores
- **What it is:** Formalizes the "memory is a directory of markdown the agent itself reorganizes" default as three roles around one store: a *management* agent integrates and organizes incoming content, a *search* agent answers with cited sources, an *execution* agent supplies trajectories that are distilled into skills — unifying declarative memory and skills in one filesystem. Sweep: memory shape (agent-organized hierarchy vs verbatim dump vs chunk retrieval), stream scale, tool harness (sandboxed shell vs memory-tool functions vs varied search), and manager/searcher strength. Load-bearing results: organized stores **roughly halve retrieval cost** where material is large; in the growth study, **organization erodes for all but the strongest management agent**; **no agent converts organization itself into better answers**; changing the *tool set* reshapes the store as strongly as swapping the model.
- **Why it matters for Justin's agents:** This is the vault + `~/.claude` + Mitamaton notes stack, measured. Two operational rules: (1) do not expect a nightly curator pass to raise answer quality — budget it for *search economy* (fewer tokens to find the note); (2) the tool surface is a first-class design choice, not an implementation detail — giving the manager a sandboxed shell vs a closed `memory_write` API will grow two different vaults. Composes with SF-AMS [arxiv:2607.22562] (eviction scoring) and PRO-LONG [arxiv:2607.20064] (log-as-searchable-memory): those say what to keep; this paper says the filesystem default does not automatically stay healthy.
- **Action signal:** `try-now` — add a weekly "store health" check (orphan notes, conflicting files, stale dates) and treat the Claude Code / Obsidian toolbelt as part of the memory architecture, not just the model.

### 2. Keep It InMind: Benchmarking the Implicit-Association Blind Spot in Agent Memory
- **Source:** arXiv (Hugging Face Daily Papers; submitted Jul 27, surfaced Jul 29 Daily)
- **Link:** https://arxiv.org/abs/2607.24368
- **Authors / org:** Ruizhe Li / Mingxuan Du / Benfeng Xu / Zhendong Mao
- **Focus area:** Agent memory (retrieval interface)
- **What it is:** Names the failure that similarity retrieval cannot see a world-knowledge bridge (allergy → almond flour → macaron). **InMind**: 125 expert-verified tasks across ten life domains, 113 grounded in citable public sources, with paired controls that separate "never stored" / "model lacks the bridge" / "stored and never surfaced." With the decisive memory placed in context, the backbone answers **84.0%** of indirect queries; when the same memory must be retrieved, six vector / graph / agentic memory systems reach at most **14.4%**, even though they recall those facts on demand at up to **100%**. An 8×-wider embedding raises answer-blind target recall for every system and **leaves the gap essentially intact**. A diagnostic that keeps memory *visible before the query arrives* recovers most of the gap.
- **Why it matters for Justin's agents:** Mitamaton's job is exactly this class of query — "can I eat this," "should I leave now," "does this conflict with the thing I said last month." Vector RAG over the vault will look healthy on "recall the allergy" and fail on "order dessert." The portable primitive is **routing, not retrieval**: a small always-on card of load-bearing personal constraints (allergies, hard calendar rules, standing nos) that is injected *before* the query, plus retrieval for the long tail. Do not spend the weekend swapping embedders.
- **Action signal:** `compare` — build a 20-item InMind-style personal probe (allergy / meds / standing constraints / recurring calendar rules) and score retrieval-then-answer vs always-visible-card.

### 3. OmegaUse-OfficeVal: Benchmarking LLM Agents on Long-Horizon Office-Suite Tasks with Economic Grounding
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2607.27155
- **Authors / org:** Jingbo Zhou / Yusai Zhao / Qi Bao / Jingjia Cao / Zhenghai Chen / Chang Gao / Kaiqi Guo / Muxin Guo / Mingxuan Li / Xinjiang Lu / Yanru Ma / Yixiong Xiao / Zenghui Zhang / Le Zhang / Hua Wu
- **Focus area:** Agent evaluation + long-horizon office / day-admin
- **What it is:** 100 office-suite tasks derived from practitioner requests, privacy-adapted. Mean human labor **2.32 hours**. Each task carries two economic signals — human labor time and a task price proxy — so you can compare inference $ to human $ and run value-weighted eval. Code-based verifiers from fine-grained rubrics. Frontier LLMs vs a human baseline: models are substantially cheaper and faster; **they have not yet approached human-level deliverable quality**. Dataset + code open.
- **Why it matters for Justin's agents:** This is the closest published stand-in for Mitamaton's actual job (spreadsheets, docs, multi-step office workflows) that also prices the work. Use it as the quality floor, not as a reason to wait: the economic framing says a 70%-quality agent that costs 1% of 2.32 hours is already a product if you keep a human in the loop on the last 30%. Pair with DocOps [arxiv:2607.19865] (structured-document failure modes) as the diagnostic checklist when OfficeVal tasks fail.
- **Action signal:** `compare` — pick 10 OfficeVal-like personal tasks (a spreadsheet clean, a deck update, a calendar+doc pack) and score deliverable quality *and* $ vs the 2.32-hour human baseline.

### 4. SkillRise: Agentic Reinforcement Learning for Cross-Task Skill Evolution
- **Source:** arXiv (Hugging Face Daily Papers)
- **Link:** https://arxiv.org/abs/2607.26784
- **Authors / org:** Zhiyuan Yao / Yuxin Chen / Zhengxi Lu / Zishan Xu / Yueqing Sun / Yifu Guo / Yuquan Lu / Zhengzhou Cai / Kangning Zhang / Zhuowen Han / Zi-Han Wang / Ziang Ye / Qi Gu / Xunliang Cai / Weiwen Liu / Yongliang Shen
- **Focus area:** Agent skills + agentic RL
- **What it is:** Standard agentic RL treats tasks as independent episodes; existing skill learners either retry one task or run multi-stage pipelines that entangle extract / retrieve / execute. SkillRise organizes related instances into progressively harder sequences and uses **one policy** that alternates solving the current task and curating an evolving skill document handed to the next (different) task. Decoupled credit: solve-head trained on current-task outcome, curation-head on discounted *downstream* outcomes. ALFWorld / WebShop / ScienceWorld: strongest Pass@1 among compared methods, **+2.3 to +8.5 pp** over the strongest baseline. Curation policy still helps on repeated attempts of the *same* task. Test-time scaling: performance rises with longer sequences of related tasks even when each task is attempted once. Runtime overhead of multi-stage skill pipelines is substantially reduced.
- **Why it matters for Justin's agents:** This is the RL-side cousin of MSCE [arxiv:2607.16621] / AgentBrew [arxiv:2607.16851]. The portable idea without training: **credit the skill edit from the *next* task's outcome, not the current one.** A Claude Code `SessionStop` hook that writes a SKILL.md patch and only keeps it if tomorrow's related task gets cheaper or more correct is SkillRise's curation head without the RL run. Cross-task (not same-task-retry) is the claim that matters for a personal agent whose Tuesday is never Monday.
- **Action signal:** `compare` — against a static `~/.claude/skills` library on a 10-task related-but-not-identical personal set; keep the "edit today, score tomorrow" gate even if you never train.

### 5. CodeNib: A Multi-View Data System for Serving Repository Context to Coding Agents
- **Source:** arXiv (Hugging Face Daily Papers; submitted Jul 28, surfaced Jul 29 Daily)
- **Link:** https://arxiv.org/abs/2607.25431
- **Authors / org:** Zhongming Yu / Hengjia Yu / Boqin Yuan / Shuting Zhao / Yizhao Chen / Aryan Dokania / Mihir Jagtap / Jiayu Chang / Yitong Ma / Yash Jayswal / Wentao Ni / Hejia Zhang / Zhaoling Chen / Gangda Deng / Jishen Zhao
- **Focus area:** Tools & connectors + coding-agent context
- **What it is:** Coding agents repeatedly rediscover repository context because indexes, language servers, and task-local histories are disconnected. CodeNib builds reusable **lexical, dense, and structural views per commit**, maps outputs to repository-relative source ranges, maintains selected views across edits, and serves ranked search, symbol navigation, and bounded context through one runtime. Across 100 snapshots: when outputs match an independent rebuild, graph and vector updates are **8.7× and 25.4× faster** at the median. On the static-navigation subset matching normalized live-server locations (63% of 1,000 requests), median live/static latency ratio is **4.7×**. Across five models, selected-context policies preserve localization with **50–87% fewer trajectory tokens** than paired grep/read.
- **Why it matters for Justin's agents:** Claude Code today pays the "grep/read the repo again" tax every session. CodeNib is the argument for a *commit-indexed, multi-view* cache that the agent queries instead of rebuilding. The 50–87% token cut is the number that matters on a 64 GB local loop and on API bills. Complements Agent Retrieval Bench [arxiv:2607.24882] (same Daily window; logged agents miss every gold file on 27–35% of samples). Do not confuse CodeNib (serving) with InMind (personal-fact routing).
- **Action signal:** `try-now` — cache ripgrep + ctags/SCIP + a small embed index *per HEAD* for the active repo and invalidate on commit; measure trajectory tokens vs raw grep/read on a 10-issue personal set.

## Conflicts & open questions
Cross-referenced against `_meta/claims-ledger.md`:
- **Convergent evidence, not conflict:** Filesystem-Based Memory + InMind + SF-AMS [arxiv:2607.22562] + PRO-LONG [arxiv:2607.20064] + Agentic Context Management [arxiv:2607.21503] all say the store-and-retrieve default is the load-bearing layer. They do **not** agree on *what to optimize*: search economy (this paper), implicit-association routing (InMind), eviction scores (SF-AMS), or log-as-memory (PRO-LONG).
- **Conflict flagged:** Filesystem-Based Memory's "organization does not raise answer quality" sits against the implicit promise of every vault-curator / wiki-maintainer design (and against later WikiSkill [arxiv:2608.27454], which *does* raise task scores — but WikiSkill gates skill *edits*, it does not claim that tidying the filesystem raises answers). Do not read "organized markdown" as a quality intervention; read it as a cost intervention.
- **Open question:** InMind's 84% → 14.4% collapse is on life-domain facts. Does the same gap show up for *code* facts (a constraint in CLAUDE.md that should change a later refactor) or is that already handled by always-injected instructions? First test: hide a standing constraint in a vault note, ask a query that requires it, compare always-visible-card vs RAG.
