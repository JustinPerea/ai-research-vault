## Items

### 1. PRO-LONG: Programmatic Memory Enables Long-Horizon Reasoning
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2607.20064
- **Authors / org:** Alexis Fox, Junlin Wang, Paul Rosu, Bhuwan Dhingra (Duke NLP)
- **Focus area:** Agent memory / context engineering
- **What it is:** A minimal context-management framework that keeps a **complete, structured interaction log** and gives the agent code-agent tools (grep, view, edit) to search it. Instead of a compaction step or a vector index, memory *is* files and the retrieval mechanism *is* the coding agent's own search skills.
- **Numbers:** +18.0 pp over base coding agent averaged across frontier models; **76.1% pass@1 on ARC-AGI-3** (matches specialized harnesses); **4.2–5.8× fewer tokens** vs alternatives; 97.4% best@2 with Fable 5 at $1,750 total cost.
- **Why it matters for Justin's agents:** Directly relevant to Justin's Claude Code + MCP loops — the pattern is "the coding agent already has grep, so keep the whole log around and let it search." Complements MSCE (2607.16621) skill-crystallization by handling the raw-log substrate underneath it; complements AgentDebugX (2607.18754) which treats the same log as a debugging artifact.
- **Action signal:** `try-now` — architecture is a re-plumb, not a training change; the exact structured-log format is worth reproducing in the vault-side pipeline. `compare` — extends the four co-evolution pathways from the Environment Engineering survey (2606.12191) with a fifth "code-native log-as-memory" pathway.

### 2. JANUS: Foreseeing Latent Risk for Long-Horizon Agent Safety
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2607.19913
- **Authors / org:** Yuan Xiong, Linji Hao, Shizhu He, Yequan Wang, Lijun Li
- **Focus area:** Long-running / autonomous loops (safety)
- **What it is:** A foresight-oriented safety framework that trains guards to **anticipate delayed risks from partial trajectories**. Multi-agent simulation synthesizes diverse trajectories; guard learns a shared policy with two coupled tasks: an anticipation task that forecasts safety-relevant futures and an adjudication task that decides safety from **both observed prefix and anticipated future**.
- **Numbers:** +15.9 pp average protection over baseline guards; **+5.1 pp benign task completion** (protection without over-blocking).
- **Why it matters for Justin's agents:** The +5.1 pp benign-completion gain is the load-bearing result — most guardrails trade capability for safety, this one gains both. For Justin's autonomous daily-loop patterns (this digest itself, PR watchers), foresight-style guards are the layer that could catch a Safety Drift trajectory (2607.18366) mid-way instead of at execution.
- **Action signal:** `compare` — sits directly opposite the Action-Aware Supervision Layer from **Operational Hallucination / Safety Drift** (2607.18366). Both target long-horizon agent failure, but JANUS is **predictive** (forecast the future) while AASL is **reactive** (compare declared intent to actual state). Open empirical question: at what trajectory length does the forecast horizon degrade below actionable resolution?

### 3. NEXUS: Structured Runtime Safety for Tool-Using LLM Agents
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2607.19356
- **Authors / org:** Elias Hossain, Md Mehedi Hasan Nipu, Tasfia Nuzhat Ornee, Rajib Rana, Niloofar Yousefi
- **Focus area:** Tools & connectors (MCP safety)
- **What it is:** A structured-plan safety monitor for tool-using agents that applies a formal intervention policy to select among four actions: **allow, block, request confirmation, request revision**. Sits between the agent's planned action and its execution.
- **Numbers:** F1 **0.949** on synthetic benchmark; 4-class intervention accuracy 0.6406; **+27.3 pp over rule-only**; F1 0.861 on R-Judge (vs 0.849 rule-only); F1 **0.881 on NEXUS-Stress**; **median latency 0.205 ms**; **<0.1% agent-loop overhead**; 0% ASR at 99% control-allow on IPI.
- **Why it matters for Justin's agents:** This is the concrete drop-in layer for the "Action-Aware Supervision" the Operational Hallucination paper (2607.18366) demanded. Sub-0.1% overhead means it's cheap enough to wrap *every* MCP tool call in Justin's Claude Code stack. The **request-revision** action is the interesting one — it's not just gate-keeping, it's a repair channel.
- **Action signal:** `try-now` — 0.205 ms median latency and IPI 0% ASR at 99% allow means the safety-vs-utility trade-off is essentially free. Worth prototyping the 4-action policy as a Claude Code hook before the next MCP-heavy loop.

### 4. DocOps: A Verifiable Benchmark for Autonomous Agents in Complex Document Operations
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2607.19865
- **Authors / org:** Jiazhen Jiang, Boxi Cao, Lingyong Yan, Yaojie Lu, Hongyu Lin, Shuaiqiang Wang, Dawei Yin, Xianpei Han, Le Sun
- **Focus area:** Evaluation (agent benchmarks) / coding agents
- **What it is:** A **deterministically verifiable** benchmark for agents doing complex document workflows, grounded in a taxonomy that breaks document operations into fundamental components at increasing complexity levels. Frontier configurations still fail on highly coupled, long-range tasks.
- **Numbers:** Three failure patterns named: **(1) long-term state tracking collapse, (2) shallow semantic verification, (3) destructive editing of structural metadata**. Specific accuracy numbers not surfaced in the abstract.
- **Why it matters for Justin's agents:** All three failure modes are things Justin hits in real-world docs work (federal-data-engineer role): state-tracking collapse is exactly what happens when agents lose thread on multi-file spreadsheet edits; destructive metadata editing is the silent failure mode in Word/Excel workflows. Complements RECON (2607.16716) which targets narrative-document memory; DocOps targets structured-document operations.
- **Action signal:** `track` — benchmark itself is useful only if the harness runs against Justin's actual stack; the three named failure modes are the immediate diagnostic checklist for any doc-agent work.

### 5. DynamicRubric: Co-Evolving LLM Evaluators and Policies
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2607.20083
- **Authors / org:** Beining Wang, Weihang Su, Hongtao Tian, Hao Kong, Tao Yang, Ting Yao, Qingyi Pan, Yueyue Wu, Qingyao Ai, Min Zhang, Yiqun Liu (Tencent/WeChat + Tsinghua)
- **Focus area:** Evaluation / reasoning
- **What it is:** Response-set-conditioned evaluator that generates **weighted binary rubric items per candidate set** and aggregates judgments into response-level scores. Theoretical framing: policy improvement is driven by **relative score gaps** between candidates, not absolute quality — so as the policy improves and candidates converge, static evaluators collapse but a co-evolving one preserves signal.
- **Numbers:** **8B backbone** beats 70B reward-model baseline and 235B static-rubric-generator baseline on both evaluator quality and downstream policy gains. Fully deployed in **WeChat Search's AI answering, tens of millions of requests/day**.
- **Why it matters for Justin's agents:** The relative-gap framing is the theoretical piece that was missing from LLM-as-a-Coach (2607.18110) — Coach argued for richer feedback modality, DynamicRubric explains *why* it matters mathematically. For Justin's eval work, the practical takeaway is that **any static rubric will silently degrade** as the policy it grades gets better.
- **Action signal:** `compare` — directly extends LLM-as-a-Coach (2607.18110); also tightens the Verification Horizon result (2606.26300, "no fixed reward function can remain effective as policy capability grows"). Together these three papers now form a coherent case: static evaluators are structurally broken for post-training; the only question is whether the co-evolution mechanism is rubric-based (DynamicRubric), coach-based (2607.18110), or judge-swap-audited (2607.08535).

### 6. SLPO: Scaling Latent Reasoning via a Surrogate Policy
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2607.19691
- **Authors / org:** Runyang You, Zhiyuan Liu, Yongqi Li, Wenjie Li
- **Focus area:** Reasoning & inference-time compute
- **What it is:** Brings outcome-reward RL to **latent (continuous-vector) reasoners** — the class that carries intermediate computation as vectors instead of decoded tokens. Two ingredients: (a) an empirical surrogate policy density over latent transitions for trajectory-level credit assignment, and (b) a correctness-supervised stopping head that outcome-reward RL refines into a **variable-horizon** policy that allocates longer latent compute to harder instances.
- **Numbers:** No headline benchmark numbers in the abstract — reports "improves Pass@k under parallel sampling" and adaptive compute allocation with higher deterministic accuracy on harder items.
- **Why it matters for Justin's agents:** Latent reasoning is the axis where the token-count tax on explicit CoT gets removed. If SLPO's variable-horizon-under-fixed-budget claim holds, it's the missing piece that lets latent reasoners inherit the test-time-scaling curve that explicit-CoT models get from outcome-reward RL.
- **Action signal:** `track` — no released weights / benchmark table yet; watch for a follow-up with Pass@k on GPQA / AIME to compare against explicit-CoT reasoners at matched compute.

### 7. OpenSkillRisk: Benchmarking Agent Safety When Using Real-World Risky Third-Party Skills
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2607.20121
- **Authors / org:** Qiyuan Liu, Tingfeng Hui, Kun Zhan, Kaike Zhang, Ning Miao
- **Focus area:** Tools & connectors (MCP / third-party skill safety)
- **What it is:** A safety benchmark of **263 dangerous skills across 7 threat categories**, each paired with user tasks and sandboxed evaluation environments. Tested 3 CLI agent frameworks × 13 SOTA LLMs.
- **Numbers:** **Even the safest configurations execute unsafe actions in ~17% of cases.** Three recurring failure patterns: (a) failing to recognize risk, (b) recognizing risk but acting before intervention, (c) following skill instructions beyond intended user scope.
- **Why it matters for Justin's agents:** Directly relevant to any MCP-server-marketplace pattern — the 17% floor is the "unsafe by default even for careful models" baseline against which NEXUS (item 3) and JANUS (item 2) need to prove their reductions. Failure mode (c) — following skill instructions beyond user scope — is the prompt-injection-via-tool-description attack surface that MCP has structurally not solved.
- **Action signal:** `compare` — sets an empirical safety floor (17%) that pairs with the Operational Hallucination / Safety Drift claims (2607.18366) and with the JANUS +15.9 pp headroom (item 2). Open empirical question: does the 17% floor hold on frontier tool-users (Claude Opus 4.7 / GPT-5.4 / Gemini 3.6 Flash) or is the number heavily weighted by the weaker LLMs in the panel?

### 8. Correlated Agreement Blindness in Multi-Agent Triage
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2607.19899
- **Authors / org:** Shay Seiya McDonnell, Avantika Singh, Quoc-Viet Pham, Vratislav Havlik, Gregory M.P. O'Hare
- **Focus area:** Agent orchestration (multi-agent supervision)
- **What it is:** Identifies a structural vulnerability in multi-agent systems: **as base learners improve, they converge, and correlated failures concentrate where disagreement-based monitoring can't see them.** ARAT combines Random Forest + kNN agents with a calibrated meta-model to detect these cases.
- **Numbers:** **57.2% of errors occurred under agreement** across 82,332 holdout samples; **90.6% of dangerous under-predictions evaded disagreement-based monitoring**; ARAT cut under-prediction from 4.80% → 1.70% via conservative override (−2.6 pp) and safety-flag gate (−0.5 pp).
- **Why it matters for Justin's agents:** Direct empirical hit on the "diverse-lens judge panel" and "N-of-M voting" patterns Justin's stacks (and most multi-agent frameworks) lean on. The 57.2% number is the "unanimous is not evidence" result in one datum. Complements Contagion Networks (2606.20493, homogeneous-committee contagion 0.157–0.352) and Minority Sentinel (2606.29270, ~25% of divergent cases have minority-correct) — three-paper convergence that **agreement-based aggregation is a broken supervision signal**.
- **Action signal:** `compare` — **CONFLICTS with the diverse-lens/majority-vote pattern used everywhere**, including the Ultracode adversarial-verify recipe. Practical implication: any multi-agent judge in the stack needs an audit of *correlated* error rates (not just marginal), and a non-agreement-based tie-breaker (ARAT-style meta-model, or the Minority Sentinel LightGBM classifier on debate features).

## Conflicts & open questions
Cross-referenced against `_meta/claims-ledger.md`:
- **JANUS (2607.19913) vs Operational Hallucination / Safety Drift (2607.18366):** Two mechanistically distinct answers to the same long-horizon agent-safety failure. JANUS is *predictive* (anticipate future risk from partial trajectory); AASL is *reactive* (compare declared intent to execution state). Not a contradiction — they compose (JANUS anticipates, AASL confirms) — but the empirical head-to-head is unrun.
- **DynamicRubric (2607.20083) vs LLM-as-a-Coach (2607.18110):** Both argue static evaluators are structurally broken; DynamicRubric supplies the theoretical framing (**relative score gaps are the actual policy-update signal**) that Coach lacked. Not a conflict — DynamicRubric strengthens the Coach thesis. Open question: is the co-evolution advantage still positive when the policy is a Justin-scale 8B local model rather than WeChat-scale traffic?
- **Correlated Agreement Blindness (2607.19899) vs the diverse-lens judge-panel pattern** (used in Ultracode adversarial-verify, in the /code-review skill, and implicitly in every N-of-M voting stack): **direct empirical conflict** — 57.2% of errors under agreement + 90.6% of dangerous under-predictions evading disagreement-based monitoring means "unanimous verifiers accept" is a corrupt signal when the verifiers share pretraining. Extends the Contagion Networks (2606.20493) + Minority Sentinel (2606.29270) cluster into a three-paper convergence. Practical retrofit: replace the current confidence-from-agreement primitive with an ARAT-style meta-classifier on the *raw debate transcript features*, not the vote counts.
- **Open empirical questions raised today:**
  - Does the OpenSkillRisk 17% unsafe-action floor (2607.20121) hold on the current frontier tool-users (Claude Opus 4.7 / GPT-5.4 / Gemini 3.6 Flash), or is it dominated by the weaker LLMs in the panel? If it holds, JANUS's +15.9 pp guard headroom and NEXUS's 0.881 NEXUS-Stress F1 are the pieces that need to compose to get the floor down.
  - Does PRO-LONG's programmatic-memory recipe (2607.20064) still beat compaction-based memory on tasks where the log is *narrative* rather than *code-like*? ARC-AGI-3 traces are code-like by construction; the RECON case-file benchmark (2607.16716) is the natural cross-check.
  - DynamicRubric was deployed in production at WeChat Search scale — but the evaluator was trained on the same task distribution it grades. Does the co-evolution advantage persist under distribution shift?
