# AI Research Digest — Saturday, July 18, 2026

## TL;DR
- **A pre-registered experiment says multi-agent debate does *not* improve AI feedback.** "Does Multi-Agent Debate Improve AI Feedback on Research Papers?" (2607.14713) had 44 meta-analysis authors rank three AI-generated reports on their own papers; **the single-pass report beat mad-research by 0.66 rank points and paper-workshop by 0.57**, while paper-workshop **burned ~30× more tokens for the worse result**. Human referees usually ranked #1 by authors but *last* by AI judges — a direct challenge to "LLM-as-judge → LLM-as-orchestrator" pipelines.
- **Persistent agent memory is a proven attack surface across Claude and Codex.** "Bad Memory" (2607.14611) evaluates prompt injection payloads planted in memory files, behavioral preferences, and knowledge bases against **Claude Haiku 4.5, Claude Opus 4.7, GPT-5.2, and GPT-5.5**; payloads persist and reactivate across sessions with success varying by system, model, and multi-session sequence. Immediate concern for anyone using LangMem-, mem0-, or Skills-style persistent state — extends "gate before commit" from write-time control to read-time verification.
- **Long-context RL now runs at 2M+ tokens on ordinary GPU budgets.** LongStraw (2607.14952, HF trending #2) demonstrates **scoring + backward passes at 2.1M token positions on 8× H20** using GRPO with selective state retention; validated end-to-end across all 78 layers of GLM-5.2, memory increase of **0.21 GB when doubling group size**, code open source. First credible path to *training* on trajectories long enough to include a full day of an autonomous agent's execution.
- **The self-evolving harness pipeline gets a sixth mechanism.** SEED (2607.14777, HF #3) converts completed trajectories into **natural-language skill descriptions** ("reusable workflows, decisive observations, failure-avoidance rules"), then re-scores actions under ordinary and skill-augmented contexts to produce a **dense token-level on-policy distillation signal**. Composes cleanly with the vault-tracked chain Handbook → QD → MemoHarness → Compound → Pairwise-Validator: SEED is the *hindsight-supervision-as-skill-mining* step that turns the harness's own log into training signal.
- **Production-agent case study drops the pattern of the week.** Allen AI's "What building Shippy taught us about building agents" (HF blog, 2026-07-15) documents a **live maritime-awareness agent for 300+ government/NGO partners** built on Claude Opus 4.6 + OpenClaw. Three architectural pieces map directly onto Justin's stack: **(soul + skills + config) versioned in Docker images**, a **deterministic CLI layer** between agent and backend to isolate LLM nondeterminism from tool correctness, and **per-session sandboxed Kubernetes pods (Mothership) with scoped JWTs** for multi-tenant isolation. OpenClaw + Harbor (eval framework) are open source.

### 1. LongStraw: Long-Context RL Beyond 2M Tokens under a Fixed GPU Budget
- **Source:** arXiv (2026-07-16) · Hugging Face Daily Papers #2 (97 upvotes)
- **Link:** https://arxiv.org/abs/2607.14952
- **Authors / org:** Changhai Zhou, Kieran Liu, Yuhua Zhou, Qian Qiao, Jun Gao, Harry Zhang, Irvine Lu, Nolan Ho, Lucian Li, Andrew Lei, Cleon Cheng, Steven Chiang, Yihang Zeng, Di Zhang, Rio Yang, Kaijie Chen, Andrew Chen, Pony Ma, Weizhong Zhang, Cheng Jin
- **Focus area:** Context engineering (long context) + long-running / autonomous loops (RL training scale)
- **What it is:** RL post-training execution framework built on **Group Relative Policy Optimization (GRPO)** that manages memory constraints through *selective state retention* and *response replay*. Achieves **scoring + backward passes at 2.1M token positions on 8× H20 GPUs** with groups of 2–8; stress-tested to **4.46M positions**; end-to-end validated across **all 78 layers of GLM-5.2 on 32× H20**; **memory delta of just 0.21 GB when doubling group size**. Models tested: **Qwen3.6-27B** (hybrid recurrent/full-attention) and **GLM-5.2** (compressed-attention MoE). Open-source at github.com/MindLab-Research/longstraw.
- **Why it matters for Justin's agents:** The vault has ~two months of items on *inference-time* long-context tricks (JoLT compression 2607.12550, Jet-Long 2607.07740, KV grafting 2607.14431, adaptive KV filtering 2607.13205). LongStraw is the first credible entry on the *training* side — enough context to fit an *entire multi-hour agent trajectory* into a single RL episode. Concrete implication for durable agents: when you can train on 2M-token episodes, you can optimize the agent's behavior over *actual* sessions instead of stitched fragments, and the harness-evolution pipeline (Handbook → QD → MemoHarness → Compound → Pairwise-Validator → SEED) has a training substrate large enough to hold the full loop. The **0.21 GB delta per group doubling** is the key operational number — it means group-size scaling is essentially free, which changes the cost math for reward-model-free RL variants like SEED. Not local-fit — H20 is Hopper-class, not M5 Max — but the algorithmic primitive (selective state retention + tiered off-load) is the same shape as Item 6 below on smaller hardware.
- **Action signal:** `track` — code available, but the M5 Max path is via Item 6's primitives, not this codebase. Also `compare` — extends the "trillion-token effective context" thread with a *training* substrate for the first time.

### 2. SEED: Self-Evolving On-Policy Distillation for Agentic Reinforcement Learning
- **Source:** arXiv (2026-07-16) · Hugging Face Daily Papers #3 (86 upvotes)
- **Link:** https://arxiv.org/abs/2607.14777
- **Authors / org:** Jinyang Wu, Shuo Yang, Zhengxi Lu, Fan Zhang, Yuhao Shen, Lang Feng, Haoran Luo, Zheng Lian, Shuai Zhang, Zhengqi Wen, Jianhua Tao
- **Focus area:** Agent orchestration (self-evolution / harness engineering) + reasoning (skill mining from trajectories)
- **What it is:** Two-phase self-improvement loop. **(1) Skill extraction:** the policy analyzes its own completed trajectories and produces **natural-language descriptions of reusable workflows, decisive observations, and failure-avoidance rules**. **(2) Distillation:** the policy re-scores actions in *both* ordinary and skill-augmented contexts, producing a **dense token-level on-policy distillation signal** combined with outcome rewards. Result: hindsight supervision *co-evolves with the policy* rather than staying static. Evaluated on text and vision agentic tasks; consistent gains and better sample efficiency; robust generalization to unseen scenarios. GitHub released.
- **Why it matters for Justin's agents:** This is the **sixth mechanism in the harness-engineering pipeline** the vault has been assembling for two weeks:
  1. Handbook (2607.13285) — *WHERE* to edit
  2. QD-Keyed archive (2607.13683) — *WHICH pathology* the patch fixes
  3. MemoHarness (2607.14159) — *WHICH dimension* the patch lives in
  4. Compound (2607.14004) — regression gate ("did this actually beat the parent?")
  5. Pairwise-Validator (2607.14408) — cheapest form of the regression gate (no reward design)
  6. **SEED — hindsight skill mining from the trajectory itself**
  
  What's specifically new: SEED closes the *training-signal* loop. The previous five pieces optimize *selection* over hand-authored or archive-mined patches; SEED lets the policy *generate its own supervision* from its own runs. Concrete transplant for Justin's Claude Code + MCP stack: after every non-trivial session, ask Claude to summarize "reusable workflows, decisive observations, failure-avoidance rules" as three plain-text bullet lists, then persist them as **Skills** for the next session. This is the *same primitive* as Shippy's soul/skills/config (Item 9) but with an automatic authoring step. **Compares directly with the Alipay-PIBench +10.31pp skill-package finding from 2026-07-17** — SEED is the mechanism that generates such packages *at agent runtime* rather than by human authorship.
- **Action signal:** `try-now` — the natural-language skill-extraction step is prompt-only and runnable as a Claude Code hook (SessionStop hook writes `SKILL_NOTES.md`). Also `compare` — completes the harness-engineering pipeline as a runnable loop.

### 3. Proof-or-Stop: Don't Trust the Agent, Trust the Evidence
- **Source:** arXiv (2026-07-15) · full title includes "Loop Engineering for Verifiable Evidence-Gated Lifecycle Control"
- **Link:** https://arxiv.org/abs/2607.14890
- **Authors / org:** Jek Huang, Jeffery Hsia, Jiayi Sun, Freddie Shi, Wei Huang, Ian H. White
- **Focus area:** Coding agents + long-running / autonomous loops (verifiable lifecycle gates)
- **What it is:** Treats every agent-issued lifecycle claim (`reviewed`, `tested`, `ready-to-merge`) as an **unverified proposition** until backed by **fresh, tracked-source-state-bound, mechanically verifiable evidence**. **Numbers:** unattended-loop engine passed **10/10 scenarios with zero false-DONE**; local-key receipt bundles rejected **18 tamper classes with zero false accepts**; ablation reduced false-pass instances from **31 → 2 per 1,800 injected cells** (~1.6 pp gain); self-application corpus **565 stories, 1,007 review findings, 94.8% resolved**. Open-source implementation.
- **Why it matters for Justin's agents:** The 2026-07-17 digest ledgered "Compound + regression gate" as the *state-of-the-art regression-control primitive*. Proof-or-Stop is a **stricter version at the lifecycle-transition layer** — instead of "did the child beat the parent," it asks "does the receipt exist, is it fresh, is it bound to the current source state, and does it match what the agent claimed?" This is precisely the gate missing between "Claude Code says `ready-to-merge`" and *actually merging*. The **10/10 zero-false-DONE** number is the operational win: for autonomous loops (Justin's babysit-PR, dynamic /loop patterns), false-DONE is the *worst* failure — the loop stops *believing* it's finished. Directly maps onto MCP: any tool that returns a claim (e.g., "tests passed", "linter clean") should return a *receipt* the agent binds to source-state hash. **Composes with SearchOS's Failure Memory (2607.15257)** — Failure Memory says "don't try that again," Proof-or-Stop says "don't call that DONE without evidence." Composes with **Pairwise-Validator (2607.14408)** — pairwise is the cheap selection filter, Proof-or-Stop is the terminal gate.
- **Action signal:** `try-now` — the receipt-bundle pattern is portable to any tool interface (`{claim, source_hash, evidence_type, verifier_signature}`). Also `compare` — adds a *lifecycle-gate* primitive above the vault's "regression-gate" primitive; ledger as a new node in the gate hierarchy.

### 4. Bad Memory: Prompt Injection Attacks on Persistent Agentic Memory
- **Source:** arXiv (2026-07-15) — multi-agent-systems category
- **Link:** https://arxiv.org/abs/2607.14611
- **Focus area:** Agent memory (security) + tools & connectors (memory-file threat model)
- **What it is:** Evaluates **prompt-injection payloads planted in persistent memory** — memory files, behavioral preferences, knowledge bases — against **Claude (Haiku 4.5, Opus 4.7)** and **OpenAI Codex (GPT-5.2, GPT-5.5)**. Finding: "payloads already planted in those files can successfully attack current and future sessions"; success and persistence vary substantially across systems, models, adversarial goals, and multi-session attack sequences. Motivates defenses that protect *memory updates* without removing useful adaptation.
- **Why it matters for Justin's agents:** This is the first paper the vault has tracked that *directly attacks the concrete stack Justin is deploying* — **Claude Opus 4.7 with persistent Skills / memory files** is exactly the vault-tracked reference architecture. Key operational take: **persistent memory is now a bidirectional trust boundary**, not a one-way write. Two implications:
  1. **Read-time verification is under-specified.** Every prior vault entry on agent memory (mem0, LangMem, MemCon 2607.13591, Oracle Agent Memory, Shared Selective Persistent Memory) has focused on *what to store* and *when to retrieve*, not *how to verify the retrieved payload is safe to inject into the next context*. Bad Memory shows the *retrieval* step is where the attack lands, not the storage step.
  2. **Multi-session persistence changes the threat class.** A single-session injection is a *bug*; a multi-session persistent injection is a *rootkit*. This is the same phase transition the security community saw with browser cookies → session cookies → persistent auth tokens.
  
  **Conflict with vault-tracked positive framing:** every memory paper covered since 2026-05 has treated persistent memory as unambiguously good. Bad Memory is the first with a rigorous adversarial measurement against production systems and finds concrete failure modes on Justin's exact target models. **Extends "gate before commit"** (which is a *write-time* control) with **"gate before retrieve"** (a *read-time* control): every retrieved memory chunk should carry a provenance receipt (compare Proof-or-Stop, Item 3) before being injected into the next prompt.
- **Action signal:** `compare` (conflict) — ledger against the vault's "persistent agent memory is a net win" thread; add a new claim primitive **"persistent memory has read-time trust dimensions equal to its write-time trust dimensions"**. Also `try-now` — implement a read-time verifier as a Claude Code hook that scans memory files for injection patterns before allowing session load.

### 5. Plover: Steering GUI Agents through Plan-Centric Interaction
- **Source:** arXiv (2026-07-16) — cs.AI
- **Link:** https://arxiv.org/abs/2607.15193
- **Authors / org:** Madhumitha Venkatesan, Shicheng Wen, Jiajing Guo, Jorge Piazentin Ono, Liu Ren, Dongyu Liu
- **Focus area:** Tools & connectors (computer use / GUI agents) + agent orchestration (planner-executor)
- **What it is:** Planner-executor GUI-agent architecture in which **the plan is a persistent, inspectable, revisable artifact** — not a hidden internal trace. Users supervise via **natural-language guidance combined with screenshot-grounded interventions**, correct at the *step* they want to fix (not restart-from-scratch), and progress is preserved during repairs. Formative study with 6 participants; benchmark failure-case repair + scenario-based workflow analyses showed many failures become *repairable* when the plan is visible.
- **Why it matters for Justin's agents:** Companion to yesterday's Tactile (2607.14443, "verifiable action substrate") — Tactile fixed the *state* layer of computer-use agents, Plover fixes the *plan* layer. The specific move worth stealing: **externalize the plan as an editable artifact instead of a chain-of-thought**. In Justin's Claude Code loops this maps directly onto `PLAN.md` — but Plover's contribution is *localized correction with progress preservation*, i.e. editing step 4 without invalidating steps 1–3. This is the first computer-use paper the vault has tracked that centers *user-interventable state* over *fully autonomous execution*; matches Justin's actual dev pattern (Claude drives, Justin corrects mid-task) rather than the babysit-nothing autonomy that dominates OSWorld literature. **Composes with SearchOS's Frontier Task + Coverage Map (2607.15257)** — Plover's editable plan is exactly the concrete instantiation of what SearchOS calls Frontier Task, applied to GUI actions instead of information seeking.
- **Action signal:** `track` — no obvious open-source implementation yet, but the *pattern* (plan-as-editable-artifact with step-local revision) is portable to any MCP loop today. `compare` — extends the "externalized state > implicit context" thread with a *user-interaction* primitive.

### 6. Long-Context Fine-Tuning with Limited VRAM
- **Source:** arXiv (2026-07-16) — cs.AI
- **Link:** https://arxiv.org/abs/2607.15105
- **Authors / org:** Vladimir Fedosov, Aleksandr Sazhin, Artemiy Grinenko, Frank Woernle
- **Focus area:** Context engineering (long-context training) + local & open models (VRAM-constrained fine-tuning)
- **What it is:** Combines **Hierarchical Global Attention (HGA)** with **segment-wise backpropagation** and **tiered KV storage** — active segment stays in VRAM, older KV chunks migrate to RAM or NVMe. **Numbers on Qwen3-8B / 4-bit QLoRA / 16 GB Quadro RTX 5000:** training context **16,384 tokens** (vs 2,048 with dense attention, an **8×** lift); evaluation context up to **131,072 tokens**; peak VRAM **15.28 GB** (fits under 16); throughput 217.75 vs 207.02 tok/s at 2K (marginally faster than dense); quality **2.7405 nat vs 2.7383 nat** for dense — statistical parity. Dataset: PG19.
- **Why it matters for Justin's agents:** The single most locally-transferable result of the week. The Quadro RTX 5000 is a **16 GB** GPU — the exact same working-memory budget as **half of Justin's M5 Max 64 GB unified**. If HGA + tiered KV storage fits Qwen3-8B fine-tuning at 16K training / 131K eval in 15.3 GB VRAM, then on M5 Max you should be able to fine-tune the same model at **~64K training / 512K eval** using the M5's ~40 GB of usable unified memory (leaving headroom for the OS and MLX). This is the first *actionable* path the vault has tracked for **agent-personalization fine-tuning on Apple Silicon** — every prior long-context fine-tuning paper assumed CUDA and 40 GB+. **Composes with LongStraw (Item 1)** — HGA + tiered KV is the smaller-hardware version of LongStraw's selective state retention; the two use the same conceptual primitive at different scales. **Composes with KV grafting (2607.14431, 2026-07-17)** — grafting stores *verified* KV state, tiered storage swaps *active* KV state; the two are complementary layers of the same "KV as first-class artifact" stack.
- **Action signal:** `try-now` + `local-fit` — the code is not obviously open sourced from the abstract, but HGA is prior-art enough (published architecture) that the tiered-KV combination can be prototyped on MLX with Qwen3-8B against PG19 as a baseline. Open empirical question: **does the NVMe tier work over Apple's fabric?** M5 Max NVMe bandwidth (~7 GB/s sequential) is ~10× lower than PCIe 5.0 x8, which is where the throughput-vs-dense parity in the paper *might* start to break down.

### 7. OmniaBench: Benchmarking General AI Agents Across Diverse Scenarios
- **Source:** arXiv (2026-07-16) — cs.CL
- **Link:** https://arxiv.org/abs/2607.14989
- **Authors / org:** Chengyu Shen + 15 co-authors
- **Focus area:** Evaluation (general-agent benchmarks)
- **What it is:** **1,431 tasks** across a hierarchical taxonomy of **90 level-1 and 354 level-2 domains** spanning B2C (ToC), B2B (ToB), and enterprise (ToE) scenarios. Four task-generation routes: DAG, DAG-S, Solver, Program synthesis. **Ten-dimensional capability taxonomy** + **eight compositional atomic difficulty factors**. **Numbers on frontier models:** **Claude-Sonnet-5 58.54% Pass@1**, **GPT-5.6-Sol 57.14% Pass@1**. - **Why it matters for Justin's agents:** The **58.54% Claude-Sonnet-5 vs 57.14% GPT-5.6-Sol** delta is small (~1.4 pp) and *below the reported spread on most vault-tracked benchmarks* — matches the emerging pattern that **frontier models are converging on capability** and the ceiling is now set by the **harness + skill package + memory + tools** *around* the model, not the model itself. This is convergent with StructAgent's "wrapper > backbone" thesis (2607.11388), Tactile's substrate-substitution result (2607.14443), and the entire harness-engineering cluster. The 10-dim capability taxonomy is worth mining as a **structured lens for the seven-axis Bousetouane rubric** (2607.14275) — OmniaBench's dimensions are *capabilities*, Bousetouane's are *context qualities*; together they specify a 17-dimensional evaluation surface for any agent deployment. Also useful as a *contamination-controlled* replacement for GAIA / AgentBench in vault-internal benchmarking.
- **Action signal:** `track` — no obvious code release in the abstract; wait for release before running on Claude Code with local skills. `compare` — extends the "capability-convergence + wrapper-matters" thread with the highest resolution frontier-model number this week.

### 8. Does Multi-Agent Debate Improve AI Feedback on Research Papers?
- **Source:** arXiv (2026-07-14) — pre-registered experiment
- **Link:** https://arxiv.org/abs/2607.14713
- **Authors / org:** Tomas Havranek, Zuzana Irsova
- **Focus area:** Agent orchestration (multi-agent debate) + evaluation (LLM-as-judge validity)
- **What it is:** Pre-registered experiment: **44 meta-analysis authors ranked three AI-generated reports on their own papers** (length- and format-controlled). Single AI pass vs two multi-agent debate tools (**mad-research** and **paper-workshop**). **Findings:** authors ranked the single-pass report highest; single-pass beat **mad-research by 0.66 rank points** and **paper-workshop by 0.57**. **Paper-workshop consumed ~30× more tokens for the worse result.** Real journal referee reports were usually ranked #1 by authors but **last by AI judges** — a direct disagreement between human quality perception and AI-judge preferences.
- **Why it matters for Justin's agents:** Two loaded findings.
  1. **Multi-agent debate has a negative net-value on this task.** The vault has ~15 items covering multi-agent orchestration (SearchOS 2607.15257, StructAgent 2607.11388, Compound 2607.14004, etc.), almost all of which report *positive* wins. This is the first pre-registered adversarial test with a *domain-expert* judge population, and it inverts the sign. This does not refute prior work (task is narrow: research feedback) but it does establish **domain sensitivity of multi-agent gains** as a live variable — the same architecture that wins on GAIA/OSWorld may lose on expert-critique tasks.
  2. **AI-judge / human-author preference divergence.** LLM-as-judge is the load-bearing evaluation primitive for **Pairwise-Validator (2607.14408)**, **Compound**, and most of the harness pipeline. The AI-judge ranking real referee reports *last* while authors rank them *first* means the calibration failure is not on frontier tasks — it's on **naturalistic quality**. Directly relevant for anyone using Claude as an eval-judge in production; the finding argues for **rubric-anchored judging over open-ended judging**, matching the Bousetouane 7-axis + OmniaBench 10-dim direction.
- **Action signal:** `compare` (conflict) — first strong counter-evidence in the multi-agent thread; ledger as a scope-caveat on prior positive results. Also `track` — the 30× token-cost multiplier is a design constraint anyone running production multi-agent orchestrations should measure before scaling.

### 9. Allen AI — "What building Shippy taught us about building agents"
- **Source:** Hugging Face blog / Allen AI Skylight team (2026-07-15)
- **Link:** https://huggingface.co/blog/allenai/shippy-tech-blog
- **Authors / org:** Ai2 Skylight team
- **Focus area:** Agent orchestration (production architecture) + tools & connectors (deterministic tool layer)
- **What it is:** Design retrospective for **Shippy**, a live maritime-domain-awareness agent serving **300+ government and NGO partners in 70+ countries**, built on **Claude Opus 4.6 + OpenClaw** (Ai2's agent framework, open source). Three architectural layers:
  1. **Soul + Skills + Config**, each versioned in a Docker image: `soul` = system prompt with behavioral boundaries; `skills` = markdown files defining capabilities; `config` = model + runtime settings.
  2. **Deterministic CLI layer** between agent and backend API: handles auth, pagination, structured output, and geometry encoding — collapses complex nested filters into typed commands, writes large query results to JSON files rather than through the shell.
  3. **Mothership** — per-session isolated Kubernetes pods with **scoped JWTs per pod**, ensuring cross-tenant data isolation across 70 countries.
  Eval framework: **Harbor** (open source), which runs scenarios against live data with weighted rubric scoring by subject-matter experts.
- **Why it matters for Justin's agents:** The most production-transferable case study in weeks. Three direct hits:
  1. **Soul + Skills + Config triple is a shippable naming convention** — matches the vault-tracked skill-package thread (SkillOpt, NVIDIA autoresearch's brev-etiquette/session-memory/autoresearch skills, Dynamic Agent Skills survey 2607.10113, Mistral Prompts+Skills). Shippy's specific framing (`soul` = personality/refusals, `skills` = capabilities, `config` = model choice) is cleaner than the vault's current mental model and worth adopting as terminology in Justin's MCP repo.
  2. **Deterministic CLI as an isolation layer for LLM nondeterminism.** This is *the missing link* between MCP transports and correctness. Instead of exposing raw HTTP APIs to Claude, Shippy exposes a typed CLI that the agent *cannot* call incorrectly — geometry validation, auth, pagination all handled below the LLM. **Direct action for Justin's MCP tools:** every MCP server should have a "typed-CLI facade" rather than exposing arbitrary parameters — this is the same primitive as Proof-or-Stop's receipt bundles (Item 3), one level lower in the stack.
  3. **Per-session sandboxed pods with scoped JWTs.** For the federal-data-engineer use case where cross-tenant data isolation is a hard requirement, Mothership's architecture is a working reference. Also, the finding "**explicit behavioral boundaries belong in prompts, not fine-tuning**" is a concrete rebuttal to the vault-tracked "post-train for tool inertia" direction (ToolAnchor 2607.14145) *at the guardrail layer* — for *behavioral* guardrails the prompt wins; ToolAnchor is only right for *tool-use inertia*.
- **Action signal:** `try-now` — OpenClaw and Harbor are open source; the soul/skills/config triple is portable as a directory convention today. Also `compare` — sixth "skill-as-first-class-artifact" data point and the first with a **7-country, 70-partner production deployment** backing the pattern; ledger accordingly.
