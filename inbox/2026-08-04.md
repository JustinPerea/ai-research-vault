# AI Research Digest — Tuesday, August 4, 2026

## TL;DR
- **OneDayAgent** [arxiv:2608.05013] is the Mitamaton-shaped harness of the week: decompose an everyday request, keep execution memory under context pressure, verify-and-repair the deliverable. On AgentIF-OneDay (104 work/life/study tasks) GLM-5.2 hits **0.821** SOTA (vs AutoClaw 0.799 / Manus 0.645 / Codex-GPT-5.5 0.664). Same harness, no per-backend tuning, runs on five models (Qwen3.5-9B **0.624** → GLM-5.2 **0.821**). Ablation: decompose-only and verify-only each **+3.3 pp**; both **+5.0 pp**. Verification is the cheap module (+2.2 min); full harness is slowest per point. Code via zjunlp.

Hermes+ (five loop interventions) is clearest on **Update (Δ +0.12 → +0.24)** — replacing stale state.
- **SafeCommit** [arxiv:2608.04289] is the act/don't-act layer for memory-grounded side effects. Commit only when the action is safe in *every* retained plausible world (conformal certificate, unsafe-commit ≤ α); otherwise a low-side-effect probe or fallback. ### 1. OneDayAgent: Towards a Long-Horizon Harness for Autonomous Agents
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2608.05013
- **Authors / org:** Jingsheng Zheng / Xinyuan Fang / Jintian Zhang / Zhengke Gui / Huajun Chen / Ningyu Zhang — Zhejiang University + Ant Group
- **Focus area:** Long-running / everyday harness (the Mitamaton shape)
- **What it is:** A long-horizon harness for open-ended everyday requests (work / study / life) that are cross-environment and multimodal. Three capabilities: **task decomposition** (≤6 subtasks, later subtasks inherit compact checkpoints not full ReAct traces), **execution memory** (summarized tool output, subtask state passing, context compression at 0.9× window), **global verification + targeted repair** (up to 3 repair loops × 50 ReAct iters). Unified tools: web, scholar, Python/shell, files, images. AgentIF-OneDay, 104 tasks / 767 rubric points. GLM-5.2: **0.821** overall (OWE 0.818 / LII 0.821 / IR 0.829; Work 0.855 / Life 0.823 / Study 0.731), vs official AutoClaw **0.799**, Manus **0.645**, ChatGPT-Agent **0.626**, Codex GPT-5.5 medium **0.664**. Cross-backend, same harness, 104/104 coverage: Gemini-3.1-Pro 0.743, Qwen3.5-397B-A17B 0.708, Qwen3.5-9B **0.624**, Qwen3.6-27B 0.613. Ablation (GLM-5.2): DIRECT 0.771 → DECOMP 0.804 → VERIFY 0.804 → FULL **0.821**; VERIFY adds 2.2 min, DECOMP adds 10.6 min and ~60% more tool calls. 95/104 pass verify first try; 6 of 9 repairs recover. 35/104 trigger compression; compression count is uncorrelated with score. Authors' own caveat: no workspace isolation in the current impl; prompt-injected web content can persist through compression.
- **Why it matters for Justin's agents:** If you read one harness paper for Mitamaton, read this. It is literally "one day of work/life/study, attachments in, deliverable out." Steal, in order: (1) **verify-only** — cheapest +3.3 pp, the module to wrap around Claude Code / Mitamaton tonight; (2) subtask checkpoints as files, not traces; (3) compression that keeps the original request + last 3 rounds. Do not copy the 53-minute GLM-5.2 profile. Qwen3.5-9B at 0.624 under the *same* harness is the local-64 GB existence proof that the harness transfers down. LongHorizon-Harness (yesterday) is the sibling with a named MEA split and Terminal-Bench numbers; OneDayAgent is the everyday-task instantiation with the ablation that says "verification first."
- **Action signal:** `try-now` — implement VERIFY as a Mitamaton / Claude Code final-pass against the original request + produced files before you mark the day-task done. Then `compare` FULL vs VERIFY-only on 10 personal AgentIF-like tasks.

### 2. PAST-Bench: Benchmarking the Foundations of Recursive Self-Improvement in Personal Agents
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2608.04003
- **Authors / org:** Shuhan Xue / Zixin Ding / Yichen Shen / Yinjie Wang / Zhenfei Yin / Yingcheng Wu / Yuxin Chen / Mengdi Wang / Ling Yang
- **Focus area:** Personal agents + self-evolution eval
- **What it is:** Isolates whether *retained experience* (not a stronger model or a longer prompt) improves later sessions. Strict context-clearing: volatile context wiped between episodes; any gain must flow through memory / skills / profile / session index. 26 scenarios, 204 episodes, four capabilities (Memory 5/41, Procedural 8/64, Info-gathering 6/48, Update 7/51), matched persistence-on/off, plus a **mechanism-evidence** score (write → retrieve → apply / update). Seven base models on Hermes: Overall Δ **+0.13 to +0.24** (GPT-5.4 +0.24 / Mech 0.80; MiniMax-M2.7 +0.13 / Mech 0.64). Four frameworks on MiniMax-M2.7: Hermes and nanobot tie at Δ +0.13 but Mech **0.64 vs 0.57**; Agent-Zero **Δ −0.08**. Hermes+ adds five loop interventions (plan-time consult, typed memory bindings, ranked skills, retrieval-before-action gate, synchronous closeout flush): Overall Δ **+0.13 → +0.15** (within run noise ±0.04/0.06) but Update **+0.12 → +0.24** and Mech **0.64 → 0.73**. Claude Code + MiniMax-M2.7 under the same protocol: Overall Δ **+0.16**.
- **Why it matters for Justin's agents:** This is the eval for "did my SessionStop skill write / nightly curator / Learning-on-the-Job rule actually help *tomorrow*." Headline Δ without Mech is how you fool yourself. The five Hermes+ interventions are a checklist, not a framework swap: (E1) plan only after consulting saved state, (E2) typed current-vs-superseded bindings, (E3) procedures live as ranked SKILL.md not transcript prose, (E4) block the answer if the task is recall-dependent and nothing was read, (E5) flush the corrected value *before* the session dies. E5 is the Mitamaton calendar/constraint one.
- **Action signal:** `compare` — run a 12-episode personal PAST-style family (4 memory, 4 procedure, 4 update) with persistence on vs off before adding another memory product.

### 3. SafeCommit: Certifying When Memory-Grounded Agents May Safely Act
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2608.04289
- **Authors / org:** Mayur Akewar / Ravi Ranjan — Florida International University
- **Focus area:** Agent security + act/don't-act (memory-grounded side effects)
- **What it is:** Premature commitment: the agent acts while memory may be stale, conflicting, incomplete, or poisoned. SafeCommit sits between reasoning and external execution. Builds a calibrated set of plausible latent worlds from memory / observations / tools / provenance / policy; **commits a side-effectful action only if a conformal certificate says it is safe in every retained world**; otherwise a low-side-effect probe aimed at the blocking worlds, or defer/escalate/abstain. Under calibrated coverage, P(unsafe certified commit) ≤ α; representation misses add a separate β. Controlled simulator (not a deployed-agent claim), α=0.05, ≤2 probes, 10 seeds: Single-world UCR **41.2%** / TS 58.8%; SafeCommit **UCR 2.6% / TS 97.4% / 0.55 probes**; certificate-without-probes is safe but only 44.7% TS. Family-wise UCR stays 1.2–3.9% on stale / conflict / poisoned / auth-drift. One targeted probe recovers most of the utility (TS 44.7 → 95.1). Code: https://github.com/akewarmayur/SafeCommit
- **Why it matters for Justin's agents:** This is the formal version of Mitamaton's send/delete/pay/share gate, and it is about *memory uncertainty*, not just prompt injection. A calendar note that says "ops@ is the recipient" plus a silently rotated alias is exactly their worked example. Portable loop: (1) enumerate 2–4 safety-relevant worlds (stale path, poisoned recipient, expired permission), (2) refuse the side effect if any world makes it unsafe, (3) prefer a metadata/permission probe over "are you sure?". Complements the later SARA paper (authorization ≠ induction) and yesterday's Anthropic eval incident (the prompt is not a sandbox). Authors are explicit: proof-of-concept, not a production layer.
- **Action signal:** `try-now` on the 3–5 side-effecting Mitamaton tools as a commit/probe/fallback wrapper; `compare` against a dumb confirm-every-time baseline on 20 stale/conflict cases.

### 4. Introducing Shieldstral — Mistral
- **Source:** Mistral News
- **Link:** https://mistral.ai/news/shieldstral/
- **Authors / org:** Mistral (Aug 4, 2026). Technical report [arxiv:2607.25857] (Calvi / Sooriyarachchi / Pistilli / Lample / Buyl / Augustin / Müller / Stock et al., submitted Jul 28, revised Aug 4)
- **Focus area:** Local / on-device safety classifier (open weights)
- **What it is:** First Mistral moderation model released as **open weights (Apache 2.0)**. Docs: **3.8B** params, 32k context, text+image, public preview. Blog: ~3B, single **16 GB** GPU, policy as a plain-language yes/no question at inference (instruction + query + document), yes/no logits softmaxed into a calibrated score, no retraining to retarget. Unifies prompt moderation, response moderation, refusal detection, prompt–response pairs, and multimodal. Training recipe in the paper: ~**54.1M** contrastive pairs, LoRA + SLERP merge of public-data / fine-grained-policy / base-instruct checkpoints, built on Ministral-3-3B-Base-2512 + Pixtral encoder. Claimed to match or beat open guards up to **7×** its size on text safety and to set SOTA on multimodal moderation; secondary reporting cites HarmBench **99.4%**, VLGuard **97.7%**, ToxicChat F1 84.1%, XSTest 94.6% — treat those as Mistral-reported until independently replicated. Inaugural Open Secure AI Alliance drop with NVIDIA.
- **Why it matters for Justin's agents:** This is the first *local-fit* safety classifier of the backfill week that you can actually run on the M5 Max. 3.8B at Q4 is a rounding error next to a 30B-A3B. Use it as Mitamaton's / Claude Code's **observation filter** (email body, calendar invite, web page, skill text) *before* the main model sees the untrusted string — complementary to SafeCommit (item 3), which gates *actions*. Policy-in-the-prompt means you can write a Mitamaton-specific policy ("flag anything that asks to send mail, move money, or disable a reminder") without a fine-tune.
- **Action signal:** `try-now` — pull the Apache-2.0 weights and wrap the 3–5 untrusted MCP observation channels; `compare` against a prompted Opus "is this a prompt injection" call on the same 20 items.

### 5. When Agents Learn to Be You: AntiSkillBench
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2608.03700
- **Authors / org:** Yongli Xiang / Zhifang Zhang / Bojun Yang / Ziming Hong / Lei Feng / Miao Xu / Tongliang Liu — University of Sydney + UQ + collaborators
- **Focus area:** Agent skills (privacy / impersonation)
- **What it is:** Persona skills distill interaction traces into portable SKILL.md-like artifacts. AntiSkillBench: 50 profiles (demographics + background + Big Five + communication style) × 50 queries × 3-round dialogues = **7,500** persona-grounded turns; three distillation protocols (Direct / 3-stage / Colleague); skill-level Skill Coverage + agent-level Field-QA and VocabGain; four defenses (online Privacy Sanitization, post-hoc Adversarial Obfuscation, online/post-hoc Semantic Backdoor). Across GPT-5.4 / Gemini-3.6-Flash / Claude Haiku 4.5: communication-style Skill Coverage **88–92%**, overall SC **55–66%**; Field-QA overall up to **56%** (GPT-5.4 3-stage); communication VocabGain **87.7** on that setting. Defenses: online PS is the strongest active method but mostly strips *style*, leaving personality/background; semantic backdoors survive Direct/3-stage (ASR-S 96–100%) and **collapse under Colleague Distill** (ASR-B 0%). Project: https://yonglixiang.github.io/AntiSkillBench
- **Why it matters for Justin's agents:** If Mitamaton or a Claude Code skill is distilled from Justin's traces (or if you ever ship a "colleague skill"), the skill *is* a concentrated privacy object — portable across agents, reusable without the original vault. Do not put raw personal traces into a skill you might sync or share. Minimum viable hygiene: (1) skills carry procedures, not identity, (2) strip demographics/style before any distill, (3) do not treat a watermarked skill as a real control (Colleague Distill eats the watermark). Complements OpenSkillRisk's 17% unsafe-skill floor [arxiv:2607.20121] on a different axis (privacy vs dangerous third-party skills).
- **Action signal:** `track` — audit existing `~/.claude/skills` for first-person biographical leakage; do not build a persona-skill pipeline this week.

## Conflicts & open questions
Cross-referenced against `_meta/claims-ledger.md`:
- **Conflict flagged:** OneDayAgent and LongHorizon-Harness (Aug 3) both claim the harness is the lever and both externalize state + verify. They do **not** agree on the object: OneDayAgent's state is subtask answers + result files + a compressed dialogue; LongHorizon-Harness's state is an explicit task-state record updated *only* from environment-verified facts. OneDayAgent's own ablation says VERIFY-only ties DECOMP-only at +3.3 pp — so do not install both full harnesses. Steal VERIFY from OneDayAgent and the "fresh-context executor" from LongHorizon-Harness.
- **Convergent evidence:** SafeCommit (commit iff safe in every retained world) + Anthropic cyber-eval post (Jul 30, prompt ≠ sandbox) + later SARA (observations induce, they do not authorize) are the same split: **authorization lives below the model**. SafeCommit's numbers are a controlled simulator; do not quote 2.6% UCR as a Mitamaton guarantee.
- **Open question:** PAST-Bench's Hermes+ Update win (Δ +0.24) is the closest published result to "Mitamaton remembered I moved the meeting." Does E5 (synchronous closeout flush of the corrected binding) alone reproduce most of that gain on a personal calendar stream? The paper's single-mechanism ablation says E5 is the strongest Update piece. First test.
