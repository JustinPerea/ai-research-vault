### 1. Reason Less, Verify More — Deterministic Pre-Execution Gates Recover a Silent Policy-Violation Failure Mode on Tool-Using LLM Agents
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2607.07405
- **Authors / org:** Vikas Reddy, Sumanth Reddy Challaram, Abhishek Basu
- **Focus area:** Tools & connectors / agent orchestration / evaluation
- **What it is:** Identifies **"silent wrong states"** in tool-using LLM agents — policy-violating actions that execute successfully *without* triggering tool errors or the agent's own self-check. The proposed fix inverts the assumption that the agent should reason harder about validity: **reduce reliance on agent reasoning; strengthen deterministic execution-side validation**. Concretely, four **read-only pre-execution gates** inspect the proposed tool call and current state, blocking policy-violating writes *before* execution rather than trying to detect them after. Benchmark: τ²-bench airline (50 tasks). Headline numbers: **gpt-4o-mini success 29.6% → 42.0% (+12.4pp, P=0.0012)**; **gpt-5.2 61.2% → 71.6% (+10.4pp, P=0.020)**; on the 26 firing-relevant tasks specifically, **+19.2pp**. Critically, the authors ran **negative controls on τ²-bench retail and BFCL** where the tools already self-enforce policy: gates add minimal benefit. This kills the "you're just adding a placebo layer" reading.
- **Why it matters for Justin's agents:** This is the write-side execution-time analog of yesterday's [arxiv:2607.05904] Self-Play Reward Hacking commit-first fix. **The lesson is symmetric: the LLM should not be the verifier of its own destructive actions.** **Concrete moves: (a)** for every MCP server in Justin's stack that exposes a write-shaped tool (file writes, DB updates, git operations, HTTP POST), **add a small deterministic gate before invocation** — a Python function that takes the proposed call + current state and returns allow/deny. The +12.4pp airline-domain delta is what to expect; the negative-control results say the gates only help where tools don't already self-enforce, so you can add them universally without penalty. **(b)** the **+12.4pp on gpt-4o-mini** is the load-bearing number for local-model deployments — small models are the ones with the highest silent-wrong-state rate, and deterministic gates recover a majority of the frontier-tier gap. This is the single strongest reason to add gates to any local-executor stack today. **(c)** the **read-only** framing of the gate is important architecturally: the gate never modifies state, only inspects the proposed call. This composes cleanly with the existing agent loop — no retraining, no prompt rewriting, no change to the agent's reasoning trace. **(d)** the τ²-bench airline benchmark is a well-shaped harness for future work: **any Claude-Code MCP tool wrapping a state-changing external service is a candidate for the gate pattern.**
  **Cross-ref:** direct constructive complement to yesterday's [arxiv:2607.05904] Self-Play Reward Hacking commit-first fix — **commit-first fixes verification at eval time; deterministic gates fix verification at execution time**. Both papers are converging on **remove the LLM from the load-bearing verification step**. **Cross-ref:** this is the ninth convergent instance of **gate-before-commit** in the tracked corpus (Janus, Mnemosyne ATP, SkillOpt validation gate, ProvenanceGuard, RoPoLL/Minority Sentinel aggregation, SkillOpt-Lite consensus gate, ContextNest provenance chains, Validity Layer in DynaKRAG, now deterministic gates in Reason Less Verify More). **The unifying claim is now sharp: "the LLM should propose; a deterministic (or at minimum independent) verifier should dispose."** **Cross-ref:** the **negative-control result** (gates add nothing on BFCL / retail) is the strongest possible refutation of the "any additional check helps" naive reading — this is a real effect, tied to the *write-side silent-failure* subclass, not a generic accuracy bump.
- **Action signal:** `try-now` + `compare` (retrofit deterministic gates on every MCP write-side tool today; +12.4pp on gpt-4o-mini is the small-model number to reference; extends the gate-before-commit lineage into execution-time territory; strongest counter today to the reference-free-judge collapse story from items 2 and 3)

### 2. Do LLM-Generated Skills Make Better AI Data Scientists? — 7,560 Runs Show Zero Improvement Over Task Prompts Alone
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2607.07504
- **Authors / org:** Wei-Jung Huang
- **Focus area:** Coding agents / agent orchestration / evaluation
- **What it is:** Full component-ablation study of the "LLM-generated reusable skill files improve agent performance" claim, run at industrial scale. Design: **56 tasks × 9 model configurations × 3 providers = 7,560 experimental runs**, with an additional **1,512-run control study**. Ablates skill *presence*, skill *content*, and skill *specificity* across the four canonical data-science workflow stages (data prep, extraction, statistical analysis, reporting). Headline: **no reliable improvement from any skill variant** — total spread across all variants is **1.2 percentage points**, and **every p-value is ≥ 0.396**. - **Why it matters for Justin's agents:** This is a direct high-power `compare` against the **SkillOpt / SkillOpt-Lite lineage that has dominated the past two weeks** — [microsoft-research-2026-06-30-skillopt] SkillOpt reported +23.5pp on GPT-5.5; [arxiv:2607.03451] SkillOpt-Lite reported GPT-5.4-nano beating GPT-5.5 baseline on SpreadsheetBench via the same three-principle recipe. **Huang's result is not a direct contradiction — the data-science workflow is a different task family than LiveMath or SpreadsheetBench — but it is the strongest signal yet that the skill-lineage numbers may not generalize.** **Concrete moves: (a)** before adopting SkillOpt-Lite in production for any Justin-relevant task family (research-agent workflows, MCP-tool authoring, code review), **run Huang's exact ablation shape**: N tasks × M configs × P providers, control for skill *content*, *presence*, and *specificity* independently. The 7,560-run pattern is the reproducible template. **(b)** the **p ≥ 0.396 across the board** is the diagnostic — if Justin's own skill-adoption A/B has p above 0.05 across the board, **assume skills are decorative until proven otherwise**. **(c)** the SkillOpt lineage headlines came from math and structured-workflow benchmarks (LiveMath, SpreadsheetBench, LiveCodeBench) where the skill "compiles" into an executable subroutine. **The mechanism for why skills fail on data-science tasks is likely that skills act as executable subroutines only when the domain admits sharp decomposition** — free-form data prep and reporting don't. **Justin's own tasks are largely at the free-form end**; treat skill adoption as domain-specific from now on.
  **Cross-ref:** direct `compare` against [microsoft-research-2026-06-30-skillopt] SkillOpt and [arxiv:2607.03451] SkillOpt-Lite — three papers together define the field: **SkillOpt/Lite = works on structured workflow; Huang = fails on free-form data science**. The load-bearing question is now: **for a new task, which side of the boundary is it on?** **Cross-ref:** mechanism explanation comes from today's item 3 (Blind Curator) — if the validation judge for skill promotion has false-pass bias, no amount of data can rescue the retirement mechanism, and skill libraries silently accumulate ineffective content. The Huang result is the empirical observation; the Blind Curator result is the theoretical prediction. **The two papers together are the mechanism-plus-evidence sequel to yesterday's [arxiv:2607.05904] Self-Play Reward Hacking.**
- **Action signal:** `compare` + `try-now` (rerun before adopting SkillOpt-Lite on any Justin-tracked task family; 7,560-run template is the reproducibility standard; p ≥ 0.396 is the diagnostic to watch)

### 3. The Blind Curator — Biased Judge Silently Disables Skill Retirement in Self-Evolving Agents Past a Sharp Threshold
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2607.07436
- **Authors / org:** Xing Zhang, Yanwei Cui, Guanghui Wang, Ziyuan Li, Wei Qiu, Bing Zhu, Peiyang He
- **Focus area:** Evaluation / agent orchestration / long-running & autonomous loops
- **What it is:** Formal analysis of *how* biased reward judges wreck self-evolving agents. Key claim: **false-pass bias is not additional noise — it categorically switches off the retirement mechanism past a sharp threshold that no amount of training data can cross**. This is stronger than the standard "noisy reward slows learning" story: false-pass bias creates a phase transition, and once you're on the wrong side, contribution-based skill retirement is *disabled*, not merely slowed. The mechanism is **universal, holding across domains and failure rates**, and — critically for detection — **surfaces in no aggregate metric**. The silent-degradation property means teams shipping self-evolving agents can be past the threshold and never know from ordinary telemetry. Practical contribution: a **cheap defect-injection audit** — inject known-bad candidates and check whether the judge false-passes them — predicts which side of the threshold a deployed judge occupies *before* the retirement mechanism is put under real load.
- **Why it matters for Justin's agents:** This is the theoretical framework that **explains why item 2 (Huang's 7,560-run null result) is not just a one-off empirical fluke** — it's the predicted outcome once false-pass bias exceeds threshold. **Concrete moves: (a)** for every self-evolving agent in Justin's stack (SkillOpt-Lite skill directory, Claude Code's own skill files, memory-write pipelines that use LLM judges for admission), **run the defect-injection audit today**: hand-craft ~20 known-bad candidates that should be retired, feed them through the judge, measure false-pass rate. **Any false-pass rate above the threshold means retirement is effectively off** — new skills will accumulate but old bad ones will not be retired, so quality drifts down while surface metrics stay flat. **(b)** the **"no aggregate metric surfaces the degradation"** claim is the strongest possible reason to add **per-skill contribution audits** rather than relying on top-line task-success dashboards. If your skill library is growing but held-out task performance is flat, you are on the wrong side of the threshold. **(c)** the sharp-threshold phase-transition claim explains **why yesterday's Self-Play Reward Hacking [arxiv:2607.05904] fix (commit-first) worked so dramatically** — commit-first collapses false-pass rate 0.719 → 0.012, which crosses the threshold from disabled retirement back to functional. **The two papers together propose a coherent playbook**: (i) audit judges for false-pass rate before deploying self-evolution, (ii) use commit-first at eval time to keep the rate low, (iii) use deterministic gates (item 1) at execution time where possible.
  **Cross-ref:** direct mechanism-side companion to today's item 2 (Huang) and yesterday's [arxiv:2607.05904] Self-Play Reward Hacking. Together these three form the strongest three-paper convergence of the summer: **reference-free reward judges are not just noisy signals; they are structurally capable of silently disabling self-evolution mechanisms, and the failure mode is invisible at the top-line metric.** **Cross-ref:** this generalizes [arxiv:2607.01661] InfoDelphi's "identical-evidence multi-agent debate collapses to herding" result — both papers describe **latent-failure modes that surface only when you look at the right internal metric**, and both propose the same defense pattern: **audit the judgment step with a synthetic probe before deployment**. **Cross-ref:** the phase-transition claim is a specific prediction the J-space work (item 1 in yesterday's digest, [anthropic-2026-07-06-global-workspace]) could test empirically: **does the J-lens show "verified" / "correct" patterns firing incorrectly on false-passed candidates?** If yes, we have interpretability-side evidence for the retirement-mechanism failure.
- **Action signal:** `try-now` + `compare` (defect-injection audit on every LLM-as-judge in the stack today; explains item 2's null result; forms the three-paper convergence with yesterday's Self-Play Reward Hacking; the "no aggregate metric surfaces the degradation" claim mandates per-skill contribution audits going forward)

### 4. Cost-Effective Agent Harnesses for ARC-AGI-1 — 67.25% pass@2 at $0.62/Task, DeepSeek V3.2, No Task-Specific Training
- **Source:** arXiv / HF Daily Papers
- **Link:** https://arxiv.org/abs/2607.06764
- **Authors / org:** Kabir Moghe, Peter Chin
- **Focus area:** Agent orchestration / reasoning & inference-time compute / coding agents
- **What it is:** Attacks the "you need ARC-specific fine-tuning to beat 50% on ARC-AGI-1" assumption with a purely orchestration-level solution. Two components: **(1) Explorer-Definer** — a two-stage pipeline that separates *pattern discovery* (finding the transformation rule from a few input-output examples) from *executable transformation synthesis* (turning the rule into a concrete Python program that produces the target grid); **(2) Reflective Orchestrator** — an outer loop that adds **autonomous re-exploration**, generating new transformation hypotheses when prior ones fail on training examples. Benchmarks on ARC-AGI-1: **baseline one-shot 15.5% pass@2**; **pipeline alone 57.5% pass@2 at $0.25/task**; **pipeline + Reflective Orchestrator 67.25% pass@2 at $0.62/task** on DeepSeek V3.2 without task-specific training. The Orchestrator specifically adds **+9.81pp on pass@1** and drives the +52pp aggregate lift over baseline. Central architectural claim: **the pipeline is generation-bound, not selection-bound** — better ranking algorithms don't unlock more; broader adaptive re-exploration does.
- **Why it matters for Justin's agents:** This is a same-week transferable pattern for **any repo-scale coding-agent task** (Justin's actual workload — Claude Code on real codebases): the Explorer-Definer + Reflective Orchestrator shape is directly applicable, and the numbers say the payoff is on the generation side, not the ranking side. **Concrete moves: (a)** in Justin's Claude Code / MCP-tool authoring loops, **treat pattern discovery and transformation synthesis as separate stages** — currently these are conflated in a single agent turn. Separate stages allow the orchestrator to re-explore on the discovery axis without re-running synthesis. **(b)** the **$0.62/task at 67.25% pass@2** is the reference number for cost-effective agent orchestration on hard reasoning — better than any prior published ARC-AGI-1 pure-inference number. **The DeepSeek V3.2 backbone is important** — this is a reasonable-cost open-weight-ish model, so the cost line is real, not a hosted-frontier discount. **(c)** the **generation-bound, not selection-bound** finding is directly `compare` with today's item 7 ([arxiv:2607.07646] RL Post-Training Builds Compositional Reasoning) — RL post-training composes primitive skills into sequential + parallel higher-level strategies, which is *exactly* the shape of the missing generation broadening that ARC-AGI-1 is generation-bound on. **Predict: the same +52pp lift will replicate with a RL-post-trained backbone at lower orchestration overhead.** **(d)** the **Reflective Orchestrator** is a clean production-shaped implementation of the same "reflect + backtrack" loop as [arxiv:2607.07492] Pyligent (item 6) — Pyligent trains the backtrack decision into the model; ARC-AGI-1 harness runs it as an outer loop. **Both are on-trend; the harness form is same-week actionable, the trained form is a next-quarter integration.**
  **Cross-ref:** direct `compare` with [arxiv:2607.07646] (RL post-training composes primitives → this paper's ARC-AGI-1 is generation-bound). **Cross-ref:** the Reflective Orchestrator is architecturally the same gate-before-commit pattern (item 1, item 3 today; and prior lineage) — the orchestrator gates whether to accept a candidate transformation before committing to synthesis; failure triggers re-exploration rather than acceptance. **Cross-ref:** the **$0.62/task** is directly comparable with item 5 ([arxiv:2607.06906] Harness Effect) which reports $0.12/task on 22 enterprise tasks — the delta reflects task difficulty, not orchestration overhead.
- **Action signal:** `try-now` + `compare` (Explorer-Definer + Reflective Orchestrator ports directly to Claude Code coding-agent workflows; $0.62/task at 67.25% pass@2 is the reference number; generation-bound-not-selection-bound is the load-bearing architectural finding)

### 5. GhostWriter — Memory Poisoning Attacks on LLM Agents: ~98% Injection / ~60% Activation Against State-of-the-Art Personal Assistants
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2607.06595
- **Authors / org:** George Torres, Sharad Shrestha, Satyajayant Misra
- **Focus area:** Agent memory / tools & connectors / evaluation (security)
- **What it is:** A two-phase memory-poisoning attack against personal assistant agents that combine conversational abilities + action planning + long-term memory. **Phase 1 (Injection):** an adversary embeds a hidden payload into some information source the agent later reads (email, web page, calendar event, doc). **Phase 2 (Activation):** the poisoned memory is retrieved during a later, unrelated task and steers the agent's behavior. Reported numbers: **~98% injection success rate** (the poison lands in the memory store), **~60% activation rate** (it fires downstream on retrieval and influences the action). Defense proposed: **Agentic Memory Sentry (AM-Sentry)** — memory-saving policies (restrict what content is written) + retrieval screening (screen candidate memories before they influence generation); reported to "dramatically" reduce success while preserving utility.
- **Why it matters for Justin's agents:** Direct adversarial pressure on **every memory-injection paper in the tracked corpus** (Memora, AutoMem, SelfMem, DynaKRAG, LongCrafter, A-TMA). All of these implicitly assume the write path is trusted — GhostWriter says it isn't, and the **98% / 60% split** is the strongest agent-side memory-poisoning result to date. **Concrete moves: (a)** for Justin's MCP research-agent stack (Obsidian vault ingest + web fetch + email/calendar connectors), **treat every non-user-authored write to memory as untrusted**. The retrieval-screening half of AM-Sentry is a same-week wrapper: at retrieval time, filter candidate memories for suspicious patterns (imperative instructions targeted at the agent, out-of-domain content, mismatched context). **(b)** the **~98% injection rate** is the load-bearing number — it says **memory-injection defense at the write path is essentially impossible with current techniques**. The defense has to be at retrieval time. This is the memory-side counterpart to item 1's argument that **the LLM should not be the load-bearing verifier of write actions**. **(c)** for Justin's Claude Code autonomous loops that read from external sources (documentation fetches, GitHub PR content, browsing sessions), **the ~60% activation rate on personal-assistant agents transfers straightforwardly to code-writing agents** — a poisoned doc string retrieved during a code review can inject an instruction into the review. Rate-limit external-source ingestion into persistent memory and require an explicit user gesture for cross-context recall. **(d)** the AM-Sentry defense architecture is worth mirroring: **memory-saving policy + retrieval screening** is the two-part canonical shape.
  **Cross-ref:** direct adversarial pressure on the memory-injection cluster ([arxiv:2607.03726] SelfMem, [arxiv:2607.06507] DynaKRAG, [arxiv:2607.02804] AutoMem, [microsoft-research-2026-06-29-memora] Memora, [arxiv:2607.03451] A-TMA). **All five papers assume trusted write-path; GhostWriter falsifies that assumption at production-relevant rates.** **Cross-ref:** the retrieval-screening half of AM-Sentry is architecturally identical to the Validity Layer in [arxiv:2607.06507] DynaKRAG — *filter the legal action/retrieval set before letting the model choose*. Emerging pattern: **restrict-then-decide beats decide-then-validate.** **Cross-ref:** the write-side vs read-side asymmetry (write is easy to poison, retrieval-time screening is the only viable defense) is the same asymmetry as [anthropic-2026-07-06-global-workspace] J-space (yesterday's item 1) — external memory injection may crowd out J-space; if the injected content is malicious, it may hijack J-space. **The two papers together argue that memory-injection systems need read-side verification, not just write-side quality control.**
- **Action signal:** `try-now` + `compare` (implement retrieval screening on every MCP memory read today; ~98/60% is the number to reference for adversarial-pressure disclosures; direct pressure on the memory-cluster papers Justin has been tracking)

### 6. The Harness Effect — Orchestration Design Cuts Token Cost 41% / Wall-Clock 44% Across Six Frontier Models on 22 Locked Enterprise Tasks

- **Link:** https://arxiv.org/abs/2607.06906
- **Authors / org:** Muayad Sayed Ali, Waseem AlShikh, and 30 additional (Writer)
- **Focus area:** Agent orchestration / tools & connectors / evaluation
- **What it is:** A controlled six-model production-scale study designed to isolate **orchestration** as an independent variable from **model choice**. - **Why it matters for Justin's agents:** Writer's paper is the ecosystem-level confirmation of what SkillOpt-Lite (yesterday) and the ARC-AGI-1 harness (item 4 today) argue at task-specific scale: **the orchestration layer is doing more of the work than the model choice**. The Writer paper says a ~40% cost delta is achievable and holds across model tiers. **(b)** the **quality slightly up (0.78 → 0.81)** result is the important secondary finding: **cheaper orchestration is not a quality-cost tradeoff** — better orchestration reduces tokens because the extra tokens weren't earning their keep. **(c)** the **six-model coverage** (three frontier tiers) makes this the definitive-for-now number to cite when arguing orchestration priority to non-technical stakeholders.   **Cross-ref:** direct `compare` with today's item 4 (ARC-AGI-1 harness) — both papers argue that orchestration dominates model choice at production scale; the Writer paper generalizes the finding across 6 models × 22 tasks. **Cross-ref:** the **cheaper AND better** result (cost down, quality up) is the same shape as [arxiv:2607.03451] SkillOpt-Lite (yesterday) — better orchestration makes smaller models overtake larger baselines. **Cross-ref:** the Writer Agent Harness (proprietary) is not the point — the point is the *methodology*: hold task set + model constant, vary orchestration, measure cost/tokens/latency/quality independently. **This is the reproducibility standard for orchestration papers going forward.**
- **Action signal:** `compare` + `track` (methodology is the reproducibility standard; 41/38/44% deltas are the leverage numbers to reference; run a two-orchestration A/B on Justin's own task set to measure specific gain; the six-model coverage makes this the definitive production-scale isolation to cite)

### 7. Pyligent — Search, Fail, Recover: Training Correction-Aware Reasoning with Explicit Backtrack Actions
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2607.07492
- **Authors / org:** Dmitry Beresnev, Vladimir Makharev, Roman Khalikov, Ivan Oseledets, Petr Anokhin
- **Focus area:** Reasoning & inference-time compute / long-running & autonomous loops
- **What it is:** A training framework that reframes chain-of-thought as **validated search over partial solution chains** with explicit **continue / finish / backtrack** actions. The key trick: use a task validator to label *both* successful continuations *and* failed branches, then train the model on the combined signal. This turns the failed branches from wasted rollouts into supervised targets that teach the model when to backtrack. Benchmarks (structured domains with exact validators): **hidden directed-graph task +72.7pp over gold-only SFT**; **4×4 Sudoku +17–18pt on mixed/expert splits**; **Sudoku with reasoning traces +27/+14pt on mixed/expert splits**; **Blocksworld +13pt**. The 72.7pp headline is not on a benchmark where 72.7 means "solved" — it means gold-only SFT is at floor and Pyligent recovers the majority of the recoverable ceiling.
- **Why it matters for Justin's agents:** This is the **trained-model counterpart** to the Reflective Orchestrator from item 4 (ARC-AGI-1). Item 4 runs the backtrack decision as an *outer harness loop*; Pyligent bakes it into the *base model's own action space*. **Concrete moves: (a)** Pyligent's headline domains (Sudoku, Blocksworld, hidden graphs) are proxies for **planning-hard domains where the intermediate state is verifiable** — code repair, SQL query construction, git-history rewrites all fit this shape. If a Pyligent-style training recipe (SFT on continue/finish/backtrack labels from a validator) becomes available for coding agents, expect strong gains on **exactly the tasks where Justin's autonomous Claude Code loops currently spin without recognizing they need to back up**. **(b)** the **+72.7pp on hidden directed graphs** is a proxy for **"structured retrieval where the model needs to know when to give up on a hypothesis and try another"** — the shape of Justin's research-agent workflow. Even without full retraining, adding an *explicit backtrack action to Justin's harness* (an extra tool the agent can invoke with rationale "hypothesis exhausted; return to step N") and logging its use is a same-week experiment. **(c)** the **gold-only-SFT as the baseline** framing is the important methodological contribution: **training only on successful trajectories throws away the signal about when to stop**. This overturns the tacit assumption in most fine-tuning-for-agents pipelines that failed rollouts are noise to be filtered.
  **Cross-ref:** direct trained-model counterpart to item 4's Reflective Orchestrator — Pyligent = training-time backtrack action; ARC-AGI-1 harness = inference-time re-exploration. **Compose**: Pyligent-trained backbone + Reflective-Orchestrator outer loop is the natural next paper. **Cross-ref:** the **learn from failed branches** move is the trained-model shape of [arxiv:2607.07040] Measuring Intelligence Beyond Human Scale (also today, not covered separately) — both argue that the signal from *disagreement* is more informative than the signal from *agreement*. **Cross-ref:** [arxiv:2607.06720] In-Context Search theory (Wolf et al., today, also not covered separately) provides the theoretical grounding: **exponential improvement from in-context search occurs precisely when reflections reliably localize early mistakes** — Pyligent trains that localization capability into the base model.
- **Action signal:** `track` + `try-now` (add explicit backtrack action to research-agent harness this week; Pyligent-style training recipe for coding agents is the paper to watch for next; +72.7pp on hidden graphs is the number to cite when arguing that failed rollouts are training signal, not noise)

## Local-model corner

Nothing shipped today with a *direct* MLX / llama.cpp / M5 Max port. But three of today's items are architecturally portable to the local stack and worth the corner:

- **Pattern: Deterministic pre-execution gates (item 1, [arxiv:2607.07405])**
  - **Applicability:** Every MCP write-side tool Justin currently runs. Read-only gate before invocation; no model change; no retraining.
  - **Expected gain on local models:** +12.4pp is the small-model (gpt-4o-mini) number; **local 7-14B models on M5 Max are the exact tier this pattern helps most** — small models silent-fail more, gates recover more. Expect Qwen3.6-35B-A3B / Gemma 4 26B-A4B / Qwen2.5-7B-Instruct to sit close to the gpt-4o-mini delta rather than the frontier delta.
  - **How to run:** each MCP tool wrapper gets a Python function `gate(proposed_call, state) -> allow | deny(reason)` invoked before `tool.call()`. Blocked calls surface the reason to the agent as a policy-violation error rather than a silent tool error, which forces the agent to reconsider rather than retry. Same-day implementation.
- **Pattern: Two-stage Explorer-Definer + Reflective Orchestrator (item 4, [arxiv:2607.06764])**
  - **Applicability:** Coding-agent workflows on M5 Max — Qwen3.6-35B-A3B, DeepSeek V3.2 (via its dense variants), Gemma 4 26B-A4B. Not specific to ARC; the pattern is task-agnostic.
  - **Expected gain on local models:** the ARC-AGI-1 numbers (15.5% → 67.25% pass@2) come from DeepSeek V3.2, a mid-tier reasoning model. Local M5 Max deployments should see a *directionally similar* multiplier on hard problems where the base model is generation-bound. The Reflective Orchestrator specifically adds +9.81pp on pass@1 — this is the relevant number for local-inference cost budgeting (each retry costs local FLOPs).
  - **How to run:** two harness layers on top of an existing MLX model — an Explorer prompt-agent that generates candidate transformation hypotheses + a Definer prompt-agent that turns each into executable code, with an outer Reflective controller that re-invokes Explorer on validator failure. All local; no additional models required.
- **Pattern: Retrieval screening (AM-Sentry from item 5, [arxiv:2607.06595])**
  - **Applicability:** any local MCP memory system that reads from external sources (Obsidian vault, web fetch, calendar, email, GitHub PR content).
  - **Expected gain on local models:** GhostWriter's ~98%/~60% injection/activation numbers are attack-side, not defense-side — AM-Sentry's own numbers are described as "dramatic reduction" but the abstract doesn't quantify. This is a **track** for the exact numbers; but the *architectural pattern* — filter candidate memories before letting them influence generation — is directly implementable today.
  - **How to run:** wrap the retrieval step with a screening filter — a small local model (Gemma 4B or Qwen3-4B) at Q8 checks whether each candidate memory contains imperative instructions targeted at the agent, out-of-domain content, or role-swapping patterns. Suspicious memories are demoted (not deleted) so the agent can still access them with a user gesture. Same-day pattern; the small screening model runs comfortably on M5 Max alongside the main executor.

## Conflicts & open questions

Cross-referenced against `_meta/claims-ledger.md`:

- **Three-paper convergence — reference-free judges structurally break self-evolution:**
  Yesterday's [arxiv:2607.05904] Self-Play Reward Hacking established that reference-free judges score plausibility, not correctness, and can be driven to 0.94 pass rate at 0.20 true accuracy via self-play; commit-first prompting drops FPR 0.719 → 0.012. Today's [arxiv:2607.07436] Blind Curator shows the mechanism is stronger than "noisy signal": **false-pass bias silently disables skill retirement past a sharp threshold**, and the failure surfaces in no aggregate metric. Today's [arxiv:2607.07504] Do LLM-Generated Skills Make Better Data Scientists? runs the exact ablation implied by the theory and finds it: **7,560 runs, all p ≥ 0.396, 1.2pp spread**. **Reconciliation with the SkillOpt / SkillOpt-Lite lineage:** SkillOpt reported +23.5pp on GPT-5.5 and SkillOpt-Lite reported GPT-5.4-nano beating GPT-5.5 baseline — these results are on math and structured-workflow benchmarks where **the validator is trivially correct** (LiveMath answers are checkable; SpreadsheetBench outputs are diffable). Where the validator becomes an LLM judge (data science, free-form report generation, agent skill retirement), false-pass bias enters, and the retirement mechanism silently fails. **Practical rule: skills work only where the validator is deterministic and reference-free judges are structurally unreliable for self-evolution loops** — commit-first + defect-injection audits are now default hygiene before any self-evolving agent ships.
  Update `_meta/claims-ledger.md` with the sharp-threshold claim and the Huang null-result as confirmation.

- **Constructive complement — deterministic gates instead of LLM verifiers:**
  Today's [arxiv:2607.07405] Reason Less Verify More is the constructive proposal that answers the three-paper convergence above: **replace LLM verifiers with deterministic read-only gates**. τ²-bench airline gpt-4o-mini +12.4pp with negative-control confirmation. Combined with commit-first at eval time, this is the recommended two-layer defense: (a) commit-first prompts on any remaining LLM judges, (b) deterministic gates on any write-side tool call where a rule-based check is possible. Both papers argue **remove the LLM from the load-bearing verification step whenever a deterministic alternative exists.**

- **Complementary architectural pattern — generation-bound vs selection-bound:**
  [arxiv:2607.06764] ARC-AGI-1 harness argues explicitly that the ARC pipeline is **generation-bound, not selection-bound** — better ranking algorithms don't help; broader re-exploration does. [arxiv:2607.07646] RL Post-Training Builds Compositional Reasoning argues that RL composes primitive skills into sequential + parallel higher-level strategies. **Open question: does RL post-training close the +9.81pp Reflective Orchestrator gap by generating broader hypotheses inside the base model, so a single-pass Explorer-Definer would match the orchestrator + baseline stack?** If yes, RL-post-trained backbones make the outer re-exploration loop redundant, cutting local inference cost by roughly half on ARC-shaped tasks. This is the specific hypothesis to watch for a follow-up paper.

- **Open empirical question — how does GhostWriter interact with J-space?**
  Yesterday's [anthropic-2026-07-06-global-workspace] identified the J-space as a small, high-connectivity mental workspace where reasoning-critical concepts sit. Today's [arxiv:2607.06595] GhostWriter poisons memory with hidden payloads that activate on later retrieval. **Open question: when a poisoned memory is retrieved and the agent takes the injected action, does the J-space show the *malicious concept* firing before the action, or does the malicious content bypass J-space entirely (matching the automaticity-bypass regime for grammar / simple facts)?** If poisoned memory bypasses J-space, the J-lens is not a monitor for memory poisoning; if it does surface, the J-lens is the strongest possible defense. This is the specific experiment to request when Anthropic exposes the J-lens.
