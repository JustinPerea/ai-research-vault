# AI Research Digest — Friday, August 28, 2026

## TL;DR
- **WikiSkill** [arxiv:2608.27454] (Google Research) is the cleanest "try this on Claude Code skills this weekend" paper of the gap month: it co-evolves filesystem `SKILL.md`s with a persistent **wiki layer** that compiles traces into compounding knowledge, then gates skill edits on validation. Across Qwen-3.5/3.6, Gemma-4-31B, and Gemini-3.5-Flash on LiveMath / SealQA / SpreadsheetBench / OfficeQA / ALFWorld, it beats EvoSkill / SkillOpt / Trace2Skill on average, with the load-bearing ablation that **wiki access for the Skill Proposer is +15pp** while wiki access for the *inference* agent during training *hurts*. Skills transfer across model families — sometimes better than self-evolved skills. Directly maps onto Anthropic's SKILL.md format.
- **PILOT** [arxiv:2608.26530] closes the other half of the harness loop: a supervisor–worker runtime that **steers the active worker mid-run** (not after) and distils skills/memory *during* the same episode. On Terminal-Bench 2.0 with frozen GLM-5.1 / Kimi-K2.6 it leads counterpart harnesses by up to **9.8pp**; in the self-improvement setting best-so-far pass rate rises **+14.6 / +12.4pp** while mean output tokens fall **42.9% / 47.4%**. Open at github.com/XiaoYang66/Pilot. The live-steering bet is the thing to compare against Claude Code subagents (which typically return only a final summary).
- **SARA** [arxiv:2608.27146] is the MCP-security primitive of the window: tool Observations may *induce* actions but must not *authorize* them. A context-isolated Action Probe records action-origin provenance; real tool calls are authorized only against the user objective + audited successful executions, with **No-History-Promotion** so a later reappearance of an injected recipient cannot launder origin into authority. AgentDojo + AgentDyn: **ASR ≤ 0.63%** across four primary settings while keeping utility competitive. This is the authorization layer Mitamaton / Claude Code MCP should grow, not another prompt filter.
- **Calibrated Enough to Know, Not Calibrated to Act** [arxiv:2608.27167] isolates the act/don't-act gate. Across 12 frontier models, commitment on a *provably unknowable* question rises **6.5% → 54.0%** when a professional dashboard is attached — and a **fully fabricated** panel is statistically interchangeable with a real one (36.8% vs 37.6%). Stated probabilities barely move. A 3B model fine-tuned on 540 dice/coin cases hits **0.0% commitment** on the original items, then breaks when the response format removes the reasoning slot. Mitamaton will sit behind calendars, weather, and market-shaped widgets; the failure is the packaging, not the numbers.
- **CaSKG** [arxiv:2608.25500] (Ant Group / Jilin) calibrates *edges* in a skill graph with textual counterfactual probes (remove / substitute / reorder) before retrieval. Vs Graph-of-Skills: ScienceWorld 72.62 → **80.50**, ALFWorld 80.01% → **86.79%**, fewer environment steps, best of 12 model×benchmark cells. Complements WikiSkill (evolve skills) with "retrieve the right bundle."
- **TwinKV** [arxiv:2608.27128] is the 64 GB local-fit hook: attention magnitude vs leave-one-out causal utility is **Spearman ρ = −0.004**, so attention-based KV eviction is on a broken premise. TwinKV is a **composable repair pass** that swaps unrecoverable evictions (orphans) for redundant retained twins, holding the wrapped policy's budget fixed. Helps StreamingLLM / PyramidKV on Qwen3-4B in a majority of cells; mixed on ExpectedAttention (already near ceiling). Training-free, attention-free.
- **Anthropic opened a research preview of the Model Hardware Standard** [anthropic-2026-08-27-mhs] (Aug 27): a model-agnostic spec for agents to operate programmable lab/factory hardware, accessible via **MCP / CLI / API**. Safety is supposed to sit in the driver, below the agent. Preview-only, not a consumer ship — but it is the first official "MCP for atoms" from the lab that defined MCP.

### 1. WikiSkill: Compiling Agent Experience into Persistent Knowledge for Skill Evolution
- **Source:** arXiv (Hugging Face Daily Papers)
- **Link:** https://arxiv.org/abs/2608.27454
- **Authors / org:** Liyan Tang / Cyrus Rashtchian / Chun-Sung Ferng / Andrew Tomkins / Da-Cheng Juan / Tu Vu — Google Research + Virginia Tech
- **Focus area:** Agent skills + long-running loops + harness evolution
- **What it is:** A three-layer workspace — immutable `raw/` traces, a compounding `wiki/` of pattern pages + evolution log + skill-impact tracker, and an evolving `skills/` tree of `SKILL.md` + `PURPOSE.md`. Loop: Inference Agent rolls out with current skills (and is *barred* from the wiki during training), Wiki Maintainer consolidates traces into patterns, Skill Proposer (ReAct) proposes one atomic create/patch, validation gating keeps the skill only if val score rises. **Wiki is never rolled back.** Evaluated on five benchmarks × five models (Qwen-3.5-4B/9B, Qwen-3.6-27B, Gemma-4-31B, Gemini-3.5-Flash). Headline numbers: WikiSkill avg 38.5 / 47.4 / 63.3 / 54.9 / 68.1 vs strongest prior skill-evolution method 35.2 / 42.3 / 53.3 / 49.1 / 56.1. Scale complementarity: WikiSkill lifts Qwen-3.5-4B / 9B / 3.6-27B by **+12.3 / +17.5 / +23.9** average points; Qwen-3.5-9B + WikiSkill (47.4) beats Qwen-3.6-27B with no skills (39.4). Cross-model transfer: Qwen-3.6-27B skills take Qwen-3.5-9B SpreadSheet 24.3 → 50.5 (vs 33.6 self-evolved); Qwen-3.5-4B skills can *hurt* Gemini-3.5-Flash on SpreadSheet (50.5 → 18.1) by encoding small-model workarounds. Ablation: Skill-Proposer wiki access 48.7 → 63.7 avg; giving the Inference Agent wiki access during training drops that to 60.9.
- **Why it matters for Justin's agents:** This is the first skill-evolution paper that is *natively* in Anthropic's SKILL.md / progressive-disclosure format. Concrete weekend experiment on Claude Code: (1) keep `~/.claude/skills` as the Skill Layer, (2) add a `wiki/patterns/` + `wiki/skill-impact.md` that a maintainer pass updates from session transcripts, (3) never inject the wiki into the live Mitamaton / coding agent — only into the proposer that edits SKILL.md, (4) gate skill writes on a small held-out task set (or on WorkBuddy / a 10-task personal eval). The "skills transfer, discovery ≠ execution" result is the Mitamaton angle: evolve skills on a strong cloud model (Opus / Gemini), ship the markdown to a local 4B–9B. Negative transfer from 4B-authored spreadsheet skills is the failure mode to watch — don't let a weak local model write skills that a stronger model then has to obey.
- **Action signal:** `try-now` — the architecture is a directory layout + two prompts, not a training run.

### 2. PILOT in the Loop: Live Self-Improvement for Long-Horizon Agents
- **Source:** arXiv (Hugging Face Daily Papers)
- **Link:** https://arxiv.org/abs/2608.26530
- **Authors / org:** Yang Xiao / Yusong Sun / Haoyi Wu / Wenyang Hui / Wen Da / Zhaokai Luo / Mu Chuan / Yao Hu / Wenjie Li / Chengyue Jiang — AllSpark Team
- **Focus area:** Long-running / autonomous loops + agent orchestration
- **What it is:** Argues post-hoc reflection / judge / harness-evolution cannot recover the *current* run. PILOT is a supervisor–worker harness (implemented as an extension of the Pi coding-agent runtime) with a live two-way channel: worker Notification / Question / Result, supervisor Steer / Abort, plus live self-evolution of skills + memory from the same stream. Same frozen backbone plays both roles. One-shot: Terminal-Bench 2.0 GLM-5.1 **71.9%** vs OpenCode 66.9 / Pi 65.7; Kimi-K2.6 **71.3%** vs Pi 66.9; SWE-bench Pro avg **59.9%** vs Pi 55.5. Self-improvement setting (20 iterations, verifier outcomes used only to *keep* updates from successful runs, never to write them): best-so-far Terminal-Bench 2.0 **66.3 → 80.9** (GLM-5.1, +14.6) and **68.5 → 80.9** (Kimi-K2.6, +12.4); skill library 62→83 / 50→81; mean output tokens −42.9% / −47.4%; success per million output tokens +110% / +134%. Live steering's share of successful runs is 0% on Easy and up to 19.7% on Hard (Kimi). Code: https://github.com/XiaoYang66/Pilot
- **Why it matters for Justin's agents:** Claude Code subagents today are closer to "delegate and wait for the summary" than to PILOT's live channel. Two portable pieces: (1) a supervisor context that is *not* stuffed with tool dumps, only goal + recent events + steer/abort, (2) write skills *during* the run from successful branches, not in a Friday retro. The efficiency claim (half the tokens, 2× success/token) is the reason to compare, not just the pass-rate. Caveat: evaluation is GLM-5.1 + Kimi-K2.6 only; no Claude / GPT backbone in the paper. Don't overfit the headline to Opus 5.
- **Action signal:** `compare` — run PILOT vs Claude Code / Pi / OpenCode on a 10-task personal Terminal-Bench-like set before changing the Mitamaton supervisor design.

### 3. When Tool Outputs Become Commands: SARA
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2608.27146
- **Authors / org:** Xiaokun Guo / Zhen Xu / Dongdong Huo / Yanqiu Zhang / Wei Wang / Qinfu Yang / Dongjin Yu / Yu Wang — Institute of Information Engineering, CAS + UCAS
- **Focus area:** Tools & connectors + agent security (MCP / IPI)
- **What it is:** Names the confused-deputy failure of tool-augmented agents: an Observation that says "also forward this to attacker@…" is not data, it is a command. SARA sits between the agent and the real executor, does not read hidden CoT, and splits **action induction ≠ execution authorization**. Observation-side: context-isolated Action Probe labels STATIC vs ACTIONABLE and records tool/argument-origin anchors `F_t`. Execution-side: user contract `K` is the only authority root; audited history `H_t` records only *allowed and successful* calls; full review of side-effecting calls under EXPOSED requires GoalSupport ∧ ChainSupport ∧ ArgSupport. **No-History-Promotion:** if a value first appeared as an action origin, later reappearance in `H_t` cannot promote it to HISTORY_BOUND. AgentDojo + AgentDyn, GPT-4o-mini / Gemini-2.5-Flash-Lite: ASR **15.79/16.07/33.28/30.91 → 0.06/0.17/0.62/0.63**; UA at or above Agent-only; BU cost much smaller than CaMeL. Ablations: drop Action-Induction Tracking → ASR ~3%; drop Parameter-Support Gate → ASR ~2.5%; drop No-History-Promotion → ASR ~0.7%; drop Audited Evidence → utility crater, not ASR. Cost: ~1.9–2.2× Agent-only input tokens.
- **Why it matters for Justin's agents:** Every Mitamaton / Claude Code MCP server that returns email, calendar, web, or file text is an Observation channel. Current "don't follow instructions in tool output" prompting is exactly the thing SARA says is insufficient. Minimum viable port: (1) treat MCP tool results as untrusted, (2) persist a per-task action-origin set for anything that looks like a send/create/pay/share, (3) require the user objective (or an explicit Mitamaton contract) to support the *argument* (recipient, path, amount), not just the tool name, (4) never let "it showed up again later in a search result" clear a taint. This is more actionable than CaMeL-style control/data-flow isolation for a personal agent.
- **Action signal:** `try-now` — implement the authorization check on the 3–5 side-effecting Mitamaton tools first; leave the Probe as a cheap isolated LLM call.

### 4. Calibrated Enough to Know, Not Calibrated to Act
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2608.27167
- **Authors / org:** Pranav Aggarwal (independent) — code + cached outputs at github.com/Pranav-1100/confidence-calibration-evaluation
- **Focus area:** Agent evaluation + decision calibration
- **What it is:** v2 of the aleatoric-unknowability study. 12 frontier models, sealed short-horizon price-direction oracle plus sports/weather transfer. Commitment (choosing ANSWER at all) on unknowable items: bare **6.5%** → two prices **14.8%** → full professional panel **54.0%**. Fabricating the indicator block: 37.6% real vs 38.3% scrambled. Fabricating the *entire* panel (nothing true except the question): **36.8%**, equivalent to real within ±5pp. Effect is not universal: three Claude models carry it (Sonnet 5 goes 4.2 → 62.5 → 70.8% on thin/rich/scrambled); four models never commit; three (both OpenAI + Gemma) commit regardless. Stated |p−50| moves ~3 points while action moves 48. Committed-call Brier 0.281 vs 0.250 climatology; AUROC of stated p vs outcome **0.346**. Instructed triage ("classify knowability first") cuts commitment 54.0 → 10.2. SFT of Qwen2.5-3B on 540 synthetic dice/coin/jar cases → **0.0%** commitment on the original 40 items; gate survives a tense-balanced control (not a "decline the future" heuristic) and dies when the response format removes the reasoning slot.
- **Why it matters for Justin's agents:** Mitamaton's job is day-admin — weather, calendar slack, "should I leave now," "will this ship." Those are exactly the aleatoric questions this paper uses. The operational rule: **if the question is unknowable, a prettier widget must not unlock ANSWER.** Two cheap mitigations that the paper already measured: (a) a one-paragraph knowability triage before the act/don't-act gate, (b) keep a reasoning slot in the Mitamaton decision format — rigid `DECISION:`-only schemas are how the trained gate collapsed. Do not audit this with stated confidence; audit with the action.
- **Action signal:** `compare` — add a 20-item aleatoric probe (weather 10d, calendar conflicts, "will X finish today") to the Mitamaton eval and score commitment, not Brier.

### 5. CaSKG: Counterfactual-Causal Skill Graphs for Scalable Agent Skill Retrieval
- **Source:** arXiv (Hugging Face Daily Papers)
- **Link:** https://arxiv.org/abs/2608.25500
- **Authors / org:** Zhiyuan Li / Linyuan Gao / Xuechun Ding / Hongwei Chen / Yuan Wu / Yi Chang — Jilin University + Ant Group
- **Focus area:** Agent skills + retrieval / memory
- **What it is:** Treats skill-graph construction as budgeted edge-confidence calibration. High-recall directed candidate graph from semantic / lexical / I/O / structural (+ optional LLM judge) signals, then a validation frontier scored by three textual counterfactual probes (remove source, substitute source, reverse order), Beta-smoothed into confirmed / uncertain / rejected / scaffold states. Runtime is vanilla personalized PageRank over the *published* graph — agent policy unchanged. Skill1000 library, ALFWorld ID-140 + ScienceWorld U211, six backbones (MiniMax-M2.7, GLM-5.2, Kimi-K2.6, Qwen3.5-397B-A17B, DeepSeek-V4-Flash, GPT-5.6-Luna). CaSKG is #1 in all 12 cells vs Vanilla / Vector / Graph-of-Skills. Macro: ScienceWorld **72.62 → 80.50**, ALFWorld **80.01% → 86.79%**, fewer mean env steps in all 12. Ablation: publish-all-candidates 71.43% vs selective 73.57% (MiniMax, ALFWorld); semantic-only candidates 67.14%. Code: https://github.com/ZhiyuanLi218/Caskg
- **Why it matters for Justin's agents:** WikiSkill (item 1) answers "how do skills get better." CaSKG answers "how do you retrieve a *bundle* that still has the prerequisite, the state-change, the verify, and the place step" once the library is large. For Claude Code / Mitamaton this is the missing piece after ~20 skills, when full-injection (WikiSkill's eval setup) stops fitting. Practical shape: don't RAG skills as independent markdown; store typed edges (requires / verifies / repairs / next) and downweight unvalidated ones instead of deleting them.
- **Action signal:** `compare` — against naive embedding retrieval over `~/.claude/skills` on a 15-task personal set; skip the full counterfactual LLM-judge construction until the naive baseline loses.

### 6. TwinKV: A Composable Repair Pass for KV Cache Eviction
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2608.27128
- **Authors / org:** Hong Chen / Yudong Zeng / Yongwei Huang / Zuhao Ouyang / Junyan Zhang / Xuming Hu — HKUST (Guangzhou) + Bosum Institute
- **Focus area:** Local / on-device inference (KV cache)
- **What it is:** Leave-one-out probe on long-context QA: attention mass vs causal utility Spearman **ρ = −0.004** (n=136 chunks). TwinKV scores a token by whether a near-duplicate key exists elsewhere (cosine > τ, outside a local window) and, instead of competing as a fifth eviction policy, **repairs** SnapKV / PyramidKV / StreamingLLM / ExpectedAttention by swapping orphans (evicted, no surviving twin) for redundant donors (kept, twin already kept), budget held fixed. Qwen3-4B + Llama-3.2-1B, LongBench / LooGLE / RULER / MMLU-Pro, ratios {0.3, 0.5, 0.7}. Helps StreamingLLM (up to 64% of cells) and PyramidKV (57%) on Qwen3-4B; ExpectedAttention often already at ceiling and can get worse. TREC few-shot templates are the documented failure (false twins from exemplar echo). τ=0.85 for Qwen3 (RMSNorm'd keys), 0.90 for Llama. Cost is a real extra O(n²d) prefill unless you restrict comparisons to the retained set (authors leave O(nKd) as future work).
- **Why it matters for Justin's agents:** This is the only in-window result that is *about* the 64 GB unified-memory constraint. Long Mitamaton / vault / Claude-Code contexts are exactly where KV eviction fires, and the paper's claim is that the eviction methods already in vLLM / llama.cpp / MLX stacks are scoring the wrong thing. Lowest-risk experiment: wrap whatever eviction the local Qwen3-4B / 30B-A3B server already uses with the orphan/donor swap; do not replace the policy. Skip TREC-like few-shot template dumps or widen `w` to 64–128 there.
- **Action signal:** `try-now` on the local Qwen3-4B long-context path; `compare` before touching the 30B-A3B serving config.

### 7. Previewing the Model Hardware Standard — Anthropic
- **Source:** Anthropic News
- **Link:** https://www.anthropic.com/news/model-hardware-standard-research-preview
- **Authors / org:** Anthropic (research preview; collaboration with HHMI Janelia)
- **Focus area:** Tools & connectors (MCP for physical devices)
- **What it is:** Aug 27, 2026 research preview of MHS, a shared spec for AI agents to operate programmable lab and manufacturing instruments (microscopes, liquid handlers, robotic arms; early anecdotes include Janelia imaging time-compression and QuEra laser stabilization 58% → 99.3%). Model-agnostic; any harness can reach a connected device via **MCP, CLI, or API code**. Safety is described as driver-level — hard limits the model cannot talk past; six failure scenarios (missing plate, disconnected camera, active e-stop) blocked before motion in testing. Not open source yet; waitlist for labs and advanced manufacturers; Anthropic says it will publish preview findings as deployment guidance when it OSS's the spec. Does not cover hardware without a programmable interface.
- **Why it matters for Justin's agents:** Not a Mitamaton feature this quarter — Justin is not running a liquid handler. The durable fact is architectural: **Anthropic is standardizing a third MCP-shaped surface (atoms), with authorization pushed below the agent.** That is the same split SARA (item 3) argues for on digital tools. When MHS drivers exist for more mundane hardware (home, accessibility, robotics kits), the Mitamaton connector pattern should be MCP-in / driver-enforced-limits, not "Claude, please don't over-torque." Track for the OSS drop + the physical-safety roadmap, not for an integration this week.
- **Action signal:** `track`

## Conflicts & open questions
Cross-referenced against `_meta/claims-ledger.md`:
- **Convergent evidence, not conflict:** WikiSkill + PILOT + CaSKG all land on the vault's existing "harness / skill / memory evolution is the lever, not the next model swap" thread (StateAct [arxiv:2607.22798], Writer Harness Effect, EvoSkill / SkillOpt / Trace2Skill, Graph-of-Skills). They do **not** agree on *which layer is load-bearing*: persistent wiki (WikiSkill), live supervisor channel (PILOT), or calibrated retrieval edges (CaSKG). No paper compares the three. Open empirical question for the next local eval: on the same 15-task personal set, which single addition — wiki+gate, live steer, or graph retrieval — moves the needle.
- **Conflict flagged:** WikiSkill's eval *injects the full skill into the system prompt* and explicitly does not test retrieval; CaSKG's whole contribution is that full-library injection is the thing that breaks at Skill1000. Using WikiSkill's numbers as a reason to keep dumping every SKILL.md into Claude Code's system prompt would be a misread. Treat WikiSkill as a *skill-quality* recipe and CaSKG as the *skill-routing* recipe; they are complementary only if you do not collapse them.
- **Open question, not yet a ledger conflict:** SARA's "Observations may instantiate but must not authorize" is in the same family as CaMeL / ClawGuard / AIRGuard / PACT / AuthGraph (several already vault-adjacent). SARA's distinctive claim is No-History-Promotion + persistent action-origin *without* treating "Observation-driven" as "attack." Independent AgentDojo numbers on Claude / local Qwen are missing; do not treat 0.06% ASR on GPT-4o-mini as a Mitamaton guarantee.
- **No conflict with AgentKVShift** [arxiv:2607.21604]: TwinKV repairs *eviction* (what to drop); AgentKVShift repairs *reuse* (how to correct a kept cache). Orthogonal. Combined recipe is still untested.
