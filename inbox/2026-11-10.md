# AI Research Digest — Tuesday, November 10, 2026

## TL;DR
- **Keep workflow state outside the context window** (2611.10884): an executable FSM enforcing at tool calls, transitions and turn end took Claude Haiku 4.5 from 48 to 139 correct SOP-Bench accounts.
- **Enforce tool policy in code, not prompts** (2611.11571): behind a task-bound monitor, Qwen2.5-1.5B/7B proposed the attacker's call in 64%/84% of episodes, yet the monitor admitted 1.3%/7.7%.
- **Intent-graph tool-call audit** (2611.11305): deterministic check per call, median 5.7 microseconds, escalating only flagged writes.
- **A model swap is a behavior change** (2611.10628): same persona, memory and rules produced drift across open-weight pairings, invisible to the model's own compliance claims. Relevant to the Fable/Mythos 5.2 migration.
- **Harness cost lever** (2611.12122): harness-side differences barely move accuracy but change cost up to 2.6x on the same model and task.
- **Self-organized, evidence-linked memory** (2611.11929): SoMem stores memory as linked documents the agent reorganizes itself.
- **Self-written skills are an attack surface** (2611.10542): poisoned evolution tasks make agents implant backdoors into their own persistent skills.
- **Hibana** (2611.10469): inference engine for unified-memory devices aimed at local agentic workloads.
- **Separate SOPs from contextual knowledge** (2611.11348): skill-equivalence 12% to 58% and less SOP-skill drift.
- **MCP routers can skip safety tools under efficiency pressure** (2611.11720): 29.2% shadow-invocation rate vs 4.2% with policy-aware routing (qwen3-32b router, early results).
- **News:** Claude Fable 5.2 / Mythos 5.2 launched with migration traps (prefix check 400s, `computer_toolset_20260801`, 30-day retention); Claude Code v2.1.321 fixes an MCP OAuth refresh-token leak. See News and changelogs.

## Items

### 1. MaxIM: Maximally Informative Incremental Summarization via Reinforcement Learning
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.12825
- **Authors/org:** Jihwan Jeong, Guy Tennenholtz, Yinlam Chow et al.
- **Focus area:** context / memory summarization
- **What it is:** MaxIM frames incremental summarization of an unbounded history as a capacity-constrained, information-theoretic reward-shaping problem, with a step-wise critic giving dense rewards; beats RL, SFT and prompt baselines on factual grounding and downstream utility across strict token budgets (long-horizon reading, multi-turn dialogue).
- **Why it matters for Justin's agents:** Gives a trainable recipe for the rolling summary a day-admin agent keeps between sessions instead of hand-prompted compaction.
- **Action signal:** `track`

### 2. AutoBuddy: Evaluating Proactive, Always-On Agents on Task Discovery and Execution in a Simulated Workplace
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.12393
- **Authors/org:** Shiqi Chen, Daniel Madrigal Diaz, Wei-Ning Chen et al.
- **Focus area:** proactive always-on agents
- **What it is:** AutoBuddy benchmarks agents that must infer a user's pending tasks from mail, chat and workspace and then complete them in the systems where the work lives, with no task handed over.
- **Why it matters for Justin's agents:** Closest benchmark to Mitamaton's day-admin loop: task discovery, not just execution, is what gets scored.

### 3. Reconfigurable Action Theories: A Formal Foundation for Dynamically Composable Agent Harnesses
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.12300
- **Authors/org:** Jianmin Ji
- **Focus area:** harness formalism
- **What it is:** Reconfigurable Action Theories let actions load and unload theory modules (tools, providers, policies) at runtime while keeping standard causal semantics when the module set is fixed; gives sufficient conditions for well-behaved reconfiguration.
- **Why it matters for Justin's agents:** A formal model for harnesses that hot-swap MCP servers, tools and policies mid-run.
- **Action signal:** `track`

### 4. System Optimizations for Cost-Efficient Agent Harnesses
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.12122
- **Authors/org:** Jongseok Park, Jiaxiang Yu, Eric Zhou et al.
- **Focus area:** harness cost
- **What it is:** Analyzes cost accumulation across agent traces: harness-side differences (system prompt, tools) barely move accuracy but change cost by up to 2.6x on the same model and task; proposes system-level optimizations to cut tokens and LLM calls.
- **Why it matters for Justin's agents:** Direct levers for trimming Claude Code / MCP harness spend without changing the model.
- **Action signal:** `try-now`

### 5. SkillDuet: Co-Evolving Models and Skills through Response Feedback
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.12109
- **Authors/org:** Xingguang Ji, Ziqiang Dong, Yubo Zhang et al.
- **Focus area:** skills / RL
- **What it is:** SkillDuet co-evolves model parameters and external textual skills: skills extracted from on-policy trajectories guide parameter updates, and feedback prunes skills that become redundant or harmful as the model improves.
- **Why it matters for Justin's agents:** Addresses skill-library rot as the underlying model changes, relevant to maintaining a skills folder across model upgrades.

### 6. Can LLM Agents Organize Their Own Memory?
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.11929
- **Authors/org:** Zichuan Fu, Junjia Qi, Wenlin Zhang et al.
- **Focus area:** agent memory
- **What it is:** SoMem lets the agent organize its own memory as linked documents: it decides what to summarize, how to group topics and when to revise, and every summary stays linked to the original interactions as evidence.
- **Why it matters for Justin's agents:** Matches a file-based, evidence-linked memory design (Obsidian-style notes) rather than fixed record schemas.
- **Action signal:** `try-now`

### 7. Correct Answers from Insufficient Histories: A Controlled Study of Agent Memory Evaluation
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.11840
- **Authors/org:** Quan Xue, Zerui Yang, Chaorui Zhang et al.
- **Focus area:** memory evaluation
- **What it is:** Shows an answer can match the reference while the reader's visible history does not determine it; on executable device logs, Qwen3-32B matched 87 hidden references among 203 insufficient raw-prefix instances with only seven appropriate abstentions.
- **Why it matters for Justin's agents:** Warns that memory benchmarks reward lucky guesses; add abstention checks to any memory eval.
- **Action signal:** `compare`

### 8. Same Error, Different Recovery: How Delivery Changes LLM Agent Behavior
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.11581
- **Authors/org:** Sunghyeun Woo, Javier Conde, Pedro Reviriego
- **Focus area:** tool-use recovery
- **What it is:** Across 13 open models (3B-70B), where a tool error appears in the conversation changes whether the model retries, corrects or stops; a new user turn that retains the failed exchange avoids severe stopping failures seen in Llama models.
- **Why it matters for Justin's agents:** Concrete guidance on how to deliver tool errors back to local models.
- **Action signal:** `try-now`
