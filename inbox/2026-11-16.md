### 1. When Should LLM Agents Forget? Memory Filtering Under Query-Critical Resolver Errors
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.17338
- **Authors/org:** Samarth Vinayaka
- **Focus area:** memory write/forget policy
- **What it is:** Shows that hard-deleting facts a resolver labels stale can reduce downstream accuracy when resolver errors delete query-critical facts. Across three models, hard-drop moves from gains of +0.186 to +0.230 at perfect resolution to losses of -0.176 to -0.181 at the lowest tested reliability; false-drop hurts significantly more than false-keep. A deployment-matched gate reaches 0.655 accuracy versus 0.641 for always hard-drop.
- **Why it matters for Justin's agents:** Do not delete 'stale' memories on a classifier's say-so in a day-admin agent; default to label-free retention unless you have validated query-critical false-drop risk.
- **Action signal:** `try-now`

### 2. Does the Ranking Hold? A Practitioner-Facing Audit of Hallucination Detectors on Small, Quantized, On-Device LLMs
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.17339
- **Authors/org:** Shubhra Mittal, Gaurav Naresh Mittal
- **Focus area:** on-device small models / hallucination detection
- **What it is:** Audits four hallucination detectors on 4-bit Llama-3.2-3B-Instruct and Qwen2.5-3B-Instruct on one Colab T4. The detector ranking inverts between the two models (Spearman rho -0.80) and the cheap lexical baseline is statistically indistinguishable from the sampling-based consistency detectors. Harness, prompts and per-item scores are released.
- **Why it matters for Justin's agents:** If Mitamaton ever gates on-device model output with a hallucination detector, re-validate the choice per model; rankings from 7B-70B models do not transfer to 3B 4-bit.
- **Action signal:** `track`

### 3. More Agents, More Samples, or More Thinking? Untangling Coordination, Ensembling, and Test-Time Compute in Multi-Agent LLMs
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.17610
- **Authors/org:** Seyed Mahmoud Sajjadi Mohammadabadi
- **Focus area:** multi-agent evaluation methodology
- **What it is:** Synthesizes nine evaluations (516 multi-agent configurations) against baselines matched on single pass, sample count and resource budget. Against matched baselines multi-agent systems average -0.042 accuracy and equal or fall below the baseline in 74% of comparable contrasts. Positive returns need partitioned evidence, external verification or error diversity across models.
- **Why it matters for Justin's agents:** Before adding sub-agents to the Claude Code / MCP stack, compare against a best-of-N single agent at equal compute; coordination alone rarely pays.
- **Action signal:** `track`

### 4. Generated Evaluation Suites as Diversity-Driven Search for Real Agent Regressions
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.17632
- **Authors/org:** Pulkit Yadav
- **Focus area:** agent regression evals
- **What it is:** Treats generated evaluation suites as diversity-driven search and injects 7 controlled defects into a tau^2-bench agent. Suite-level pass rate can move the wrong way (tool removal destroys every covered scenario while the suite pass rate rises); per-cell scoring recovers it. A kind-diverse suite detects the orchestration defect in 5 of 20 draws, a happy-path-only suite detects nothing.
- **Why it matters for Justin's agents:** If you generate eval suites for an agent, score per cell and report coverage; a single mean pass rate can hide a removed tool.
- **Action signal:** `compare`

### 5. What LLM Agents See and What Users Say
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.17639
- **Authors/org:** Yue Zhao, Angela Huyue Zhang, S. Alex Yang et al.
- **Focus area:** tool-result design / safe writes
- **What it is:** Uses presupposition theory: an agent should act only if each claim behind the act is seen to hold, answered by the user, or disclosed while undoable. Under a role-only prompt a count of a second record leaves most of 36 earlier agents acting on the one they see, whereas listing both stops most. A lookup returning a same-name customer first led to wrong-account writes in about a quarter of conversations.
- **Why it matters for Justin's agents:** Make your MCP lookups list or check competing records instead of returning a count or the first hit; a day-admin agent that writes to the wrong contact is the failure.
- **Action signal:** `try-now`

### 6. Learn then Bet: Learning Interpretable Rules for Reliable Agent Intervention
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.17662
- **Authors/org:** You-Lin Chen, Xinyi Lisa Chen, Pedro Herrero-Vidal et al.
- **Focus area:** runtime monitors / intervention
- **What it is:** LeBet learns an interpretable OR-of-AND monitor and accumulates evidence with a betting statistic, with finite-sample false-positive control. On SWE-bench Lite with Ministral 3 8B the learned monitor saves 34.46% of input-plus-output tokens and raises output precision from 18.33% to 21.59%, with an empirical false-positive rate of 13.64%.
- **Why it matters for Justin's agents:** Replaces turn limits and keyword filters in a long-running agent harness with a monitor that has a stated false-stop rate.
- **Action signal:** `compare`

### 7. Co-Sight Harness: Externalized Control Assets and Deterministic Enforcement for Long-Horizon Business Agents
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.17696
- **Authors/org:** Luyao Wang, Xijun Zhu, Zhaohui Hao et al.
- **Focus area:** harness / long-horizon workflows
- **What it is:** Keeps the model fixed and moves workflow definition, state and domain knowledge into versioned control assets enforced by a state machine and machine-checkable acceptance gates, with an independent auditor. On Domain A unattended completion rises from 50% to 100% and end-to-end latency drops from 440 to 159 minutes; two other domains were taken over by teams that did not write the assets. Code is released.
- **Why it matters for Justin's agents:** A concrete case for externalizing workflow state and acceptance gates outside the model, the same direction as skills plus hooks in Claude Code.
- **Action signal:** `compare`

### 9. Can Agents Keep Up with Time? An Empirical Analysis of Temporal Adaptation After a Conversational Hiatus
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.17806
- **Authors/org:** Hongguan Su, Ming Wang, Shun Zhang et al.
- **Focus area:** temporal awareness in personal agents
- **What it is:** Studies agents returning to a conversation after a long hiatus while scheduled dates have passed. Agents reliably query the clock and note the date has passed, yet many still tell users to prepare for the expired event; supplying explicit temporal context reduces this and providing the computed date relation removes it entirely. Benchmark code is released.
- **Why it matters for Justin's agents:** Directly Mitamaton's failure mode: inject the computed relation between stored dates and now into context instead of just the current time.
- **Action signal:** `try-now`

### 12. Soteria: Formally Verified Planning with Runtime Enforcement for Safe LLM Agents

### 20. Only as Safe as the Weakest Agent: A Break That Appears Only When the System Is Multi-Agent
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.17520
- **Authors/org:** Keegan Wang, Anantika Mannby
- **Focus area:** multi-agent security
- **What it is:** Shows Claude Code, Codex and a reference harness can be broken through their own sub-agent mechanisms by a forged record planted in a file store: strong orchestrators searching themselves commit almost zero harmful revisions in over 1,000 trials, but delegating to a cheaper sub-agent fails 20/180, 44/180, 75/180 and 553/900. - **Why it matters for Justin's agents:** Sub-agent delegation lowers system safety to the weakest reader; audit what cheap sub-agents read and what the orchestrator trusts.

### 22. Superfluid: Local AI Server for Distributed LLM Inference
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.17753
- **Authors/org:** Prabod Rathnayaka, Isura Manchanayake, Srikandabala Kogul et al.
- **Focus area:** local inference server for agents
- **What it is:** Superfluid is an Apache-2.0 local LLM server driving llama.cpp, MLX or BaseRT with a scheduler that puts interactive requests ahead of agent work, shares prompt prefixes, and writes every token to a durable log. ### 23. LuthorSQL: A One-Pass Text-to-SQL Model as System 1 for a Slower LLM Agent

- **Link:** https://arxiv.org/abs/2611.17780
- **Authors/org:** Ibrahim Memon, Armin Karamzade, M. Hanif Jhaveri et al.

### 25. Securing Multi-Agent Systems by Design
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.17883
- **Authors/org:** Xilong Wang, Xiaoxing Chen, Neil Gong
- **Focus area:** multi-agent aggregation security
- **What it is:** Proposes response manipulation attacks (ReMA) on multi-agent systems and SecMAS, a secure aggregation rule choosing the response most consistent with a sufficiently large subset of others, with security guarantees. Existing aggregation rules are vulnerable while SecMAS defends against all evaluated attacks, including adaptive variants, at comparable utility.
- **Why it matters for Justin's agents:** If you aggregate several agents' answers, majority-style rules can be attacked by one malicious agent; semantic-consistency aggregation is a cheap defence.

### 26. Do Verifier Judgments Survive Abstraction? Measuring Verification Transport for LLM Agent Evaluation
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.18471
- **Authors/org:** Disha Sheshanarayana, Sai Linisha Reddy Goli
- **Focus area:** verifier reliability under abstraction
- **What it is:** Introduces Verification Transport: matched native, abstracted and restored views of the same frozen executions test whether LLM verifier judgments survive composed tools, delegation or compacted histories. Across four benchmarks, seven verifier backbones and four protocols, transport failure reaches about 31% under macro abstraction and delegation; restoring execution provenance recovers 85.5%.
- **Why it matters for Justin's agents:** If your harness compacts history or delegates, an LLM judge sees less; keep provenance available to the verifier.
- **Action signal:** `try-now`
