# AI Research Digest — Saturday, June 27, 2026

## TL;DR
- **Memory governance gets a bi-temporal ledger** — MemStrata (Yadav, arxiv:2606.26511) frames retrieval-vs-temporal-validity as a structural problem (cosine similarity 0.59 AUROC on contradicted facts vs duplicates) and gets 0.95–1.00 vs 0.20–0.47 RAG accuracy on evolving knowledge with a deterministic (subject,relation,object) supersession rule and ~2.1s latency vs 16–18s for LLM-rerank alternatives.
- **CoT training doesn't reward what you think it rewards** — Liu et al. (arxiv:2606.26935) show CoT post-training improves **prompt-action quality**, not the CoT-vs-prompt advantage; later checkpoints become *less* likely to revise actions based on generated reasoning. Direct counter to "more CoT data = better agent reasoning" assumption.
- **InfoKV breaks the attention-only spell on KV cache compression** — Kai et al. (arxiv:2606.26875) show attention-selected tokens influence *nearby* contexts but predictive-uncertainty-selected tokens influence *distant* future contexts; combining entropy with attention beats attention-only across Llama-3.1/3.2 and DeepSeek-R1 on long-context reasoning.
- **Process supervision exposes 14.5pt grounding gap on root-cause diagnosis** — OpenRCA 2.0 + PAVE (arxiv:2606.27154) shows 76.0% of agents identify a correct root-cause service but only 61.5% ground it in a verified causal path; exact root-cause recovery is **20.7%** across 11 frontier LLMs.
- **Google ships frozen-MTP speculative decoding on Pixel 9/10** (research.google blog, 2026-06-26) — bit-for-bit identical output, 50%+ speedup, 130 MB memory savings per instance vs standalone drafter; backbone weights frozen, only MTP head trained. Pattern is transportable to MLX/llama.cpp Metal.

## Items

### 1. MemStrata — Temporal Validity in Retrieval Memory
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.26511
- **Authors / org:** Neeraj Yadav
- **Focus area:** Agent memory
- **What it is:** RAG fails on facts that change because cosine similarity gives stale and current values nearly identical scores (0.59 AUROC distinguishing contradicted facts from duplicates — barely above chance). MemStrata adds a bi-temporal ledger: facts are stored RAG-style for static recall, but a deterministic (subject, relation, object) supersession rule retires stale values when contradicted. On evolving knowledge: **0.95–1.00 accuracy vs RAG's 0.20–0.47**; stale-fact errors **15–40% → ~0%**; retrieval latency **~2.1s vs 16–18s** for LLM-reranking alternatives. Code, datasets, marker-free eval protocol released.
- **Why it matters for Justin's agents:** This is the cleanest formulation yet of the "MCP tool docs went stale and the agent kept calling the deprecated signature" problem. Long-running companion agents accumulate facts that mutate (user preferences, API specs, calendar state). MemStrata's bi-temporal ledger is implementable as a small extension to existing vector stores — pair the embedding with a (subject, relation, object) key, and when a new value arrives with the same key, mark the prior version retired with a tombstone timestamp. Composes directly with prior memory-governance work: [arxiv:2606.18829] GateMem at the write gate, [arxiv:2606.24535] MemClaw on propagation, MemStrata on temporal retirement.
- **Action signal:** `try-now`

### 2. JERP — Joint Learning of Experiential Rules and Policies
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.27136
- **Authors / org:** Shicheng Ye, Chao Yu
- **Focus area:** Agent memory / agent training
- **What it is:** Most "agent with memory of rules" systems keep the natural-language rule pool and the policy weights on separate tracks — rules drift from evolving policy, weight updates don't fix local rule errors. JERP couples both: every episode updates *both* the rule pool and the policy, conditioned on the same trajectory and a comparison against successful reference trajectories. AlfWorld + WebShop show consistent decision improvements over rules-only and policy-only baselines.
- **Why it matters for Justin's agents:** The "rules drift from behavior" pathology is exactly what happens to long-lived system prompts in production MCP agents — operators edit the prompt, the underlying model has been fine-tuned/swapped, and the two no longer match. JERP's joint-update protocol is the first formalization of the "co-evolve rules with policy" idea in a way that's measurable. Concept is portable even without weight access: maintain rule-pool versions, A/B against a frozen-rule baseline, and demote rules whose ablation no longer hurts.
- **Action signal:** `track`

### 3. InfoKV — Information-Aware KV Cache Compression for Long Reasoning
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.26875
- **Authors / org:** Jushi Kai, Zhuiri Xiao, Alexandra Birch, Zhouhan Lin
- **Focus area:** Context engineering / KV cache
- **What it is:** Attention-only KV-compression methods (StreamingLLM, SnapKV, etc.) select tokens that primarily influence *nearby* contexts. InfoKV adds a Forward Influence metric that explicitly measures token effect on *distant* future contexts, using predictive uncertainty + layer-wise representation evolution as proxies. The key empirical finding: high-uncertainty tokens have substantially stronger long-range influence than high-attention tokens. Combining entropy with attention scores beats attention-only on long-context reasoning benchmarks across Llama-3.1, Llama-3.2, and DeepSeek-R1.
- **Why it matters for Justin's agents:** Long-horizon agent loops (planner-executor with thousands of tool calls) hit KV cache pressure long before they hit context window limits. The conventional wisdom "attention-based eviction is the SOTA" turns out to be incomplete: attention is a *near-future* signal. For reasoning agents that need to recall a fact from 50K tokens ago, entropy-based retention catches what attention misses. Pairs with [arxiv:2606.24033] Block-GTQ KV quantization — orthogonal axis (which tokens to keep vs how to compress kept tokens), composes for stacked compression on M5 Max long-context loops.
- **Action signal:** `track`

### 4. PersistentKV — Page-Aware Decode Scheduling for Long-Context LLM Serving
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.26666
- **Authors / org:** Muhammad Ahmed
- **Focus area:** Long-running / autonomous loops (serving)
- **What it is:** Workshop paper on a native block-table decode attention engine for grouped-query attention (GQA). Schedules work by KV-head group with tile reuse across query heads, supports native page tables with compact workqueue scheduling, and executes only non-empty row-KV-head-sequence-split tasks. Tested on RTX 3060 FP16 with Llama-class config (Hq=32, Hkv=8, d=128, page size 16): **1.063–1.265x throughput on B8 bimodal/uniform/Zipf workloads, 1.399x on B1 bucketed**.
- **Why it matters for Justin's agents:** Modest single-machine gains, but the design (page-aware scheduling targeting GQA architectures) is exactly the pattern needed to make local long-context serving on M5 Max viable for agentic workloads with mixed sequence lengths. Most existing engines optimize for batched chat traffic, not heterogeneous agent loops with one big context + many short tool-response sequences. Worth tracking whether MLX picks up the page-table primitive.
- **Action signal:** `local-fit`

### 5. Frozen Multi-Token Prediction on Gemini Nano (Pixel 9/10)
- **Source:** Google Research blog
- **Link:** https://research.google/blog/accelerating-gemini-nano-models-on-pixel-with-frozen-multi-token-prediction/
- **Authors / org:** Google Research / Android team
- **Focus area:** Local & on-device inference
- **What it is:** Retrofits a lightweight MTP head onto pretrained Gemini Nano v3 *without modifying backbone weights*. The MTP head cross-attends directly to the main model's frozen KV cache (zero-copy "late exit" design) rather than maintaining a duplicate drafter. Predicts ~2 additional tokens per main-model pass. Results on Pixel 9: **50%+ speedup, 130 MB memory savings vs standalone drafter, up to 55% token-acceptance improvement on predictable text structures, bit-for-bit identical output**. Released 2026-06-26.
- **Why it matters for Justin's agents:** The frozen-backbone constraint is the interesting part. Mobile inference and M5 Max local inference share the same binding constraint: model weights are huge and you don't want to retrain. A small MTP head that cross-attends to the main model's KV cache is a *retrofit* for any pre-quantized GGUF/MLX model: train the MTP head once, ship it as a sidecar. llama.cpp has speculative decoding support but it expects a separate draft model; the frozen-MTP pattern (one model, two prediction heads) is a cleaner Metal port target and avoids the draft-model-weight overhead.
- **Action signal:** `local-fit`

### 6. Thinking to Recall — Reasoning Unlocks Parametric Knowledge
- **Source:** Google Research blog (post links arxiv:2603.09906)
- **Link:** https://research.google/blog/thinking-to-recall-how-reasoning-unlocks-parametric-knowledge-in-llms/
- **Authors / org:** Zorik Gekhman, Jonathan Herzig (Google Research)
- **Focus area:** Reasoning & inference-time compute
- **What it is:** Why does enabling reasoning help even on *single-hop* factual questions where no multi-step problem-solving is needed? Authors identify two mechanisms: (1) Computational buffer — extra tokens give additional forward passes for latent computation to refine internal states toward hard-to-reach facts. (2) Factual priming — models generate topically related facts that act as semantic warm-up (analogous to spreading activation in human memory). Tested on Gemini-2.5 Flash/Pro and Qwen3-32B over SimpleQA Verified + EntityQuestions; reasoning-on recovers answers "virtually unrecoverable" with reasoning off. **Hallucinated intermediate facts substantially degrade final accuracy** — factual priming is double-edged.
- **Why it matters for Justin's agents:** This is the cleanest mechanistic explanation yet of "why does CoT help on lookup tasks?" — and it directly informs agent design. For factual-recall tool calls (vault search, MCP knowledge lookup), letting the model think first improves accuracy; but the hallucinated-intermediate-fact failure mode means a *grounded retrieval first, reasoning second* pipeline is safer than letting the model freestyle. Pairs with today's MemStrata (item 1) as the upstream "fix the retrieval substrate" companion. Direct compare against [arxiv:2606.26935] CoT-Gains-Land (item 7): two papers pull in opposite directions on whether CoT's benefit is "real reasoning" — needs resolution.
- **Action signal:** `compare`

### 7. Where Do CoT Training Gains Land in LLM-Based Agents?
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.26935
- **Authors / org:** Jingyu Liu, Zhiwen Wang, Yuxin Jing, Huanyu Zhou, Yong Liu
- **Focus area:** Agent training / reasoning
- **What it is:** Counterintuitive finding: post-training on CoT data does **not widen the gap between CoT-action and prompt-action quality** — it widens prompt-action quality alone. Later checkpoints become *less* likely to revise actions based on generated reasoning, suggesting the reasoning chain becomes ornamental rather than functional. Proposed fix: selectively mask action-token supervision during training so the model is forced to route through the reasoning chain.
- **Why it matters for Justin's agents:** This is the supervision-side companion to a quietly building thread: [arxiv:2606.26300] Verification Horizon (Qwen — verifiers must co-evolve with policy), [arxiv:2606.26027] CASIA (tool-use RL collapses without dynamic supervision), and now Liu et al. arguing CoT data hyper-trains prompt-action quality at the cost of reasoning influence. Operational read: if you're SFT-ing on CoT traces from a stronger model, the agent gets "smarter without reasoning" — which sounds great until you hit a task where the reasoning chain is the only thing that helps. Targeted action-token masking is a concrete training intervention.
- **Action signal:** `compare` (against item 6 — Thinking to Recall claims CoT *is* the load-bearing mechanism; Liu et al. claim CoT training de-loads it)

### 8. OpenRCA 2.0 — From Outcome Labels to Causal Process Supervision (PAVE)
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.27154
- **Authors / org:** Aoyang Fang et al.
- **Focus area:** Evaluation
- **What it is:** Root-cause analysis benchmark v2 with **PAVE**, a step-wise labeling protocol that annotates causal propagation paths rather than just root-cause services. Run on 500 cross-system instances across 11 frontier LLMs. Outcome-only metric: 76.0% of cases identify a correct root-cause service. Process-supervision metric (must ground that service in a verified causal path to the symptom): drops to **61.5%**. Exact root-cause recovery: **20.7%**. The 14.5pt outcome→process gap is named **ungrounded diagnosis**: plausible cause found, actual causal mechanism unverified.
- **Why it matters for Justin's agents:** Replicates and quantifies the "agents land on plausible answers without grounding" failure mode in a domain (root-cause diagnosis) where it's directly observable. For Justin's federal-data-engineering work, this is the eval pattern for any "agent that debugs the pipeline failure" tool. Confirms thread with [arxiv:2606.24428] EDV (consensus-verify before memory write), [arxiv:2606.24839] Grading the Grader (graders themselves need cascades), and [arxiv:2606.27226] BINEVAL (atomic binary decomposition) — *outcome scores are not enough* is becoming the consensus position on agentic eval.
- **Action signal:** `track`

### 9. OPID — On-Policy Skill Distillation for Agentic RL
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.26790
- **Authors / org:** Shuo Yang, Jinyang Wu, Zhengxi Lu, Yuhao Shen, Fan Zhang, Lang Feng, Shuai Zhang, Haoran Luo, Zheng Lian, Zhengqi Wen, Jianhua Tao
- **Focus area:** Agent orchestration / agent RL
- **What it is:** Outcome-only RL is stable but gives no guidance on intermediate decisions. OPID extracts **hierarchical skills** (episode-level for global workflows + step-level for critical decisions) directly from completed on-policy trajectories. A critical-first routing mechanism picks which skill guidance to inject; the policy re-scores under both original and skill-augmented contexts, producing token-level self-distillation advantages combined with outcome advantages. ALFWorld + WebShop + Search-QA show improvements in success, sample efficiency, robustness over outcome-only PPO baselines. Code released.
- **Why it matters for Justin's agents:** Continues the "static supervision schedules fail multi-turn RL" thread (Verification Horizon + CASIA collapse + SAGE-OPD). OPID's "skills-as-self-supervision" is the actionable pattern: instead of paying a verifier at every step, mine intermediate guidance from the agent's own successful trajectories. Structurally similar to [arxiv:2606.26669] SKILL-DISCO (trace-subgraph distillation as composite tools) but at training time rather than tool-library time — together they sketch a two-tier "skills mined from traces" stack: SKILL-DISCO compiles to runtime callable tools, OPID compiles to training-time auxiliary supervision.
- **Action signal:** `track`

## Local-model corner
Nothing in today's items is a new MLX or GGUF release, but two patterns are directly portable to the M5 Max + 64 GB setup:

- **Frozen MTP retrofit** (item 5): the design — small head trained against a *frozen* base model's KV cache, bit-for-bit identical output — translates directly to MLX. Today's llama.cpp speculative decoding requires shipping a separate draft model (extra weights, extra memory, lifecycle drift between drafter and main). A frozen-MTP head trained once against e.g. Qwen3.6-35B-A3B in MLX would deliver speculative-decoding throughput gains at the cost of *just the head weights*, not a second model. Worth watching whether anyone open-sources the head training recipe.
- **PersistentKV-style page scheduling** (item 4): the 1.06–1.40x throughput numbers are on a single RTX 3060, but the underlying observation — agent loops have heterogeneous sequence lengths and existing schedulers waste cycles on empty row-KV-head splits — applies just as much to MLX serving. M5 Max unified memory makes the page-table layout cheaper than CUDA, where copies between pages cost real bandwidth.

No new MoE release fits in 64 GB today (Qwen3.6-35B-A3B class and Gemma 4 26B-A4B class remain the current ceiling for "comfortable" local agentic loops; 70B Q4 still in tight-fit territory at 64 GB once KV grows).

## Conflicts & open questions
Cross-referenced against `_meta/claims-ledger.md`:

- **Item 6 (Thinking to Recall) vs Item 7 (Where Do CoT Training Gains Land)** — direct tension. Gekhman + Herzig argue CoT is the load-bearing mechanism that recovers facts otherwise unrecoverable; Liu et al. show CoT *post-training* de-loads the CoT chain in agent settings (prompt-action quality rises, CoT-vs-prompt gap doesn't). Reconciliation candidate: the two papers measure different lifecycle stages — Thinking-to-Recall is *inference-time* CoT on a frozen model where the reasoning chain is the only substrate; CoT-Gains-Land is *training-time* CoT injection into a model that already has prompt-action competence to lean on. If true, the practical read is "use CoT at inference for hard recall; don't assume CoT-only SFT teaches reasoning *over* prompt-action." Logged as `compare` for both items.
- **Open empirical question raised by Item 1 (MemStrata):** The 0.59 AUROC for cosine-similarity-based contradiction detection is on its own a strong indictment of pure vector RAG for evolving facts — but the eval framework's "marker-free" protocol needs independent reproduction on a memory-heavy real-world workload (e.g., long-running personal companion agent over months) before this becomes load-bearing for production design.
- **Open question raised by Item 8 (OpenRCA 2.0):** 20.7% exact-root-cause recovery across 11 frontier LLMs is a *much* sharper number than the 17.8% NatureBench ceiling on coding-agent SOTA-matching ([arxiv:2606.24530]). Two different research-grade benchmarks now in the ~20% region. Convergent ceiling, or domain coincidence?
