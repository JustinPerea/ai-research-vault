## Items

### 1. MobilePA-Bench: Benchmarking Mobile Planner Agents on Complex Real-World Tasks
- **Source:** arXiv (Hugging Face Daily Papers)
- **Link:** https://arxiv.org/abs/2608.23035
- **Authors / org:** Yi Zhu / Xiongwei Wu / Qiyi Wang / Tingyu Qu / Jiajun Liu / Sihan Cao / Long Chen / Weigao Sun / Feida Zhu / Yiran Zhong / Steven Hoi — Tongyi-MAI (Alibaba)
- **Focus area:** Mobile planner agents (Mitamaton-shaped)
- **What it is:** Interactive, stateful, tool-centric sandbox with live application databases and structured feedback. **13** functional domains, **212** realistic mobile tools. Beyond basic tool use: Sub-agent Collaboration, Memory Usage, Skill Usage (pre-packaged composite skills vs planning every step). Frontier LLMs remain unreliable: performance drops sharply under strict tool ordering, permission limits, and unexpected runtime errors. Positions itself as a diagnostic bench *and* an RL environment. Code: github.com/Tongyi-MAI/MobilePA-Bench. Submitted Aug 24 (v2 Aug 25); abs verified.
- **Why it matters for Justin's agents:** Closest published eval to Mitamaton's iOS day-admin job that is not GUI-click-only. Four axes map onto the vault: tools, subagents, notebook, skills. The failure modes (tool order, permissions, runtime errors) are the ones a personal agent actually hits. Use as a design checklist even if you never run the sandbox.
- **Action signal:** `compare` — score Mitamaton on the four axes with a 15-task personal set; do not wait for the full 1.7k-task dump.

### 2. Prime Agent: A Self-Improving RLM Harness
- **Source:** arXiv (Hugging Face Daily Papers)
- **Link:** https://arxiv.org/abs/2608.23552
- **Authors / org:** Seth Karten / Alex L. Zhang / Kevin Thomas / Sebastian Müller / Elie Bakouch / Daniel Auras / Mika Senghaas / Fares Obeid / Konstantin Dunas / Johannes Hagemann / Sami Jaghouar — Prime Intellect
- **Focus area:** Long-horizon coding harness (RLM + continual skills)
- **What it is:** Open-source harness: persistent IPython REPL (Recursive Language Model abstraction) plus Continual Harness that preserves histories, memories, skills, prompts, and subagent specs across trajectories. Recursive subagents with direct agent-to-agent communication; Agents View for daemon sessions. ARC-AGI-3 RHAE Best@1 **30% → 95.5%**; matches or exceeds native/popular harnesses on long-context coding, GPU-kernel gen, emulator construction, nanoGPT speedruns. Factorio: refinement enables continuous tech progression; dedicated subagents parallelize work. Code: github.com/PrimeIntellect-ai/prime-agent. Submitted Aug 24; abs verified.
- **Why it matters for Justin's agents:** Same "harness is the lever" family as PILOT / StateM / Continual Harness. The load-bearing safety flag from the broader Prime Agent writeup: an agent can save an RCON cheat *as a skill* — refinement persists exploits. That is SkillJack's cousin inside a self-improving harness. Do not let Mitamaton / Claude Code write skills from unverified successful-looking branches.
- **Action signal:** `compare` — against PILOT live-steer and Claude Code subagents; gate skill writes.

### 3. Apodex 1.1: Scaling Agentic Intelligence for Complex Work
- **Source:** arXiv (Hugging Face Daily Papers)
- **Link:** https://arxiv.org/abs/2608.23283
- **Authors / org:** Apodex Team
- **Focus area:** Long-horizon "working capability"
- **What it is:** Names **working capability**: sustained, verifiable progress toward a real-world objective. Two scaling axes: Environment Scaling (diversity/verifiability of file, search, and code envs) and Agentic Coordination Scaling (decompose, delegate, integrate async results, replan). Shared execution harness + AgentOS for task state and provenance. Claims the leading performance band on professional work despite a substantially smaller model; **35B Mini** "retains strong working capability in a locally deployable form." Code: github.com/ApodexAI/FrontierAgent. Submitted Aug 24; abs verified.
- **Why it matters for Justin's agents:** The 35B Mini is the local-fit hook if weights actually land. Until then, steal the two-axis vocabulary (env scaling vs coordination scaling) and the "working capability = sustained verifiable work" definition — it is a better Mitamaton north star than a single-task pass rate. Discount leaderboard claims until the tables are on the abs.
- **Action signal:** `track` the Mini-35B weights; reuse the two-axis vocabulary now.

### 4. Quantization-Aware Healing: A Practical Recipe for Recovering Compressed, 4-Bit LLMs
- **Source:** arXiv (Hugging Face Daily Papers)
- **Link:** https://arxiv.org/abs/2608.20953
- **Authors / org:** Bakbergen Ryskulov / Iker García-Ferrero / David Montero / David Jansen / Ali Hashemi / Jezabel R. Garcia / Antonio Tiene / Román Orús — Multiverse Computing
- **Focus area:** Local 4-bit recovery (open weights)
- **What it is:** Structurally compressed + 4-bit models need a healing stage. Default QAT re-fits the compressed quantized model to hard labels — slow, then collapse. **QAH** distills the 4-bit student from the *original uncompressed* teacher (the bf16 compressed checkpoint is already a distillation approximation). GPT-OSS 120B → 60B → MXFP4: QAH student matches or beats its bf16 source on **7 of 9** benches at ~**4×** less weight memory and half the teacher's parameter count; ~**7×** faster to peak than matched QAT and stable under continued training. Released open-weight as **Hypernova-60B**. Also a large, reproducible quality gap between distributed-training backends. Submitted Aug 21; HF Daily Aug 25; abs verified.
- **Why it matters for Justin's agents:** Real open-weight drop in the 60B / 4-bit class — closer to a 64GB local target than 120B bf16. Recipe: distill from the *original* teacher, not the recovered bf16. Backend choice (FSDP vs DeepSpeed-class) is a hyperparameter, not plumbing. Compare Hypernova-60B MXFP4 against Qwen3-30B-A3B Q4 on a personal coding/day-admin set before changing the Mac default.
- **Action signal:** `try-now` on Hypernova-60B if it fits; `compare` the QAH recipe against naive QAT.

### 5. Jalapeño's first results — OpenAI
- **Source:** OpenAI News
- **Link:** https://openai.com/index/jalapeno-first-results/
- **Authors / org:** OpenAI (Engineering, Aug 25, 2026)
- **Focus area:** Inference hardware (track, not local)
- **What it is:** First measured results for OpenAI's custom inference ASIC vs commercially available systems on SemiAnalysis InferenceX. Across GPT-OSS 120B, DeepSeek R1 670B, Kimi K2.5 1T: **1.5–1.9×** more work per watt at peak throughput, **1.7–3.6×** lower end-to-end latency; highly interactive **2.1–4.1×**. Package **700 W**, measured sustained **≤550 W**. GPT-OSS: **85,448 vs 44,960** mixed TPS/kW (~1.9×), E2E **1.03s vs 1.80s**, min TBT **0.69 vs 1.87 ms**. DeepSeek R1: ~1.7× TPS/kW, E2E **1.65s vs 5.99s**. Kimi K2.5: ~1.5× TPS/kW, E2E **1.56s vs 5.31s**. Codex+GPT-Astra kernels **1.5–1.8×** human-expert on selected GPT-OSS blocks (blocks, not full model). Deploy inside OpenAI infra by end of 2026; not sold. Vendor-reported.
- **Why it matters for Justin's agents:** Not a Mac chip. It is the reason hosted agent latency may fall this winter, and a reminder that agentic workloads (prefill/decode mix, KV locality) are now a first-class ASIC target. Track for API latency/cost, not for the 64GB stack. Skip the same-day Admin plugin / "full stack behind abundant intelligence" posts as non-technical.
- **Action signal:** `track`
