# AI Research Digest — Wednesday, May 20, 2026

## TL;DR
- **The computer-use agent eval has its first real CLI counterpart to WildClawBench.** Yale's OpenComputer (Arman Cohan group) builds **verifiable software worlds across 33 desktop apps and 1,000 finalized tasks** with app-specific state verifiers and partial-credit auditable rewards; finds **hard-coded verifiers align with human judgment far better than LLM-as-judge for fine-grained app state**, and that open-source models drop sharply from their OSWorld-Verified numbers. Pairs with last week's WildClawBench [arxiv:2605.10912] as the second real-CLI long-horizon eval to land in a week.
- **A Qwen3-30B-A3B long-context RL recipe lands open-source and credibly matches the 235B-A22B frontier.** GoLongRL (TMN-Reweight: task-mean normalization + difficulty-adaptive weighting) trains **Qwen3-30B-A3B to match DeepSeek-R1-0528 and Qwen3-235B-A22B-Thinking-2507** on long-context tasks using 23K RLVR samples across 9 task types. Direct **M5 Max local-fit** — the 30B-A3B MoE class is the sweet spot for 64 GB unified memory.
- **A second context-management primitive (after [arxiv:2605.04050] LCM and [arxiv:2605.05191] LongSeeker) gets a clean implementation.** PEEK (Stanford/MIT — Omar Khattab, Sam Madden) caches **"orientation knowledge"** (what's in the context, how it's organized, which entities mattered) as a compact context map; **6.3–34% gain on long-context reasoning, 93–145 fewer iterations than ACE, 1.7–5.8× lower cost**. Sits on the same axis as LCM and InsightReplay [arxiv:2605.14457] — what to keep accessible, not just how to compress.
- **A clean numbers contradiction on auto-research lands.** AutoResearchClaw (36-author cluster including Caiming Xiong, James Zou, Sheng Wang) claims **+54.7% over AI Scientist v2 on ARC-Bench**; same week Cornell's ResearchArena tests **3 frontier code agents (Claude Code Opus 4.6, Codex GPT-5.4, Kimi Code K2.5) on 13 CS tasks × 3 trials = 117 papers**, finds manuscript-only review matches ICLR average but artifact-aware scoring collapses with **Kimi at 77%/72% paper-vs-artifact mismatch**. Both flagged as `compare`.
- **Strategic move on the MCP stack: Anthropic acquired Stainless.** Stainless built every official Anthropic SDK and generates TypeScript / Python / Go / Java SDKs, CLIs, and MCP servers from API specs. First-party MCP-server generation is now an in-house Anthropic capability — direct downstream effect on every MCP-based agent stack.

## Items

### 1. OpenComputer: Verifiable Software Worlds for Computer-Use Agents
- **Source:** arXiv (cs.AI / cs.SE, submitted May 19, 2026)
- **Link:** https://arxiv.org/abs/2605.19769
- **Authors / org:** Jinbiao Wei, Qianran Ma, Yilun Zhao, Xiao Zhou, Kangqi Ni, Guo Gan, Arman Cohan — **Yale University / Arman Cohan cluster** (LongBench, FinanceBench, GAIA-style benchmark history)
- **Focus area:** Evaluation / Tools & connectors / Coding agents
- **What it is:** Verifiable software environments for computer-use agents. **33 desktop applications** (browsers, office tools, creative software, dev environments, file managers, communication apps), **1,000 finalized tasks**, four components: (1) **app-specific state verifiers** providing structured inspection endpoints over real applications; (2) self-improving verification layer; (3) task generation pipeline; (4) evaluation system that records full trajectories and computes **auditable partial-credit rewards**. Two empirical findings reported: hard-coded verifiers align with human judgment substantially better than LLM-based evaluation for fine-grained application state; open-source models show **sharp drops** from their OSWorld-Verified numbers on this harder, real-system benchmark.
- **Why it matters for Justin's agents:** Three operational pulls for Justin's stack. (a) The hard-coded-verifier-beats-LLM-judge result is the right alarm bell for any custom MCP harness that judges its own tool calls with an LLM-as-judge gate — when the gate's job is "did this action change state correctly?", **typed state inspection wins**. Same conclusion ECA reaches on a different axis (#8 below) — typed certificates beat free-form model text. (b) 1000 tasks × 33 apps is the **first benchmark a custom Justin-built MCP harness can credibly run against** in the computer-use regime; pairs with WildClawBench [arxiv:2605.10912] (CLI side) as the two real-system long-horizon evals. (c) The OSWorld → OpenComputer score drop suggests open-source models that look competitive on OSWorld-Verified hit a real-world reliability floor that doesn't show up on the older benchmark — production GUI-agent companion apps should require dual-benchmark validation before claiming OSWorld parity = production parity.
- **Action signal:** `try-now` `compare` — when OpenComputer code/data drop, run any custom MCP harness against the open-source-model subset to size the OSWorld → OpenComputer reality gap before committing to a model choice.

### 2. GoLongRL: Capability-Oriented Long Context Reinforcement Learning with Multitask Alignment
- **Source:** arXiv (cs.CL / cs.LG, submitted May 19, 2026)
- **Link:** https://arxiv.org/abs/2605.19577
- **Authors / org:** Minxuan Lv, Tiehua Mei, Tanlong Du, Junmin Chen, Zhenpeng Su, Ziyang Chen, Ziqi Wang, Zhennan Wu, Ruotong Pan, Jian Liang, Ruiming Tang, Han Li — **Huawei Noah's Ark / Kuaishou** (Ruiming Tang is Huawei Noah's Ark, Han Li is Kuaishou, both well-known)
- **Focus area:** Local & open models / Context engineering / Reasoning
- **What it is:** Open-source long-context RL recipe with **TMN-Reweight** (task-level mean normalization for cross-task reward scale alignment + difficulty-adaptive weighting). Training data: **23K RLVR (RL-with-verifiable-rewards) samples across 9 task types** (books, academic papers, dialogues). Headline result: **Qwen3-30B-A3B trained with GoLongRL matches DeepSeek-R1-0528 and Qwen3-235B-A22B-Thinking-2507** on long-context reasoning, outperforming closed-source QwenLong-L1.5 dataset under identical training conditions. Both dataset and method released under CC BY 4.0.
- **Why it matters for Justin's agents:** This is the most directly **local-fit** result of the week. Qwen3-30B-A3B is **the** sweet-spot model for M5 Max + 64 GB: ~30B total / ~3B active MoE, runnable at Q4_K_M in ~17–19 GB of unified memory leaving room for 128K-context KV cache. If GoLongRL's claim survives independent reproduction, the operational implication is that **a long-context-tuned 30B-A3B running locally on M5 Max can match a 235B-A22B-Thinking frontier MoE** on documents/codebases/conversations that fit Justin's actual companion-app workloads. Pairs with [arxiv:2605.13301] SU-01 (same 30B-A3B class, math reasoning) as the second result this month suggesting **the 30B-A3B local-fit point is becoming a legitimate per-task substitute for closed frontier models** when the task is narrow enough.
- **Action signal:** `try-now` `local-fit` — once GoLongRL-trained weights post to HF, MLX-converted Qwen3-30B-A3B-GoLongRL is the next local long-context backbone to A/B against current Qwen3-30B-A3B baseline on Justin's longest-context coding/research workloads.

### 3. EnvFactory: Scaling Tool-Use Agents via Executable Environments Synthesis and Robust RL
- **Source:** arXiv (cs.CL, submitted May 18, 2026)
- **Link:** https://arxiv.org/abs/2605.18703
- **Authors / org:** Minrui Xu, Zilin Wang, Mengyi Deng, Zhiwei Li, Zhicheng Yang, Xiao Zhu, Yinhong Liu, Boyu Zhu, Baiyu Huang, Chao Chen, Heyuan Deng, Fei Mi, Lifeng Shang, Xingshan Zeng, Zhijiang Guo — **Huawei Noah's Ark** (Lifeng Shang, Fei Mi, Xingshan Zeng are Noah's Ark; Zhijiang Guo is HKUST)
- **Focus area:** Tools & connectors / Agent orchestration
- **What it is:** Framework that automatically constructs verifiable tool environments and generates multi-turn trajectories. **85 verified environments across 7 domains** producing **2,575 trajectories** (SFT + RL combined). Reported gains on Qwen3-series: **+15% BFCLv3**, **+8.6% MCP-Atlas**, **+6% on conversational benchmarks (τ²-Bench and VitaBench)**. Uses **~5× fewer environments** than comparable prior approaches while achieving superior results.
- **Why it matters for Justin's agents:** Two concrete pulls. (a) The **+8.6% MCP-Atlas** number is the cleanest "trained on MCP-style tools, evaluated on MCP-style tools" gain in the open-RL literature this month; pairs with ToolCUA [arxiv:2605.12481] (+66% rel. on OSWorld-MCP) and CAST [arxiv:2605.15041] (+5.85pp BFCL + 26% length reduction) as the third "tool-use-RL actually moves the production numbers" datapoint in 3 weeks. (b) The 5× environment-efficiency win argues for **synthetic-environment scaling** over raw trajectory scaling — directly relevant to Justin building task-specific MCP servers: a small, well-verified set of executable environments beats a large unverified trajectory dump for fine-tuning the agent layer on top.
- **Action signal:** `track` `compare` — wait for code/data release; if reproducible, the synthetic-environment recipe is a candidate template for an in-house MCP-server training set tied to Justin's actual companion-app tool surface.

### 4. PEEK: Context Map as an Orientation Cache for Long-Context LLM Agents
- **Source:** arXiv (cs.CL / cs.AI, submitted May 19, 2026)
- **Link:** https://arxiv.org/abs/2605.19932
- **Authors / org:** Zhuohan Gu, Qizheng Zhang, **Omar Khattab** (ColBERT/DSPy author), **Samuel Madden** (MIT CSAIL DB systems lead)
- **Focus area:** Context engineering / Agent memory
- **What it is:** Caches **orientation knowledge** (what's in the context, how it's organized, which entities have been historically useful) as a **compact context map embedded in the agent's prompt** — distinct from caching trajectories or raw material access. Three components: **Distiller** (extracts transferable knowledge), **Cartographer** (creates structured edits to the map), **Evictor** (maintains token budget). Headline numbers: **6.3–34.0% improvement** over strong baselines on long-context reasoning; **93–145 fewer iterations** than the ACE prompt-learning framework; **1.7–5.8× lower cost** than SOTA prompt-learning; **6.0–14.0% improvement on solving rate** on context-learning tasks; **7.8–12.1% better rubric accuracy at 1.4× lower cost than ACE** on related evals.
- **Why it matters for Justin's agents:** Third clean primitive in the **context-engineering taxonomy** that's been forming this month — alongside [arxiv:2605.04050] LCM (recursive compression as content) and [arxiv:2605.14457] InsightReplay (re-promote critical fragments near the cursor). PEEK sits at a different layer: **structured map of what's *in* the context, not the content itself**. For Justin's coding/research agents working over repositories or document collections, the practical implementation is **a compact JSON/Markdown map of the corpus structure passed into every turn**, plus a Distiller / Cartographer / Evictor loop maintaining it. The 1.7–5.8× cost reduction vs. ACE is the operationally-binding number — context-map maintenance is cheaper than prompt-learning. Khattab's authorship makes a DSPy reference implementation highly likely.
- **Action signal:** `try-now` — pattern is harness-side, no training; immediately portable to MCP coding agents (the map is the repo skeleton; Cartographer updates it on file change; Evictor drops cold subtrees). Likely to land in DSPy.

### 5. How Far Are We From True Auto-Research? (ResearchArena)
- **Source:** arXiv (cs.AI, submitted May 18, 2026)
- **Link:** https://arxiv.org/abs/2605.19156
- **Authors / org:** Zhengxin Zhang, Ning Wang, Sainyam Galhotra, **Claire Cardie** (Cornell — long-standing NLP / discourse / fact-verification lead)
- **Focus area:** Evaluation / Coding agents / Long-running loops
- **What it is:** ResearchArena tests three production code agents — **Claude Code (Opus 4.6), Codex (GPT-5.4), Kimi Code (K2.5)** — across **13 CS tasks × 3 trials = 117 generated papers**. **Manuscript-only review** (review the PDF only, no access to underlying code/data) shows Claude Code matching the human ICLR 2025 submission average. **Artifact-aware review** (reviewer reads the actual experimental code and rerunnable outputs alongside the manuscript) **drops scores sharply**, exposing three named failure modes: **fabricated results, underpowered experiments, plan-execution mismatches**. Worst case reported: **Kimi Code at 77%/72% paper-vs-artifact mismatch and fabricated references — roughly 15× higher error rate than Codex**. Bottom line: **none of the 117 papers met top-tier venue acceptance standards**.
- **Why it matters for Justin's agents:** The cleanest "auto-research has a reproducibility problem, not a writing problem" datapoint to date. Two implications. (a) For any agent product that emits a polished artifact for human consumption (research summary, market analysis, code review), **the artifact-aware vs. manuscript-only gap is the production-relevant failure mode** — a polished output that looks good to skim is the default failure pattern, not the exception. The fix is to design eval and review at the artifact level (PrefixGuard / Evidence-Supported Bounds territory), not the writeup level. (b) The 15× spread between Kimi Code and Codex is a model-/harness-level signal worth tracking — agent-product reliability differs substantially across closed-source coding agents on tasks where the agent is writing the artifact and the artifact is being judged.
- **Action signal:** `track` `compare` — pairs as a direct foil with item #6 below; together they're the conflict of the week. Joins the agent-eval-credibility thread now at 7+ papers (AuditRepairBench / Evidence-Supported Bounds / Rollout Cards / Counterfactual Trace Auditing / BenchJack / HarnessAudit-Bench / TRAIL / ResearchArena).

### 7. The Open Agent Leaderboard
- **Source:** Hugging Face blog — IBM Research (May 18, 2026)
- **Link:** https://huggingface.co/blog/ibm-research/open-agent-leaderboard
- **Authors / org:** Elron Bandel et al., **IBM Research** (paper linked at arxiv.org/abs/2602.22953 per the post; Exgentic framework released alongside)
- **Focus area:** Evaluation / Agent orchestration
- **What it is:** Open benchmark framework evaluating **full agent systems** (model + harness + tools, not just models) on **5 models × 5 agents × 6 benchmarks** (SWE-Bench Verified, BrowseComp+, AppWorld, τ²-Bench Airline/Retail, τ²-Bench Telecom). Four headline empirical findings: (1) **same model with different agents produces different results and costs** — the agent-around-the-model already changes outcomes meaningfully; (2) **general-purpose agents are competitive with specialized ones without benchmark-specific tuning**; (3) **failed runs cost 20–54% more than successful ones** on average; (4) **tool shortlisting improved performance across every tested model**; (5) **open-weight models trail frontier by 18–29 percentage points**. Open releases: leaderboard, **Exgentic** evaluation orchestration framework, paper.
- **Why it matters for Justin's agents:** Three high-value findings for production. (a) The **20–54% failure-cost premium** is the right answer to "should I add early-exit / failure-prediction monitors?" — failures don't fail fast; they burn extra tokens trying to recover. PrefixGuard [arxiv:2605.06455] / AgentTrust [arxiv:2605.04785] / Counterfactual Trace Auditing [arxiv:2605.11946] are now the obvious cost-saving wins, not just safety wins. (b) The **tool-shortlisting-helps-every-model** finding directly endorses the [arxiv:2605.10787] ComplexMCP failure mode #1 ("tool retrieval degrades as action space expands") fix: keep the per-turn tool list short. For Justin's MCP harness, this argues for a learned shortlister (Switchcraft-style) over throwing every MCP server's full tool catalog at the model. (c) The **18–29pp open-vs-frontier gap on full agent systems** sets a realistic expectation for any "swap Opus 4.7 for Qwen3-30B-A3B" reliability comparison — the model gap is not the whole gap; the harness can both widen and narrow it. Exgentic is the framework to use for in-house A/B testing.
- **Action signal:** `try-now` — Exgentic is a credible eval harness to A/B Justin's MCP harness against published agent configurations on real benchmarks; the 20–54% failure-cost finding is immediately actionable in any production cost model.

### 8. Hallucination as Exploit: Evidence-Carrying Multimodal Agents (ECA)
- **Source:** arXiv (cs.AI, submitted May 18, 2026)
- **Link:** https://arxiv.org/abs/2605.19192
- **Authors / org:** Guijia Zhang, Hao Zheng, Harry Yang (Harry Yang is HKUST CSE — known for diffusion / multimodal safety work)
- **Focus area:** Tools & connectors / Evaluation / Multimodal agents
- **What it is:** Reframes multimodal-agent hallucination as a **security exploit primitive** — when an agent makes a false visual claim about a screenshot or document, that claim can trigger destructive actions (clicks, emails, financial transfers). ECA's core move: **treat free-form model text as inadmissible evidence**; require external verification through constrained verifiers that produce **typed certificates authorizing specific actions**. Reports: **gate bypass reduced 15% → 1.3% after targeted hardening**; **0% unsafe-action rate on 200-task end-to-end pipeline** (95% UB 2.67%); **120-task browser proof-of-concept with 4.3% upper bound**; baseline **naïve agents at 100% unsafe execution, prompt-only defense 49.6%**, ECA prevents unsupported claims from reaching unsafe execution. Tested over 7,488 GPT-5.4 benchmark traces.
- **Why it matters for Justin's agents:** Architectural complement to AgentTrust [arxiv:2605.04785] and PrefixGuard [arxiv:2605.06455]: those two intercept tool calls at call/trajectory layer; ECA constrains **what the agent is allowed to claim before a tool call is issued**. The principle — **typed certificates from constrained verifiers over free-form model text** — is the same as OpenComputer's app-specific state verifiers (#1) and Formal Skill's executable state machines: the production-realistic pattern is converging on "**don't let the LLM be the source of truth for state assertions that authorize destructive actions**". For Justin's MCP servers wrapping anything destructive (file writes, financial APIs, federal data submission), this is the right gate architecture: every destructive tool call requires a typed evidence certificate, not a model-produced narrative.
- **Action signal:** `try-now` — apply the typed-certificate pattern to any destructive MCP tool in Justin's stack. Wait for code release for the full ECA verifier suite, but the gate architecture is portable today (require structured evidence object, not narrative, as precondition to destructive tool).

- **Memory fit:** Q4_K_M ~17–19 GB; Q5_K_M ~22–24 GB; Q6_K ~26–28 GB. M5 Max 64 GB unified leaves **30+ GB of headroom for KV cache at 128K context**, comfortable at 256K with Q4. The MoE pattern (3B active) keeps decode tok/s within MacBook-friendly latency.
- **Realistic tasks:** if GoLongRL's claim ("matches DeepSeek-R1-0528 and Qwen3-235B-A22B-Thinking-2507") survives third-party reproduction on Justin's actual long-context workloads (codebase Q&A, research-document synthesis, MCP-tool-call planning over long traces), this becomes the **default local backbone for context-heavy companion-app tasks** where the only frontier-model justification was long-context capacity. Not for: short-horizon agentic tool-use (OpenComputer-style — open-source models drop sharply there), proactive multi-session social reasoning (SocialReasoning-Bench / π-Bench territory still favors frontier closed models).
- **How to run:** **MLX** is the right runtime once weights post — Qwen3-30B-A3B has a stable MLX conversion pipeline. Fall back to **llama.cpp** with the Q4_K_M GGUF if MLX conversion lags. **LM Studio** for an out-of-box smoke test; **Ollama** for harness integration.
- **Speed estimate:** Qwen3-30B-A3B at Q4_K_M on M5 Max benchmarks historically land in the **35–50 tok/s decode** range (single-stream, short prompts) per published M-series MoE numbers, dropping to ~12–20 tok/s at 128K context fill. GoLongRL training doesn't change the parameter shape, so the tok/s envelope should match base Qwen3-30B-A3B on the same hardware.
