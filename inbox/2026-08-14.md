## Items

### 1. LycheeMemory V2: Semantic Segment-Level Consolidation
- **Source:** arXiv (Hugging Face Daily Papers)
- **Link:** https://arxiv.org/abs/2608.12990
- **Authors / org:** Dongfang Li / Zixuan Liu / Junmai Wang / Jiahe Huang / Fuhao Li / Bonian Jia / Baotian Hu / Min Zhang
- **Focus area:** Agent memory
- **What it is:** Argues eager per-interaction consolidation makes memory construction cost grow with conversation length; coarse summaries drop evidence; bigger retrieve-or-multi-hop just moves the cost to query time. LycheeMemory V2 batches exchanges into **semantic segments**, encodes each finalized segment into context-independent typed records, and indexes them for query-planned retrieval. Semantic boundary detection beats fixed windows for event-level / temporal evidence. GPT-4.1-Mini: **LoCoMo 89.22%, LongMemEval-S 92.20%**; vs A-Mem, construction tokens **−86.0% (LoCoMo) / −75.9% (LongMemEval-S)** with no increase in query-time tokens. Submitted Aug 13; abs verified this run.
- **Why it matters for Justin's agents:** This is the cost model for a nightly Obsidian / Mitamaton memory pass — do **not** call a summarizer after every chat turn. Batch a day's Claude Code + Mitamaton transcripts into semantic segments (calendar block, coding session, research skim), write typed records once, retrieve with a query plan. The 86% construction-token cut is the reason it is cheaper than mem0-style eager extract. Pair with SPIEval's localization warning (2026-08-12): cheap construction is useless if retrieve still commits to the first plausible record.
- **Action signal:** `try-now` — replace per-session memory writes with a once-a-day segment consolidator; keep the record schema tiny (who / when / fact / source).

### 2. SKILLER: Language-Level RL for Reusable Skills in Small Models
- **Source:** arXiv (Hugging Face Daily Papers)
- **Link:** https://arxiv.org/abs/2608.10538
- **Authors / org:** Chenhao Dang / Siyuan Xiong / Conghui He / Weijia Li
- **Focus area:** Agent skills + local / small models
- **What it is:** Skills constrain a harness cheaply, but popular harnesses (Codex, OpenClaw) stay expensive if the *executor* is a closed frontier model. SKILLER treats skill generation for compact open models as RL in natural language: strong model = actor/critic, small-model agent system = environment, all rewards/updates as text. Qwen3.5-9B and Qwen3.5-4B, five benchmarks, vs three open + one closed skill-generation/evolution methods: **+4.3 to +20.4 pp (9B), +1.8 to +13.3 pp (4B)**; matches strong closed models on single-skill SkillsBench tasks. Code: https://github.com/DANG-ai/SKILLER. Submitted Aug 11 (v2 Aug 14); abs verified this run.
- **Why it matters for Justin's agents:** Completes yesterday's AI4AI result. AI4AI [arxiv:2608.12307] writes a *harness* for a weak model; SKILLER writes *executor-specific skills*. The 4B/9B numbers are the local-fit hook — these are the sizes that actually run on the 64 GB Mac. Practical recipe: evolve SKILL.md on Opus / Gemini 3.7 Flash *against* a Qwen3.5-4B Mitamaton loop (the small model is the environment, not the author), then ship the markdown. Do not let the 4B write its own skills (later WikiSkill negative-transfer warning, 2026-08-28, is the same failure mode).
- **Action signal:** `try-now` on a 10-task personal set with Qwen3.5-4B as executor; `compare` against hand-written SKILL.md and against SkillZip-compressed ones.

### 3. AutoDesign: Meta-Harness Optimization for Long-Horizon Agentic Design
- **Source:** arXiv (Hugging Face Daily Papers)
- **Link:** https://arxiv.org/abs/2608.13560
- **Authors / org:** Yaxin Luo / Haobin Jiang / Jialv Zou / Xu Huang / Wenhao Yan / Haodong Li / Zhengrong Yue / Jing Li / Xiaofu Chen / Xiaohan Zhao / Jiacheng Liu / Jiacheng Cui / Zhiqiang Shen / Xiaotong Li
- **Focus area:** Agent harness evolution
- **What it is:** A meta-harness optimizer that matches "human design priors": a supervisor guides a code agent to recursively edit the harness from rollout feedback. Instantiated on academic paper → poster. PosterBench = 100-paper Main Track (five disciplines) + 10-paper mini. AutoDesign **78.32**, **+7.45** over closed-source Claude Design. Across seven code-agent × model configs, the learned DesignHarness lifts average score **54.99 → 67.39 (+12.4%)**. Fully autonomous loop: 253 tool calls, 11 editing turns, 40 minutes, **<$3**, conference-poster quality in human eval; system-blind human study prefers it. Code: https://github.com/Yaxin9Luo/AutoDesign. Submitted Aug 13; abs verified this run.
- **Why it matters for Justin's agents:** The domain (posters) is not Mitamaton. The primitive is: **a harness that edits its own prompts/tools from rollout feedback, transferred across backbones (+12.4% average)**. That is the same bet as later DarwinX / PILOT / StateM, measured here as a portable DesignHarness artifact rather than a live supervisor channel. Steal the loop (rollout → harness edit → freeze → transfer), not the poster renderer.
- **Action signal:** `compare` — one harness-edit loop on a 10-task personal set vs a frozen CLAUDE.md; skip if the only available eval is "make a poster."
