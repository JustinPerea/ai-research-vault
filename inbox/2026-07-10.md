## Items

### 1. Jet-Long: Efficient Long-Context Extension with Dynamic Bifocal RoPE
- **Source:** arXiv (cs.CL)
- **Link:** https://arxiv.org/abs/2607.07740
- **Authors / org:** Haozhan Tang, Zerui Wang, Yuxian Gu, Song Han, Han Cai (NVIDIA)
- **Focus area:** Context engineering / long-context
- **What it is:** A tuning-free, zero-shot long-context extender that pairs a local RoPE-faithful window with a long-range window whose rescaling factor adapts to the current sequence length. An inclusion-exclusion attention merge plus on-the-fly RoPE correction keeps overhead low. On Qwen3 1.7B/4B/8B up to 128K it beats RULER by +4.79 / +2.18 / +2.03 points, wins HELMET-RAG, wins PG-19 perplexity, hits 1.39× FA2 prefill throughput on H100, and stays ≤4% overhead at every single-batch length. Generalizes to hybrid attention architectures (Jet-Nemotron) without retraining.
- **Why it matters for Justin's agents:** This is the retrofit long-context wants: zero fine-tuning, hyperparameter-resilient, works on Qwen3 8B (the M5 Max sweet spot). It sidesteps the fixed-rescaling-factor pathology (short-context regression) that has blocked most prior RoPE extensions from being drop-in. The 4% single-batch overhead ceiling is the number that makes it deployable on a laptop; on M5 Max with 64 GB, running Qwen3-8B at 128K for repo-level coding / RAG / episodic-memory retrieval becomes a one-flag change instead of a fine-tune.
- **Action signal:** `local-fit` — Qwen3-8B GGUF or MLX + Jet-Long overlay is the natural experiment for the local coding-agent stack.

### 2. From Atomic Actions to Standard Operating Procedures: Iterative Tool Optimization for Self-Evolving LLM Agents (EvoSOP + Tool-Making Pipeline)
- **Source:** arXiv (cs.CL)
- **Link:** https://arxiv.org/abs/2607.08010 (production tool-making); companion https://arxiv.org/abs/2607.07321 (EvoSOP framework)
- **Authors / org:** Kalle Kujanpää, Ning Liu, Shahnawaz Alam, Yeshwanth Reddy Sura, Tianyu Yang, Kristina Klinkner, Shervin Malmasi (production pipeline); Haipeng Ding, Yuexiang Xie, Zhewei Wei, Yaliang Li, Bolin Ding (EvoSOP framework)
- **Focus area:** Tools & connectors / agent orchestration
- **What it is:** Two same-day papers propose the same architectural shift — replace runtime code-gen with an offline tool-making pipeline that compiles repeated multi-step logic into validated, versioned tools. The production paper (2607.08010) grounds synthesis in the live environment (collects execution traces, observes backend schemas + values, generates candidate tools, repairs against labeled cases). At runtime the agent calls compiled tools directly and only falls back to code-gen when needed. Deployed on a fulfillment-center alarm-triage workflow (44-node SOP, heterogeneous metric backends, 1,500 historical alarms): p50 latency −42%, end-to-end error rate down up to 53% (variance elimination is the driver), further −62% p50 latency in a direct-call ablation. EvoSOP (2607.07321) formalizes the same idea as construct → merge → evaluate → prune cycles over an SOP library extracted from execution traces.
- **Why it matters for Justin's agents:** This is the "MCP server as compile target" pattern with production numbers behind it. Any repeated multi-step MCP tool sequence in Justin's stack (auth flow, doc-scrape → summarize → store, `date` + `git log` + issue-open loop) becomes a compiled tool with versioning + audit trail + drift detection. The auditability side-effect ("versioned tools exposed specification gaps and data drift") converts observed drift into a signal instead of a silent failure — an execution-time complement to yesterday's [arxiv:2607.07405] Reason-Less-Verify-More gates. Retrofit target: for every subagent, log its top-K action k-grams; when frequency crosses a threshold, mint an SOP tool and gate the write path with a Python-shaped validator.
- **Action signal:** `try-now` — the 42%/53% latency-and-reliability delta is directly reproducible in the MCP-tool layer; wire it in and measure before the next digest.

### 3. UniClawBench: A Universal Benchmark for Proactive Agents on Real-World Tasks
- **Source:** arXiv (cs.CL)
- **Link:** https://arxiv.org/abs/2607.08768
- **Authors / org:** Zhekai Chen, Chengqi Duan, Kaiyue Sun, Bohao Li, Yuqing Wang, Manyuan Zhang, Xihui Liu (HKU-MMLab)
- **Focus area:** Evaluation / agent orchestration
- **What it is:** 400 bilingual real-world tasks executed inside live Docker containers (no static replay), organized around five competencies: skill usage, exploration, long-context reasoning, multimodal understanding, cross-platform coordination. Closed-loop evaluation with executor + hidden supervisor + user simulator, step-by-step completion checkpoints, and multi-turn feedback with grading criteria hidden from the agent. Headline finding: base-model capability × agent-framework design jointly determine performance — neither is sufficient alone. Code + benchmark at github.com/HKU-MMLab/UniClawBench.
- **Why it matters for Justin's agents:** This is the evaluation harness that measures what agentic products actually sell — proactive multi-step task completion across surfaces — instead of measuring the base model in isolation. Cross-platform coordination is the axis every companion app / MCP orchestrator competes on and is chronically under-benchmarked. Practical use: run Justin's default Claude Code + MCP stack against the 400 tasks, and log per-competency deltas as harness variations are introduced. The "hidden supervisor + user simulator" pattern is directly transferable — Justin can build the same shape for his companion-app QA loop without the benchmark's scoring criteria leaking.
- **Action signal:** `try-now` — clone the Docker harness, target 20 tasks per competency in the first pass, publish per-competency deltas for the current harness before the next release.

### 4. LLM-as-Judge Reliability: Judge Upgrades Are Not Interchangeable
- **Source:** arXiv (cs.CL)
- **Link:** https://arxiv.org/abs/2607.08535
- **Authors / org:** Zongyou Yang, Yinghan Hou, Xiaokun Yang
- **Focus area:** Evaluation / reference-free judge cluster
- **What it is:** Comparative reliability audit of two "obvious" LLM-judge upgrades: Qwen3 dense 1.7B → 32B, and MiniMax M2 → M2.7. Findings: only Qwen3 1.7B → 4B produces robust adjacent improvements — most other upgrades shift scores non-monotonically even when the evaluated responses are identical. Larger judges reduce (but never eliminate) position and verbosity biases. Repeated-sample juries provide "minimal value when evaluation errors correlate" — matches the [arxiv:2607.05904] 3-judge-ensemble-accepts-55%-of-hacked-responses number from July 8. Structured debate can shift decisions substantially but requires parser + fallback logs to attribute causal contribution.
- **Why it matters for Justin's agents:** Directly extends the reference-free-judge collapse cluster (Blind Curator + Self-Play Reward Hacking + Huang null result) with the operational question — "how do you audit before deploying an upgrade?" The concrete recommendations (dataset slices + bias probes + error-dependence estimates + protocol audit trails) are the checklist form of the Blind Curator's defect-injection audit. Retrofit: any place Justin's stack swaps judges (regressions, safety triage, memory-write validation), the swap needs an error-correlation delta measurement, not just a mean-score comparison.
- **Action signal:** `compare` — extends [arxiv:2607.07436] Blind Curator + [arxiv:2607.05904] Self-Play Reward Hacking + [arxiv:2607.07504] Huang null result; the four-paper cluster is now the strongest tracked-corpus signal about reference-free judging.

### 5. Two Axes of LLM Abstention (Wrong-Answer vs Should-Not-Answer)
- **Source:** arXiv (cs.CL)
- **Link:** https://arxiv.org/abs/2607.08456
- **Authors / org:** Benedikt J. Wagner
- **Focus area:** Reasoning & inference-time compute / agent design
- **What it is:** Establishes that "answer confidence" and "question answerability" are independent axes — standard confidence thresholds cannot distinguish "I would get this wrong" from "no one should answer this." Five instruction-tuned models (2B–14B) across three families. On CREPE (false-premise questions), answer-confidence, P(IK), P(True), and direct premise-checking all "stay near chance"; a hidden-state probe hits 0.69–0.77 AUROC. Direct instruction to check premises yields 57% false challenges — routing with the probe roughly triples challenge precision. Two-axis policy certifies 0.75 coverage of correct answers vs 0.31 for single-threshold; at 14B, the two-axis policy is the only one that certifies at all.
- **Why it matters for Justin's agents:** Directly relevant to agent refusal engineering — "the user asked a false-premise question" and "the model would answer this wrong" are the two failure modes that most user-facing agent interfaces conflate. The 57% false-challenge number from direct prompting is a warning against the naive "did you check whether the premise is valid?" pre-prompt. The hidden-state probe (small, cheap, routable) is the operational primitive — Justin can train a probe on false-premise data locally on M5 Max and gate the agent's response head on the two-axis output.
- **Action signal:** `track` — the 14B-scale certification-only-with-two-axes number is the datapoint to watch; if the probe recipe generalizes to Qwen3-8B, it's a `try-now` gate for the companion-app refusal layer.

### 6. Hallucination Self-Play: Detector-Generator Co-Evolution on RAGTruth
- **Source:** arXiv (cs.CL) — accepted COLM 2026
- **Link:** https://arxiv.org/abs/2607.07993
- **Authors / org:** Shiping Yang, Shining Liang, Weihao Liu, Wenbiao Ding, Linjun Shou, Lu Cheng, Angel X. Chang
- **Focus area:** Reasoning & inference-time compute / self-play
- **What it is:** Two roles initialized from the same base model — a hallucination detector fine-tuned on human-labeled data, and a generator trained via RLAIF using the detector as reward model. The evolved generator produces harder-to-detect hallucinated responses, which then feed rule-based RL to sharpen the detector further. RAGTruth: small LLMs progressively match or exceed advanced-LLM detectors without external supervision.
- **Why it matters for Justin's agents:** Nominally in tension with [arxiv:2607.05904] Self-Play Reward Hacking (July 8), which showed self-play RL against a reference-free judge collapses to reward-hacking. HSP escapes that failure mode because: (a) the detector is initialized on human labels (grounded, not reference-free), (b) rule-based RL provides deterministic signal on the detector-training side, and (c) the roles are asymmetric (detector = grounded, generator = adversarial). The lesson: self-play is only pathological when both sides are reference-free; anchoring one side to ground truth restores it. Retrofit for Justin's stack: any memory-write validator or refusal filter can be trained under this recipe, provided the initial fine-tune is on human-labeled examples.
- **Action signal:** `compare` — reconciles rather than refutes [arxiv:2607.05904]; the split is "reference-free-both-sides" (broken) vs "one-side-grounded" (works). Adds a decision rule for when self-play is safe.

### 7. DeepSearch-Evolve: Self-Distillation for Deep Search Agents on a Verifiable Environment
- **Source:** arXiv (cs.CL)
- **Link:** https://arxiv.org/abs/2607.07820
- **Authors / org:** Xinyu Geng, Xuanhua He, Sixiang Chen, Yanjing Xiao, Fan Zhang, Shijue Huang, Haitao Mi, Zhenwen Liang, Tianqing Fang, Yi R. Fung
- **Focus area:** Agents / coding-adjacent / evaluation
- **What it is:** DeepSearch-World is a deterministic verifiable environment with reproducible search + page-reading capabilities and 420K multi-hop QA tasks derived from entity-level random walks. It supports progress verification, grounded reflection, and failure recovery. DeepSearch-Evolve is an iterative self-distillation loop over this environment: trajectory generation → filtering → data mixing → fine-tuning, no external teacher. A 9B parameter model reaches BrowseComp 31.2 / GAIA 61.5 / HotpotQA 93.4 — competitive with substantially larger baselines and without distillation from a bigger model.
- **Why it matters for Justin's agents:** The verifiable environment + rule-based-RL pattern is the same one that makes Hallucination Self-Play work (item 6) and that the Reason-Less-Verify-More gates (yesterday's [arxiv:2607.07405]) exploit at execution time. DeepSearch-Evolve validates it at training time for the long-horizon web-agent case. The 9B ceiling is the local-inference-relevant number: MLX or GGUF at Q4 fits in ~5–6 GB of unified memory, leaving room on M5 Max for a full search-agent + memory-store + probe-based safety layer in a single process. The 61.5 GAIA number for a 9B model is the local-model coding-adjacent agent tier that until recently required 70B+.
- **Action signal:** `track` — pending model weights release; if the 9B checkpoint ships, it's a `local-fit`.

## Local-model corner
**Jet-Long overlay on Qwen3-8B for M5 Max (64 GB, ~600 GB/s):**
- **Model:** Qwen3-8B, GGUF Q4_K_M or MLX 4-bit
- **Memory fit:** Weights ~4.5 GB (Q4) / ~5.5 GB (MLX 4-bit). At 128K context with Jet-Long bifocal windows, KV cache dominates: naive full attention KV ≈ 2 × 128K × n_layers × n_heads × head_dim × 2 bytes (fp16). For Qwen3-8B this is ~15–18 GB; Jet-Long's local-window design keeps the base per-token cost inside the local window, so effective KV footprint stays substantially lower than the naive estimate. Practical headroom: run at 32K–64K with plenty of margin, push to 128K with monitoring.
- **Realistic tasks:** Repo-level coding-agent context assembly (whole-package retrieval + reasoning without splitting); RAG over long documents (HELMET-RAG results are the closest analog); episodic-memory replay for a companion agent (128K of interleaved memory + new turn). Not realistic yet: full long-video summarization, multimodal 128K.
- **How to run:** MLX-LM for Qwen3-8B is already available; Jet-Long is described as tuning-free zero-shot with an inclusion-exclusion attention merge + on-the-fly RoPE correction rotation — natural fit for a llama.cpp attention-layer patch or an MLX operator overlay. Watch NVIDIA / Han Lab for a reference kernel.
- **Speed estimate:** M5 Max Qwen3-8B at Q4 typically runs ~30–50 tok/s at short context. Jet-Long's H100 numbers (1.39× FA2 prefill, ≤4% single-batch overhead) suggest the M5 Max long-context prefill hit stays within tolerance; expect a ~5–10% wall-clock hit at 128K vs shorter contexts, well under the alternative of full-attention explosion. No M5-Max-specific benchmark exists yet — this is the first project to build one from.

**DeepSearch-Evolve 9B (pending release):** if weights ship, MLX Q4 at ~5 GB weights, plus a local search-agent trajectory buffer + probe-based safety layer + memory store still leaves >40 GB free on M5 Max — the single-process autonomous local search-agent stack becomes buildable.

## Conflicts & open questions
- **Reconciled (not conflict): [arxiv:2607.07993] Hallucination Self-Play vs [arxiv:2607.05904] Self-Play Reward Hacking.** Both use self-play; only one collapses. Reconciliation: HSP grounds one side of the loop on human-labeled data + rule-based RL, breaking the reference-free symmetry that Self-Play Reward Hacking showed is pathological. Emerging rule: self-play is safe iff at least one role's training signal is anchored to ground truth outside the model family.
- **Extension (adjacent cluster): [arxiv:2607.08535] Judge-Upgrade Auditing extends [arxiv:2607.07436] Blind Curator + [arxiv:2607.05904] Self-Play Reward Hacking + [arxiv:2607.07504] Huang null result.** Four-paper cluster now converges on: reference-free LLM judges (a) are structurally unreliable in ways aggregate metrics hide, (b) exhibit correlated errors that kill jury voting, (c) do not become monotonically better with model-size upgrades, and (d) require operational audit protocols (defect injection + error-correlation slices + protocol trails) before deployment. This is now the highest-signal open cluster in the tracked corpus; every LLM-as-judge in Justin's stack should be marked for audit.
- **Open empirical question:** does Jet-Long's bifocal RoPE composition survive the Hidden-Decoding-style ([arxiv:2607.08186]) sequence-length expansion primitive? If the two compose, effective per-token attention capacity multiplies across two orthogonal axes at fixed depth.
- **Open empirical question:** for Two-Axes Abstention (item 5), does the hidden-state probe generalize from CREPE-style false-premise questions to production ambiguous-user-intent tickets? The 0.69–0.77 AUROC gap between models suggests the probe's transferability is not automatic.
