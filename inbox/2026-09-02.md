### 1. ContextPipe: Database-Inspired Context Assembly for Long-Horizon Agents
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2609.00749
- **Authors / org:** Peng Xu / Zuyu Zhang / Yuze Sun et al. (6 authors)
- **Focus area:** Memory / context assembly for long-horizon agents
- **What it is:** Context assembly treated as query planning: a five-phase Plan–Bind–Optimize–Execute–Feedback pipeline with a structured data-source catalog, a deterministic cache-aware optimizer, and an EXPLAIN ANALYZE trace. On the SWE-bench Pro Qutebrowser subset vs append-only context construction, ContextPipe cuts total token volume 31%, LLM calls 23%, and response time 9%, at the cost of a lower KV cache-hit ratio. Context is auditable, replayable, and failure-isolated.
- **Why it matters for Justin's agents:** Yesterday's Measure-Before-You-Manage [arxiv:2608.31057] said typed residency accounting comes first; ContextPilot [arxiv:2608.28476, 08-31] said fold the working transcript. ContextPipe is the runtime that actually *assembles* the next prompt under a hard window and a byte-sensitive prompt cache. Steal without a database rewrite: (1) catalog context sources (transcript / skills / tool results / memory), (2) plan what to include, (3) log an EXPLAIN of every prompt. Do not read the 31% token cut as a Mitamaton guarantee — Qutebrowser subset only.

### 2. CacheBridge: Efficient Cross-Model KV Cache Transfer
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2609.00891
- **Authors / org:** Xingyu Qu / Siyuan Lu / Zhiyu Chen et al. (5 authors)
- **Focus area:** Local / multi-model serving — closed-form cross-model KV transfer
- **What it is:** CacheBridge is a training-free affine mapper from source to target KV caches. It restricts each target head to a matched source head, weights reconstruction by causal attention sensitivity, and uses a fused GPU kernel. Recovers two Ministral 3 transfer directions where Full-Head Mapping loses substantial accuracy while preserving 99.83% mean target retention on Qwen3. On Qwen3 14B→32B: mapper storage −8×, application up to 3.0× faster, matches full-head with 1/10 the calibration data, 500-sequence construction 92.63→8.63 s (10.7×).
- **Why it matters for Justin's agents:** Direct sibling of yesterday's UT Dallas learned transport [arxiv:2608.30963]. That paper trains a translator per pair; CacheBridge is closed-form + architecture-indexed, cheaper to stand up on a local Qwen ladder. Compare both on a fixed Mitamaton long context before building either. TwinKV remains within-model eviction. Latency/quality numbers are GPU-kernel; not a drop-in for Apple Silicon without a serving stack that can host the mapper.
- **Action signal:** `compare`
