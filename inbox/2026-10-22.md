# AI Research Digest — Thursday, October 22, 2026

## TL;DR

- **MemoryTax** (2610.29823): with Claude Opus 5.5, a coding agent searching raw history (Pi) hit 99% on a LoCoMo conversation at under half the cost of full context; Mem0 only beat full context with GPT-4o-mini and its build cost more than a full-context rollout — designed memory is capped by its writer model (one conversation, one run per cell).

- **Silent cue loss** (2610.30026): formatting-blind ingestion drops author-flagged requirement recovery from F1 0.690 to 0.150/0.075; highlight and colour carry the loss — preserve and label them.
- **D-Skill** (2610.28914): black-box teacher behavior distilled into a skill document closes 75-95% of the teacher-student gap with no weight updates, 5.7-8.3x cheaper inference.

- **Stuck agents** (2610.28834): specifications help repair most, test feedback little, retrieved code ~0; frontier models pick feedback 95-100% of the time and do worse than random.

### 1. MemoryTax: The Bitter Lesson of Agent Memory
- **Source:** arXiv (cross-list)
- **Link:** https://arxiv.org/abs/2610.29823
- **Authors/org:** Zedong Peng
- **Focus area:** agent memory vs raw-history search
- **What it is:** Short empirical study on one LoCoMo conversation (419 turns, 152 questions): four memory methods (full context, BM25, Mem0, Zep) vs three coding agents (Pi, Codex, Claude Code) that keep raw history and search it with their own tools, each with GPT-4o-mini, GPT-6 Luna and Claude Opus 5.5, with per-rollout cost. Mem0 beats full context only with GPT-4o-mini, and its build alone costs more than a whole full-context rollout; memory quality is capped by the model that writes it. With Claude Opus 5.5, Pi tops the cost-accuracy frontier at 99% for under half the cost of full context. One conversation, one run per cell; part of the lead comes from photo captions only agents could read.
- **Why it matters for Justin's agents:** Argues for keeping raw history plus agentic search over pre-distilled memory once the model is strong — the opposite of building a heavy memory layer for Mitamaton. Small-n, so a hypothesis to test on Justin's own logs.
- **Action signal:** `compare`

### 2. Combining Long-Term Memory and LLMs Comes at a High Cost: From Prompt Injection to Persistent Compromise
- **Source:** arXiv (cross-list)
- **Link:** https://arxiv.org/abs/2610.28810
- **Authors/org:** Pedro H. Barcha Correia, Matheus Azevedo de Sá, Paulo H. Gomes de Senna, Giovanni Mandel Martignago, Victor Takashi Hayashi, Charles Christian Miers et al.
- **Focus area:** memory injection / persistent compromise
- **What it is:** General threat model for memory injection in LLM-as-a-service: all NIST attack goals are achievable across ChatGPT Instant 5.3, Claude Sonnet 4.6 and Gemini 3 Flash. Injection vectors include personal memories, projects, skills, organization instructions and MCP-connected resources; services can be made to persistently spread disinformation, generate harmful content or simulate unresponsiveness in fresh sessions. In Claude, shared-memory features let an attacker compromise multiple users in an organization and exfiltrate prompts. Nearly half of the derived mitigations remain unimplemented.
- **Why it matters for Justin's agents:** Skills, project instructions and MCP resources are exactly Justin's surfaces; treat anything written to memory/skills from tool output as untrusted. Extends Oct 21's CarryoverBench finding to production services.
- **Action signal:** `try-now`

### 3. PerMIT: Securing Persistent Memory for LLM Agents via Machine-Checked Integrity Theorems and Scalable Community Trust
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.28987
- **Authors/org:** Tanqiu Jiang, Min Bai, Sadat Shahriar, Wanyu Du, Sandesh Swamy
- **Focus area:** memory integrity / provable gating
- **What it is:** PerMIT: memory architecture where only user-typed inputs and gate-confirmed values are trusted; untrusted environment-derived values flow through a finite memory interface. Two integrity theorems, machine-checked in Lean 4, ensure environment-derived memory reaches a sensitive action only if confirmed at the gate. Zero observed attack success on Trojan Hippo; endorsements accumulate across users so items become community-confirmed; on tau2-bench, communities of up to 90 agents build shared knowledge bases with no injection promoted and better new-agent performance.
- **Why it matters for Justin's agents:** A concrete design for Mitamaton memory writes: every attack reduces to one auditable confirm-at-gate decision. Worth comparing with ClawMMU (Oct 21).
- **Action signal:** `compare`

### 4. Back Up Before You Regret: Measuring Backup Awareness and Automating Backup in Coding Agents
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.28934
- **Authors/org:** Xu Li, Simon Yu, Minzhou Pan, Yiyou Sun, Zhaorun Chen, Bo Li et al.
- **Focus area:** reversibility / backup layer for coding agents
- **What it is:** RegretBench: 205 executable tasks grounded in real user 'regret moments'. Six frontier models complete 86.1% of tasks but back up before these moments in only 15.2%. BackUpper, a harness plug-in that checks every tool call and preserves affected state (rules plus a lightweight subagent, rule table grows over time), covers every regret-moment action, restores state at 92.2% similarity, costs $0.014 per task with 7x fewer tokens than main-agent self-backup, and matches human 'worth preserving' labels at 84.5% F1.
- **Why it matters for Justin's agents:** Cheap harness-level reversibility for any agent touching Justin's files or settings — implementable as a PreToolUse hook. Task success does not imply care for state.
- **Action signal:** `try-now`

### 5. PAUSE: Search-Free Steering of Coding Agents Before Their First Source-Code Edit
- **Source:** arXiv (cross-list)
- **Link:** https://arxiv.org/abs/2610.29870
- **Authors/org:** Viral Patel, Boyin Tan, Jason Xue, Youcheng Sun
- **Focus area:** coding-agent steering / single planning intervention
- **What it is:** PAUSE intercepts a coding agent's first source-code edit (median 60% of trajectory progress), has a separate Planner write one repair plan from the pre-edit transcript, and resumes the same Executor with its context and workspace. No learned monitor, no checkpoint search. With Qwen3-coder Executor and GPT-5.6 Sol Planner: +16.8% resolution on SWE-bench Verified (OpenHands), +14.7% on Multilingual (SWE-agent); comparable to SICA's periodic overseer at ~11-15% of its Planner cost. Offline it recovers 35.4% of eligible failed tasks with 33-41% fewer Executor tokens than restarting.
- **Why it matters for Justin's agents:** A one-hook pattern for local-model coding loops: cheap local executor, frontier planner called once at the first Edit. Easy to try as a Claude Code hook.
- **Action signal:** `try-now`

### 6. What the Author Wrote, What the Agent Reads: Silent Cue Loss in Enterprise Document Ingestion
- **Source:** arXiv (cross-list)
- **Link:** https://arxiv.org/abs/2610.30026
- **Authors/org:** Yikai Zhao, Saurabh Pandey, Pradeep Kumar Misra
- **Focus area:** document ingestion / silent context loss
- **What it is:** On 76 real policy documents, formatting-blind ingestion collapses recovery of author-flagged requirements from micro F1 0.690 to 0.150 (docling) and 0.075 (plain text), replicated across five Claude models and GPT-5.6. The loss localizes to highlight (+0.302) and colour (+0.262); bold/italic/etc. are ~0. 32.8% of 6,460 documents carry deliberate colour or highlight, 10.3% on an obligation. Typing the cue for the agent adds +0.085 beyond preserving it. Scored by a deterministic matcher, no LLM judge.
- **Why it matters for Justin's agents:** Any Mitamaton flow that ingests user documents/PDFs should preserve and label highlight/colour; ingestion, not reasoning, is the failure point.
- **Action signal:** `try-now`

### 7. D-Skill: Distilling Teacher Knowledge through Agent Skills
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.28914
- **Authors/org:** Shuo Yuan, Dacheng Li, Joseph E. Gonzalez
- **Focus area:** skills as distillation
- **What it is:** D-Skill treats a teacher agent as a black box, compares paired teacher/student rollouts for behavioral divergences, and consolidates lessons offline into a natural-language skill document given to the student at inference. No labels, no extra environment interaction, no weight updates. Across SpreadsheetBench-Verified, ALFWorld and chess puzzles it closes 75-95% of the teacher-student gap, beats one-epoch SFT and is competitive with multi-epoch SFT; student inference is 5.7-8.3x cheaper than the teacher.
- **Why it matters for Justin's agents:** Direct recipe for moving Claude-level behavior into a local model via a SKILL.md instead of fine-tuning.
- **Action signal:** `try-now`

### 8. Correlated Failures of AI Approval Monitors
- **Source:** arXiv (cross-list)
- **Link:** https://arxiv.org/abs/2610.29178
- **Authors/org:** Luca Zanolini
- **Focus area:** approval monitors / correlated failure
- **What it is:** Borrows fail-prone systems from distributed computing to combine monitors that check consequential actions. On payment approval with twelve small open-weights monitors (plus Claude Opus 5.5, GPT-6 Astra, Gemini 4 Argon, DeepSeek-V3.2): every reliable fooling into approving fraud came through one evidence source and reached only that source's readers; small models and DeepSeek obeyed planted notes, the closed models ignored them in all but one case. Counting sources instead of votes blocked 0.9% of correct payments vs 7.4% for the best counting rule at equal safety. The pre-registered worst-case test failed; adding a non-persuadable rule engine restored a safe and live rule.
- **Why it matters for Justin's agents:** For Mitamaton actions (pay, message, change), stacking LLM monitors on the same input is not independence; diversify inputs and keep a deterministic rule engine in the loop.
- **Action signal:** `compare`

### 9. Who Verifies the Builder? Toward Independent Assurance for Agent-Produced Software

### 10. VerifierBench: Benchmarking the Generation of Executable Verifiers for LLM Agents
- **Source:** arXiv (cross-list)
- **Link:** https://arxiv.org/abs/2610.28679
- **Authors/org:** Jianing Yin, Ziyi Chen, Hao Wang, Yiyou Sun, Zijian Jin, Dawn Song et al.
- **Focus area:** verifier generation benchmark
- **What it is:** VerifierBench: 222 tasks from six agent benchmarks (tool-call, state-based, code) with 4,993 hidden test cases including alternative valid solutions and attacks, audited by a six-check Verifier4Verifier. ### 19. PreCoMem: Predictive Cognitive Memory for Self-Evolving Long-Term Dialogue Agents
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.29467
- **Authors/org:** Jian Zhong, Zeyu Liu, Pingchuan Cao, Rongduo Han, Shunye Tang, Guohuan Xie et al.
- **Focus area:** user memory consolidation
- **What it is:** PreCoMem models user memory as confidence-weighted beliefs updated by 'effective surprisal' (semantic deviation plus contradiction, downweighted when retrieval is diffuse). - **Why it matters for Justin's agents:** The PROFILE waiting room is a simple pattern for Mitamaton preferences: don't overwrite a user fact on one contradicting turn.
- **Action signal:** `compare`

## Conflicts & open questions

- **Designed memory vs raw history + search.** MemoryTax (2610.29823) finds pre-built memory (Mem0, Zep) a costly patch for weak models and capped by the writer; PreCoMem (2610.29467) reports SOTA on LoCoMo/LongMemEval-S with belief-style consolidation, and MCCL (2610.29357) argues memory should drive continual learning. - **Memory as attack surface vs shared memory as a feature.** The production study (2610.28810) shows shared org memory spreads compromise across users; PerMIT (2610.28987) argues community-confirmed shared memory can be safe under its trust assumption (only user input and gate-confirmed values trusted). Open: PerMIT's guarantee depends on the gate; the production attacks enter through skills and MCP resources users may confirm without reading. Extends Oct 21's CarryoverBench / ClawMMU thread.
- **Who should verify an agent's work.** Fresh-context same-provider verification adds detection and another provider adds none (2610.28667); VerifierBench (2610.28679) shows generated verifiers share the builder's wrong assumptions; VeriEvolve (2610.29005) gets reliable evaluators only when an external verifier exists for calibration; approval monitors on the same evidence fail together (2610.29178). - **Do self-evolving harnesses keep improving?** SSR (2610.28815) shows existing methods degrade as the task pool grows; HGM-Dual (2610.30042) reports 2-4x budget savings; the scored-edit RSI study (2610.29121) shows gains over HGM vanish with Claude Sonnet 4.5 (86.6% vs 86.5%); GuideEvolve (2610.30017) is evaluated only on MGSM/MMLU. Extends Oct 21's RSI evidence-audit carry-forward.
- **Single-turn vs interactive rankings.** UserSWE (2610.29822) finds coding-agent rankings change with interaction budget; SWE-DIVE (2610.30047) gives no numbers; PAUSE (2610.29870) and the stuck-agent study (2610.28834) are evaluated on single-turn SWE-bench Verified.
