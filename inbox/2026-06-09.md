# AI Research Digest — Tuesday, June 09, 2026

## TL;DR
- **Anthropic publishes the cleanest "tool layer beats model choice" result yet.** *Paving the way for agents in biology* introduces **VirBench** (120 viral-sequence queries × 40 pathogens) and shows raw frontier models swing from **16.9% → 91.3%** depending on series, with **same-query run-to-run variability so bad Claude Sonnet 4 returned 106 / 15 / 5 sequences on three identical runs (expected 266)**. The post explicitly argues that *adding the deterministic layer made model choice much less important* — the strongest published case for the "infrastructure-first, model-second" agent design pattern.

First public architecture explicitly grafting Kahneman's dual-process split onto agent memory, with the *implicit-reasoning-across-sessions* benchmark family as the right evaluation target.
- **Agent harnesses are now self-improving with measured 15–21 point gains on Terminal-Bench 2.0.** [arxiv:2606.09498] *Self-Harness* runs a three-stage loop: identify model-specific failure patterns → generate harness modifications → validate via regression testing. **MiniMax M2.5: 40.5% → 61.9%, Qwen3.5-35B-A3B: 23.8% → 38.1%, GLM-5: 42.9% → 57.1%**. Best same-auditor localization accuracy across all four benchmarks, with the **largest gains on structured tool-use traces** and explicitly works *even when ground-truth answers are unavailable*. Direct production-debugging pattern.

## Items

### 1. Paving the Way for Agents in Biology — VirBench (120 queries × 40 pathogens); Raw Models 16.9%–91.3%, gget virus Tool Lifts All to >90%, Peak 99.7% (GPT-5.5); Run-to-Run Variability Eliminated
- **Source:** Anthropic Research
- **Link:** https://www.anthropic.com/research/agents-in-biology
- **Authors / org:** Anthropic (post dated June 8, 2026); collaboration with NCBI
- **Focus area:** Tools & connectors (deterministic retrieval layers for agents) / Frontier-model behavior under tool grounding
- **What it is:** Position-and-evidence post arguing that biological data infrastructure needs explicit redesign for AI agents, parallel to how software dev infra has optimized for agent navigation. Introduces **VirBench**, a benchmark of **120 realistic viral-sequence queries spanning 40 pathogens**. Without specialized tools, frontier models produce dramatically different answers — **mean accuracy ranges 16.9% to 91.3%** across Claude Sonnet 4, Claude Opus 4.7, Biomni OSS, Edison Analysis, GPT-5.2-pro, and GPT-5.5. **Run-to-run variability under identical queries is severe**: Claude Sonnet 4 returned 106, 15, and 5 sequences on three runs of the same query (correct answer: 266). When agents are given access to **gget virus** — a deterministic NCBI retrieval layer — **every model exceeds 90% accuracy, peaking at 99.7% (GPT-5.5)**, and run-to-run variability is largely eliminated. The paper explicitly concludes that "adding a deterministic retrieval layer made model choice much less important," letting cheaper models with appropriate tools match frontier models on reliability.
- **Why it matters for Justin's agents:** This is the cleanest published statement of the "infrastructure-first" position for production agents — and Anthropic is the source, making it doubly relevant for Justin's Claude Code + MCP stack. Three concrete takeaways: (1) the **same-query non-determinism** (106 / 15 / 5 sequences on repeated runs) is the failure mode that's hardest to catch in CI because it's not a deterministic regression — it's *trial-level variance*; any production agent over an external API will exhibit this without a deterministic intermediary. (2) The **gget virus** layer is structurally what MCP servers *should* be — a thin, deterministic, well-typed wrapper over an authoritative source. It is the production-ready instantiation of the precondition-effect-contract pattern from [arxiv:2606.06284] CMTF / ToolChoiceConfusion. (3) "Model choice matters less when tools are right" is the direct operational counterpart of [arxiv:2606.05806] ToolMaze's "fault tolerance scales 3.66× slower than baseline as model size grows" — both papers converge on *don't outscale the problem; close it at the tool boundary*. For Justin's companion-app and federal-data work, the actionable read is: wherever there's an authoritative API (NCBI, OpenAlex, SEC EDGAR, agency endpoints, internal DBs), the right move is a thin deterministic MCP wrapper that quietly turns model-choice into a sub-dominant variable.
- **Action signal:** `try-now` — `gget virus` is open source; the pattern (deterministic wrapper, query normalization, schema-validated returns) ports directly to any well-typed API Justin already hits from MCP. The benchmark structure (a small set of queries with known-correct return sets + repeated runs) is also reusable as a CI shape for *any* MCP server.

### 2. DCPM / Memory Beyond Recall — Dual-Process (System1 / System2) Cognitive Memory for Self-Evolving Agents; +5.20 on PersonaMem-v2, Gains on LongMemEval Implicit Reasoning, Minimal on Span Recall
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.09483
- **Authors / org:** Tianxiang Fei, Mingyang Song, Mao Zheng, Xiang Yu
- **Focus area:** Agent memory (dual-process cognitive architecture)
- **What it is:** Memory architecture organizing agent state **hierarchically from raw inputs → atomic facts → diachronic belief trajectories → identity → domain schemas**. Two complementary processes inspired by Kahneman's System1 / System2 split: **System1 records belief updates inline** (fast, low-cost, synchronous), **System2 asynchronously identifies patterns and consolidates schemas** (slower, off-path consolidation). Headline numbers: **+5.20 on PersonaMem-v2** where cross-session inference is rewarded; explicit gains on **LongMemEval implicit-reasoning tasks**; strongest gains on tasks requiring "understanding how users evolve over time." Span-recall gains are *minimal* — by design, since the architecture is targeting consolidation, not retrieval.
- **Why it matters for Justin's agents:** Direct successor to the memory-systems consolidation thread that's been building since [arxiv:2606.06448] (systems-level memory taxonomy, June 5) and last night's [arxiv:2606.05761] SubtleMemory ("all systems weak on relational discrimination"). DCPM is the first public architecture that explicitly *names the two-process structure* most production memory layers (Mem0, A-Mem, LangMem, MemOS) leave implicit — and the empirical pattern (span recall flat, implicit-reasoning-over-time strong) is the right shape: it tells you what kind of bug the architecture *should* fix. For a companion app, this maps directly to "the user said something three sessions ago that contradicts what they're saying now" — exactly the case SubtleMemory said current systems fail. The asynchronous-System2 path is also structurally compatible with a heartbeat / monitor-driven loop: schema consolidation runs on its own cadence, not inline. Composes with [arxiv:2606.04703] Continual Experience Internalization's "principle-level durable, instance-level induces collapse" finding — DCPM's hierarchy explicitly distinguishes the two: atomic facts and belief trajectories at the instance layer, schemas at the principle layer, and the consolidation step is what moves signal from one to the other.
- **Action signal:** `try-now` — the dual-process abstraction is small enough to graft onto an existing memory layer (Mem0 / MemOS / a vault-backed retrieval store): the System1 path is what most systems already have; adding an asynchronous System2 consolidator (run nightly on the vault, materialize schemas back into the retrieval layer) is a discrete, testable change. PersonaMem-v2 + LongMemEval are the right evaluation pair.

### 3. Self-Harness — Harnesses That Improve Themselves; +21.4 (MiniMax M2.5), +14.3 (Qwen3.5-35B-A3B), +14.2 (GLM-5) on Terminal-Bench 2.0
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.09498
- **Authors / org:** Hangfan Zhang, Shao Zhang, Kangcong Li, Chen Zhang, Yang Chen, Yiqun Zhang, Lei Bai, Shuyue Hu
- **Focus area:** Agent orchestration (harness-level self-improvement) / Coding agents
- **What it is:** Framework where LLM agents **autonomously enhance their operational harnesses** via an iterative three-stage process: (1) identify model-specific failure patterns from execution logs, (2) generate **targeted harness modifications** (not generic prompt edits), (3) validate via regression testing before adoption. Three models tested across **Terminal-Bench 2.0**: **MiniMax M2.5: 40.5% → 61.9%**; **Qwen3.5-35B-A3B: 23.8% → 38.1%**; **GLM-5: 42.9% → 57.1%**. The authors emphasize that the framework *does not simply add generic instructions* — it turns **model-specific weaknesses into concrete, executable harness changes**, framing agents as participants in optimizing their own operational environment, not static artifacts shaped only by human design.
- **Why it matters for Justin's agents:** Third consecutive week of self-improvement papers, but this is the first to attack the **harness layer** explicitly — distinct from [arxiv:2606.05922] RHO (harness optimization), [arxiv:2606.06741] OpenSkill (skill bootstrapping), and [arxiv:2606.07412] Socratic-SWE (trace-distilled skills) by *naming the model-specific failure pattern* as the unit of edit. The MiniMax M2.5 gain (+21.4 absolute) is the largest single-model lift Justin has seen in a self-improvement paper since Vortex, and the fact that all three gains are double-digit on the *same benchmark* is the strongest evidence yet that the harness layer is undersold as a tuning target compared to the model or skill layers. For Justin's Claude Code + MCP setup, the pattern is directly transferable: Claude Code's session log already captures the equivalent of "model-specific failure patterns" (retry loops, mis-typed tool args, premature stop conditions); a Self-Harness-style loop running over recent Claude Code transcripts and producing CLAUDE.md / settings.json / MCP-config diffs is the natural shape. Pairs with [arxiv:2606.08348] Bayesian-Agent (today, separate listing) — Bayesian-Agent operates at the skill-state layer with patch/split/compress/retire/explore actions, Self-Harness operates one layer up at the harness layer; both treat the agent's operational structure as a posterior to update.
- **Action signal:** `try-now` — the failure-pattern → harness-edit → regression-test loop is implementable against any logged-trace store; for Claude Code specifically, the harness *artifacts* (CLAUDE.md, agent files, settings.json, hooks, MCP allowlists) are exactly the kind of structured, version-controlled surface this loop edits well.

### 4. REFLECT — Intervention-Supported Error Attribution for Silent Failures in LLM Agent Traces; Best Same-Auditor Localization Across 4 Benchmarks; Largest Gains on Structured Tool-Use Traces; Works Without Ground Truth
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.09071
- **Authors / org:** Xiaofeng Lin, Yingxu Wang, Tung Sum Thomas Kwok, Daniel Guo, Sahil Arun Nale, Charles Fleming, Guang Cheng
- **Focus area:** Agent orchestration (silent-failure diagnosis / debugging) / Error attribution
- **What it is:** Error-attribution method for "silent failures" — agent traces where the final output looks plausible but contains errors that downstream consumers don't catch. Loop: (i) diagnose a candidate error step, (ii) **test it via controlled replay with a diagnosis-specific patch**, (iii) use the **verified outcome-flip** (does patching this step actually fix the trace?) as contrastive evidence to refine the final attribution. Benchmark results: **best localization accuracy among same-auditor methods across all four benchmarks tested**, with the **largest gains specifically on structured tool-use traces**. Critically, the method **works even when ground-truth answers are unavailable** — the outcome-flip is itself the evidence.
- **Why it matters for Justin's agents:** Silent failures are the most expensive class of bug in production agent stacks because they evade outcome-based monitoring — exactly the class [arxiv:2606.05806] ToolMaze named (`Perturbation Recovery Rate drops 37% under *implicit* semantic failures because agents over-trust corrupted outputs`). REFLECT is the **diagnostic counterpart** to that observation: where ToolMaze measures recovery, REFLECT localizes the step at which trust was misplaced. The "works without ground truth" property is the operational lift — in a production Claude Code session or an MCP-server-heavy companion app, there is no labeled correct trace; the only signal available is "does intervening at this step change the final outcome?" That is exactly REFLECT's primitive. The largest-gain-on-tool-use-traces finding is the direct fit for Justin's stack, where most session-level errors *are* in the tool layer (mis-parsed JSON, stale auth, wrong arg shape). Together with [arxiv:2606.09498] Self-Harness (today), this forms a clean two-stage post-mortem pipeline: **REFLECT localizes the failure, Self-Harness edits the harness so the failure doesn't recur**.
- **Action signal:** `try-now` — replay infrastructure already exists in Claude Code (transcripts + deterministic tool dispatch + a settable seed); the REFLECT loop is implementable against a transcript store today. The controlled-replay primitive is also reusable for unit-testing MCP server changes.

### 5. Latent Context Language Models (LCLMs) — Encoder-Decoder Context Compression at 1:4 / 1:8 / 1:16, Pre-Trained on 350B+ Tokens; Long-Horizon Agents Compress Then Selectively Expand
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.09659
- **Authors / org:** Ang Li, Sean McLeish, Haozhe Chen, Nimit Kalra, Zaiqian Chen, Artem Gazizov, Venkata Anoop Suhas Kumar Morisetty, Bhavya Kailkhura, Harshitha Menon, Zhuang Liu, Brian R. Bartoldson, Tom Goldstein, Sanae Lotfi, Micah Goldblum, Pavel Izmailov
- **Focus area:** Context engineering (end-to-end learned compression, encoder-decoder)
- **What it is:** Addresses the long-context KV-cache memory wall by training **Latent Context Language Models** (LCLMs) with an **encoder-decoder architecture** that maps long token sequences into **shorter latent embeddings the decoder consumes directly**. The paper runs an explicit architecture search and continually pretrains **0.6B-encoder + 4B-decoder models on 350B+ tokens each**, at compression ratios of **1:4, 1:8, 1:16**. Improvements reported across general-task benchmarks, compression speed, and peak memory usage, and — important for agents — the architecture **lets long-horizon agents compress contexts while selectively expanding relevant segments** rather than committing to one fixed compression ratio.
- **Why it matters for Justin's agents:** This is the first end-to-end-learned long-context compression paper at frontier-relevant scale (350B+ tokens of continual pretraining) that **publishes an agent-shaped use case** (compress-then-selectively-expand) rather than just a static long-context benchmark number. The selective-expansion property is the key piece for autonomous loops: Justin's heartbeat-style and monitor-driven agents accumulate context faster than they can read it, and the operational pattern they want is *not* "always-on full attention" but "summary in latent space, expand on demand." LCLMs put that expansion under the model's control instead of the harness's. Composes naturally with [arxiv:2606.09079] FlashMemory-DeepSeek-V4 (separate today): FlashMemory cuts KV-cache footprint at *inference* time via lookahead-sparse-attention indexing (13.5% of full-context cache, +0.6% accuracy on average), LCLMs cut it at *encode* time via learned compression. The two attack the same memory wall from opposite directions and can stack. **Not local-runnable today** (the 0.6B + 4B configuration is small enough but the paper does not release weights yet) but defines the architecture Justin should expect to see in MLX form within months.
- **Action signal:** `track` — paper-level result, no weights yet. The compress-then-selectively-expand interface is the architectural signal worth carrying into design conversations now; integrate when an open release lands.

### 6. Anything2Skill — Compiling External Knowledge Into Reusable, Executable Skills; 98.85% qsv, 94.10% GitHub-CLI; SkillBank With Taxonomy-Aware Compilation and Lifecycle Tracking
- **Source:** arXiv
- **Link:** https://arxiv.org/abs/2606.09316
- **Authors / org:** Qianjun Pan, Yutao Yang, Junsong Li, Jie Zhou, Kai Chen, Xin Li, Qin Chen, Liang He
- **Focus area:** Tools & connectors (knowledge → reusable skill compilation) / Agent orchestration
- **What it is:** Compiler-style framework that takes **heterogeneous external knowledge sources** (docs, repos, web) and emits **reusable, retrievable, executable skills** rather than treating them as passages for retrieval-augmented generation. Pipeline: evidence decomposition → skill extraction → structured **skill contracts** with **invocation conditions, action sequences, constraints, and confidence scores** → a persistent **SkillBank** with taxonomy-aware compilation and lifecycle tracking. At inference, agents read **both** declarative passages (RAG-style) *and* procedural skills (Anything2Skill). Headline numbers: **98.85% success on the qsv benchmark, 94.10% on GitHub-CLI**, both "substantially outperforming RAG-only agents."
- **Why it matters for Justin's agents:** This is the direct architectural answer to the "RAG doesn't know how to *do* anything" failure mode that hits every MCP-heavy stack. Anything2Skill says: stop retrieving prose; compile knowledge **into a tool the agent can invoke**, with explicit preconditions and confidence scores. The GitHub-CLI score (94.10%) is the most relevant to Justin's day-to-day — `gh`-style CLI invocation is exactly the surface where prose retrieval consistently underperforms because the model has to reconstruct argument shape from text every call. The skill-contract schema (preconditions / effects / confidence) is also structurally compatible with [arxiv:2606.06284] CMTF's precondition-effect-contract filter from last week — Anything2Skill *produces* contracts, CMTF *consumes* them at selection time. Composes upstream of [arxiv:2606.06741] OpenSkill (no-supervision verifier bootstrapping) — OpenSkill discovers verifiers from open-world resources, Anything2Skill discovers skill contracts. Together they're a credible end-to-end pipeline from "agent has access to docs and repos" to "agent has typed, verifiable skills."
- **Action signal:** `try-now` — the skill-contract schema is the smallest extractable piece and the highest-leverage to graft onto Justin's MCP server registry; even a manual one-time pass over a few key repos (Justin's own MCP servers, gh, gget, jq, ripgrep, etc.) to emit skill contracts would tighten tool selection materially.

### 7. Multi-Turn Evaluation of Deep Research Agents Under Process-Level Feedback — Self-Reflection ≈ 0 Net Gain; Process Feedback +8–15 pts Single Round at ~35–40% Incorporation; Up to 24% Regression on Previously-Satisfied Criteria Across Turns (ICML 2026 SCALE Oral)
- **Source:** arXiv (ICML 2026 SCALE workshop, Oral)
- **Link:** https://arxiv.org/abs/2606.09748
- **Authors / org:** Rishabh Sabharwal, Hongru Wang, Amos Storkey, Jeff Z. Pan
- **Focus area:** Evaluation (multi-turn deep-research agents under feedback)
- **What it is:** Empirical study asking whether deep-research agents can actually *improve* across iterative feedback rounds. Introduces **Research Gap Inference (RGI)** to identify strategic gaps in the agent's research process (not just output errors). Three findings: (1) **Self-reflection produces negligible net improvement** — agents incorporate and regress on rubric criteria at nearly equal rates; (2) **a single round of process-level feedback yields ~8–15 normalized points** of improvement with **~35–40% incorporation rate**; (3) **multi-turn regression is severe** — agents regress on **up to 24% of previously-satisfied rubric criteria** when rewriting full reports. Authors conclude that "reliable multi-turn improvement remains out of reach" for the evaluated architectures.
- **Why it matters for Justin's agents:** This is the single most important *negative* result for any long-running autonomous-loop design Justin is considering. The headline that "self-reflection is roughly net zero" is consistent with the broader 2025–2026 finding that introspection without external feedback is weak, but the **24%-regression-on-previously-satisfied-criteria** number is what changes loop design. It says: the naive "every cycle, re-edit the whole report" loop *loses ground* on prior wins as fast as it gains on new ones. The implication for a deep-research-style companion app or federal-data report-generation pipeline is sharp: **constrain the edit surface per cycle** (only the rubric criteria flagged "not yet met" get touched), or use a **rubric-pinned diff** rather than a full rewrite. Process-level feedback at ~35–40% incorporation also implies a need for *graders* that produce specific, addressable suggestions, not holistic scores. Composes against [arxiv:2606.09498] Self-Harness (today) — Self-Harness shows *harness-level* self-improvement *does* work when the edit surface is structurally constrained (failure-pattern → executable harness change → regression test); the contrast with this paper's full-rewrite-style multi-turn regression is exactly the "constrain the edit surface" lesson.
- **Action signal:** `track` (decision-affecting) — the 24% regression number should be reproduced in Justin's own loop before adopting any "rewrite-every-cycle" multi-turn improvement pattern; the rubric-pinned-diff design is what to build instead.

### 8. OpenEnv — Open Standard for Agentic-RL Environments; Gymnasium-Style API Over HTTP / WebSocket / MCP; Backed by Meta-PyTorch, NVIDIA, Reflection, Unsloth, Modal, Prime Intellect, Hugging Face + 20 More
- **Source:** Hugging Face blog (collaboration announcement)
- **Link:** https://huggingface.co/blog/openenv-agentic-rl
- **Authors / org:** Hugging Face + Meta-PyTorch + ~20-org coordinating committee (Reflection, Unsloth, Modal, Prime Intellect, NVIDIA, Mercor, Fleet AI, vLLM, SkyRL/UC Berkeley, Lightning AI, Axolotl AI, Stanford Scaling Intelligence Lab, Scale AI, and others); published June 8, 2026
- **Focus area:** Tools & connectors (open standard for RL environments) / Long-running autonomous loops
- **What it is:** An **interoperability layer for RL environments** — terminals, browsers, code sandboxes — that agents interact with. Architecture: **client/server, Gymnasium-style API** (`reset() / step() / state()`), transports over **HTTP, WebSocket, and MCP (Model Context Protocol)**, Docker-packaged for deployment. **Protocol layer only** — does *not* define rewards or training loops; reward design and trainer code stay with the user. Repo at github.com/huggingface/OpenEnv. Coordinating committee includes Meta-PyTorch, Reflection, Unsloth, Modal, Prime Intellect, NVIDIA, Mercor, Fleet AI, and Hugging Face; further backing from PyTorch Foundation, vLLM, SkyRL (UC Berkeley), Lightning AI, Axolotl AI, Stanford Scaling Intelligence Lab, and Scale AI.
- **Why it matters for Justin's agents:** Two structural signals matter independently of whether Justin trains anything. (1) **MCP is now a first-class transport for RL environments** — not just for chat-time tool calls. That confirms the protocol Justin's stack already speaks is the one the agentic-RL infrastructure is standardizing on; environment authors can ship a single Docker image and have it consumable from training stacks *and* runtime MCP clients with the same protocol. (2) The **~20-org coordinating list is the broadest open-stack alignment of the last six months** — Meta-PyTorch + NVIDIA + vLLM + Modal + Prime Intellect + Hugging Face on the same protocol is the open-source posture closing the gap with OpenAI-style closed RL environment loops. For Justin specifically, the practical wins are: existing MCP servers can expose RL-environment surfaces (terminal, browser, code sandbox) with minimal wrapping, and downstream skill / harness / agent-evolution research (Self-Harness, RHO, OpenSkill, Bayesian-Agent) gets a standard environment substrate to evaluate against. Not a research result per se — but the protocol decision is consequential for what's runnable in 2026.
- **Action signal:** `try-now` (low-effort) — the `reset() / step() / state()` shape over MCP is small enough that Justin can prototype an OpenEnv-compatible terminal environment as a thin layer over an existing MCP server; the Docker-packaged shape makes it trivially shareable.

## Conflicts & open questions
Cross-referenced against `_meta/claims-ledger.md`:
- **No direct conflicts flagged today.** Today's items mostly *extend* prior claims:
  - **VirBench / gget virus (Anthropic)** is the empirical confirmation of [arxiv:2606.05806] ToolMaze's "fault tolerance scales 3.66× slower than baseline as model size grows" thesis from the opposite angle: ToolMaze said *more model doesn't fix tool fragility*; Anthropic shows *the right tool layer makes model size sub-dominant*. Same conclusion, two independent benchmark families.
  - **DCPM (Memory Beyond Recall)** extends [arxiv:2606.06448] systems-level memory taxonomy and last night's [arxiv:2606.05761] SubtleMemory by making the System1/System2 split explicit and giving the relational-discrimination gap that SubtleMemory documented a candidate architectural fix (asynchronous schema consolidation in System2).
  - **Self-Harness** extends the trace → skill / harness self-improvement cluster ([arxiv:2606.05922] RHO, [arxiv:2606.06741] OpenSkill, [arxiv:2606.07412] Socratic-SWE, [arxiv:2606.04703] Continual Experience Internalization) by operating at the *harness* layer (not skill / not weights) and giving the first cross-model triangulation with double-digit gains across MiniMax / Qwen / GLM.
  - **REFLECT** is the *diagnostic* counterpart to [arxiv:2606.05806] ToolMaze's *measurement* of recovery: where ToolMaze names implicit-failure recovery as the bottleneck, REFLECT provides the controlled-replay primitive for finding where the trust-misplacement happened.
  - **LCLMs** stack with [arxiv:2606.09079] FlashMemory-DeepSeek-V4 (today, separate listing): LCLMs compress at *encode* time, FlashMemory compresses at *inference* time. Two layers, same memory wall.
  - **Multi-Turn DR Eval's 24% regression** is a sharp negative result against the implicit "iterative feedback monotonically improves" prior of much 2026 agent work — and it's the *complement* to Self-Harness's positive result: Self-Harness constrains the edit surface (failure-pattern → executable harness diff → regression test) and gains compound; the DR Eval setup lets agents rewrite full reports and gains decay. Same paper-pair, opposing edit-surface designs, opposite directions of change — the cleanest "constrain the edit surface" lesson published this week.
  - **OpenEnv** confirms MCP as the consensus runtime/training transport but does not contradict any prior claim.
- **Open empirical questions:**
  - Does DCPM's System2 asynchronous-consolidation gain hold when System2 runs on a *smaller* model than System1 (the realistic deployment posture for a vault-side consolidator)?
  - Does Self-Harness's harness-edit loop produce gains on a *frontier-class* base model (Claude Opus / GPT-5.5 / Gemini), or is the 15–21 point lift specific to mid-tier models where there's more headroom?
  - REFLECT's "works without ground truth" claim — how does diagnostic accuracy decay when the *outcome flip* signal is noisy (e.g., stochastic tools, flaky environments)? The Anthropic VirBench data (106 / 15 / 5 sequences on repeated identical runs) is a real-world instance where outcome-flip would be unreliable.
  - LCLMs' selective-expansion behavior — does the model learn to expand the *right* segments under agent workloads, or does it default to expanding the most recent? The paper presents the capability; agent-task ablations would settle whether it's controllable.
  - VirBench-style "swap the tool, not the model" benchmarks: does the result transcend biology, or is the gap specific to NCBI being a notoriously brittle API? Replication on SEC EDGAR / OpenAlex / agency-data endpoints would tell.
