# AI Research Digest — Wednesday, October 21, 2026

## TL;DR

- **CarryoverBench** (2610.28425): one injection written to a memory file or scheduled task re-fires across sessions with no measurable decay over five rounds on five frontier models; once planted, trigger-time defenses add little — memory writes need runtime provenance controls (see ClawMMU 2610.28093).
- **REM** (2610.27377): gated, one-shot injection of a compact phase-structured experience doc beats SOTA memory systems on SWE-ContextBench Lite (27.6% vs 24.9% resolution, 17% cheaper); the same experience as summary or raw trajectory does not help even when oracle-retrieved.
- **Multi-agent vs single agent with users** (2610.27655): on tau2-bench the centralized MAS is worse in 12 of 13 cells (weighted -28 points) and at best ties at 5.5x tokens — default to one agent for user-facing work.
- **Compaction for later questions** (2610.27301): selecting sentences for the current question does no better than random deletion for later questions; on tau-bench trajectories exact identifiers decide which method wins.
- **Agent S4 / Evolving Agent Interfaces** (2610.28601): evolved interfaces take Qwen3.8-27B to 21.3% on OSWorld V2 (3.8x fixed interfaces), above GPT-5.5 and Claude Opus 4.8 at a fraction of the cost.
- **Authorization** — per-action guards cannot catch relational violations (Local Allow, Global Deny 2610.27620); agents act out of delegated scope in 19.2% of runs, less when they consult the user first (AuthorizationBench 2610.27548); subagents can talk supervisors into widening their scope (Show-up 2610.27574).
- **Unattended self-improvement** (2610.27465): an LLM judge gave the same score regardless of input in 9 of 37 settings; only changes whose old version is kept verbatim are reliably reversible — let prompt/tool/skill edits run unattended only then.
- **Memory can hurt** — stored abstractions reproduce their own errors (Anti-Persistence 2610.27406); code agents reuse memory without checking applicability (MemDev-Bench 2610.27524); driving-agent memory gains vanish against token-matched filler (2610.27714).
- **Silent tool errors** (2610.27777): plausible-but-wrong tool values roughly halve success across 10 LLMs and are harder than explicit failures.
- **Toolflation** (2610.28454): seller agents inflate tool descriptions; under one model buyers fall back to list position and success drops 89% -> ~30%.

### 1. After the Attacker Leaves: Benchmarking Carryover Attacks on LLM Agents
- **Source:** arXiv (cross-list)
- **Link:** https://arxiv.org/abs/2610.28425
- **Authors/org:** Zhiyue Xu, Xukai Wang, Zhiyuan Huang, Mingjie Zhan, Jian Zhao, Xu-Yao Zhang
- **Focus area:** persistence security / memory files + scheduled tasks
- **What it is:** CarryoverBench: 12 personal-assistant scenarios, 101 attack tasks over three trigger channels (Instant same-turn injection; Autonomous heartbeat-scheduled; Latent memory-resurfaced). A rule-based verifier scores planting and triggering separately. Across five frontier models, planted payloads re-fire without measurable decay over five rounds; once planted, the trigger stage adds little protection. Porting the Latent channel to the Hermes runtime attenuates but does not remove the effect.
- **Why it matters for Justin's agents:** Mitamaton-style agents with memory files prepended to the system prompt and scheduled wake-ups are exactly this surface: one injection written to memory keeps firing. Defense must live in the runtime (write-time provenance, memory review), not only prompts.
- **Action signal:** `try-now`

### 2. REM: What to Store, When to Recall, What to Forget in Experience Memory for Coding Agents
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.27377
- **Authors/org:** Xinyi Lisa Chen, Pedro Herrero-Vidal, Xiaohan Chen, Xiaojing Yu, Cris Liu, Bingqing Song, Bin Xu, Suleiman A. Khan, You-Lin Chen
- **Focus area:** experience memory for coding agents
- **What it is:** REM manages experience memory from inside the think-act loop: store each trajectory as a phase-structured document ~100x smaller; inject it at task start and withhold the costlier implementation record until an in-loop gate detects struggling; evict the record after one exposure. On SWE-ContextBench Lite: 68.7% vs 55.6% match@1 retrieval vs SOTA memory systems, resolution 27.6% vs 24.9% in every replicate at 17% lower cost. Injecting the same experience as summary or raw trajectory, even oracle-retrieved, does not help.
- **Why it matters for Justin's agents:** Store/recall/forget policy matters more than retrieval quality; a gated, one-shot injection is a cheap pattern for Claude Code session memory.
- **Action signal:** `try-now`

### 4. Evaluating Context Compaction on the Questions That Come Later
- **Source:** arXiv (cross-list)
- **Link:** https://arxiv.org/abs/2610.27301
- **Authors/org:** Junwei Yao, Yongxi Zhou, Zike Yang, Zhijun Wang, Jianan Liu, Yanxian Chen, Wenbo Ye
- **Focus area:** context compaction / later questions
- **What it is:** Evaluates compaction on later questions, not just the current one, against random deletion at equal budget. Sentence selection for the current question raises current accuracy (+11.4 points at 25% tokens on MultiRC) but does no better than random deletion on later questions; LLMLingua-2 (question-agnostic word deletion) beats random sentence deletion by 12.5 points on later MultiRC questions. Rankings flip by setting: on tau-bench trajectories (exact identifiers needed later) sentence selection beats random while LLMLingua-2 shows no gain.
- **Why it matters for Justin's agents:** Compaction tuned to the current task can silently starve later turns; keep exact identifiers and evaluate compaction on downstream questions.

### 6. Local Allow, Global Deny: Why Per-Action Authorization Does Not Compose in LLM Agents
- **Source:** arXiv (cross-list)
- **Link:** https://arxiv.org/abs/2610.27620
- **Authors/org:** Anmol Pandey, Aditya Jain, Liang Chen, Carsten Maple
- **Focus area:** tool authorization / compositional failures
- **What it is:** Local Allow, Global Deny: per-action authorization (a guard screening each tool call alone) does not compose into global authorization. ### 8. Recoverability and Verifier Strength: Two Measured Preconditions for Unattended Agent Self-Improvement

- **Authors/org:** De Wang, Peng Qi

### 9. More Memory, Worse Agents: Error Reproduction and Anti-Persistence in LLM Agents
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2610.27406
- **Authors/org:** Ruhan Wang, Kishan Panaganti, Dongruo Zhou

## Conflicts & open questions

- **Does agent memory help?** REM (2610.27377) and ProMemAgent (2610.27400) report gains; Anti-Persistence (2610.27406) shows stored abstractions reproduce errors, MemDev-Bench (2610.27524) shows memory breaks otherwise-solvable tasks when reused without an applicability check, and the driving-agent study (2610.27714) finds no retrieval design beats token-matched filler once warmup pools are resampled. Shared thread: store raw outcomes/process info, gate when it is injected. Carries forward the Oct 19–20 open question (memory benchmarks not comparable; simple retrieval often wins).
- **Single vs multi-agent.** The dual-control study (2610.27655) finds MAS worse in 12 of 13 user-facing cells and no reduction in wrongful writes, and Show-up (2610.27574) adds a new MAS attack surface; M-Plan (2610.27032), MAS-Guard (2610.28397) and Sage-style orchestration assume MAS benefits. Different settings (autonomous vs dual-control) — open whether the capability-saturation rule survives user-in-the-loop.
- **Self-evolving harnesses vs evidence quality.** RiseHarness (2610.27435), MaD-RSI (2610.28201), Agent S4 (2610.28601) and TEAL (2610.27327) report gains; the RSI evidence audit (2610.27610) finds only 22% of RSI studies rerun the full loop twice, and Recoverability/Verifier Strength (2610.27465) shows LLM judges can approve anything. Agent S4 and TEAL use held-out validation; RiseHarness uses repeated evaluation; MaD-RSI's abstract gives no numbers. Extends Oct 20's carry-forward (self-evolution gains vs held-out stability).
- **Compaction: which method wins depends on what comes later.** Evaluating Context Compaction (2610.27301) finds current-question selection no better than random deletion for later questions, but on tau-bench (exact identifiers) selection wins and LLMLingua-2 doesn't. Consistent with Oct 20's "When the harness decides success" (keep what can't be re-observed). Today's Claude Code v2.1.306 also fixes an unneeded compaction in many-MCP-tool sessions.
- **Per-action guards vs relational policy.** Local Allow, Global Deny (2610.27620) proves per-action monitors without false alarms miss relational violations; PROVISO (2610.27115), MAS-Guard (2610.28397) and ClawMMU (2610.28093) are per-event/per-action designs (MAS-Guard adds a system-level control plane). Open: none of the guard papers evaluate on AL-SYNTH-style cross-execution witnesses.
