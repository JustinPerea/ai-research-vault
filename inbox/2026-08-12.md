## Items

### 1. SkillZip: Evaluation-Free Skill Compression for Self-Evolving Agents
- **Source:** arXiv (Hugging Face Daily Papers)
- **Link:** https://arxiv.org/abs/2608.11079
- **Authors / org:** Xiaofan Bai / Hongqiang Lin / Chao Liu / Yantao Zhang / Xuan Jin / Xipeng Cao / Yuhong Li
- **Focus area:** Agent skills + self-evolution + context budget
- **What it is:** Self-evolving agents append procedures and failure fixes until the same requirement is restated across branches, examples, and warnings, and common action sequences are copied rather than reused. Generic prompt compression fails because a skill is typed: name/description (when it applies), workflow (how), tool/output contracts (validity), rare exceptions (must keep even if no sampled task hits them). SkillZip finds the **shortest faithful structural explanation** under a typed minimum-description-length objective over a skill contract + residual, with a hard coverage constraint for every extracted trigger, workflow edge, tool requirement, obligation, and output field. One-shot mode = one structured extraction call + deterministic optimization; **Zip-on-Write** integrates each self-evolution patch without replaying tasks or reparsing history. Authors report gains on compression, generalizability, and cost vs prior methods (headline tables not in the abs). Abs verified this run.
- **Why it matters for Justin's agents:** This is the hygiene pass the vault's skill-evolution thread has been missing. WikiSkill / SkillOpt / Trace2Skill (later and earlier vault entries) *grow* the library; SkillZip *keeps it injectable*. Concrete weekend experiment: run Zip-on-Write over `~/.claude/skills` after each successful Mitamaton / Claude Code session — factor repeated action sequences into shared procedures, keep unique rare rules, never flatten SKILL.md into a passage compressor. Do not wait for an eval set to decide what to delete.
- **Action signal:** `try-now` — the one-shot extraction + coverage constraint is a prompt + a checklist, not a training run.
