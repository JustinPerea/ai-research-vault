# AI Research Digest — Wednesday, May 06, 2026

## TL;DR
- **Agent memory had a strong day**: two new edge-oriented frameworks landed — MEMTIER (tripartite memory, +33 pp on LongMemEval-S, runs on 6 GB GPU) and ScrapMem (bio-inspired forgetting, **93% memory reduction** at SOTA Joint@10 51.0). Both target on-device agents.

End-to-end discovery still ~3% perfect — far from solved. *First measured benchmark for Opus 4.7.*

## Items

### 1. MEMTIER: Tiered Memory for Long-Running Autonomous Agents
- **Source:** arXiv (cs.AI, May 5, 2026)
- **Link:** https://arxiv.org/abs/2605.03675
- **Authors / org:** Bronislav Sidik, Lior Rokach
- **Focus area:** Agent memory / Long-running loops
- **What it is:** Tripartite memory system (episodic store + weighted retrieval + semantic consolidation) designed for the OpenClaw runtime. Motivating data point: tool-execution success rates **degrade 14 pp over 72-hour windows** when agents use flat-file memory. On LongMemEval-S, MEMTIER lifts accuracy from a **5% baseline to 38.2%**, with single-session recall 68.6–71.4% and temporal reasoning 32.3% — running locally on a consumer laptop with a 6 GB GPU.
- **Why it matters for Justin's agents:** This is the first published number quantifying *drift* in agent tool-call success over multi-day operation. The tripartite split (episodic vs. semantic vs. consolidated) is exactly the architecture decision a companion-app needs to make early. The 6 GB GPU constraint means it's already runnable on M5 Max.
- **Action signal:** `try-now` — architecture is clearly described; the OpenClaw runtime reference is worth chasing for an open implementation.

### 2. ScrapMem: Bio-Inspired Optical Forgetting for On-Device Agent Memory
- **Source:** arXiv (cs.AI, May 5, 2026)
- **Link:** https://arxiv.org/abs/2605.03804
- **Authors / org:** Jiale Chang, Yuxiang Ren
- **Focus area:** Agent memory / Local & on-device
- **What it is:** Multimodal memory for edge LLM agents. Organizes data into "Scrapbook Pages" and applies "Optical Forgetting" — progressive compression of older memories, conceptually closer to a perception-layer decay than to a TTL/eviction policy. Reports **51.0 Joint@10 (SOTA), 70.3 Recall@10**, and a **93% memory-footprint reduction** via the forgetting schedule.
- **Why it matters for Justin's agents:** Compression-as-forgetting is a different mental model than mem0/LangMem's recency/importance scoring. For a companion app where users accumulate years of conversation, "what to keep at full fidelity" is the real question; ScrapMem's structured aggregation via an Episodic Memory Graph is a concrete answer.
- **Action signal:** `track` — strong numbers but the implementation and the benchmarks aren't widely reproduced yet; revisit if a repo lands.

### 3. QKVShare: Quantized KV-Cache Handoff for Multi-Agent On-Device LLMs
- **Source:** arXiv (cs.AI, May 5, 2026)
- **Link:** https://arxiv.org/abs/2605.03884
- **Authors / org:** Pratik Honavar, Tejpratap GVSL
- **Focus area:** Context engineering / Tools & connectors / Local
- **What it is:** Token-level mixed-precision KV-cache transfer between agents on the same device, with a self-contained "cache card" representation and a HuggingFace-compatible injection path. On 150 GSM8K problems with **Llama-3.1-8B-Instruct**, adaptive quantization stays competitive across repeated handoffs. Headline latency: handoff **TTFT 397.1 ms vs. 1029.7 ms (full re-prefill) at 8K context**. Authors note post-injection generation, not card creation, dominates remaining latency — i.e. the bottleneck has shifted.
- **Why it matters for Justin's agents:** If you build supervisor + worker agents on a single M5 Max, today's pattern is "re-send the prompt and re-prefill" or "share full FP16 KV." This paper's quantized cache card is the missing primitive. Direct applicability to MCP-style multi-agent stacks where a planner hands a workspace to an executor.
- **Action signal:** `try-now` — HF-compatible injection path means a small prototype on Llama-3.1-8B should be feasible without custom kernels.

### 4. Workspace-Bench 1.0: Agents on Real File Dependencies
- **Source:** arXiv (cs.AI, May 5, 2026)
- **Link:** https://arxiv.org/abs/2605.03596
- **Authors / org:** Zirui Tang et al. (20 authors, lead Xuanhe Zhou)
- **Focus area:** Evaluation / Coding agents / Tools
- **What it is:** Benchmark of **388 curated workspace tasks** across **5 worker profiles, 74 file types, 20,476 files (up to 20 GB)** with realistic cross-file dependencies. Best agent **68.7%**, humans **80.7%**, average agent **47.4%**. Workspace-Bench-Lite (100 tasks) cuts eval cost ~70%.
- **Why it matters for Justin's agents:** "Run an agent against a real workspace, not a synthetic sandbox" is the right shape for evaluating a federal-data or repo-scale assistant. The 12 pp gap to humans on real file structures is a sober counter-signal to SWE-bench saturation talk; coding-agent evals on tiny repos are not predictive of multi-GB workspaces.
- **Action signal:** `track` — adopt Workspace-Bench-Lite once any internal agent works on multi-file tasks; the cost ratio matters.

### 5. Robust Agent Compensation (RAC): Log-Based Error Recovery
- **Source:** arXiv (cs.AI, May 5, 2026; ACM CAIS 2026)
- **Link:** https://arxiv.org/abs/2605.03409
- **Authors / org:** Srinath Perera, Kaviru Hapuarachchi, Frank Leymann, Rania Khalaf
- **Focus area:** Agent orchestration / Long-running loops
- **What it is:** Architectural extension that lets an agent compensate for a failure by replaying/inverting through logged state, rather than asking the LLM to plan a recovery. LangChain implementation, also runs on LangGraph. On **τ-bench and REALM-Bench**, RAC is **1.5–8× better in latency and token economy** than SOTA LLM-based recovery.
- **Why it matters for Justin's agents:** This is the missing layer for any long-running MCP agent — when a tool call fails midway through a multi-step plan, "ask the model to figure out what to undo" is both expensive and unreliable. Log-and-compensate is borrowed from saga-pattern transactions and is essentially free at runtime.
- **Action signal:** `try-now` — pattern is implementable today on Claude tool use; the LangGraph reference is a concrete starting point even if you stay outside LangChain.

### 6. Gemma 4: Multi-Token-Prediction Drafters Land for Speculative Decoding
- **Source:** Google Blog (May 5, 2026)
- **Link:** https://blog.google/innovation-and-ai/technology/developers-tools/multi-token-prediction-gemma-4/
- **Authors / org:** Google DeepMind / Google
- **Focus area:** Frontier models / Local & open models / Inference-time compute
- **What it is:** New MTP drafters for the Gemma 4 family (E2B, E4B, **26B MoE / 3.8B active, 31B Dense**, Apache 2.0, up to 256K context on the larger models). The drafter predicts multiple future tokens in parallel; the target verifies in one pass. Reported **up to 3× speedup** with no quality degradation. On **Apple Silicon at batch 4–8**, the 26B MoE specifically gets **~2.2×**. Drafters ship for LiteRT-LM, **MLX**, HF Transformers, and vLLM.
- **Why it matters for Justin's agents:** This is the first MoE that's a credible default for an M5 Max agent loop. 3.8B active params + MTP drafter via MLX means real-time tool-calling and reasoning on-device, with 256K context headroom for long sessions / large file loads. Gemma 4 itself dropped April 2; the May 5 piece is what makes it locally compelling.
- **Action signal:** `local-fit` — see Local-model corner below for memory math.

### 8. ARIS: Auto-Research-in-Sleep — Adversarial Multi-Agent Research Harness
- **Source:** arXiv / HF Daily Papers #1 trending (May 4, 2026; 8.1k upvotes)
- **Link:** https://arxiv.org/abs/2605.03042
- **Authors / org:** Ruofeng Yang, Yongcan Li, Shuai Li (Shanghai Jiao Tong University)
- **Focus area:** Agent orchestration / Long-running loops
- **What it is:** Open-source research harness pairing an executor with a **cross-model-family reviewer** that critiques intermediate artifacts to catch the "plausible but unsupported" failure mode in long-running research agents. Three layers: execution (65+ Markdown skills, model integrations, persistent wiki), orchestration (5 configurable workflows), assurance (integrity verification, claim-to-evidence mapping, claim auditing, math-proof checks). Abstract reports deployment experience, not benchmarks.
- **Why it matters for Justin's agents:** "Different model family as reviewer" is a directly portable pattern — Claude executor + Gemini/GPT reviewer (or vice versa) for any long-running MCP agent that produces written claims. The "Markdown-defined skills" pattern is conceptually the same as Claude Code skills.
- **Action signal:** `track` — no benchmarks yet, but the orchestration template is worth keeping; revisit if/when results land.

## Local-model corner

**Today's headline: Gemma 4 26B MoE + MTP drafters on M5 Max via MLX.**

- **Model:** Gemma 4 26B MoE (3.8B active, Apache 2.0), paired with an E2B MTP drafter
- **Memory fit (rough math):**
  - 26B weights at Q4: **~13 GB**
  - E2B drafter at Q4: **~1 GB**
  - KV cache at 32K context, FP16, GQA: **~6 GB** (full 256K context would push KV alone past 40 GB — don't run max context on a 64 GB box)
  - **Total at 32K context, Q4: ~20 GB.** Comfortable headroom on 64 GB unified memory for tool-use stacks.
- **Realistic tasks:** Agentic loops with tool calls, code edits over a single repo, structured extraction, RAG over a moderate corpus. *Not* deep reasoning at 256K — context-quality on extreme lengths still degrades and the KV math kills you anyway.
- **How to run:** **MLX** is the clean path on M5 Max; the multi-token-prediction blog explicitly ships MLX support today. llama.cpp/Ollama also listed but MLX is preferred for Apple Silicon.
- **Speed estimate:** Google reports **~2.2× speedup at batch 4–8 on Apple Silicon** for 26B MoE with the drafter, on top of the MoE's already-fast 3.8B-active inference. No M5 Max-specific tok/s number published — likely well into the high tens of tokens/sec for single-stream, more for batched.

**Honorable mentions for the M5 Max:** MEMTIER's 6 GB-GPU footprint and ScrapMem's 93% memory reduction are both edge-targeted; either becomes a real option for an on-device companion-app memory layer once code lands. QKVShare's HF-compatible cache cards make multi-agent setups on a single M5 Max viable without re-prefill costs.
